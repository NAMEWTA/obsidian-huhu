Incomplete rows are refused (`source-incomplete`), never guessed. Same native id under two accounts is never merged.
- Preview creates no Session (HistoryCommands.preview unchanged and read-only; chain test asserts zero Sessions).
- Explicit import (`SpaceService.importHistorySession`, GUI `controller.importHistory`, control `history.import`): persists a `SessionRecord.nativeImport` evidence block (sourceRef, accountKey, deviceId, importedAt) plus `historyOwners[sourceRef]` in one write. Refusals are decided before the writer queue so they never mark the persistence layer failed. Annotations untouched (they live in NativeHistory metadata by row key).
- Continue (`NativeResumeService.resumeSource`, GUI `controller.resume`, control `history.resume`): row must be owned by the Space and have an imported Session (else `not-imported`, no empty session). Live runtime (launch-pending/connected) -> attach/locate only. Unconfirmed previous run (disconnected / unconfirmed exit) -> refuse. Ended -> pre-spawn checks in order: source status, provider supported, `verifyResume` (new in launcher.ts: account/device reference + transcript + provider enabled + program, no prompt/record/spawn), Space-authorized cwd equals row cwd (`SpaceService.resolveSpaceCwd`, new read-only), then machine-wide occupancy; then `launchExistingResume` in controller: `prepareSession(..., existingSessionId)` -> `reserveManaged` -> existing `resumeAgent` (literal argv from `resumeArgs`) = SAME Session, new runtime generation. Declined permission -> `cancelled` result, lock released. No fork exists anywhere (not offered).
- Cross-instance occupancy (`native-reference/occupancy.ts`): lock dir `~/.huhu/native-refs/` (per user, outside every Vault). Atomic complete-content create (temp file + hard link, fallback `wx`), JSON record: lockId, owner instanceId/vaultId/spaceId/sessionId/runtimeId, pid, process start marker (Linux /proc starttime, macOS `ps lstart`), hostname, acquiredAt. Reclaim only when owner liveness is `dead` (pid absent, or same pid with different start marker); other host / unknown marker / corrupt file -> conflict, never stolen; reclaimers serialized by a guard file and re-verify lockId. Release only by the lock's own lockId, and only after verified exit (`runtimeEnded`: confirmed termination evidence or exited+confirmed; `disconnected`/unconfirmed exit keep the lock) or when the generation was replaced; launch failure before a generation is reserved releases immediately; `NativeResumeService.dispose()` (controller dispose) releases the rest. Second instance gets `OWNER_CONFLICT` (`occupied`, details spaceId/sessionId/instanceId), same instance other Session `occupied-here`, double click `resume-in-progress`.
- Control ops `history.open|resume|import` now available (schema `available:true`, generator run; Rust wire regenerated), wired in `commands.ts` `captureHistory` (mutation, phases record-saved / launch-pending / running / cancelled / completed, resolved target gains sessionId/runtimeId), explicit `spaceId` required (open derives it from the Session, SCOPE_MISMATCH on conflict). CLI and GUI share `NativeResumeService`.
- GUI (SessionHistoryPanel): Continue now shows an inline confirmation (provider + directory, "choose Space first" note for unassigned), Escape/Cancel start nothing; loading status; single in-flight guard (double activation ignored); success info and error alerts with Dismiss; "Import into Space…" for unassigned rows only (menu + button); Continue disabled with reason when source is not `available`.
