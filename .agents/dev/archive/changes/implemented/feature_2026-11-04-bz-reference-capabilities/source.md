- **直接复制/改编源码**：逐文件记录原路径、提交、原作者、许可、修改点及虎虎落点；例如分卷边界、部分归一化或队列策略，须先剥离宿主与隐式依赖。

## 3. 总体设计原则与归属

### 3.1 不改变虎虎分层

继续沿用 `app / shell / ui / theme / host / shared / modules`；每个业务模块仍由 `manifest.ts → module.ts → core/platform/services/ui` 装配。[H1][H6]

- `core/shared` 放纯模型、判定和算法，不能依赖 Obsidian、React、DOM 或 Node 宿主。
- `host` 负责共享宿主适配，不反向 import `app/contracts`；由 app 装配注入。
- `ui` 放无业务所有权的 React 组件；业务组件归相应模块。
- 跨模块只经对方 `api.ts` 的公开契约，服务获取遵守 `peek/acquire/watch` 和撤销信号。
- UI 只订阅服务状态并发动作，不从组件直接读写 Vault。
- React/Radix/翻页引擎等不得进入插件启动同步依赖闭包。

### 3.2 预定 owner

| 能力 | 预定归属 | 原则 |
| --- | --- | --- |
| 临时反馈协议/策略 | 纯协议在 shared；宿主适配在 host；React 展示在 ui；app 注入 | 不依赖通知模块才能提示写入失败 |
| 持久通知 | 现有 notifications | 不另建中心，不把持久任务等同 toast |
| 领域事件 | shared 通用原语＋各域 api 中的事件契约，app 提供实例/生命周期 | 不用 module-level 全局 Map 跨实例共享 |
| 文件事件适配 | host/obsidian，app 管理其生命周期 | 域语义由 owner 解释，不在 host 硬编码所有业务目录 |
| 密码本 | 现有 safe | 不开放任意模块检索密码的 API |
| 档案×脸谱 | archives 内人物增强子域 | 人物实体/关系仍归 archives；敏感材料通过受控加密端口 |
| 归物本 | archives 物品预设＋专属视图/命令 | 同一物品只有一份主记录；专属界面不等于另建数据库 |
| 日记 | navigator 的周期笔记能力及新增工作台页面 | 增加页面/路由，不增加第二套日记 owner 或 Obsidian ViewType |
| 数据体检 | 拟新增 health 模块，owner provider 贡献 | 必须正式登记 ModuleId、manifest、路由、设置与 i18n；这是规划，不是现成模块 |

只有同时出现两个真实消费场景的纯能力才提炼进 shared；不要借此把所有领域模型提前抽象成万能框架。

## 4. 公共能力 A：统一操作反馈与通知

### 4.1 分成三层，而不是一个 notify 包办

| 层 | 使用场景 | 持久化 |
| --- | --- | --- |
| 即时反馈 | 保存成功、参数无效、复制失败、可撤销操作 | 默认不落盘；页面内 sonner，工作台外原生 Notice，沿用现有规则 |
| 操作状态 | 导入、批量转换、体检、报告计算 | 状态由业务任务服务持有；UI 可关闭/重开观察，是否跨重启由具体任务契约决定 |
| 通知收件箱 | 用户离开后仍需回看的结果、定时提醒、重要任务失败 | 走 `NOTIFICATION_INBOX`，按原幂等/渠道/设备数据规则 |

`NotificationRequest` 当前 `target/presentation` 带自动化语义。[H9] 通用结果接入应扩展可辨别类型或合适的 source/opener，不伪造 automationId/runId，不把 `() => void` 序列化进 inbox。

### 4.2 统一协议应具备的语义

拟议字段：操作 ID、去重键、显式级别、来源域、目标窗口、可本地化文案、确定/不确定进度、动作描述、取消策略、隐私级别、终态。字段命名在 P0 固化，不把本节示意当作已存在 API。

要求：

- 同一任务更新同一反馈实例，不能每处理一个文件弹一条；批量结果显示成功/失败/跳过计数与查看详情。
- 未知总量显示不确定进度，不能伪造百分比；结束状态区分成功、部分成功、失败、用户取消、等待解锁。
- 去重有明确作用域与时间窗；重复回执不重复通知，但不同失败不可因同文案被吞掉。
- 字数较多可延长停留；悬停/键盘焦点中的可操作消息不突然消失；重要动作可从持久页面找回。
- 任务进度/有操作按钮的提示不能被普通成功消息挤走；常驻任务过多须聚合且有上限。
- 降低通知等级不能屏蔽数据未保存、权限失效、冲突和必须处理的确认；防止“已保存”先于提交成功。
- Undo 是 owner 的有条件补偿命令：绑定操作 ID、原对象版本/哈希和有效期；对象已被修改时提示冲突，不覆盖新状态。
- 删除确认不能机械全取消。普通可恢复删除可采用“执行＋撤销”；永久销毁、批量重置、密文迁移继续显式确认。
- 密码/聊天/画像原文不进 toast、系统通知、持久 inbox、错误堆栈和遥测；锁定后只保留脱敏结果。
- 一个 Document 一个宿主，窗口关闭后清理 Portal/计时器/监听；业务任务是否继续由服务决定，不由 toast 是否消失决定。

验收：连续 100 次同任务进度只有一个活动反馈；两窗口归属正确；成功提示仅在真实 commit 后出现；撤销不能覆盖他人/外部新写入；禁用 notifications 时 safe/archives 仍能报告必要错误。

## 5. 公共能力 B：领域事件与文件变化监听

### 5.1 先区分三种机制

**命令**要求执行结果，走 owner API；**领域事件**描述已经发生的事实或索引失效，用于解耦刷新；**持久任务/审计记录**负责重启恢复、幂等与历史，不能用内存事件替代。

上游 bus 是同步 fire-and-forget，不能等待异步 handler，也不保证持久化/去重。[B2] 虎虎可沿用轻量核心，但需补：

- 类型化 event key 与 payload，事件契约归所属域的 api；shared 原语不反向 import 全部业务类型。
- 以当前插件/Vault 实例为作用域，订阅返回幂等 disposer，并可绑定 `AbortSignal`/模块 lifetime。
- 同步异常与异步拒绝都隔离；避免 `async` handler 被误当成已完成命令。
- 本地已提交的操作才发“已变更”；未提交草稿不得冒充持久事实。
- payload 最小化为普通资源 ID、版本/哈希、operationId、原因等；敏感 safe/私密脸谱只发范围失效/锁状态，不广播记录标题、密码或聊天片段。
- 事件只作为失效提示，消费者重新从 owner 查询；不让 React 同时维护一份独立业务真相。
- 防回环使用 operationId/来源/版本及幂等消费，不用简单“忽略下一次 modify”误吞外部编辑。
- 保留现有 zustand subscribe / ServiceAccess.watch 的用途，不为统一而把细粒度状态推送全部改造成 bus。

### 5.2 文件适配策略

参考 bz 将 Vault 事件和 metadata 就绪分开这一关键设计。[B3] 实施前先盘点虎虎现有监听点，再分模块渐进接入，避免一刀切破坏 Navigator/Archives/Versioning 各自的正确性。

共享适配至少处理：文件创建、修改、删除、重命名、目录移动、元数据更新、批次失效。rename 必须含 oldPath/newPath；旧、新路径所属范围都要失效，不能只通知新目录。

必须覆盖：

1. Vault modify 发生时 frontmatter 尚未解析；依赖 metadata 的读取方应等待对应就绪或自己验证内容版本。
2. 文件夹重命名和批量移动；`.md → .txt` / 反向改名；移出档案根目录仍要更新旧索引。
3. 外部编辑、同步临时缺件和事件乱序；短暂缺失先报状态，不立即删实体/关系。
4. 同一保存既有 owner commit 事件又有 Vault 事件时不重复执行业务副作用。
5. 私有 `.huhu/` 的 adapter 写入**不保证有普通 Vault 文件事件**：由对应 repository 成功提交后主动失效，另有手动重读/有限校准；不能指望监听覆盖全部。
6. 高频 modify 可以按路径合并刷新，但不能抹掉 rename/delete 的语义；有界队列、最大等待时间及丢失时的保守 rescan。
7. 卸载/禁用/换窗口后所有监听与 debounce 清理；旧 generation 的异步结果不得更新新会话。
8. 初始索引与事件交接不得漏变化；检索缓存只是投影，重启后能从权威文件重建。

**不把事件中心做成新的写入层**：真实修改仍经 ArchivesCommands、Safe 服务、周期笔记 owner、共享文档修改/恢复队列等完成。[H7][H8][H10][H11]

## 6. 公共能力 C：UI 与操作生命周期

参考的是 bz 的交互一致性，不复制其整套 native DOM/CSS。虎虎现有 [UI 约定][H12] 和 [设计系统][H5] 是实现约束。

### 6.1 优先组合与补齐

在现有 `src/ui/components/huhu/` 中复用/提炼：

| 组合 | 必需行为 |
| --- | --- |
| 列表—详情工作区 | 侧栏/筛选、搜索、选中态、稳定滚动位置；窄容器改为列表→详情，不重复嵌一套 shell |
| 字段与表单 | 可选字段、错误定位、帮助、自动长高备注、重复子项、dirty guard、明确保存状态 |
| 搜索与选择器 | 键盘上下/Enter/Esc，IME composing 不误提交，空结果与加载状态不同 |
| 来源/证据卡 | 来源类型、定位、时间、处理状态、已变化/缺失；敏感内容受锁状态控制 |
| 操作进度 | 已完成/总量/阶段/耗时、暂停/取消/重试及部分失败；组件不自己管理进程 |
| 统计摘要 | 单一计算口径、说明统计范围/时间/币种，缺数据不能显示成 0 |
| 空态/错误态 | 空数据、未初始化、被禁用、未解锁、权限失败、损坏、过期分别呈现 |
| 对话框/菜单 | 使用现有 Radix/Dialog；Esc 只关闭最上层；恢复焦点；危险操作与可撤销动作区分 |

视觉重点：参考密码本三栏、脸谱折页和纪事、归物本 KPI＋状态条、日记的书本阅读节奏；颜色/字体/圆角/阴影仍用虎虎语义 token，不能把参考项目的硬编码皮肤铺进全局。

### 6.2 不可违反的 UI 行为

- 使用所属元素的 Document/Window、对应 Portal；不能顶层捕获全局 window/document。
- ReactSurface 关闭 unmount，隐藏时暂停无必要轮询；领域任务与页面分离。
- 桌面命中目标至少 32px、触屏 44px；有可访问名称、键盘路径、焦点和读屏状态。
- 中文长内容、超长 URL、窄栏、系统缩放、亮暗主题必须覆盖；密码等不因换行策略泄露。
- 支持 reduced-motion；动效不能影响选字、滚动、输入法和表单提交。
- 服务异步写入必须区分 pending/committed/conflict/failed；脏稿离开、上锁、模块禁用各自处理。
- P0/P1 先做代表性可交互样稿，使用生产组件和契约 fixture，防止“原型好看、接入后另写一套”。真实截图与操作验收在实现阶段补齐。

## 7. 数据架构：借鉴职责分离，不照搬存储路径

### 7.1 选择原则

**Markdown**：人要长期阅读、编辑、链接、导出和版本管理的权威内容。可用 frontmatter 存稳定结构，正文保留自由书写。

**JSON**：明确属于结构化交易状态、偏好、任务进度或可重建索引的场景。是否权威取决于业务契约，不能简单认为“JSON 都是缓存”。虎虎 Tasks 的单事务 JSON 就是反例。

**加密载荷**：敏感原始材料、密码、未公开的画像与证据、敏感任务中间产物。结构即使是 JSON，也只能作为加密容器内的明文，不能旁路写到普通 JSON、日志或备份。

**可重建缓存/内存态**：分页、缩略图、检索投影、临时选择、动画和进度展示。不得成为恢复业务事实的唯一依据。

### 7.2 本期数据落点与唯一写入者

| 内容 | 权威格式与位置 | 唯一写入者/约束 |
| --- | --- | --- |
| 已有档案实体、定义、修订、关系 | 继续 `huhu/档案/` 可见 Markdown | ArchivesCommands 和定义/迁移流程；稳定 ID，不按显示名连线 |
| 归物实体及生命周期 | 档案的物品类型 Markdown，复用实体与重复事件字段；最终 schema 在 P0 确定 | archives 物品业务命令；**不同时维护 belongings.json 主副两份** |
| 手动确认的公开人物事实、纪事 | 档案定义允许的字段/正文/关系 Markdown | 预览后由 ArchivesCommands CAS 写入，不能覆盖未涉及字段 |
| 私密聊天、画像草稿、证据、任务断点、敏感缩略图 | 拟议 `.huhu/archives/private/` 下版本化加密集合，路径与信封格式须独立 ADR | archives 私密材料 repository＋有限加密端口；不是新的人物主库，不塞进密码本所有账号的单一载荷 |
| 密码本 | 保持 `.huhu/safe/vault.enc` 及既有加密备份/冲突副本 | safe 独占；格式变化需兼容迁移，普通 JsonStore 禁止消费 |
| 日记正文 | 继续 navigator 的周期 Markdown；默认日路径 `huhu/日志/日记/YYYY/MM/YYYY-MM-DD.md` | 现有周期笔记/文档修改服务；书页只读投影，不复制正文 |
| UI 偏好 | 既有 vault/device settings namespace 或有界叶子状态 | 现有 SettingsStore；锁定私密材料不恢复正文/查询词 |
| 体检状态 | 默认内存报告；可选显式脱敏导出，非敏感缓存可在拟议 `.huhu/health/<device-id>/` | health，仅保存诊断与指纹，不能复制业务原文 |
| 持久通知 | 现有 `.huhu/notifications/<device-id>/inbox.json` | notifications owner，不另建全局 notifications.json |
| Bot 调用/记录 | 保留现有 HAP/Runner/SQLite 事实来源 | 不在 TS 创建另一个 AI Run JSON 权威；敏感内容另过留存审查 |

**三条特别约束**：

1. 不采用 bz 新默认 `<插件目录>/storage`。虎虎插件安装目录只放程序和许可；用户内容放 `huhu/`，配置/运行私有文件放 `.huhu/`。[H2][B5]
2. 点前缀目录不代表加密，也不保证不会被同步或备份。设备级路径同样需要说明用户同步工具可能复制什么。
3. `.md` 也不都意味着普通用户文档：虎虎已有隐藏的受管 dashboard/automation 定义；继续通过相应 owner，不用“扩展名是 md”绕过私有文件边界。

### 7.3 写入、冲突、迁移与恢复

- 遵守共享 `storageWriteQueue` 与现有恢复 owner；该队列是单运行环境的顺序保证，不是分布式事务锁。[H10]
- 所有 mutation 有 operationId/idempotencyKey、预期版本/哈希、真实提交回执；重要多文件操作先有恢复计划，不能声称多个 rename 天然原子。
- `missing / unreadable / invalid / unsupported-version / conflict / locked` 分开，读失败不得建空文件覆盖现场。
- 保留未知 YAML、注释、自由正文、未触及字段；已打开编辑器有未保存修改时先处理冲突。
- 非兼容 schema 发布、归物预设升级、加密集合升级都需预览、源备份、校验、回执、可重跑；运行中禁用不留下双权威。
- 私密数据的 backup/staging/conflict/repair/undo 产物同样加密；文件名和索引避免裸露联系人名。
- 新建加密集合前明确密钥派生/分域、AAD、随机 IV、文件大小、分块、附件、旧密码备份、改密/轮换/中断恢复、锁定后提交点与版本回退威胁。不能以“bz 用 AES”代替安全设计。
- 日记/档案删除走既有回收或恢复语义；不复制上游加密后直接移除明文的特殊路径到一般删除。

## 8. 密码本：保留安全底座，仿造高效交互

### 8.1 现有模型不降级

虎虎已有一个条目包含 1–50 个账号、五类账号内容可选、账号级关联、标签、加密图标、加密回收站和备份合并。[H3] bz 的单条 platform/account/password 模型更简单，不作为虎虎新 schema。

继续遵守：搜索不检索密码；无远程网站图标；无跨域明文搜索、AI 或自动化读取；主密码不 trim/归一化；自动锁和多页面共享会话；成功改密后的处理；当前备份/冲突恢复协议。

### 8.2 学习与实现内容

- 桌面组织为“范围/分类 → 条目与账号 → 详情与关系”，可以使用 shell 侧栏，不能再套一整套导航 chrome。
- 详情内完整显示可选手机号/邮箱/账号备注；长备注自动增长或受控滚动，操作栏始终可到达。
- 展示当前账号的关联与反向引用，跳转保持条目/账号稳定 ID，失效关系显示诊断不静默丢失。
- 增加或统一轻量“快速取密”：先解锁，按平台/条目名/账号搜索，键盘选择后显式复制；命中结果不展示明文密码。[B8][B9]
- 搜不到时显示明确空态及“生成新密码”动作，**不能因用户输入完毕就自动生成/覆盖**。
- 收藏可作为加密条目的可选字段，老数据默认 false；是否需要独立收藏或用现有标签表达在 P0 原型中定稿，不保存到外部偏好文件。
- 当前表单生成密码继续 **12 位、四类字符、安全随机、覆盖确认、只改草稿、不自动复制/保存**。不机械采用 bz 默认 16 位或其网站字符经验。
- “无解锁快速生成”属于可选增强，必须独立命令、显式复制；若保留待存状态，只限短时内存、可丢弃、无明文持久化，不改变现有表单按钮语义。
- 剪贴板沿用虎虎当前 **30 秒条件清理**及锁定处理，不照搬 bz 的 60 秒；不承诺清除系统剪贴板历史。
- 禁用/锁定后关掉选择器、撤销已展示秘密、清搜索与草稿；晚到的解密/复制回调不能重新展示秘密。

### 8.3 不借此扩张密码库职责

`safe` 当前公开功能范围不包含一般附件/聊天仓或手机解锁。[H3] 为脸谱复用加密能力必须另行设计受限端口，不能 import safe 内部服务，也不能把大批聊天塞进现有约 5 MiB 明文载荷限制的密码库。上游改密只重新包装密钥，与虎虎当前重加密方案不同，不在 UI 改造中悄悄替换。[B27]

验收：旧 v1/v2/当前格式可读取并按既有规则迁移；新 UI 不损失 phone/email/关系/标签；长备注与多账号可操作；快速搜索取消无副作用；锁定/窗口迁移/复制失败/备份冲突测试全覆盖；无密码进入通用日志、事件、缓存、截图 fixture 或通知。

## 9. 档案 × 脸谱：深度融合方案

### 9.1 融合判断

**可以且应深度融合，但融合的是“档案实体＋证据＋互动纪事＋可审阅画像”，不是把 bz 的 people 数据层直接嵌入虎虎。**

虎虎通用档案负责确定的实体、字段、定义修订和关系；脸谱能力提供理解一个人物及一段关系的阅读层。两者结合比建立第二套联系人表更合适。

| bz 脸谱概念 | 虎虎对应设计 |
| --- | --- |
| 联系人/人物卡 | 现有 person 类型档案 entityId；企业/自定义类型不被强制套人物布局 |
| 聊天仓/媒体素材 | 绑定 entityId 的受控来源集合；保留来源身份及导入批次，不另创人物 ID |
| 《其人》 | 人物画像版本：带证据的行为/兴趣/偏好归纳，不自动写成确定事实 |
| 《相交》 | 用户与该人物的互动/关系叙述；不等于通用关系表中的已确认关系 |
| 《纪事》 | 可定位的互动时间线，合并手工纪事和已确认来源，不抹除来源差异 |
| 原话/时刻/未竟之事 | 证据片段、重要事件、待跟进建议；确认后才调用既有 Task/Automations |
| 生成任务 | 有阶段、预算、源指纹、可取消/恢复的任务，不随 UI 重开重复计费 |

### 9.2 人物详情交互

建议人物详情提供“概览 / 资料 / 关系 / 纪事 / 素材 / 画像”视图，窄容器使用可达的分段导航。

- 概览：已确认事实、近期纪事、手工备注、资料完整度；不显示算法推测为事实。
- 资料：既有动态表单和 schemaRevision 不变；增强 Markdown 阅读预览，不丢原文编辑能力。
- 关系：复用独立 relation records，显示双向投影和时效；不由聊天频率自动创建“朋友/同事/恋人”。
- 素材：导入来源、时间范围、消息数、处理覆盖率、敏感级别、是否允许外发；可单独删除或撤回授权。
- 纪事：按时间筛选、打开证据、编辑手工事件；源已删除或内容变更有明确提示。
- 画像：分卷式《其人》《相交》《纪事》可以保留参考命名或使用虎虎中文命名；每段有来源、生成时间、版本和“待确认/已采纳/已否决/已过期”。

### 9.3 来源与导入

首期支持用户主动提供的 Markdown/TXT/明确版本 JSON 导出及手工纪事；UI 先预览联系人映射、数量、范围、媒体和隐私选择。微信工具链可作为后续可选适配，不先引入进程取密钥、版本降级与高权限依赖。

- 人物映射使用稳定外部 source/contact ID → archive entityId；同名人物必须人工确认，不能仅靠名字合并。
- 消息去重以来源 ID＋外部消息 ID 为优先，缺 ID 才使用已定义的稳定指纹；重复导入必须幂等。
- 记录来源文件哈希、parserVersion、导入批次、时区、原始时间精度和语义类型；不能把未知时间补成当前时间。
- 原始外部资料保持只读；工具生成旁路结果，最终资料写入归虎虎 repository 一个 owner。
- 全量/增量范围必须明示；文件不同名不代表新增人物，内容没变也不重新调用 AI。
- 处理路径、文件大小、压缩包路径穿越、媒体类型和恶意文本均设边界；导入的文本是数据，不是系统指令。

### 9.4 证据模型与画像流水线

学习 bz 的“采集素材再全局归纳”，而非直接把所有聊天扔给模型。[B12][B13]

拟定流程：`预检 → 规范化/去重 → 分批素材提取 → 合并证据 → 人物画像 → 互动画像 → 纪事 → 待审阅`。

每个可展示结论至少能关联：entityId、sourceId、message/range 定位、sourceHash、批次、原文证据、生成模型/策略版本、生成时间和人工状态。敏感字段全部在加密集合内。

- 区分原文事实、用户手工确认、模型推断；不把模型 confidence 当成真实概率或客观心理诊断。
- 原话必须可回查，不能让模型编造引文；不确定则保留“无充分证据”。
- 保留矛盾与多版本，不把旧画像反复喂回作为独立证据产生自证循环。
- 超长材料有明确字符/条数/批次数预算；展示覆盖与抽样方式，不宣称通读全部。
- 每批完成有检查点；重试跳过真正完成的批次；来源 hash/解析版本/提示词策略改变需要判定重用范围。
- 中断、取消、部分失败、未配置模型、额度不足、锁定、授权撤销各有状态；关闭面板不自动丢任务，模块禁用必须收尾。
- “采纳到档案”必须展示字段 diff，并经 `ARCHIVES_COMMANDS` 的预期版本/哈希写入；自由正文和用户已有值不自动覆盖。[H7]
- AI 提议新增关系、提醒或任务时只是建议，确认后通过对应公共 API，复用原有幂等和权限流程。

### 9.5 隐私与 AI 边界是前置门槛

“本地加密”不等于“云端分析不外发”。选择服务商前明确本次要发送的人物、时间段、素材种类与预估量；允许只用手工资料，不配 AI 仍能用档案。

复用虎虎已有模型/凭据体系，但**不能直接把私密聊天送进默认会话，而让 Runner 的 SQLite、事件日志、trace、artifact、崩溃日志或明文缓存留下副本**。先审计全链路留存，设计有限的、可撤销的敏感分析能力；若当前通道做不到，就停留在手工资料/非敏感授权素材阶段，不以另建 provider 和明文持久化绕过。[H13]

- 私密原文、提炼中间结果、画像、证据片段及预览均加密；不进入普通全局全文索引/看板时间线/通知。
- 用途、范围与授权版本绑定任务；上锁/撤销立即停止新请求，并取消可取消的在途调用。
- 已发给服务商的内容不能“撤回”，必须如实说明；迟到结果不回灌已锁会话，不落明文临时文件。
- 解锁后恢复需要确认授权仍有效；不得静默恢复上次云端上传。
- 人物删除、来源删除、撤回授权时对私密集合/画像/索引/任务生成影响预览；不自动删用户提供的外部原件。
- 明文导出和把敏感推断写入普通 Markdown 属显式解密披露行为，逐次确认，不自动“为了方便备份”导出。

验收：同名两个人不混档；重复导入不翻倍；来源改变使旧结论可识别；画像每段可回查证据；取消/锁定没有明文落地或晚到 UI 泄漏；未经采纳，实体字段和关系记录逐字不变；企业/自定义档案功能不受人物增强影响。

## 10. 归物本：通用档案上的专用产品

### 10.1 为什么不直接复制 belongings.json

bz 的小型物品账本使用 JSON 是合理的，但虎虎已经有可编辑的通用档案实体、精确 money、关系和定义修订。再建 `belongings.json` 后同步进档案会制造双写、身份和恢复冲突。因此默认选择：**物品类型预设＋专属归物视图＋档案内的领域命令**。独立入口可以存在，独立权威库不建立。

### 10.2 数据与状态

物品预设包含：稳定 ID、名称、分类、图片/图标、规格/备注、购入日期、购买金额及币种、当前状态、出离日期、售价、相关凭证，以及可选所有者/关联人物/企业/地点。自定义字段继续由档案体系提供。

四态：`使用中 / 闲置 / 已转卖 / 已丢弃`。第一次离场可以预填今天，但必须允许用户修正历史日期。离场态互换保持既有日期；返库是新生命周期事件，**不能把旧的出售/离场历史直接抹掉**。

生命周期事件建议作为具稳定 rowId/eventId 的 repeatable 结构，与物品写在同一权威实体中；预设和专门 transition 命令校验日期、当前状态与事件一致性。当前状态可以作为可验证投影，但不得拥有另一条独立写路径。最终字段与 schemaRevision 由 P0 定稿。

### 10.3 界面与报告

学习 bz 的“顶部四格 KPI → 状态条 → 搜索/年份/排序 → 物品卡片 → 详情流转”。提供列表/卡片、分类筛选、所有者关联、查看凭证、编辑、状态迁移、回收和撤销。

年度视图至少包括购入/离场、月度购入金额、分类分布、回收金额、持有时间和成本趋势。统计由一份纯计算规则提供给卡片/KPI/报告，不能各自重算。

### 10.4 金额、日期与统计必须先定口径

- 金额沿用档案 `decimal string + currency`；切显示单位不等于汇率换算；不同币种分栏，未实现汇率时不求一个“总金额”。
- `unknown` 售价与真实 0 分开；未知日期、未来计划购入、只有年月精度均不能冒充精确持有天数。
- 明确区分购入额、在库原始投入、已实现回收、净持有成本和当前估值；本期不凭空生成估值。
- 单件净成本日均建议为 `(实际购入额－已实现回收额) / 有效持有日数`；零天、负净成本、返库与多生命周期单独定义。显示负值时说明是净回收收益，不静默钳成 0。
- 组合“总净成本/总持有日”与“各物品日均求和”并非同一指标，必须采用一个明确名称与说明，不能混用。bz 的单件/组合口径不可机械复制。[B17][B18]
- 月末趋势需要按当时有效事件重放；不能拿今天的最终状态反推去年所有月份。
- 可关联已有记账记录，但不因登记物品就自动再生成一笔费用；避免双重记账。
- AI 分类仅为明确触发的可选建议，不自动上传发票或备注；离线手动分类完整可用。

验收：四态流转及返库可回顾；重复命令不新增事件；多币种不混算；0/未知金额和月精度不混淆；重建索引不丢生命周期；卡片、详情、年度报告取同一计算结果；归物专属页面和通用档案编辑不会相互覆盖。

## 11. 日记：仿书页体验，不另造日记数据模型

### 11.1 需要参考的真实设计

bz 当前日记是书页式阅读、书口月份索引、台历跳日、搜索高亮、书内写作、分类贴纸和媒体灯箱，并通过分卷避免一次渲染全部条目。[B19][B20][B21][B22] 其旧媒体墙不是本期主要目标。

**但 bz 是“一条记录一个时间戳文件”，虎虎已有“一日一个周期笔记＋模板”。只借鉴展示与交互，不改变虎虎的文件身份和用户正文。**

### 11.2 页面与数据接入

- 在 navigator owner 下增加日记工作台页面/子能力，保留现有侧栏、首页日历和周期导航。
- `NAVIGATOR_PERIODIC.inspect/preview/prepare/open/ensure` 是周期语义的公共入口；必要时扩展批量只读列表能力，不跨模块直接扫描 navigator 内部状态。[H8]
- 路径/模板/周起始日由现有 owner 解析；模板取消或能力不可用要如实返回，不能偷偷落空白默认文件。
- 浏览空白日期不创建笔记；第一次真实写入才经显式动作和模板准备创建。
- 同一天多次记录可显示为正文中的段落/标题/时间块，原有任意 Markdown 仍可展示；不得静默拆文件或重排用户段落。
- 首页日历、Navigator、日记书本打开同一文件；写完另一面及时更新，不能两份文件彼此同步。

### 11.3 交互目标

桌面宽容器：纸页阅读、可见翻页按钮、键盘方向导航、书口月份索引、日历定位、搜索、明确“写一笔/打开原文”。

窄容器/手机：单页或日栈纵向浏览，无强制双页/3D 翻书。容器断点优先于全局屏幕宽度。原生滚动优先，不能在输入框/文本选择/长内容内抢滚轮和触摸手势。

写作：书内编辑面板提供日期、正文、必要分类、附件入口、保存状态和放弃确认；用虎虎现有编辑/文档修改契约处理未保存 editor buffer、外部修改与冲突，不直接覆盖整个 md。[H11]

媒体：可点击图片灯箱、音频/视频按需加载；本地资源经宿主 API；不要自动请求不受信的远程图或复制私密附件到普通缩略图目录。

分卷与定位：改编 `splitVolumes/monthSpans` 等算法，使其适配“天/月份”而非硬套“50 条记录”。卷容量是性能与体验参数，不是新事实来源；持久位置使用日期＋路径＋可用锚点，不保存会随插入变化的绝对页码。

搜索：区分正在建立索引、仅已加载范围、全部范围；首卷加载完不能把未扫描全文宣布为“无结果”。只为当前页和邻页保留有限 DOM/媒体，预取可取消。

### 11.4 动效与加密边界

优先用现有设计系统允许的 transform/opacity 动效做原型。采用上游 StPageFlip 或其他引擎前，单独审查许可、包体、CPU 空闲循环、多窗口、选字和 reduced-motion；按需加载并具无动画回退，不照搬对第三方私有内部结构的补丁。

“信封/加密日记”可以作为远期设计参考，但虎虎 safe 当前不是通用笔记附件保险库。**本期不能为复刻一个按钮就自动删除明文、迁移日记格式或绕过加密集合 ADR**；未提供该能力时不显示虚假可用按钮。

验收：不浏览即建文件；模板仅在真实创建消费一次；现有日记可无迁移阅读；书页与原文编辑一致；中文输入法、长文选字、音视频、窄栏、方向键和减少动效可用；隐藏/关闭后无永久动画循环；大库打开不全量建 DOM。

## 12. 基本数据体检：模块贡献、只读默认、修复归 owner

### 12.1 首期检查内容

| 类别 | 检查对象 | 默认处理 |
| --- | --- | --- |
| 可读取/解析 | 所选域的 JSON/Markdown/frontmatter、文件存在与权限 | 明确 missing/unreadable/invalid，不初始化或覆盖 |
| 结构/版本 | 必需字段、稳定 ID、版本、档案修订分支 | 未知字段不等于损坏；未来版本只报不认识 |
| 引用完整性 | 档案关系端点、来源/附件/周期路径、重复实体 ID | 报告和定位；同步未完成时标记待复核，不直接删除 |
| 一致性 | 归物状态与生命周期、索引与源、通知引用等 | 调 owner 的检查规则，不能抄一份业务推导 |
| 恢复健康 | 中断操作、冲突副本、未确认恢复、坏文件留档 | 展示可执行下一步，不擅自清理“多余文件” |
| 加密容器 | 在允许范围检查容器存在/版本/大小；解密完整性必须另行授权 | 锁定显示 skipped/locked，绝不显示“通过”或尝试暴力解密 |

检查全部相关域是长期目标，首期至少覆盖 archives、归物、周期日记和安全容器的非敏感元信息；notifications/settings 的诊断可按现有 owner 能力接入，不以缺 provider 伪装全库扫描成功。

### 12.2 Provider 契约

拟新增 `health/api.ts` 的贡献点：每个数据 owner 提供检查 ID、支持范围、权限条件、只读 scan、诊断结果和可选 repair plan。health 只负责选择、编排、预算、展示与协调，不能直接 import archives/safe 的内部 repository。

- 枚举 provider 时不强制启动所有模块；手动检查时才申请所需 lease。禁用/不支持/需解锁各自标明。
- provider 的 read-only 路径必须做到不存在也不自动写文件；若激活一个域必然初始化落盘，需要先分离无副作用检查路径。
- 增量分片、限并发、AbortSignal、可见真实进度；一个域失败不拖垮其他域。
- 状态包含通过、警告、错误、跳过、不可用、取消、未完成；报告明确已检查范围/数量/排除项。
- 保留一次结果便于重开，显示检查时间与数据是否已变化；mtime 仅为提示，修复前必须用当前内容版本/哈希重验。
- 报告内容脱敏，默认不收集笔记正文、账号名、聊天原句；分享/导出有预览。

### 12.3 有限修复流程

`只读检查 → 修复计划与影响预览 → 用户确认 → owner 重新验证版本/权限 → 备份/恢复事务 → 修改 → 复查 → 有条件撤销或恢复入口`。

首批允许的是可证明可重建的派生索引、或用户明确选定且 owner 支持安全修复的引用；没有安全方案的项只提供定位与说明。**不照搬 bz 的集中修复函数直接改各模块 JSON**。[B23]

禁止：自动清空坏 JSON、自动删除无端点关系、自动销毁孤儿密文、清除尚未完成的迁移备份、把无法解锁判断成空库、用全文件覆盖实现撤销。

验收：在文件写 API 上挂 spy 运行完整扫描，零创建/零修改/零删除；坏数据扫描前后字节相同；取消结果不标全绿；锁定项不是通过；报告过期后修复拒绝旧哈希；部分修复失败能列明每项已提交/未提交，不伪称整批原子成功。

## 14. 分阶段实施与 PR 拆分

每个阶段可单独形成 PR，不把整套系统塞进一个不可审查的大 diff。以下是执行顺序与交付物，不是工期承诺。

| 阶段 | 交付 | 依赖/退出条件 |
| --- | --- | --- |
| P0 冻结契约与样稿 | 更新 dev 差异；现有监听/反馈清单；数据 owner/路径矩阵；通知事件/私密集合/归物统计/日记路径 ADR；五类交互样稿；来源登记骨架 | 未通过安全/数据决策的子能力不得写入真实用户数据 |
| P1 公共反馈与生命周期 | 现有 sonner/Notice＋Inbox 的适配；有界进度、去重、操作结果、条件撤销；公共 UI 组合 | 至少 safe＋archives 两个实际消费，不建立第二套 UI；老行为回归 |
| P2 文件/领域事件 | 实例作用域、类型契约、metadata 分层、目录变化、repository 失效、多窗口清理 | 先接一个现有 owner 验证，再逐域收口；不强制一次重写全插件 |
| P3 基本只读体检 | health provider、扫描/取消/错误/缓存/脱敏报告；首批检查项 | 零写入扫描测试通过；先不开放危险修复 |
| P4 密码本 UX | 三段式布局、快速取密、长备注/关系体验、可选收藏 | 旧 schema/密文/自动锁/复制/恢复全回归；密码生成默认不变 |
| P5 归物本 | 档案预设、专用命令/UI、状态事件、统一计算与年度报告 | 单一实体来源；精确金额/币种与事件时间测试通过 |
| P6 书页日记 | navigator 页面、月份索引、无副作用浏览、书内写作、有限 DOM/缓存 | 与周期模板/编辑器冲突/首页日历一致；动效可降级 |
| P7 档案×脸谱基础 | 人物阅读页、手工纪事、来源映射、导入预览、证据导航；私密集合设计与实现 | 不依赖云 AI 也可用；加密/备份/锁定边界通过 |
| P8 脸谱分析 | 有限 AI capability、预算、分批证据、画像版本、人工采纳、断点恢复 | P7＋全链路敏感留存审查通过；否则不得开放敏感材料外发 |
| P9 有限修复及整体验收 | owner 修复计划、CAS/恢复、性能与多窗口/平台回归、用户文档和来源通知 | 所有高风险门禁通过；不可用功能明确降级 |

P4/P5/P6 在公共契约稳定后可并行；P7 的纯档案阅读可以先行，私密材料和 P8 不能绕过安全前置门。P9 的修复只对真正具备安全实现的项开放，不为“清空所有问题”强行补写逻辑。

### 关键设计决策的默认建议

1. 归物首期归档案 owner，不另起权威库。
2. 日记首期归 navigator owner，保留一日一文件。
3. 通知复用现有模块，操作反馈保持可独立于 inbox 工作。
4. 人物资料继续 Markdown，私密材料/画像草稿加密分域，不整体加密所有既有档案。
5. 先只读体检，再安全修复；先手工人物材料，再 AI。
6. 复制纯逻辑，重写宿主/UI；安全与持久化不随手迁入。

调整上述默认建议必须补 ADR、数据迁移影响和验收变化，而不是在实现途中隐式换方向。

| 端到端 | 编辑档案→来源/关系变化→只刷新相关视图；归物流转→报告→撤销；书本写日记→原文件/日历一致；体检→修复→复查 |
| 安全回归 | safe 当前完整测试＋旧版本升级/账号关联/12 位生成/30 秒剪贴板/自动锁/备份合并，不以 UI 重构豁免 |

### 15.2 性能要求

遵循 #16：不在启动同步路径读取整库、不等待 AI/网络/密钥、不全量渲染日记/聊天，不在 React render 中扫描 Vault。

建议验收样本：普通小库、1,000 篇日记、10,000 篇混合笔记、大量档案及长聊天。数字是拟议测试规模，不是当前性能承诺。使用同设备、同 Obsidian 版本记录改动前后启动、首屏、输入响应、扫描吞吐、内存和空闲 CPU；P0 依基线约定具体预算。

事件突发后合并有限重读；删除/重命名语义不丢。日记只挂当前卷/页及有限预取；health 分批让出主线程；关闭/隐藏无无限 rAF 和无界轮询。不要把开发机毫秒数直接当所有设备 SLA。

平台声明：公共 UI/档案/日记/体检按虎虎支持范围验收；safe 保持当前桌面边界；涉及桌面文件与外部程序的脸谱适配明确 desktop-only。不能写“已支持手机”，却只是手机显示一个会失败的按钮。

### 15.3 仓库门禁

按实际变动运行相关单测/DOM 与实机用例，并遵守现有验证选择表。仓库已有脚本可用于后续 PR：`pnpm test:unit`、`pnpm test:architecture`、`pnpm test:safety-regressions`、`pnpm test:workbench-lifecycle`、`pnpm test:i18n`、`pnpm test:docs`、`pnpm check:styles`、`pnpm check:notices`、`pnpm test:license-texts`、`pnpm build`、`pnpm check:bundle`；档案规模使用 `pnpm accept:archives-v2-scale`。[H15]

这些是要求执行的门禁，**不是本次研究已运行或已通过的结果**。新增能力还需自己的故障注入和状态机测试，不能只靠现有构建通过。

## 16. 总体验收清单

- [ ] 每个借鉴点有固定上游提交/文件、采用方式和虎虎落点，许可与构建通知齐全。
- [ ] 未新增平行通知中心、人物主库、归物主副库或日记正文副本。
- [ ] 公共能力符合分区与 api 边界；没有全局 App/DOM 状态污染，也未拖慢启动闭包。
- [ ] 通知、任务状态和持久回执分离，成功/部分成功/取消/失败如实呈现。
- [ ] 文件事件覆盖 metadata 就绪、目录迁移、私有写入失效与卸载清理。
- [ ] Markdown/JSON/加密/缓存各自 owner 与备份恢复范围记录清楚；读失败不重建空数据。
- [ ] 密码本现有可选手机号/邮箱、多账号、关系、标签、生成、锁定与备份能力不退化。
- [ ] 归物复用档案，金额/币种/日期/历史统计有明确一致口径，操作可审计恢复。
- [ ] 书页日记复用周期笔记，浏览不创建，写入不丢现有正文或未保存编辑。
- [ ] 档案与脸谱使用同一实体 ID；资料、推断、证据分层，采纳才改事实。
- [ ] 敏感材料从导入、任务、模型调用到缓存/日志/备份全链路有验证；加密不被 `.huhu` 隐藏目录替代。
- [ ] 只读体检零写入；不可用/锁定/取消不算通过；修复由 owner 重新验证后执行。
- [ ] 真实 Obsidian、多窗口、代表性规模与适用平台完成验收，并附实际结果与尚存边界。
- [ ] 更新架构、数据、safe、archives、日记与体检用户文档；不保留与当前实现矛盾的说明。
