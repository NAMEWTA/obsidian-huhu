# UI-001 技术评审（结论报告）

结论：**通过**。离线运行，无网络请求，无脚本错误（见 browser.json 的 console_errors）。

## 方法
- `materialize-prototype.mjs --check`：三个源码块与 final/ 逐字一致。
- 交互任务脚本（56 项）：任务完成划线/保存中/失败恢复/撤销；DateField 严格校验（`2026-02-31` 保留为草稿并报错）、错误通过 aria-describedby 关联、点选写入 yyyy-MM-dd、Esc 只关弹层；范围反向时禁用应用；自动化列表 DOM 与滚动保持、开关与行点击隔离、失败回滚、空格键切换、Esc 后焦点回到来源行、深链缺失；档案树方向键展开与选中分离、搜索保留祖先、清空后恢复；未保存修改提示与离开确认；设置实时换色/明暗/密度；命令面板、输入法回车保护；对话框焦点限制与脏数据确认；保险箱错误密码/解锁/锁定清除；体检扫描与取消；窄屏导航 Sheet 与详情模态 Sheet；1100px 按主区余宽切换 Sheet。结果 56/56 通过。
- 逐状态检查：渲染、无横向溢出、Tab 可达且有焦点环、长标题、200% 缩放、减少动效。缩放检查的 CSS 视口为 max(320, 宽度/2)：1440 → 720，390 → 320（WCAG 1.4.10 的重排基准）。首轮把 390 减半到 195px，低于该基准，12+2 个用例失败；320px 下逐页复核没有页面级溢出，智能体标签条在自身横向滚动区内超出，属于设计行为。

## 发现与修复（已复核）
1. 模板把 `false` 渲染为空串，导致 `aria-checked=""` 和 `aria-selected=""`（开关停用态读不出来）。已改为输出 `"false"`，全量复测通过。
2. Air Datepicker 在从未打开时调用 `hide()` 会抛 TypeError。已在调用前判断 visible。
3. 日期字段失焦后的延迟提交重建任务列表，冲掉了还原后的焦点。改为值未变化不回调、字段已卸载不提交，并在列表重建时保留焦点所在的行。
4. 日期弹层 Esc 冒泡关闭了右详情。改为在字段容器捕获阶段先处理。
5. 智能体终端页缺少 H1。已补充仅读屏可见的页面标题。

## 边界
本证据只证明原型路径，不证明生产 React、DayPicker v10、Obsidian 宿主、多窗口 Portal 或持久化。
