# 设计危险信号

综合前筛查每个候选。危险信号是修改或拒绝该形态的理由。

## 浅模块

浅模块暴露很大的接口，却隐藏很少的复杂性。通过公共接口背后隐藏的能力与策略相对于接口大小的比例判断深度。优先选择以实质行为支撑的简单接口。

不要把深模块和深调用链混为一谈。深调用链把理解分散到多层；深模块把能力集中在一个接口后面。

留意以下迹象：

- 调用者需要协调多个方法才能完成一个操作。
- 公共选项暴露内部阶段或实现选择。
- 学会接口后，调用者仍不得不学习实现。

## 信息泄漏

信息泄漏让多个模块依赖同一个内部决策。某种表示方式、策略或协议细节出现在多个位置，因此修改它需要协调多处编辑。

公开重新导出传输类型或线协议类型就是泄漏。在接口后把外部数据解析为领域类型。存储模式、框架对象和协议细节应保持私有。

## 按时间分解

按时间分解根据执行顺序而非拥有的知识组织模块。分开的加载、校验、转换和保存阶段，往往在多个边界重复同一种表示及其不变量。

围绕领域知识与所有权组织代码。在不同时间运行的方法，如果保护的是相同决策，仍可以属于同一模块。

## 透传方法

透传方法把相同参数转发给另一个形状相同的方法。它增加了一层，却没有隐藏复杂性。

删除它，或把职责移动到能够完成整个操作的模块。只有转发边界增加了策略、适配或独立抽象时才保留它。

## 所有权分裂

不止一个模块写入同一份状态，或各自保留它的副本。只编辑一个写入者的智能体看不到其他写入者，因此规则会分叉。

让每一份状态都有唯一所有者。其他模块读取它，或请求所有者修改它。

## 一件事有两种做法

设计支持多种完成相同任务的方式。智能体会复制最先找到的那一种，因此每一种都会不断新增调用者。

只保留一种。在同一改动中，把调用者从其他方式迁移过来，再删除它们。

## 可导入的内部实现

调用者能导入模块内部实现。智能体选择能编译的最短路径，因此会直接导入，内部实现随后成为接口的一部分。

让模块外部无法触及内部实现，使外部导入在构建时失败。

## 手工同步的列表

两个或更多位置列出相同条目，新增条目就必须编辑每份列表。只看到一份列表的智能体只会更新那一份。

保留一份列表，从中派生其余列表。若某份列表无法派生，则在列表不一致时让构建失败。
