# 归档与项目记忆

减少下次接手时必须重新发现的知识。保留代码没有表达的意图、真实取舍、领域词义和重复犯错的原因；实现细节指向当前代码。按未来决策价值判断，不追求文档数量或删减比例。

## 读取与落点

从当前项目、这次需求和用户指定范围开始。读取项目 `AGENTS.md`、`.agents/dev/AGENTS.md` 及有关目录说明、相关规格、实际 diff/提交，再按关键词定位有关现役笔记。涉及交付或部署时核对对应证据；只说明已经核实的状态，没有上线证据不得声称已上线，归档本身不证明开发或部署完成。

本套技能新增的项目资料统一以 `.agents/dev/` 为根，按需使用以下分区。已有资料先按真实位置查阅引用；明确迁移时保留内容与标识并修复链接，不为增加根目录擅自搬迁目标项目文件：

| 内容 | 默认位置 |
| --- | --- |
| 当前需求及证据 | `.agents/dev/changes/<YYYY-MM-DD-slug>/` |
| 已交付的需求 | `.agents/dev/archive/changes/implemented/<type>_<YYYY-MM-DD>-<slug>/` |
| 明确不实施的需求 | `.agents/dev/archive/changes/rejected/<type>_<YYYY-MM-DD>-<slug>/` |
| 术语和别名 | `.agents/dev/notes/glossary.md` |
| 模块背景与规则 | `.agents/dev/notes/context/<topic>.md` |
| 有持续价值的决策 | `.agents/dev/notes/decisions/<YYYY-MM-DD-topic>.md` |
| 可复用的错误经验 | `.agents/dev/notes/errors/<topic>.md` |
| 模块学习说明 | `.agents/dev/notes/learning/<topic>.md` |
| 有历史价值的退役笔记 | `.agents/dev/archive/notes/`，保留原分类和文件名 |
| 部署现状与发布历史 | `.agents/dev/deploy/<environment>/runbook.md`、`releases/` |

不要在 `.agents/skills/` 内写项目数据。除安装器按所选领域补齐的目录说明骨架外，只创建本次需要的文件；不建立 JSON 台账、全局状态机、必填空文档或知识数据库。

归档任务前读取[change 收尾方法](references/change-closure.md)：活跃 change 不改命名，归档时才判定 implemented/rejected，并按 architecture、feature、bug-fix、refactor、process 选择一个主类型、移动和重命名。暂缓、阻塞或必要交付未完成的任务仍留在 changes；已有历史不自动迁移。

## 做一次有证据的收尾

1. **核实结果。** 对照用户目标、规格、当前实现、实际验证和环境记录，列出完成、未完成与未验证事项。仍有工作就留下明确下一步，不能通过归档把它变成完成。取消的需求可以归档，但写明取消原因和未交付内容。
2. **反思少量值得保留的变化。** 什么判断有效，什么假设被事实推翻，什么错误会再次发生？只提取有证据的结论。正式 ADR 采用难逆转、缺背景难懂、真实取舍三项条件；其他长期知识进入背景、错误经验或术语，不因未达 ADR 条件而丢弃。普通改名、一次页面微调、已经消失的临时绕路不必变成永久经验。可用 [复盘提纲](assets/retrospective.md)，没有实质内容时不生成复盘文件。
3. **先找旧的归属。** 每条新知识都搜索相同决定、概念、机制和别名。已有文件能承载就更新；同一个事实只保留一个主要说明。按 [知识写法](references/knowledge.md) 区分术语、背景、ADR、错误与学习说明。
4. **处理当前与历史。** 对照源码核验路径、符号、调用关系和默认值。当前实现事实变了，就修改现役说明；真实决策反转就建立后继记录。按 [保留与替代](references/retention.md) 分清完整替代、部分替代和仍有用的反对理由，不把旧 ADR 改写成相反的决定。
5. **清理引用与导航。** 更新当前文档、`AGENTS.md` 和 `.agents/dev/notes/index.md` 的相关入口。索引只放主题、适用范围和链接，不再复制正文。修复移动/删除文件的入链；历史文件只有在明确引用过去时才作为目标。
6. **归档并交接。** 按 change 收尾方法，在用户已授权范围内将已结束需求移入结果目录并增加主类型前缀，保留原创建日期，检查目标冲突、目录深度变化造成的相对路径和已知入链；不覆盖、不重复加前缀。有独立历史价值的退役笔记仍移到 archive/notes 并标明退役时间和当前替代位置。核对相对链接、原始证据和未完成事项，返回真实路径和结果。普通归档不要求另走审批流程；授权不足仅阻塞超出范围的操作。

## 判断依据

- 说明“现在怎样运行”时，以已检查的当前源码、配置和真实运行证据为准；最新明确需求决定“希望怎样运行”。两者冲突时写明差距，不能让旧代码取消新需求，也不能把计划写成已实现。
- 注明实际检查的提交或工作区状态及日期。只更新亲自复核过的条目，不给整个知识库批量刷新“已核验”日期。
- 领域同义词要记录映射和适用范围，例如“账号 / 用户账户 → 项目中的 Account”；先核实代码与用户语境，不把身份、登录凭据、租户等不同对象擅自合并。
- 项目长期约束写在有关笔记，`AGENTS.md` 保持短小，只留下高频规则和读取入口。部署文档记录凭据引用、账号用途和配置位置；不把密码、令牌、私钥写进可提交的知识文件。
- 开发与验证方法根据任务选择；归档记录实际采用的方法、行为约定和验证证据，保留有价值的既有测试与回归检查。
- 重复错误若能被类型、接口、状态所有权或准确的静态规则预防，在已有修复授权内将经验落实到结构；可用 `dev-guardrails` 深入处理。保留规则覆盖的真实错误与例外，不要求每次纠正都新增 lint。涉及状态模型或性能预算时，同步检查代码映射、模型假设、测量条件及反例是否仍然有效；过时证据不能继续代表当前版本。

## 完成时交付

说明核对了哪些需求和知识，哪些保持现役、合并、修正、归档或删除，为什么；给出关键新链接、仍需处理的问题和实际做过的检查。保留有争议的取舍及证据，不用“全部整理完毕”掩盖未检查的范围。
