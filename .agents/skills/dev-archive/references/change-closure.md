# Change 收尾、分类与重命名

在归档已结束任务时读取。活跃任务仍使用 `.agents/dev/changes/<YYYY-MM-DD-slug>/`；分类只在归档时进行，不要求开发阶段预分类或改名。知识替代与保留判断继续使用[保留与替代](retention.md)。

## 先判断任务是否结束

| 情况 | 处理 |
| --- | --- |
| 约定交付范围已完成且有对应证据 | 归入 `implemented` |
| 明确拒绝、取消、确认重复或不适用，决定不再实施 | 归入 `rejected`，记录结论来源与理由 |
| 尚待决定、暂缓、被阻塞、仍有必要交付或缺少结果证据 | 留在 changes，不强行归档 |

implemented 表示本任务约定的交付已完成，不自动表示已合并或已上线。用户要求上线而尚未上线时，整个任务仍未完成。只要求设计、规范或文档时按其约定产物验收，但明确“设计已交付，代码未实施”等真实边界，不把方案当成运行事实。

rejected 不是“尚未开始”的同义词。AI 不能凭个人判断取消用户要求；结论应来自用户决定、有效项目规则或已确认的关闭依据。记录已经做过什么、未交付什么，以及有价值的重新考虑条件。

部分完成时列清完成、未完成与放弃范围。用户已接受缩减范围时保留原目标、调整决定和理由，再核验最终范围；真正独立的后续任务可另建关联 change。仍有本任务必要工作时保持活跃，不通过拆目录或改写验收隐藏未完成要求。

## 按最终主目标选择一个类型

| 类型 | 判断标准 | 例子与反例 |
| --- | --- | --- |
| `architecture` | 对外交付源码的结构性决策：模块与包关系、运行时核心词汇、接口和所有权边界 | 单独确定包边界及迁移契约；不因功能实现需要拆模块就改成架构任务 |
| `feature` | 面向用户或模型的新能力、功能点或行为扩展 | 新增邀请能力；必要的架构、测试和文档属于同一目标 |
| `bug-fix` | 修正交付代码缺陷、安全漏洞或对有效行为契约的违反 | 修复越权、为运行时漏洞升级依赖；不能把未经证实的报告写成已确认缺陷 |
| `refactor` | 不增加新能力，移除冗余代码、多余行为或无必要的暴露面 | 内部去重；列清保留契约，收窄接口影响合法调用者时明确兼容性取舍 |
| `process` | 工程工具、规范、工作流、文档、CI、包管理等周边调整，不涉及交付产品运行时逻辑 | 修复 CI 判断、调整 lint；交付 CLI 的运行修复仍可属 bug-fix，技能正文新增模型能力可属 feature |

按主目标而非调用的技能分类。一个任务只选一个类型，辅助工作不另建 change；被拒绝的任务按原拟交付目标分类。调研、原型和验证是方法，不是第六种类型。纯解释不必创建 change；任务目标仍无法确定时保留现有记录并标出未知，不强塞进 process。

## 提炼知识后再移动

1. 对照原目标、有效规格、实际产物、验证和部署证据，确定最终结果。先读有关目录 AGENTS.md 和现役知识，不把文件存在当作交付证据。
2. 按[知识写法](knowledge.md)搜索已有归属，更新术语、背景、决定、错误经验或导读，完成完整/部分替代检查。rejected 的真实否决理由也可有长期价值，但不能写成已实现 ADR。没有新知识时不硬造复盘。
3. 在已有 brief、progress 或收尾记录中写明结果及依据、主类型、原路径、最终路径和归档日期；保留原创建日期与目录内部结构，不新增必填元数据文件。
4. 新归档目标为 `.agents/dev/archive/changes/<result>/<type>_<YYYY-MM-DD>-<slug>/`，result 为 implemented 或 rejected。先搜索入链并核对目标冲突；目标存在时不覆盖、不自动合并。发现已归档的同一任务就核实并返回真实路径，不再次移动或重复增加类型前缀。
5. 在已授权收尾范围内移动和重命名。保留历史身份；原名无法拆成标准日期与主题时保留原标识，不编造日期，按项目现有约定说明例外。
6. 修复已知入链，以及因目录深度变化而失效的源码、notes、部署和外部证据引用。可访问的 Issue、PR 按既有授权修正；无法修改的外部引用列为未完成，不宣称已全部修复。
7. 回读变更文件，检查原始证据、相对链接、知识导航和未完成事项，返回路径映射及实际检查范围。之后按历史快照维护，安全删密、事实纠错与必要修链注明原因，不随新实现持续重写。

## 兼容与知识检索

- 已有历史归档继续按真实路径读取，不批量移动到新层级或猜测实施结果。历史迁移需要单独明确范围，逐项核实结果、类型和入链。
- 类型与结果只组织 change 历史；`.agents/dev/notes/` 不按这五类或 implemented/rejected 再分层。退役知识仍按原分类放入 `.agents/dev/archive/notes/`。
- 默认先查现役 notes 和当前代码，追溯过去时才读 archive；需要继续约束开发的知识不能只埋在归档中。
