# 知识提取、纠错与合并

从本次需求或独立维护主题的真实材料中提取知识。需求整体完成或取消，不证明每条内容都值得长期保留。已有来源缺什么就如实记录，不为流程补空文件。

## 提取来源

先枚举实际存在、与本次问题有关的产物，再按候选问题读取：

1. 目标、规格与交付证据：确定交付边界、实际验证和剩余风险。
2. 本次架构决策：保留正式决定及真实理由。
3. 讨论或设计日志：寻找尚未正式记录、但有持续价值的选择。
4. 背景与术语记录：核对项目规范词和用户别名。
5. 设计说明：当前视觉与交互约定，原型和截图只作为佐证，不重复产生多份规则。
6. 诊断、评审、原型、问答和实际生成的其他知识材料。

独立维护只按主题读取有关现役条目和真实来源，不要求先创建需求。

## 正式 ADR

按[正式决策格式](decision-format.md)判断：难以逆转、缺少背景就难理解、确有真实取舍三项同时成立时，通常值得正式 ADR。长期命名、业务规则、安全或恢复知识未满足三项，也可以进入背景或错误经验，不丢弃。

已有 ADR 充分捕获同一选择时，以它作为唯一候选；日志、规格和证据只补充依据，不再生成重复 ADR。没有当前 ADR、但日志中确有符合条件的决定时，可以建立正式记录，引用真实来源，不编造当时未考虑的方案。

保留既有记录的内容与编号并按真实位置引用。新增 ADR 统一按需创建 `.agents/dev/notes/decisions/<YYYY-MM-DD-topic>.md`，同名冲突才加后缀，不建编号注册中心。内容可短至一段，只要背景、决定和理由清楚；真实方案、后果、否定保证和恢复义务确有价值就保留。

决策反转创建后继，旧记录开头说明替代范围与当前位置。部分替代保留仍有效内容并双向链接。完整合并删除只有在独有理由、方案、后果、验证、覆盖缺口与恢复义务全部承接后才可进行，详见[保留与替代](retention.md)。

## 术语、背景与错误经验

项目特有的领域词、稳定约束、可复用经验或错误模式可以保存；通用编程常识、单次未证实猜测和暂时进度不升级为项目事实。

- 新增术语统一写入 `.agents/dev/notes/glossary.md`；已有词汇表先按真实位置核对引用，避免重复定义。用短定义、用户别名、代码实体、领域和易混对象表达，不将别名全部禁用。
- 已有同名术语时对比含义。一致则保留原条目并补必要证据；事实能由代码确定时直接纠正；真实业务含义仍有冲突时列双方与证据，只澄清会影响结论的问题。
- 术语更名保留旧称作为可搜索别名。相同词在不同领域含义不同，则分开定义，不制造跨领域的假统一。
- 新增背景按主题保存到 `.agents/dev/notes/context/`，引用已有模块文档，写意图、责任、适用条件与代码入口。
- 错误经验保存到 `.agents/dev/notes/errors/`，说明触发信号、已证实原因、处理办法、恢复义务、验证与来源。一个严重且可再现的错误也值得记录，不强制凑多次事故。

索引只负责导航，正文和真实依据负责知识。没有索引时用文件与关键词定位；确有需要再增加轻量 `.agents/dev/notes/index.md`。不要另建 JSON 台账或强制统一错误数据库。

错误经验不写成无条件全局禁令。成功经验保留适用边界；机械性约束优先交现有检查。多份报告引用同一事件只算一份证据。

## 设计知识

新增的稳定设计变量、组件约束和跨页面交互模式说明统一进入 `.agents/dev/notes/context/`，按真实位置引用已有设计文档。单个页面、未落地方案和临时实验留在当次需求。

每条声称已实施的规则都需要可定位实现证据；页面获批、需求标完成或原型截图不等于生产代码已遵循。当前说明尽量引用组件和设计变量代码，不维护第二套数值表。

已有当前设计文档原地核实更新。只有旧协议、旧数据或重大设计取舍确有独立历史价值，才保留历史记录；不建立设计发布网关、不可变 revision 引擎或 Schema 状态流。

## 其他已有知识位置

先按真实位置查阅已有操作手册、部署记录、领域模型或课程导读，判断当前主题由哪份资料负责，并保留必要引用。新增资料统一放入 `.agents/dev/` 对应分区，只有明确需要迁移时才搬迁并修复链接，不为整齐移动整个知识库。新的文件只在确有内容需要、属于用户任务范围时创建。

不因另一领域目录存在就越界写入。知识无法适配现有位置时，提出具体合理归属；只有会改变用户组织方式的实质歧义才询问。

## 保护与恢复

- 写前重读，保留必要原状态，不覆盖并发更新。
- 已经证实的过时事实可原地纠正，不要求永久只追加，让错误长期存在。
- 保留来源与实际检查日期；有需求则引用其真实位置，独立维护引用实际材料、决定或会话，不虚构需求来源。
- 当前事实只更新已核查部分，不能给整库批量刷新日期。
- 旧数据、兼容消费者或恢复义务仍在时，相应解释继续现役。
- 历史记录不做普通格式整理或当前路径追赶；明确需要删密或事实纠错时记录修订。
- 当前代码不能证明作者当初为什么放弃某方案，没有历史证据就写未知。

## 完成条件

所选材料中的有关候选均有结论：已有、更新、合并、保留当次、正式决策、背景、错误经验或历史。每个实际写入都有真实依据、明确归属、动作和理由。冲突列出双方证据，删除或退出记录满足完整承接要求。

回读修改、检查相对链接与可搜索符号、确认导航真实可达；没有检查的领域保留未验证，不宣称全库都已整理。
