# 领域词汇表格式

## 结构

```md
# {上下文名称}

{用一两句话说明这个上下文是什么，以及为什么存在。}

## 语言

**Order（订单）**：
{用一两句话描述这个术语}
别名或易混对象（需由项目证据确认）：Purchase、transaction

**Invoice（发票）**：
交付后向客户发送的付款请求。
别名或易混对象（需由项目证据确认）：Bill、payment request

**Customer（客户）**：
下订单的个人或组织。
别名或易混对象（需由项目证据确认）：Client、buyer、account
```

## 规则

- **有明确主张。** 同一概念有多个词时，选择规范名，并将用户实际用语保留在“别名”中；只有确实会产生误解的词才标为避免使用。不要把有用的搜索词一律禁用。
- **定义紧凑。** 最多一两句话。定义它是什么，而不是它做什么。
- **只包含本项目上下文特有的术语。** 通用编程概念，如超时、错误类型、工具模式，即使项目大量使用，也不应放进来。添加术语前先问：这是本上下文独有的概念，还是通用编程概念？只有前者属于这里。
- 自然形成簇时，**用小标题对术语分组**。如果所有术语都属于一个紧密相关的领域，平铺列表即可。

## 单上下文与多上下文仓库

**单上下文，大多数仓库：** 新增术语统一保存在 `.agents/dev/notes/glossary.md`；已有词汇表先按真实位置核对并引用，避免重复。

**多上下文：** 在 `.agents/dev/notes/index.md` 列出上下文、真实位置及相互关系，引用已有的领域导航：

```md
# 词汇表映射

## 上下文

- [订购](./src/ordering/GLOSSARY.md)：接收和跟踪客户订单
- [计费](./src/billing/GLOSSARY.md)：生成发票和处理付款
- [履约](./src/fulfillment/GLOSSARY.md)：管理仓库拣货与发运

## 关系

- **订购 → 履约**：订购发出 `OrderPlaced` 事件；履约消费事件并开始拣货
- **履约 → 计费**：履约发出 `ShipmentDispatched` 事件；计费消费事件并生成发票
- **订购 ↔ 计费**：共享 `CustomerId` 和 `Money` 类型
```

技能自行判断适用结构：

- 如果存在领域导航，阅读它寻找上下文。
- 如果只有一份现有术语表，采用单上下文。
- 如果都不存在，在首个术语确定时才创建 `.agents/dev/notes/glossary.md`。

存在多个上下文时，推断当前主题属于哪个上下文；无法确定时询问。
