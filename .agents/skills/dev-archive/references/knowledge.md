# 写入值得记住的项目知识

需要把开发过程中的发现变成项目背景时读取。目标是让后来者找到事实和理解约束，不是保存整个对话或重新描述源代码。

## 先判断是否值得记住

满足一个具体用途就可能值得保留：省去反复查找的领域映射；解释无法从代码知道的决定；防止一个仍然可能出现的错误；帮助接手者理解跨模块机制。一个严重且可再现的故障也足够，不强制凑满多次事故。

临时进度、未经验证的猜测、机械编辑清单和通用编程知识留在当次需求资料中即可。不能因为需求上线了，就把其中每段话提升为永久知识。明确不实施的需求也可提炼有证据的否决理由与重新考虑条件，但不写成已实现的决定。没有值得新增的内容时，正确结果可以只是修正两条引用。

## 放到主要归属

| 类型 | 内容 | 默认文件 |
| --- | --- | --- |
| 术语映射 | 用户词汇、规范概念、代码对象、适用范围和易混对象 | `.agents/dev/notes/glossary.md` |
| 模块背景 | 模块职责、入口/出口、稳定约束和实际代码位置 | `.agents/dev/notes/context/<topic>.md` |
| 决策 | 问题、选择、真实替代方案、取舍、后果和重新考虑条件 | `.agents/dev/notes/decisions/<date-topic>.md` |
| 错误经验 | 症状、触发条件、已核实原因、处理方法及验证证据 | `.agents/dev/notes/errors/<topic>.md` |
| 学习说明 | 按业务路径解释模块如何串联，保留必要术语与证据 | `.agents/dev/notes/learning/<topic>.md` |
| 环境事实 | 环境/实例、部署版本、运行配置、运维命令和凭据引用 | `.agents/dev/deploy/<environment>/runbook.md` |

已有对应文档先按真实位置核对引用；新增知识统一放入 `.agents/dev/` 对应分区，避免复制已有正文。明确维护既有记录时直接更新它，并在统一根目录保留必要导航。不要将同一 ADR 同时复制到 change、knowledge 和 deployment；保留一个主要记录，其他位置链接它。

### 术语不是单纯的同义词列表

例如用户说“用户账户”和“账号”，先检查它们是否确实指同一实体。条目可这样写，具体名称和路径必须来自实际项目：

| 用户用语/别名 | 本项目概念 | 实现定位 | 范围与区别 |
| --- | --- | --- | --- |
| 用户账户、账号 | Account | 项目真实路径与符号 | 个人账户；与登录凭据或租户不同 |

旧词有助于检索，保留为别名，不一律写成禁止使用的词。相同词在不同领域有不同含义时分开列出，明确范围；不要制造一个看似统一却改变业务含义的总映射。未经核实的映射标为待确认，不通过模型猜测固化为事实。

### 记录有依据的事实

对会变化的断言，保留项目相对路径和可搜索符号，并注明实际检查的提交、日期或工作区状态。需要不可变历史证据时追加提交链接；需要知道现在在哪里时保留当前路径。不要只给容易漂移的行号，也不要为每一句常识制造引用。

笔记可用普通段落写“核对：日期；提交；范围”，无须机器状态字段。一次只检查了某段就只更新该段的核对信息。缺少运行环境时明确“源码已读、运行未验证”。

### 背景写意图与边界

用一两句话指出模块解决什么问题、哪些职责归它、哪些由其他模块负责。再给关键入口和引用。对非显然规则写出适用条件与后果；代码能够直接表达的调用细节不再铺成一篇副本。

### ADR 保留真实取舍

记录真实发生过的选择，不能为了模板完整而发明替代方案。若历史理由不在任何记录中，写明未知。代码可以证实实现，却不能证明作者当初的动机。

改变实际实现位置时更新现役事实；改变决定本身时建立后继并说明替代范围。格式可参照 [决策模板](../assets/decision.md)，没有内容的段落删除即可。

### 错误经验保留适用条件

写清“在哪种条件下会出现什么信号、证据支持什么原因、如何处理和验证”。不要把一次平台特例变成全局禁令，也不要把症状误写成根因。证据不足就保留为诊断线索，不能写成已验证的预防规则。

错误已经无法再次发生、且不再解释现实约束时移出默认检索；仍涉及旧数据或兼容消费者时保留有关部分。

## AGENTS 与导航

安装器在选中 dev 领域的任意技能时补齐简短目录说明，包括 `.agents/dev/AGENTS.md`；这些说明只记录职责、边界与导航，不是业务知识，也不保证被宿主递归加载。读取资料时按需显式读取有关说明。`dev/context/` 是宿主配置，`dev/notes/context/` 是业务与模块背景，不能混用。

根 `AGENTS.md` 保留项目专有的少量高频规则与阅读入口，链接到术语、模块和部署的主要说明；不要把它变成架构教科书。已有内容与当前工作无关时不顺便整份重写。

`.agents/dev/notes/index.md` 是轻量主题导航，表格记录主题、何时读取、文件；不再重复每个决定的状态和正文。没有内容时不创建。文件夹和关键词搜索仍可直接定位资料，不依赖中央索引才能工作。

读取顺序：用户请求 → 相关入口/术语 → 命中的少数笔记 → 当前代码与证据。发现陈旧内容就纠正现役文件或标出待核实范围，不把整库全文塞进上下文。

## 敏感信息与事实范围

普通笔记只存凭据的名称、用途和安全存储位置，例如环境变量名、密码管理器条目或本机未跟踪配置路径。不要写入令牌值、密码、私钥、含凭据的连接 URL 或未经脱敏的日志。若源材料含凭据，先脱敏引用，原值只在已授权的安全存储中处理。

项目意图、实际行为、运行证据、历史说明分别注明。旧笔记不能推翻最新明确的用户目标；未上线的目标也不能冒充线上事实。
