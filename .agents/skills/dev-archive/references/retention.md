# 保留、替代与归档

在新知识写入或现役笔记整理时读取。判断原则：未来指导价值决定保留；历史价值决定归档；篇幅和年龄只帮助发现候选。

## 每份笔记应得到的处理

| 情况 | 处理 |
| --- | --- |
| 仍解释真实取舍、所有权、兼容性、持久化语义、安全约束或何时可以重新考虑 | 保持现役；同步已核实的代码位置与事实 |
| 只复述一次微小 UI 调整、机械搬文件或临时执行过程 | 无独有理由时删除冗余说明，并修复入链；原始需求证据按其生命周期保留 |
| 完成的历史决定，未来指导价值很低，但有独立历史意义 | 归档为明确的历史记录，链接到当前说明 |
| 尚未实现且仍有意义的提案 | 留在需求/提案资料中；不得因时间久而当作已实现归档 |
| 不再打算实施的提案 | 写明放弃原因；有必要时作为已取消需求归档，不冒充已实现 ADR |
| 被拒方案仍容易诱人重复犯错 | 保留真实拒绝理由、适用条件和重新考虑的触发条件 |
| 被拒方案已不可能发生，或其前提已经消失 | 删除没有独立历史价值的重复记录；有价值的事实先转入其现役归属 |

“小改动”不等于“没有长期价值”。一次改名也可能明确领域词义；一个小 bug 可能暴露跨进程持久化义务。不要只根据 diff 大小、字数或完成状态分类。

## 新知识必须检查旧知识

围绕概念、机制、原名称和现名称搜索现役笔记及它们的入链。不要只搜新标题。每次新增笔记就在同一次修改中处理已知重叠；不将明确冲突推迟给一次未来的全库清理。

### 同一个决定，实现位置改变

原地更新现役文件中的路径、符号、默认值和实现事实，链接到当前代码。保持原有理由和真实取舍，不追加一串“后来又改成……”来代替当前说明。

### 决定被反转

建立新的决定记录，写明改变的原因、替代范围及实际后果。旧记录保留原本的决定，在开头指向后继。原文件仍有独特的解释价值就保持可发现；仅剩历史价值时才归档。

### 完整替代

仅在旧记录的每项有效内容已被承接或确实失效时退出旧记录。现役文件必须保留仍有用的：

- 决定及为何作出它；
- 真正考虑过的替代方案及放弃原因；
- 负向保证、兼容责任、持久化或恢复义务；
- 现存验证、覆盖缺口以及重新引入条件。

不以 Git 历史作为这些独有理由的唯一可发现位置。承接完且没有独立历史价值时才删除冗余文件；否则归档。禁止为了减少文件数把相互不同的决定揉成没有条件的总规则。

### 部分替代

明确哪些段落已经过时，哪些仍约束当前行为。更新当前事实并双向链接；不要因为一个默认值、界面或传输方式被移除，就整份归档仍然解释存量数据、另一种调用方式或安全边界的记录。

## 文档冲突的处理

当前实现事实能由代码验证时直接纠正陈旧说明，引用证据并指出影响；不必为了普通路径修正打断工作。若冲突是业务概念含义、未记录的历史动机或用户希望的行为，保留两种说法与证据，只澄清会改变实际结论的问题。不从当前实现倒推“当初为什么这样设计”。

代码仅证明其实际行为。测试证明被检查的场景；部署回执证明对应版本和环境；设计稿证明被批准的设计。它们不能相互冒充。

## 移动和链接

移动前搜索入链，确认目标不与现有文件冲突。移动已结束的需求目录时，按[change 收尾方法](change-closure.md)选择结果与主类型并重命名，保留原创建日期和内部相对结构；修复它引用的现役笔记、代码和部署记录的相对路径；不能仅移动目录就宣布完成。并发修改时先重新读取最新文件，不覆盖另一人的新增内容。

现役文档的链接优先指向当前主要说明；必须引用历史时明确标注。归档笔记写清归档日期、当时适用版本和当前替代位置。之后按历史快照对待，不为了追赶新代码、排版或过时的外链持续重写；安全性删密、事实纠错等另有明确需要时单独说明修订，保留发生过修订的事实。

默认检索先查 `.agents/dev/notes/` 和当前代码；只有需要追溯过去才显式查 `.agents/dev/archive/`。不要让旧架构说明与当前资料无差别进入上下文。

## 轻量复核

回读改动文件；确认当前代码链接/符号可定位、导航指向真实文件、被删除或移动的资料没有遗留错误入链，且规格与上线状态没有被夸大。报告实际检查范围；不新增一套归档状态机、哈希封印或必须全仓扫描的门禁。
