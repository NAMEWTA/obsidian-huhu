# 对运行进程取证

观测活进程，不凭源码猜测。默认交付有证据的诊断；用户明确要求并授权时才进入修复。先确认目标进程、环境、隐私范围与允许的观测影响。

1. **采集实时信号。** 使用实际可用工具，针对空转进程取 CPU profile，针对泄漏取堆快照，针对界面毛刺取浏览器或运行时 trace。工具须适合当前平台和程序；不假定 CDP、特定模拟器或原生剖析器已经存在。记录采集条件与观察对程序的影响。
2. **缩减到关键证据。** 找出热路径函数、泄漏对象到 GC 根的保留链、没有输入却触发的循环。大产物有独立代理时委派只读解析，主线程保留结论与证据指针；没有时分块解析，不把整个捕获塞入上下文，见`dev-guardrails`（上下文预算）。
3. **确认机制。** 优先通过已有计数器和只读观测取得区分假设的证据。确需临时观测注入或热修改时，使用已授权的隔离实例，说明影响与清理；不能把“只读诊断”当作修改生产进程的许可。没有权限就报告当前证据支持的假设与所需下一步，不伪称已证明。
4. **映射回源码。** 指出文件、符号、分配或调度位置，记录运行版本。缺少符号或源码映射时，明确缺口，不把地址猜成函数。
5. **保留范围和结果。** 简短记录这是只读取证还是含授权临时观测，不为形式添加吞吐清单。原始产物可能含用户数据，保存在受控位置，仅分享本任务必要且脱敏的部分。

报告采集信号、缩减发现、机制如何被证明或尚未证明、源码位置和产物路径。未要求就不修代码。原因已知且已授权改动时，进入[性能问题](performance-issue.md)；行为缺陷按真实契约修复。
