# 对已有轨迹取证

分析用户已有的捕获；产物是固定数据集，默认只读，不重跑目标程序。运行进程取证见[运行时取证](runtime-forensics.md)。工具按格式选择：cpuprofile、压缩 JSON 用支持该格式的分析器，spindump 用文本分析，heapsnapshot 用相应堆工具，不假定任一工具已安装。

1. **识别与加载。** 确认格式、采集版本、时间范围与环境。大产物有代理能力时分配独立只读分析，默认当前可用模型；否则分块解析，保留关键指针，见`dev-guardrails`（上下文预算）。
2. **得到可查询表示。** 使用支持的分析器或转换工具，必要时将轨迹、样本、帧或堆节点导入 SQLite 等查询形式。已有工具能直接查询就复用，不为形式重写解析器。读取压缩大文件时考虑体积，保留原件；记录转换是否丢失信息。
3. **收敛机制。** 查耗时最多的帧，沿调用树定位热路径。泄漏沿对象到 GC 根的保留链；spindump 看线程是在 CPU 上运行还是阻塞，以及等待对象。不把单个排名自动当作根因。
4. **归因源码。** 用产物自身符号和匹配版本，将热点映射到文件、符号和位置。没有源码映射的帧尚不足以形成完整诊断；能解析就继续，不能则明确产物未提供什么。
5. **比较成对捕获。** 有前后数据时核对相同负载和环境再比较。只有一份捕获时，将结论标为产物支持的最强假设；时间相关性不自动证明因果。
6. **交付可复查结论。** 提供产物、格式、查询/过滤方法、发现、源码位置与成对捕获是否确认。只读任务不修改代码；用户已授权修复时再进入[性能问题](performance-issue.md)。不为只读调查强制创建 PR、状态清单或后台任务。
