# 按规格实现

以规格定义结果，以代码实现结果，再取得风险相称的行为证据。使用任务前沿、上下文指针和独立实施者，按可验证小单元推进，明确所有权并在同一交付面验证。

先明确本次行为契约和关键设计，再选择最有用的反馈方式。用户要求测试先行，或稳定的公共接口与快速测试能降低风险时，调用 `dev-tdd`，逐个完成失败测试与最小实现的红→绿循环；完整测试方法只在该技能维护。本技能负责实现切片和集成，不复制测试教程。也可以按规格直接实现后验证；不为低影响修改增加形式化流程。

实施主线见[功能交付](references/feature-delivery.md)，行为保持型修改见[重构](references/behavior-preserving-refactor.md)；已有复杂切片依赖时补充[任务图实施](references/implement-task-graph.md)，沿用已有计划，不重复创建流程。

## 开始或恢复

读取规格、计划、进度和影响本次代码的项目规范。复核最新代码、分支和未提交改动；保留用户与其他任务的工作。恢复会话时，以当前工作树、远端记录和实际产物复核旧进度，不盲信“已完成”。

没有正式 spec 的小任务，先在现有记录中写清目标行为、范围和验收即可。缺失会改变产品目标或数据语义的决定时，只阻塞相关部分，不擅自猜成定案。

明确故障的调查修复以 `dev-debug` 为主，性能指标改善以 `dev-benchmark` 为主，显式测试先行采用 `dev-tdd` 方法。当前已在实施的任务复用这些方法与证据，不因为换用方法而重新规划或另开任务。

新增工作记录统一使用 `.agents/dev/changes/<YYYY-MM-DD-slug>/`，按需维护 `spec.md`、`plan.md`、`progress.md` 与 `evidence.md`。这些是项目工作记录，不属于技能安装目录。

## 从前沿推进

把计划看成带真实阻塞关系的任务图。每次选所有前置产物已经可用的切片；完成一个就重新计算前沿。切片交付完整行为，不把各层的半成品当成已完成。

有可独立推进的工作时并行处理；有共享状态、共享文件或紧密接口耦合时先确定唯一所有者。优先消除不必要共享，再考虑串行。小任务由一个实施者完成即可。

需要代理协作时，按 [委派与整合](references/delegation.md) 提供目标、契约、可写边界、依赖和完成证据。优先给文件与提交指针，不复制整段上下文。不同任务可用独立上下文和工作树；工具不可用时顺序完成同样的工作，不把工具依赖变成阻塞。

## 实现一个可验证单元

1. 确认切片的输入、行为、数据形状和成功条件。
2. 按现有约定推进一个行为。非平凡设计先确定接口与所有权；选择测试先行时，先观察行为测试因尚未满足契约而失败，再写最小实现使其通过。已有设计与证据足够时直接实现。
3. 保持范围清楚。新发现若阻塞本次目标，纳入并说明；无关改进记为后续项。
4. 选择能证明该行为的最便宜充分检查，核对当前实现的实际结果。重要回归可在实现前用测试锁定，也可在实现过程中补齐；低影响修改不为数量添加测试。
5. 记录实际结果、产物和仍未验证的部分，再推进下一单元。

验证入口必须匹配交付物：UI 打开页面并操作相关状态，CLI 实际执行，服务调用接口，存储检查写入后重载。类型检查、构建和静态审查各自有价值，但不能证明它们没有观察的行为。

给已有正确行为补测试时，保持产品行为不变，用现有公共接口验证契约；需要检验测试敏感性时使用隔离故障注入，不为满足红绿形式增加产品改动。

遇到失败时依证据排查。被证据否定的试探性修补应撤回，不留下“可能有用”的代码。故障调查调用 `dev-debug`，传入当前切片、失败证据与预期行为；修复验证后返回原切片，不另开计划。

## 构建可操作界面

用户明确要求按钮、状态面板或机器人操作页面时，按[完整操作界面方法](references/action-ui.md)实现前端、服务端、真实 webhook 接入与验证，并用[接口约定](assets/action-contract.md)固定允许的动作、身份校验和失败结果。复用已有设计系统；密钥只留服务器，HTTP 接收成功与业务完成分开验证。查看进展本身不触发构建，按钮也不扩大动作授权。

## 整合与复核

先阅读实际 diff 和行为产物，再接受实施者的完成报告。整合依赖更新后，复核受影响的接口；发生冲突按契约解决，不能通过保留两个互相矛盾的实现来消除冲突标记。

分开审查两件事：实现是否满足规格，是否符合项目规范。较大工作可用独立审查者；也可在新一轮上下文中自行审查。调用 `dev-review`，复用当前规格、差异与行为证据。

检查结果绑定具体工作树或提交。代码后来变化时，判断原证据是否还覆盖当前交付；受影响的验证重跑。不要重复已经充分证明且未受影响的检查。

## 持续到授权的交付点

按照用户要求和项目流程提交、推送、创建 PR 或继续部署。外部动作只在已有授权覆盖时执行；用户已经授权的步骤直接完成，不反复问是否继续。没有被要求的 PR 评论、issue 关闭或团队通知不自动发送。

达到完成点时明确：

- 哪些规格行为已实现，证据在哪里。
- 哪些验证已运行，哪些因环境限制尚未完成。
- 实际提交、远端、PR 或部署状态；排队、配置成功和执行成功分开。
- 下一步是否属于本次授权范围。

若本次目标包括部署，代码完成只代表进入部署阶段，调用 `dev-deploy`。完整需求完成后将可复用知识交给 `dev-archive`，继续沿同一任务完成知识收尾。
