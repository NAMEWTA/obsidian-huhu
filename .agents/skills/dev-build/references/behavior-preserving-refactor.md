### 重构

**你负责契约。结构改变，行为不变。** 区别于新增行为的功能开发，以及纠正行为的缺陷修复。

清理暴露缺功能或真缺陷时，拆出去，先按固定契约交付结构变更。允许重新设计，但要点明并路由功能开发。大型或横切结构工作属于 **复杂任务规划**。本手册用于聚焦至中等范围改动。

1. 先固定行为契约。对受影响子系统运行 **模块探索** 理解契约，先读取现有行为证据、运行现有程序并记录必要的输出或快照，明确要保持的规格契约。覆盖不足且存在合适接口时，在结构修改前建立特征测试、快照或等价性检查，固定当前正确行为；已有证据充分时直接复用。再实施结构修改并重跑相同检查，不能省略最终等价证据，也不为低影响编辑堆积无关测试。类型检查与 lint 不能固定行为。
2. 按 **领域结构** 指出代码缺少的结构。形态已清楚且局部时，保留朴素代码。重塑必须删除分支或非法状态，不能增加间接层。
3. 指出目标形态。说明今天重建时模块布局、类型、调用图应怎样，遵循 **工程原则（基础设计）**、**工程原则（重新建模）**。目标跨函数边界时，移动前用 **架构设计** 并行探索形态。
4. 先删后加。引入新形态前删除死代码、折叠单调用者包装、删冗余校验与孤立引用，遵循 **工程原则（先删后加）**。只交付达到目标形态的最小改动，遵循 **工程原则（最小充分改动）**。“也许有用”的猜测性清理回滚。
5. 以保持行为的小步移动，每步保持固定机制通过。API 重塑在同一轮迁移所有调用者并删除旧 API，遵循 **工程原则（迁移调用者后删除旧接口）**。不留兼容垫片，不并存新旧路径。对照真实文件抽查每次重命名，字符串、文字、反向引用中的用法常被静默漏掉。给使用已配置重构模型（默认继承当前会话模型）的子智能体明确范围，含路径、移动名称、应保持行为，委派机械编辑。按本包执行支持与当前工具能力选择实际可用的模型、推理能力和速度。
6. 在真实产物证明行为不变，不是“能编译”，遵循 **real-evidence**。较大重塑跑等价检查：比较旧新输出的脚本、对新代码重放已记录基线、或通过匹配界面的控制技能做冒烟。
7. 确认改动值得保留。成功指标是读者负担降低，遵循 **工程原则（降低阅读负担）**。差异未在任何地方降低读者负担就回滚。
8. 按可审查单元组织提交：先减法，再重塑，再后续清理。只有实际需要整理历史、分支由本任务独占且已有授权覆盖时才重排或变基，不为重构流程自动改写共享历史。按 **可验证单元** 塑形，让每个保持行为的切片在下一个之前保持绿色。交付目标包含 PR 时执行 **PR 交付流程**，否则按当前授权的提交或交付方式收束。

**回复：** 改变的结构、固定契约的方法、等价证据、读者负担变化、交付与回滚内容。没有新行为。
