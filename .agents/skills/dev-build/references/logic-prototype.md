# 逻辑原型

单个、自包含的 HTML 文件，即**可分享演示**，让任何人都能通过点击按钮操控状态模型。当问题涉及**业务逻辑、状态转换或数据形状**时使用：这些东西在纸面上看似合理，只有经历实际场景才会感觉不对。

因为只有一个文件且无需安装，可以交给非开发者，例如设计师、产品经理或领域专家，让他们亲自感受模型。所以它说的是他们的语言，而不是代码语言。

## 何时适用

- “我不确定这个状态机是否处理了先 X 后 Y 的边界情况。”
- “这个数据模型真的能表示这样的场景吗……”
- “写 API 之前，我想先感受它应该是什么样。”
- 任何希望**按按钮并观察状态变化**的情况。

如果问题是“它应该长什么样”，选错了分支。使用 [界面原型](ui-prototype.md)。

## 流程

### 1. 写明问题

写代码前，写下原型针对什么状态模型、回答什么问题。用一段话放在演示顶部的可见介绍里，不要只放在注释中。回答错误问题的逻辑原型是纯浪费，所以要明确问题，以便稍后检查，无论用户当前在看还是过后无人值守地回来查看。

### 2. 把逻辑隔离为可移植模块

把真正回答问题的逻辑放在单个 `<script>` 块中，写成小型纯模块，之后可以抽出并放进真实代码库。周围页面是一次性的，这个模块不是。

正确形态取决于问题：

- **纯 reducer**：`(state, action) => state`。动作是离散事件、状态是单一值时适用。
- **状态机**：显式状态和转换。当“当前到底允许哪些动作”就是问题的一部分时适用。
- 在普通数据类型上操作的**少量纯函数**。不存在隐含当前状态、只有数据转换时适用。
- 当逻辑确实拥有持续内部状态时，使用带清晰方法表面的**类或模块**。

选择最适合问题的形态，**不是**最容易接上页面的形态。保持纯粹：没有 DOM、没有 `document`、没有伸入内部的按钮处理器。页面调用模块，模块不反向访问页面。这让原型在自己的生命周期结束后仍有价值：问题回答后，已验证的 reducer、状态机或函数组可以独立搬进真实模块。

### 3. 构建可分享 HTML 文件

一个文件，普通 HTML／CSS／JS：不用框架、打包器或服务器，全部内联，双击即可打开，也经得起通过邮件转发。任何人只需打开就能运行。

面向非开发者编写。每个标签使用**领域语言**而非代码：按钮和状态应像业务说法，而不是 reducer。用简单语言解释正在发生什么。

自上而下建立清楚层级：

1. **标题和一行说明**：演示能探索什么，即第 1 步的问题。
2. **当前状态**：全部相关状态，以易读面板呈现，使用带标签的字段，而非原始 JSON。每次点击后重新渲染，使变化可见。如果有助于非开发者跟上，明确指出刚刚改变了什么。
3. **自由操作按钮**：每个动作一个按钮，始终可用，让任何人都能按任意顺序试探模型。每次点击派发动作并重新渲染状态。
4. **引导演练**：一组**场景**，每个场景一个标签页。每个标签页先用简短自然语言描述场景，包括设置什么情境、注意什么；下方按顺序列出场景中**应按的按钮**。每一步都是真按钮，点击即执行动作并进入下一步。启动演练时重置到已知初始状态，让场景每次表现相同。

挑选能演示棘手情况、纸面上难以推理的场景：正常路径、一个复杂边界情况，以及尝试做一件应属非法的事。

保持漂亮而克制：清晰字体、充足间距、一种强调色。不用动画或花招，不让任何东西与状态和按钮争抢注意力。

### 4. 交给用户

发送文件或替用户打开。用户有空时会点击演练和自由操作；有价值的时刻是他们说“等等，这不应该能发生”或“原来如此，我以为 X 会不同”。这些是**想法**中的缺陷，正是原型的目的。如果他们需要新动作或新场景，补上。原型会演进。

### 5. 记录答案并保留原型

原型回答问题后，先记录答案，再按 [原型方法](prototype-method.md) 的方式保留原型。逻辑分支的具体映射：已验证的 reducer、状态机或函数组进入真实模块，代表决定被吸收；HTML 外壳随原型进入隔离原型目录或分支，作为一手资料保留。因为它是单个自包含文件，在那里仍然很容易重新运行。

## 反模式

- **不要添加测试。** 需要测试的原型已经不再是原型。
- **不要接真实数据库。** 除非问题特别涉及持久化，否则使用内存状态。
- **不要泛化。** 不讨论“如果未来想支持 X 呢”。原型只回答一个问题。
- **不要混淆逻辑与页面。** 如果纯模块引用 DOM、`document` 或按钮处理器，就无法独立搬走。页面应只是纯模块上的薄壳。
- **不要使用框架、打包器或服务器。** 接收者双击单文件就能打开；React 应用或开发服务器破坏了可分享性。
- **不要把 HTML 外壳送入生产。** 页面为手动点击体验优化，值得保留的是背后的逻辑模块。

原型仅回答问题，不等于正式交付。正式实现根据已明确的行为选择测试先行、实现后验证或组合方法；保持原型数据隔离，不让生产构建暴露原型分支或选择器。
