# 部署与发布记录

交付的是**指定环境中实际运行的版本及可恢复的操作记录**。先读项目真实启动方式、现有部署配置与本次规格，不凭技术栈猜一个通用部署命令。

## 固定本次发布

- 核实环境、账号或集群、主机、项目路径/命名空间、对外入口与实际权限；不能沿用上次聊天的生产目标。
- 固定源码提交及实际构建制品，例如镜像 digest、包版本或静态产物摘要。工作区有未提交更改时说明其来源，不能只写 HEAD 冒充制品版本。
- 确认用户授权覆盖的部署范围。已明确要求把此项目上线到此环境就持续执行；环境或权限仍不清楚时，先准备制品、计划、差异、迁移与恢复办法，最后只问缺少的关键决定。

## 准备并执行

1. 读取真实构建、启动、健康检查、环境变量、持久化目录、依赖与数据库迁移。验证是当前制品的结果；此前版本的绿灯不能代替。
2. 比较环境现状与目标，保留已知可用版本和必要备份。区分“应用回滚”和“数据恢复”；有不可逆迁移时写明恢复前提与数据损失窗口，不假装一次镜像回退就能撤销数据库变化。
3. 采用现有发布工具和目录。项目部署权限只覆盖该项目及获准依赖，不隐式取得整台服务器的清理、升级或代理修改权限。
4. 执行可重复的准备、依赖检查、单一迁移执行、发布和切换。多环境/多主机逐个保留实际结果，不能宣称跨主机原子成功。
5. 在真实入口验证版本、健康及至少一条相关业务路径。授权内使用可识别的验证数据并清理；只看端口打开、进程存活或 CI 成功不算上线验收。
6. 有失败先保留证据、停止依赖失败结果的后续步骤，再按已批准的恢复方案处理。不得删除数据库或盲目重复有副作用的迁移。

按需读取 [环境与发布方式](references/environments.md) 和 [凭据、备份与恢复](references/secrets-recovery.md)。发布验证针对指定环境中的实际行为。开发方法不限制交付：使用已有行为检查、必要的部署探针与真实业务操作，选择能够证明当前制品的证据，不为凑覆盖率增加测试。

## 持久化

新增部署资料统一放在 `.agents/dev/deploy/<环境>/`；已有手册按真实位置查阅引用，不擅自移动实际服务或数据目录：

- `runbook.md`：当前入口、实际项目根、构建发布方式、数据目录、依赖、检查、回滚与凭据**引用**。使用 [运行手册模板](assets/runbook.md)。
- `releases/<日期-版本>.md`：本次版本、命令摘要、迁移、验证证据、结果与未完成项。使用 [发布记录模板](assets/release.md)。

真实密码、令牌、私钥只进入用户选定的密钥管理器或受限的未跟踪配置；普通文档只记账号用途、配置键和获取方式。维护服务器侧文档时同步实际运行事实，并注明哪些副本已核对。

部署结束后把有长期价值的环境约束、决策和错误经验交给 `dev-archive` 或直接整理到 `.agents/dev/notes/`。没有上线成功就明确标记失败、回滚或待部署，不把整个需求写成“已交付”。
