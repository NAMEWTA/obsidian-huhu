# 按实际环境发布

本表用于定位项目已有的方式，不是要求安装新平台。执行具体命令前读取本项目与当前版本的官方说明。

| 方式 | 需要核实 | 业务验证与恢复 |
| --- | --- | --- |
| 本地 / 开发环境 | 端口、配置来源、依赖与数据是否可丢弃 | 启动实际应用，走相关用户路径；记录清理方式 |
| 容器 / Compose | 镜像 digest、真实 compose 文件、项目名、网络、卷、健康检查与迁移命令 | 发布明确服务，检查实际镜像和持久化；保留旧镜像及配置，不默认删卷 |
| systemd / 进程服务 | 已有 unit、运行用户、WorkingDirectory、环境配置、权限和日志 | 用既有服务机制切换版本；检查重启后真实行为；不扩大成主机升级 |
| Kubernetes | context、namespace、workload、镜像 digest、secret 引用、迁移 job、探针和路由 | 确认 rollout 与入口版本；业务检查；按实际数据兼容性判断能否 rollout undo |
| PaaS / Serverless | 目标项目、账号、预览与生产区别、构建产物、环境变量与流量入口 | 确认实际部署 ID/URL、函数或服务版本与关键路径；保留可切回版本 |
| 静态站点 | 构建目录、base path、静态资源、CDN/缓存与 SPA 回退 | 从真实 URL 验证页面、资源与路由；回退精确产物，核对缓存传播 |

## 数据与共享依赖

区分专有数据库、共享实例中的逻辑资源和外部托管服务。不要因为应用需要 Redis 就重装服务器上已有 Redis。账号仅绑定实际需要的数据库、bucket 或命名空间，记录依赖归属与升级影响。

在发布前确认哪些目录是数据、日志、临时构建或备份。记录容器内路径到宿主实际路径的映射，重启后检查数据存在。没有验证备份可读或恢复方法时，明确恢复能力未验证。

## 配置与运行文档

手册记录执行入口和少量关键约束，具体行为引用仓库中的 deployment manifest、构建脚本和 migration。不要在手册复制几十行会频繁变化的配置。实际线上事实需要环境名、版本和核对时间，不能仅靠代码推断生产状态。
