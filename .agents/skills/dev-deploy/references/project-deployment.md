# 项目与共享服务部署

固定一个项目与明确目标服务器，配置容器或服务、依赖、升级和两侧文档；项目部署不隐式取得整台服务器维护权限。开始时读取本包 [环境方式](environments.md)、[凭据与恢复](secrets-recovery.md) 及当前项目部署记录。

## 读取范围

只加载当前项目、目标主机、环境与实例需要的事实。规划、执行和恢复前核对工作区、授权、持久化、秘密保存、部署布局与恢复条件；存在共享依赖时同时核对其所有权和受影响消费者。

## 流程与完成标准

先固定项目、明确服务器列表、环境和实例。展示每个目标已核实部署根及项目目录，不从当前目录、默认登录目录或上次目标猜测。缺少接入或系统基线时，先在授权范围准备；已授权的前置准备和部署可连续执行，不重复确认。公共数据库、缓存和对象存储作为独立共享服务维护；主机级入口与隧道服务单独记录，不伪装成应用项目。

从用户指定本地路径或精确提交读取实际清单。只要求分析时不执行仓库代码。获取源码按任务授权固定完整版本，不用浮动分支名冒充已交付版本。来源版本更新写入本次计划，不改写历史部署事实。核对构建所用脚本和输入，发现会扩大权限或改变目标的输入时先说明具体差异。

识别真实启动、构建、所有持久化参数、环境变量、迁移、健康和恢复能力。不能只生成通用容器配置就宣布完成。区分专用、共享、外部依赖，遵循已指定提供方；多候选按现有配置和证据选择，产品或账户不明确才询问。数据库、缓存、对象存储分配明确逻辑资源与应用账号。未知产品保留原名，查真实仓库和版本，不凭名字猜适配方式。

需要业务验证时，由项目负责人维护可重复真实路径及已知错误情况；参考 `dev-verify`（验证方法生成） 和 `dev-verify`（验证维护）。记录脚本、依赖、夹具和实际检查入口。端口存活不等于业务成功。验证写入、网络与清理仍须在当前授权范围内，未执行配方标为未验证。

为应用维护专属服务配置、受限环境配置、按组件和用途区分的数据、日志、备份、发布产物和运行手册。公共服务独立放置，不把物理数据复制进应用。应用副本可按实际设计共享同一逻辑分配，不同应用默认使用不同逻辑数据与凭据。跨配置文件、跨主机依赖用明确连接信息和执行顺序协调，不用单一配置中的依赖字段冒充跨系统编排。

计划说明持久化映射、来源与制品摘要、执行顺序、账号用途、版本、网络、受影响消费者、数据库迁移唯一执行者、备份与恢复限制。新装和已有提供方都先准备验证，再分配逻辑资源，最后部署消费者。跨主机失败停止依赖失败结果的后续动作，逐主机保留事实，不声称全局事务。

沿本次已授权目标连续执行。升级、回滚明确目标版本和恢复步骤，不把旧计划的目标或数据破坏权限隐含继承。迁移单独记录来源与目标实例、数据备份、复制、追平、验证和切换；具体数据库恢复命令必须经本项目验证，不从通用模板猜测。

卸载默认只停止本应用和退出其连接关系，保留数据、账号、公共服务和共享网络。删除逻辑业务数据需要明确范围与授权，不作为卸载默认动作。

完成条件是相关业务步骤与健康检查成功。服务端运行手册包含最新版本、时间、配置引用、持久化、操作步骤和依赖；控制端保存发布记录和必要受限配置。普通文档只记凭据引用，不保存秘密值。核对两侧文档内容及必要摘要，记录哪些副本已验证；文档未同步时不能报告全部完成。更新项目到主机、主机到项目的 Markdown 索引，可用 [主机入口模板](../assets/host.md)。

使用项目已有工具、脚本和平台执行，不强制安装专有执行网关。每条写入命令都必须与已核对目标和授权一致。

## 接收开发交付

仅在任务包含交付时，读取开发方的规格、提交、制品和验收证据，以真实路径连接开发与部署事实。没有其他技能也能依据可核查原始材料部署，不创建虚假变更记录。开发授权与部署授权分别按用户当前请求核实；已明确要求指定环境上线时持续完成。部署记录只写实际结果，不擅自关闭外部工单。
