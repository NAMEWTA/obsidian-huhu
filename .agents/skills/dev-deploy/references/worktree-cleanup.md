### 工作树和模拟器清理

1. 快照与审计。记录 `df -h /`，运行[本地只读审计](local-tools.md)中的 `worktree-audit.mjs`，结合磁盘占用、分支合并状态、工作树差异和显式选择的会话记录核对，遵循 工程原则（构建验证工具）。默认以实际默认分支判断合并；PR 目标不同时按其目标基线核对，不能只凭分支名推断可删除。路径来自 `git worktree list`，不手输，因为手输 `myrepo-worktrees/x` 会漏掉 `<工具工作树目录>/myrepo/x` 中的工作树，遵循 structural-learning。按大小、年龄、合并状态、未提交工作、PR 状态、最近触及它的聊天分类，再建议分组。只在当前环境支持后台执行且任务需要时后台运行；否则在本会话执行，不声称已建立后台任务。
2. 分组是建议，不是许可。固定和活跃聊天才是真实产物，遵循 real-evidence。从用户或侧栏获取该集合，逐候选核对。`safe` 分组仍可能对应用户固定的工作树，因此固定集合优先。
3. 删除前验证使用情况。对每个 `verify-recent-chat` 行或任何疑点，扇出子智能体读记录，报告聊天是否固定或进行中、触及哪些工作树，遵循 工程原则（上下文管理），因为对话是大内容。固定聊天通过后台子智能体在兄弟工作树创建 方案比选 和复现树，即使名称没出现在侧栏，也正在使用。按本包执行支持与当前工具能力选择实际可用的模型、推理能力和速度。
4. 不可逆丢失时暂停。`wip:N` 是 N 项已跟踪未提交编辑，先展示差异取得决定，因为干净工作树可从分支恢复，未提交内容却会丢失。未跟踪文件不等于可丢弃内容。逐项核实归属、可再生性与授权，列出文件；不明内容保留。按自主性，干净、已合并、不使用的继续；`wip` 和使用中的暂停。
5. 清理已确认集合。仅对已核实干净、未使用且授权范围内的路径执行 `git worktree remove <path>`。命令拒绝时重新检查，不默认强制。忽略文件仍可能有价值；明确可再生且获准才按精确路径清理，然后 `git worktree prune`。分支引用仍在，因此不丢提交。用 `df -h /` 和重新列举确认。
6. 模拟器和其他空间来源。模拟器通常是下一大收益。先列出测试模拟器，核实无运行任务与需保留状态，只删除本次确认的设备；`xcrun simctl delete unavailable` 清不可用项，`xcrun simctl runtime list` 后 `runtime delete <id>` 清旧运行时。需要时再看 Xcode `DerivedData`、`iOS DeviceSupport`、当前开发工具的用户缓存目录 中 `state.vscdb.backup` 和 `snapshots/roots/<root>`，以曾作为工作区打开的文件夹命名的 root 会膨胀，以及 pnpm、uv、brew、yarn 包缓存。只清用户未要求保留的缓存。

这是唯一删除用户状态而没有代码审查兜底的手册，因此以上门禁就是审查。

**回复：** 清理前后 `df -h /` 与回收空间、已删除工作树、每个保留项的一行理由，如被哪个聊天使用或有未提交工作。
