# 形式化验证与维护

选取缺陷代价高、普通测试难以触达的一个真实承诺，使用最适合问题的工具获得可复核证据。先读代码和既有验证；用户已经指定领域时从那里开始。普通低风险改动不自动增加形式化工作，项目流程也不因本技能变成强制状态机。

开发方法按任务选择，可以结合规格、测试、生成输入、模型检查或证明。形式化结果仅覆盖明确的对象、假设与边界，不宣称项目没有缺陷。

## 选择入口

| 当前任务 | 执行过程 | 输出 |
| --- | --- | --- |
| 没有现成检查，或需要验证新承诺 | [创建检查](references/create-check.md) | 已实际运行的模型或验证框架、项目本地技能、代码映射与反例证据 |
| 覆盖代码已改变，或怀疑模型过时 | [维护检查](references/maintain-check.md) | 每项检查的同步、已更新、缺陷或阻塞结论，更新后的证据与基线 |
| 工具与边界尚不清楚 | [工具选择](references/tool-choice.md) | 选型理由、风险、成本和未覆盖范围 |
| 使用 TLA+ | [本地执行与反例阅读](references/tla-guide.md) | 真实 TLC 输出、完成状态、反例与代码重放 |

## 工作约定

1. 用一句普通语言说明属性，再用一句话说明被破坏的用户损失。确认它不是凭空新增的承诺。
2. 列明模型变量、动作、原子性、初始状态、外部环境、失败假设和规模边界；每项关联可打开的代码。形式化对象与真实实现的差异必须显式保留。
3. 运行检查。记录真实命令、工具版本、代码与模型版本、退出码、完成范围及反例。没有运行成功的检查仍是草稿；未完成与通过分开报告。
4. 在隔离副本中注入与该属性相关的真实故障，确认检查能失败；撤掉故障后复查基线。单独弄坏手工模型不能证明它能发现真实代码退化。
5. 对反例逐步回放真实代码。如果一步不能发生，修正建模错误；如果每步可发生，报告代码缺陷；无法判明时保留待查结论。用户已授权修复则继续相应任务，不为了通过而弱化属性。
6. 维护[检查记录](assets/check-record.md)、[项目验证技能](assets/verify-skill.md)和真实可运行命令。模型、脚本和生成的项目技能按真实源码或技能目录维护；新增检查记录统一写入 `.agents/dev/changes/<日期-主题>/verification/`，长期假设与代码映射写入 `.agents/dev/notes/context/`。已有资料按真实位置查阅引用，不擅自搬迁。

## 附带本地工具

将 `SKILL_DIR` 设为本技能 `SKILL.md` 所在目录。

- [TLC 运行脚本](assets/run-tlc.mjs)调用本地 Java 与 JAR，保留结果与退出码；复制到项目验证包后填写真实模型路径。
- [有限状态检查器](scripts/check-model.mjs)使用 Node.js 22.14+ 标准库，穷举可信 JavaScript 模型给出的可达状态并检查状态不变量，保留最短反例。它不解释 TLA+、不检查时序逻辑或公平性，也不替代通用证明器。
- [示例说明](references/example.md)介绍一个有两个请求、一个名额的演示；[运行演示](scripts/demo.mjs)真实检查示例代码、在临时副本中移除提交校验并证明检查捕获故障。例子数字是教学边界，不是其他项目的默认配置。

```sh
node "$SKILL_DIR/scripts/demo.mjs"
node "$SKILL_DIR/scripts/check-model.mjs" /absolute/project/model.mjs --max-states 1000
```

第二条命令的 `1000` 只是命令格式示例；实际预算从本次模型的规模和资源限制决定。达到预算而未穷尽时，报告未完成。图示调用 `dev-statechart`，复用已检查模型，不重新创建另一套模型。

## 交付

报告选中目标和工具原因、检查属性与范围、真实运行结果、故障注入结果、反例的代码重放、同步或漂移判断，以及仍未覆盖的内容。提供一条可重跑命令。把验证变更与产品修复分别说明；生成的技能必须带齐自己的本地模型和脚本，清除占位项。
