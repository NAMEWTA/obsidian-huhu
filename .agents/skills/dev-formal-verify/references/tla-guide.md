# 本地运行 TLA+ 并解释反例

## 准备与执行

使用本地 Java 11+ 和兼容的 `tla2tools.jar`；本技能的执行模板基线为 TLC 1.7.4。记录真实版本与 JAR 摘要，不自动升级工具。`TLA2TOOLS` 指向 JAR 绝对路径，`JAVA` 可指定实际 Java 可执行文件。

模型使用 `.tla`，配置使用 `.cfg`。初始谓词、后继动作、常量值、状态不变量和时序属性都必须明确列出。把动作写成可辨认的析取，让反例中的动作能够对应到真实代码。

```sh
export TLA2TOOLS=/absolute/tools/tla2tools.jar
export JAVA=/absolute/java/bin/java
node "$SKILL_DIR/assets/run-tlc.mjs" /absolute/models/Model.tla \
  /absolute/models/Model.cfg /absolute/runs/model-001
```

`SKILL_DIR` 指本技能目录。模板会创建全新输出目录，保存 Java 版本、原始输出、退出码和 TLC 状态文件。模型引用的模块必须在实际可读取的本地位置。JAR、Java 或模型缺失时先说明具体阻塞，不能把没有求解的结果写成通过。

项目验证包复制这个脚本及本地说明后即可独立执行。脚本遵守本次工具原始退出码：TLC 1.7.4 的成功为 0，通常的死锁、不变量及时序属性反例分别为 11、12、13；其余退出码结合输出判断。它与把这些反例统一归为 1 的图形包装器不同，不能混用退出码说明。

## 先识别完成状态

核对实际读取的模型和配置、生成的初态数量、探索状态数、队列是否清空，以及最终结论。运行未完成、资源耗尽、语法错误、内存异常和没有初态分别报告。没有初态或所有路径被约束排除时，不能声称真实承诺已经得到证明。

INVARIANT 应在每个可达状态上成立；PROPERTY 的意义取决于其时序公式。没有 `[]`、`<>` 或 `~>` 的 PROPERTY 可能只检查初态，应核实是否本应声明为 INVARIANT。安全性与进展性分开；“从不超额”不意味着“请求最终完成”。

CONSTRAINT 和 ACTION_CONSTRAINT 控制搜索范围，不能承担待证明结论。使用 VIEW 或 SYMMETRY 时核对状态归并与属性是否相容。为可解释性和可复现性先保留单工作线程，随后扩大范围时记录配置变化。

## 把反例变成代码故事

1. 读取输出中指出的具体规则和初始状态，保留所有影响规则的变量。
2. 按编号写出每个动作的用户或业务含义、前置条件和状态变化，链接真实函数与事务边界。
3. 对状态不变量，解释最终状态如何违反承诺；对时序属性，保留循环入口、无限重复或停顿，不能截掉导致失败的循环。
4. 在隔离环境中按同样的动作顺序调用真实代码，必要时受控调度并发、重试或故障。
5. 某一步不可能发生时，检查模型原子性、类型、环境与初态；每一步都可发生时，把它列为代码缺陷。无法重放时明确未验证。

TLC 对状态不变量常用广度优先探索给出短路径，但不要把所有时序反例都称为全局最短。模型抽象或状态归并后，路径需要解释其映射。原始工具输出作为证据保存，交付叙述使用中文。

## 图示与维护

需要状态图时，调用 `dev-statechart`，本次不需要图示时直接使用原始轨迹判断；不要把一张图当成额外证明。

依据[维护流程](maintain-check.md)记录代码变更、模型变化、属性变化证据、重跑结果与故障注入。只有在模型与真实代码重新对齐且检查可运行之后，才推进同步基线。
