# 工具选择、假设与证明范围

## 由问题选工具

| 问题 | 合适的起点 | 结果能说明什么 |
| --- | --- | --- |
| 并发顺序、重试、消息丢失、租约、状态迁移 | 小型 TLA+ 模型与 TLC；已有其他模型检查器时复用它 | 声明的状态模型在选定边界内的安全或时序属性 |
| 数据结构不变量、整数溢出、内存访问、解析器 | 能直接处理该语言的验证器或 SMT 框架 | 被建模或直接处理的代码在工具假设内的属性 |
| 所有规模都必须成立的数学性质 | 证明助手、归纳证明或支持所需逻辑的验证器 | 在列出的公理、逻辑和可信基础下的证明 |
| 没有适用的代码级验证器 | 生成输入、模糊测试、属性测试并直接调用真实代码 | 已执行输入及生成策略覆盖内的证据，不冒充穷尽证明 |
| 小型明确有限的状态对象，验证器不必要复杂 | 本技能的标准库有限状态检查器或项目已有等价工具 | 枚举器实际生成且穷尽的可达图中的状态不变量 |

不因为某工具熟悉而选最容易建模的目标。选择用户危害与测试盲区相匹配的目标；若无法合理建立代码映射，说明验证只是设计探索。

## 写清假设

至少检查以下会改变结论的假设：

- 原子性和隔离：读、检查、提交、锁与事务是否真正不可分割；多线程和多进程是否共享相同保护。
- 环境行为：消息是否可能重复、丢失、重排；时钟是否单调；存储是否持久；外部服务是否会部分失败。
- 类型与取值范围：集合大小、整数范围、队列容量、连接数量、重复次数，以及输入语法边界。
- 进展假设：是否使用弱公平、强公平或最终恢复；安全性通过不自动证明最终成功。
- 初始状态和故障注入：模型是否涵盖冷启动、恢复、半完成事务和历史脏数据。
- 抽象：哪些代码细节被省略；抽象是否会引入真实代码不可能的路径，或隐藏真实风险路径。

区分环境假设、用于控制搜索成本的边界、要验证的属性。不能把希望证明的结论悄悄放进环境假设或状态约束。

## 证据强度与空洞通过

“未发现反例”需要同时说明工具是否完成、边界是什么、有哪些规则未检查。没有初态、不可达触发条件、恒真属性、缺少状态变量、过强前置约束或错误原子化都可能造成空洞通过。至少用一个能到达目标路径的正例和一次相关故障注入校准检查。

工具退出成功不等于全部属性都验证完成。保留超时、资源边界、未知求解结果、被跳过的规则和只检查初态等信息。穷尽一个有限实例不自动推出任意规模；需要另行证明可推广性或明确保留有限结论。

## 真实代码与模型的对应

按[检查记录模板](../assets/check-record.md)列出每个动作或断言对应的文件、函数和事务边界。读最新代码而非仅靠历史说明；代码改名、拆分、调用方变化、新写入路径和异常恢复都会造成漂移。

代码级验证需要说明编译器、语言语义、未定义行为处理、外部函数抽象和运行时模型。模型级验证需要反例回放：把模型动作转换为真实调用或受控调度，并确认数据前置条件实际可达。无法重放的反例仍有调查价值，但不能直接宣布为代码缺陷。

## 维护边界

属性只有在承诺有意改变且有证据时才能修改。记录旧承诺、新承诺及依据，保留相关反例。缩小搜索范围必须有原因并在结论中公开，不能通过降低上限掩盖缺陷。

工具版本、验证命令、模型代码、属性代码或覆盖范围改变时，重新执行并校准失败能力。记录最后核对代码的提交与工作区差异；阻塞的检查保持旧同步基线。
