# 体验优先

适用：涉及产品、UX 或功能范围取舍时使用。优先用户愉悦，而不是实现方便；交付少而精的功能，而不是更多粗糙功能。

实现方便与用户愉悦冲突时，选择愉悦。

- 每个功能、控件与选项都必须有理由。
- 少交付，交付得更好；三个功能的精致体验优于十个功能的粗糙体验。
- 决定前先做原型；在一次性 HTML 中做设计决定，比在生产代码中便宜。
- 把细节做好，包括过渡、对齐、间距、反馈和错误状态。
- 收紧核心循环；每个功能都应服务核心工作流，或者不妨碍它。

用户就是使用这项成果的人。对 UI，是终端用户；对库或内部 API，是导入它的同事。下一个维护代码的工程师也是用户。同样重视他们的体验，并从他们的角度说明影响。

基础建设应服务体验。基础性思考决定工作的*顺序*，本原则决定工作的*目标*。
