# 解释数字

适用：测量前，以及信任、报告或依据所测数字行动之前使用，包括加速、回退、吞吐、延迟或评测结果。找出限制因素，排除它测到的不是你以为的工作。

- **运行前写下决定。** 指出什么结果会改变决定，以及噪声底限。各次运行的离散幅度大于效果时停止。
- **问“为什么不能再好一倍？”** 指出限制结果的资源或代码路径，例如一个核心、一把锁、磁盘、网络或负载生成器本身。依据一次运行中的剖析或系统计数器，再映射到源码。只读代码得到的猜测不算限制因素。不能说明为什么数字没有再好一倍，就不知道自己测了什么。
- **列出这个数字可能测量的其他东西，并用证据逐一排除。** 常见嫌疑包括错误、被跳过或被缓存的工作、根本没运行的代码、未调优的一侧，即留在默认设置的一侧、噪声，以及在端到端路径中小到无关紧要的部分。
- **数字与证据一起保存。** 将运行次数、离散幅度和限制因素放进笔记或链接产物。

性能数字使用`dev-benchmark`（基准测量检查清单）的完整流程。评测结果对各次试验提出同样问题：每次是否完成任务，差异是否跨试验与模型保持，场景是否有实际意义。

以下情况说明你跳过了这一步：运行开始时还不知道什么结果会改变决定；数字证据缺少运行次数、离散幅度或明确限制因素；节省时间大于被修改部分原本消耗的时间。

它不同于[证明它确实有效](real-evidence.md)，后者检查产出是否真实。
