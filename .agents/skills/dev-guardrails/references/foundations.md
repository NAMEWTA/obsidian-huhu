# 基础性思考

适用：写逻辑前使用：选择核心类型与数据结构，安排基础设施和功能的顺序，考虑并发参与者共享什么。把数据结构选对，让后续代码变得自然清楚。

**结构决定**保护未来选择空间。**代码层决定**保护简单性。

**数据结构优先。** 写逻辑前先把数据形态设计正确。尽早定义核心类型，追踪每种访问模式，选择符合主要路径的结构。

在代码层，对结构去重，不对每一行去重。类型与数据模型应收敛。三条类似语句仍优于过早抽象。优先明确，而非巧妙。测试行为和边界情况，不测试行数。

**并发推论。** 执行者共享状态前，先问“另一个执行者并发修改它会怎样？”如果答案不是“没有影响”，就隔离。

**基础设施优先。** 一件事能帮助所有后续阶段时，就先做。问“它先存在，是否能让每个后续阶段受益？”CI、lint、测试基础设施与共享类型属于基础设施。按未来选择空间安排顺序：先设置再功能，先测试再修复。提交保持小而单一。

每次增量应交付一项连贯抽象，或加深已有抽象。不要把新能力以特殊情况协调的形式散布到调用者。

删减先于基础设施。先删除死代码，再打基础。
