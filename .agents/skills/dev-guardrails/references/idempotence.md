# 让操作幂等

适用：设计会经历崩溃、重启与重试的命令、生命周期步骤或处理循环时使用。不论先前部分运行停在哪里，都收敛到相同最终状态。

设计操作，使其无论运行多少次、前一次停在哪里，都收敛到正确状态。每个修改状态的操作都应回答：“连续运行两次会怎样？上次在中途崩溃会怎样？”

**原因：** 命令、生命周期操作与处理循环所在环境中，崩溃、重启和重试很常见。部分状态若会改变下一次结果，每次重启都会变成调试。

**思路：** 根据实际存在的状态推导每一步，不根据上次想做什么。读取当前状态，与目标比较，只应用差异。这样的步骤可以安全重复，因为重跑时会发现已无事可做。

一次运行留下的任何东西，包括锁、临时文件、写了一半的记录或已认领任务，都必须让下一次运行能识别其是否失效。判断过时与否所依赖的证据，应在前一次可能停止的任何位置都成立，不只在常见情况成立。下一次运行无法判断的标记，会让每次崩溃都需要人工清理。例如，写入临时路径后重命名到目标位置，或按内容而非创建顺序比较产物。

**检验：**
1. 连续运行两次会怎样？
2. 前一次在每个可能的位置崩溃，会怎样？
3. 重新执行能收敛到相同最终状态吗？

任一答案是“取决于留下了什么状态”时，操作就需要一个对照当前状态进行修复的步骤。
