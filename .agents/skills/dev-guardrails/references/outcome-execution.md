# 面向结果执行

适用：在具有明确阶段边界的计划性重写或迁移中使用。收敛到目标架构，不用会被丢弃的兼容代码维持平滑的中间状态。

为预期且可验证的最终状态优化，而非维持平滑的中间状态。

**原因：** 让每一个中间步骤都完全稳定，通常会产生最终成为长期债务的临时兼容代码。收敛到目标架构，在明确的验证边界证明正确性。

**核心规则：**

- 最终状态的完整性优先于过渡期的稳定性。
- 中间破损若已规划、范围明确且可逆，就可以接受。

**边界：**

- 只用于具有明确阶段边界的计划性重写和迁移。
- 声明哪些地方允许暂时不可用。
- 迁移期间，为正在改动的区域保留高信号检查。
- 计划完成时要求完整的静态和运行时验证。
