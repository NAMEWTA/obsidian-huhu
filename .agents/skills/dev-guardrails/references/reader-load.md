# 减少读者负担

适用：审查或塑造难以追踪的代码时使用。计算问题与答案之间的层级，以及读者必须记住的隐藏状态；折叠只有一个调用者的包装，缩小可变状态范围。

可维护性就是读者为了理解代码必须做的工作。跟踪两个维度：**需要追踪的层级**，即问题与答案之间的间接层；以及**需要记住的状态**，即读者必须放在脑中的隐藏或可变上下文。代码行数、圈复杂度和“整洁架构”都是替代指标，读者负担才是关键。两个维度相互独立。一个带 50 个全局变量的平铺文件，可能和 6 层适配器栈一样难以推理。两者都要控制。这是[保护上下文窗口](context-budget.md)在人类阅读中的对应原则；人的工作记忆也有限。

- **折叠成本大于收益的层级：** 只有一个调用者的包装、没有第二种实现的适配器、从未用到的推测性间接层。将它们内联。
- **让相邻层改变抽象层次。** 重复同样方法和参数的层，只增加读者负担，没有压缩信息。折叠透传层。
- **要求接口压缩复杂度。** 宽泛接口却隐藏很少复杂度，会让读者同时学习接口与实现。优先选择隐藏有意义决策的边界。
- **缩小状态作用域：** 优先纯函数，即返回值而非修改状态；局部变量优于字段，字段优于模块状态，模块状态优于全局状态。用派生代替同步。
- **在边界命名不变量，** 不在每个消费者重复，让读者只学习一次。
- 添加层级或状态前，问：它是否至少同等程度地降低了其他位置的读者负担？

**检验：** 可用“新读者约 30 秒内能否回答”作为启发式自查，而非硬性计时门禁：“X 从哪里来”和“什么能改变 X”吗？如果不能，就减少层级或状态。
