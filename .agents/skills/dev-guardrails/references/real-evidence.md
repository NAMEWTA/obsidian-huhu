# 证明它确实有效

适用：任务完成后、宣布结束前使用。针对真实产物验证（运行功能、读取实际值、检查 diff），不要依赖替代指标、自我汇报或‘能够编译’。

直接检查真实对象，验证每一个任务输出。不要从替代指标、自我汇报或“能够编译”推断。

**原因：** 未验证工作的正确性未知。间接验证，例如文件修改时间、输出是否新鲜、代理自我汇报、缓存截图，看起来比直接观察便宜；根据错误推断采取行动，代价却远高于核对来源。

检查真实对象，而非替代物：

- 直接检查进程是否存活，不通过派生状态间接判断。
- 读取真实值，不读取缓存或派生表示。
- 验证失败时，先怀疑观察方法，再怀疑系统。

## 可以时，把检查写成脚本

最强的证据是能够重复执行同一比较的确定性脚本，而不是一次肉眼查看。编写脚本、运行脚本，并保留输出，让审查者能重新运行这个产物，而不必相信你的口头陈述。

让人类能够看到这个产物。只有大型或复杂工作需要以后审计轨迹时，例如大型移植或迁移，才将它提交；记录测量、命令、结果与复核范围；新增记录统一放在 `.agents/dev/changes/<日期-主题>/`，已有证据按真实位置引用。
