# 按可验证单元排列工作

适用：用于多步骤工作（全量修改、迁移、一系列相似编辑），以及提交和 PR 的排列。把工作拆成结束时可验证的小单元，进入下一项前检查当前项，并按能够向审查者自证的顺序交付。

把工作排成一串小单元，每个单元结束于可检查的状态；当前单元没有通过，就不前进。

**原因：** 在产生问题的单元中发现破坏，定位成本很低。整批完成后才发现，问题会被埋住，而且你已经在破损的基础上继续构建。把这些单元排成审查者能够重放的交付顺序，便能将“相信我”变成“看它先失败，再通过”。

**执行。** 在全量修改、迁移或任何一串相似编辑中，开始下一项前先验证当前改动。每个单元都有一个前后对照：已知正常状态、一次改动、执行检查，然后继续。记录并核验实际基线；只有分支关系确实需要且授权覆盖时变基，不为套用流程重写用户历史。工具批量实施改动时，逐单元检查几乎不额外花成本；仍然执行它。

**交付。** 按能够证明工作的顺序排列提交和 PR。可以先建立能复现问题的测试，再完成修复，也可以先实现再取得行为证据；按当前任务与项目流程选择。测试先行时明确何时允许中间失败提交，不把失败状态直接交付到受保护主干。其他叙事顺序包括先删减再重塑、先采集基线再处理、先搭骨架再加功能。每个提交都可独立落地，整个顺序读起来是一段论证。

它补充 [真实证据](real-evidence.md) 原则技能，由后者保证每次检查真实；也补充 [构建执行工具](repeatable-tools.md) 原则技能，由后者降低逐单元检查成本。
