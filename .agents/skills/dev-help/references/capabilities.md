# 开发能力地图

名称对应相互协作的技能。咨询使用[完整指南](guide-index.md)，跨阶段执行调用 `dev-workflow`，阶段明确时调用相应技能；专用工具仍以实际环境为准，技能安装不代表已具备浏览器、后台调度或外部账号权限。

| 技能 | 职责与可组合模式 |
| --- | --- |
| `dev-help` | 选择方法、解释调用方式、组织提示词、排查流程偏离 |
| `dev-setup` | 发现真实宿主能力、配置角色模型和推理预算、明确作用域 |
| `dev-workflow` | 协调跨阶段交付、恢复阶段尚不明确的任务；记录与复核任务决定及实际证据 |
| `dev-intake` | 接收不同来源要求，先复述目标与根本问题，区分事实、范围和待决定事项 |
| `dev-grill` | 沿关键产品决定逐轮澄清，只问会改变方案的问题 |
| `dev-spec` | 明确行为、边界、成功条件与必要约束 |
| `dev-plan` | 拆分垂直切片、识别真实依赖、建立可验证的多阶段计划 |
| `dev-sharpen` | 用四问深化待执行请求，交付提示词；复杂任务的实施仍由当前负责人推进 |
| `dev-architecture` | 从调用者用法确定类型、接口、模块与状态所有权，比较不同方案 |
| `dev-parallel` | 切片覆盖、竞速与多候选比较，隔离写入并综合验证 |
| `dev-ui-design` | 统一产品界面、落地页和设计系统；在项目代码中使用 token、组件与状态，无需设计工具账号 |
| `dev-build` | 按明确规格实施新功能、重构、原型和视觉对齐；为既有正确行为补测，构建真实动作面板 |
| `dev-tdd` | 显式采用测试先行时，按公共接口逐行为红绿循环；在当前实现任务内作为方法使用 |
| `dev-debug` | 普通 UI、API、CLI 或 Issue 功能故障的真实复现、根因、修复与复核 |
| `dev-guardrails` | 对已识别的约束或反复错误建立类型、接口、状态所有权、lint 或 CI 防护 |
| `dev-review` | 规格与工程规范两轴检查、对抗审查、影响范围和有证据的发现 |
| `dev-verify` | 真实入口与副作用验证，创建和维护项目专用验证方法与功能图 |
| `dev-formal-verify` | 选择属性与工具，建立代码映射，检查反例，维护模型与实现一致性 |
| `dev-statechart` | 运行 TLA+ / TLC 模型，生成规则标记和最短反例的中文状态图；普通说明图不进入模型检查 |
| `dev-benchmark` | 围绕延迟、吞吐和资源等指标完成测量、运行取证与优化，保留公平基线 |
| `dev-deploy` | 在指定环境交付真实制品，核对服务与业务结果，记录发布和恢复方式 |
| `dev-learn` | 解释当前模块机制、组织教学或直接通俗复述；帮助接手和理解修改入口 |
| `dev-why` | 调查某项设计当时为何采用及历史约束；区分证据、推断与未知 |
| `dev-archive` | 反思交付，更新术语、背景、ADR 与错误经验，处理冲突和过时引用 |
| `dev-writing` | 完整技术写作标准、文档模式、清晰表达、PR 与提交说明 |
| `dev-status` | 只读汇报当前或指定历史范围的进展、证据与待决事项；按需制作报告视频 |
| `dev-personalize` | 从明确授权的历史材料中提炼稳定工程偏好，形成可审查的个人技能 |
| `dev-issue-setup` | 初始化来源、身份、追踪器、仓库路由、UI 控制与实际触发能力，按来源配置报告监控 |
| `dev-issue-triage` | 按已配置来源适配器读取报告、分类、去重和分流；不运行复现或修复 |
| `dev-issue-fix` | 在可信分诊与真实 UI 控制前提下，仅复现、验证已有补丁，或完成授权的受限修复 |

运行声明要与证据相称。没安装专用技能不证明项目缺少同类能力；先检查既有脚本、验证代码、连接器与知识。形式化、测试、实际操作和静态约束互补，任何单项都不能替用户证明需求本身正确。

完整原则正文见[原则指南](guide-principles.md)，注释处理见`dev-guardrails`（注释审查）。
