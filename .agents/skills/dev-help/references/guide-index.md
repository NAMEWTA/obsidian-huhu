# 本项目技能 指南

不再微观管理代理时，本项目技能 最有效。描述你要什么，以及如何判断完成；`$dev-workflow` 选择操作流程，在步骤需要时运行其他技能，再展示证据。本指南用真实提示词培养这种习惯。

你将学到：

1. [配置 本项目技能](guide-setup.md)：确认安装与宿主能力，按需要配置角色与预算。
2. [通过 `$dev-workflow` 分派工作](guide-routing.md)：给它目标，看它选择流程。
3. [理解代码](guide-understanding.md)：按当前机制、历史理由、教学或任务接续选择所需方法，沿用已有证据。
4. [设计变更](guide-design.md)：在代码固定形状前使用 `$dev-architecture`、`$dev-parallel`、`$dev-parallel`、`$dev-review`、原型和计划。
5. [构建并清理变更](guide-building.md)：构建流程、`$dev-tdd`、`$dev-writing` 和 `$dev-guardrails`。
6. [验证并交付](guide-verification.md)：在真实应用中证明行为，形式化验证测试难触达的情况，用 `$dev-benchmark` 核验数字，再开一个聚焦的 PR 并推进到合并。
7. [睡觉时继续工作](guide-autonomous.md)：先信任再循环，夜间约定，可审计决定日志，以及超出单个执行者规模的持续项目与实际自动化能力。
8. [用原则名称引导](guide-principles.md)：24 个能在任务中途重新引导代理的名称。
9. [变成自己的工作方式](guide-personal.md)：自己的模式，用 `$dev-guardrails` 解决重复错误，以及如何测试技能变化。
10. [常用做法与常见问题](guide-recipes.md)：可复制提示词和应避免的错误。

第一次按顺序阅读，之后每页都可以独立使用。

卡住或不确定哪个技能适合时，输入 [`$dev-help`](help-method.md) 和问题：

```text
$dev-help 我应该用哪个技能审查这个分支？
```

它回答问题，给出一个可使用的提示词，并链接到本包完整材料。独立帮助问题不启动新工作；用户已经要求执行时沿现有授权继续，不要求重复发送。宿主是否自动选择技能，以实际发现机制为准。

## 只记住一件事的话

用自己的话给代理目标与检查方式：

```text
$dev-workflow 运行中途发生重试时，导出会写入重复行。先复现，再修复并验证。
```

不需要指定流程或列出技能。“先复现”和可检查结果，已经给出 `$dev-workflow` 所需的全部分派信号。它匹配缺陷修复流程，把步骤复制到任务清单，并在每一步调用适合的技能。
