# 接入开发技能并运行首个任务

先确认技能已经安装，选择需要的角色与预算，再完成一个真实小任务。配置应是少量可解释设置，不是新的工作流引擎。

## 确认安装

本项目技能安装在目标项目的 `.agents/skills/<domain>-<name>/`，目录下应有 `SKILL.md` 及其引用资源。只检查用户选择的领域或技能，不把其他宿主目录当作额外安装目的地。

尚未安装时，使用当前技能源仓库实际提供的安装器及其帮助，或由用户指定的安装机制复制完整包。不能在未找到脚本时编造命令，也不能只复制 `SKILL.md` 而漏掉参考、模板和配套许可。已经能读取完整包时直接进入配置。

宿主可能通过技能菜单、显式名称或读取 `SKILL.md` 使用技能。按 [宿主适配](harness-adapter.md) 检查实际行为；某个斜杠前缀或插件命令存在于其他环境，并不意味着当前环境也支持它。

## 选择模型

安装时选中任意 dev 技能，安装器就一次性补齐 `.agents/dev/` 根、六类分区和 implemented/rejected 归档入口的九份短 AGENTS.md；选中 system 技能另补系统根说明。显式选择、领域选择和交互选择遵循同一规则，预览不写入，重复安装会补缺失并自动覆盖更新固定位置的模板说明，内容相同不重写。根 AGENTS.md 与业务记录不覆盖，不预填业务知识，不需要再调用技能建立骨架。根 AGENTS.md 如需导航只作语义补充；按当前任务显式读取相关说明，不假定宿主递归自动加载。

按 `dev-setup`（角色配置） 检测当前可用模型与推理组合，读取已有预算，展示代码、判断与评审角色，然后只解决尚未决定的选择。本套技能新增的项目配置统一保存到 `.agents/dev/context/model-roles.md`。

预算档位表达推理与成本偏好。较高档位使用已确认支持的较高推理等级，不保证所有家族都存在同样上限。不同家族分别匹配，无法满足时如实标明。较低档位通常可以降低消耗，但实际成本和延迟应以宿主信息及使用结果判断，不作固定节省承诺。

只覆盖用户关心的角色。没有覆盖的角色保持当前默认；删除覆盖后采用当前默认。再次配置保留用户明确更改的模型、列表或继承选择。之前写入的具体值可能把历史默认固定下来，更新默认时要检查这些显式覆盖，不能无声改变它们。

本地角色值 `inherit-parent` 和 `auto` 都表示继承父会话。调用子智能体时采用宿主支持的继承方式，不把本地别名误传成模型标识。评审列表每个条目对应一个独立上下文，列表长度表达评审规模；实际并发受当前能力和预算限制。并行工作者使用角色默认值，只有受控比较需要且已获授权时才按分支覆盖。

## 选择是否补齐验证

配置结束前，检查项目是否有真实应用驱动设施或验证技能。两者都没有时，只提出一次按 `dev-verify`（创建验证技能） 补齐的建议。

用户已同意或已明确要求生成时，在其指定源仓库创建标准项目技能；安装目标仍是 `.agents/skills/`。该技能应能启动应用、诊断实例、驱动真实用户路径、保留证据并清理本次资源。交付前至少完整执行一次，才能称为已证明可用。用户不需要时继续其他配置；之后也可以独立补齐。

能检查真实结果的智能体，才有依据继续修复并达到完成条件。缺少驱动能力时，结果会频繁回到人手里检查。对经常开发的项目，优先补一条高价值真实路径，比仅增加流程文字更有用；不能因为工具不可得就假装已经验证。

随后检查是否需要 `dev-setup`（形式化验证）。行为测试覆盖实际运行的例子；模型检查或证明在明确假设与范围内检查某个属性，例如“一个作业不会同时运行两次”。并发、重试、状态转换或解析器中，若缺陷代价高且常规测试难触及，可选择一个属性。其余任务可以跳过，不把形式化工具变成每个项目的门槛。

最后说明配置如何加载。当前会话能读取时继续完成小任务；只有宿主明确需要新会话时才告知相应操作。不能仅因写入文件就声称新会话自动应用，也不要求为格式检查重启开发环境。

## 控制成本

子智能体和独立评审会增加调用成本。按任务风险使用它们：

- 调低角色推理预算或选择当前确实可用、符合需要的较低成本模型；难判断的主任务与明确实现任务可以采用不同配置。
- 需要沿用会话模型时选择继承，避免无意义的额外覆盖。
- 缩短评审列表，让每个独立视角都有具体作用，不追求数量。
- 简单、明显的小改动直接处理；完整多阶段流程留给有实际风险或依赖的任务。

## 运行第一个任务

选一个真实但较小的目标，用普通话说清用户行为和不应改变的契约，例如：

```text
为这个命令添加 --json 标志。文本输出保持逐字节一致。验证两种输出。
```

把与任务匹配的实施步骤列入简短待办。完成、未检查和跳过应区分；跳过的步骤记录具体理由，让用户能看懂实际范围，不把未执行伪装成通过。

此后正常追问即可。若宿主支持持续技能模式，可以按真实界面使用；否则在任务记录中保留当前目标，并按需读取本地技能。不能假定某个键盘快捷键、菜单或“模式”在所有宿主存在。

完成首个任务后，留下配置、实际验证证据及仍未覆盖的条件。准备把任务交给持续执行时，再读 [无人值守指南](guide-autonomous.md)。
