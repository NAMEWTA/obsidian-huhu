仓库的 `.agents/dev/notes/context/scope-decisions/` 目录持久记录被拒绝的功能请求。它有两个用途：

1. **组织记忆**：记录功能为什么被拒绝，让事项关闭后理由不会丢失。
2. **去重**：新事项与先前拒绝匹配时，技能可以提出已有决定，而不必重新争论。

## 目录结构

```text
.agents/dev/notes/context/scope-decisions/
├── dark-mode.md
├── plugin-system.md
└── graphql-api.md
```

每个**概念**一个文件，而不是每个事项一个文件。多个提出同一需求的事项归在同一文件下。

## 文件格式

采用轻松、易读的风格，更像一份短设计文档，而不是数据库记录。使用段落、代码示例和例子，使第一次遇到它的人也能清楚理解理由并从中受益。

````markdown
# 深色模式

本项目不支持深色模式或面向用户的主题切换。

## 为什么不在范围内

渲染流水线假定只有一套在 `ThemeConfig` 中定义的调色板。
支持多主题需要：

- 包裹整个组件树的主题上下文提供器
- 每个组件能识别主题的样式解析
- 持久保存用户主题偏好的层

这是显著的架构变化，不符合项目专注于内容创作的方向。
主题是嵌入或再分发输出的下游使用方应关心的问题。

```ts
// 当前 ThemeConfig 接口没有针对运行时切换设计：
interface ThemeConfig {
  colors: ColorPalette; // 单套调色板，在构建时解析
  fonts: FontStack;
}
```

## 先前请求

- #42：“添加深色模式支持”
- #87：“用于无障碍的夜间主题”
- #134：“深色主题选项”
````

### 文件命名

为概念采用简短、描述性的 kebab-case 文件名，例如 `dark-mode.md`、`plugin-system.md`、`graphql-api.md`。名称应足够易辨认，让浏览目录的人无需打开文件就知道什么被拒绝了。

### 编写原因

理由应有实质内容：不只是“我们不想要”，而是为什么。好的理由会引用：

- 项目范围或理念：“本项目聚焦 X；主题属于下游关注点。”
- 技术约束：“支持它需要 Y，而 Y 与我们的 Z 架构冲突。”
- 战略决定：“选择 A 而不是 B，因为……”

理由应持久。避免引用暂时情况，例如“现在太忙”；那是延期，不是真正拒绝。

## 何时检查 `.agents/dev/notes/context/scope-decisions/`

分诊第 1 步收集上下文时，阅读 `.agents/dev/notes/context/scope-decisions/` 的全部文件。评估新事项时：

- 检查请求是否匹配已有范围之外概念。
- 按概念相似性匹配，而非关键词，例如“夜间主题”匹配 `dark-mode.md`。
- 如果匹配，向维护者提出：“这与 `.agents/dev/notes/context/scope-decisions/dark-mode.md` 相似，之前因 [理由] 拒绝过。你现在仍然持相同看法吗？”

维护者可能：

- **确认**：把新事项加入现有文件的“先前请求”列表；有关闭授权时再关闭。
- **重新考虑**：删除或更新该文件，事项进入普通分诊。
- **不同意**：两个事项相关但不同，继续普通分诊。

## 何时写入 `.agents/dev/notes/context/scope-decisions/`

只有**增强**请求而非缺陷，被以 `wontfix` **拒绝**时才写入。这同样适用于增强类 PR：在这里记录被拒绝 PR，防止相同请求以新代码的形式再次出现。

如果因为**已经实现**而以 `wontfix` 关闭，**不要**写入这里。那是已构建功能，不是被拒绝功能；记录会给去重检查注入错误拒绝。关闭评论应改为指出功能已经存在的位置。

流程：

1. 维护者决定某功能请求不在范围内。
2. 检查是否已有匹配的 `.agents/dev/notes/context/scope-decisions/` 文件。
3. 如果有，把新事项追加到“先前请求”列表。
4. 如果没有，新建文件，包含概念名称、决定、理由和第一条先前请求。
5. 已授权发布评论时解释决定并提及该文件；否则在本地简报记录待发布内容。
6. 用户已授权关闭时，按现有跟踪器约定关闭；否则只交付本地记录和建议，不写入外部系统。

## 更新或移除范围之外文件

如果维护者对曾拒绝的概念改变主意：

- 更新或移走不再有效的当前范围记录；保留有价值的历史理由及替代关系，过时且无价值的内容删除。
- 技能无需重新开启旧事项，它们是历史记录。
- 触发此次重新考虑的新事项进入普通分诊。
