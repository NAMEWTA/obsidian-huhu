# 控制适配器契约

本方法不假定知道如何启动和操作每一种应用。为目标应用配置一个实际实现此契约的控制技能、连接器或项目驱动。复用已经存在且验证过的能力，不要求另装某个命名技能。

在 `control.skill_name` 中设置其技能名称。

在 `control.feature_map_path` 中设置填写完整的用户视角功能映射路径。把 [功能映射示例](../assets/feature-map.md) 复制到技能安装包之外的项目资料目录并填写，例如 `.agents/dev/project/issue-automation/feature-map.md`，而不要编辑安装包里的示例本身。

如果技能、功能映射或某项所需能力缺失、含糊或不完整，复现和修复工作必须停止。

## 所需能力

### 启动

在指定测试环境中启动应用的指定版本。

输入：

- 仓库和版本
- 构建或启动模式
- 工作区、账户、夹具和功能状态要求
- 工件目录
- 填写完整的功能映射路径

返回：

- 会话标识符
- 适配器如何确认应用和环境正确
- 稳定的应用标识
- 后续调用需要的运行进程或目标详情
- 缺失的任何能力

适配器必须能够区分目标应用与类似窗口、外壳或生产实例。

### 操作 UI

执行真实用户动作：

- 点击
- 输入
- 按键
- 滚动
- 拖动
- 调整大小
- 通过应用控件导航

优先使用角色、标签和稳定选择器。只有在刚获取截图之后才使用坐标。

返回每个动作及观察到的状态变化。

不要设置内部状态、调用隐藏的应用方法、直接写入存储，或注入 DOM 变更来制造症状。

### 操作映射的功能和状态

在操作应用之前，阅读相关功能映射章节。

适配器必须提供以下方式：

- 通过用户可见的路径导航到每个映射的功能。
- 调用该功能列出的适配器动作名称。
- 在适用时操作默认、悬停、焦点可见、激活、禁用、加载、空、错误、选中、打开、展开及功能专属状态。
- 通过安全夹具数据、权限、标志、服务响应或支持的测试控件设置状态。
- 重置功能，以进行第二次独立复现。
- 捕获功能映射指定的截图、视频和只读交叉核对证据。

使用角色、可访问名称、ARIA 关系、稳定组件标识，以及按用途命名的数据属性。绝不使用生成的 CSS 或 StyleX 类名、动态哈希、子节点下标或脆弱的 DOM 位置。

安排前置条件并不意味着可以注入报告中的症状。复现本身仍必须来自真实用户交互。

### 检查状态

读取状态，以确认 UI 显示的内容。

例如：

- 无障碍树
- DOM 或视图层级
- 进程状态
- 本地日志
- 网络请求状态
- 应用公开的调试状态

检查是只读的。如果一个查询会改变状态，它就属于“操作 UI”，而且必须代表真实用户动作。

### 截图

把当前应用状态捕获到指定路径。

返回：

- 文件路径
- 捕获时间
- 应用标识或窗口标题
- 对应可见内容的简短说明

截图必须展示足够的应用界面框架，以证明正在测试正确的应用。

### 录像

在完整复现路径前后开始和停止屏幕录像。

返回：

- 文件路径
- 开始和停止时间
- 捕获的窗口或区域
- 是否排除了音频或敏感覆盖层

录像必须展示能够区分结果的最终状态，而不只是设置过程或加载画面。

### 清理

停止适配器创建的进程和会话。

删除可丢弃的：

- 浏览器或应用配置文件
- 临时工作区
- 适配器创建的测试账户或夹具
- 调试端口和隧道
- 超出保留窗口的捕获文件

返回停止、删除、保留或留给人工处理的内容。

清理不得删除用户的工作。

## 适配器行为

适配器必须：

- 在复现开始前报告能力。
- 报告它能够操作的功能映射章节，以及受阻的章节。
- 对基线和修补后的构建使用相同的环境输入。
- 如实将启动失败呈现为失败。
- 限制重试次数。
- 不把秘密信息放入日志和工件。
- 将捕获文件保存在仓库之外。
- 支持在两次复现之间使用全新或重置状态。
- 除非用户明确配置了安全测试动作，否则避免生产变更。

## 环境转换

在宣称环境阻塞之前，不使用平台专属名词重述缺陷，并判断是否可以在可用环境中安全测试同一种行为。

例如：

- 指定的浏览器可能表示任意外部浏览器。
- 指定的按键可能表示已配置的快捷键。
- 指定的远程主机可能表示延迟或断开的远程目标。

只有转换后的尝试测试相同底层行为时才使用它。将其标记为经过环境转换的证据。如果缺失环境本身就是缺陷的一部分，不要称它为精确复现。

硬件提示、操作系统权限对话框、仅设备可用的 API，以及不可用的账户状态，可能是真实阻塞。

## 设置检查

启用复现自动化之前，在用户已授权的测试环境中运行一次无害的适配器检查：

1. 启动应用。
2. 确认稳定的应用标识。
3. 加载一个填写完整的功能映射章节。
4. 通过其用户路径导航到该功能。
5. 通过映射的适配器动作操作一个可丢弃状态。
6. 检查产生的状态。
7. 捕获截图。
8. 录制一段短片。
9. 清理。

只有全部九个步骤都成功，且未涉及向报告来源外发消息时，才启用复现工作。
