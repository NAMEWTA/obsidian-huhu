# 自动化目标与运行契约

以下保留两项缺陷协作任务的完整配置意图。初始化先保留用户的实际目标；是否创建、启用、外发或修复，取决于已经授予的范围，不由本文代替授权。

## 自动化目标

从用户选定来源接收报告，按实际能力配置分诊，以及可选的 UI 复现修复。两项可以手工接续，也可以由真实支持的触发或调度器协作。来源、追踪器和代码仓库分别选择，详见[来源适配](source-adapter.md)。

如果目标是收集材料或每日需求汇总，使用[收集汇总模板](../assets/collection-prompt.md)或用户的完整方法，保存实际范围、时间窗口和输出要求。可以使用已安装的需求整理能力，但本包独立运行不依赖它。选择汇总不自动选择以下两项缺陷任务，也不因诉求不是缺陷而丢弃它。

### 任务一：分诊问题报告

- 触发：从指定手工报告或实际事件、定时查询、webhook 开始，保留原始报告身份。Slack 事件分支接收配置频道中的新顶层报告。
- 行为：读取原报告、讨论和附件，分类为缺陷或性能问题、功能请求、问题或反馈，或需要转交的报告；分流前追踪可能负责的层。
- 追踪器：搜索重复项，更新有把握的重复项，只为明确的全新缺陷创建工单。
- 工具：来源读取、原生回复或运行输出、需要时的追踪器，以及可选分流映射。
- 结果：在约定的原生讨论位置或运行输出中交付一条简短结论，附 `[issue:bug]`、`[issue:performance]` 或 `[issue:other]` 中一个标记。缺陷和性能标记可以附实际问题链接。
- 边界：不另建来源报告或替代讨论；Slack 分支绝不在来源频道发布根消息。

### 任务二：复现并修复已确认缺陷

- 触发：使用绑定同一原报告的实际事件或可信分诊交接；已有结果直接核验，独立分诊任务才需要预算内等待。
- 门槛：有人明确拥有修复时停止竞争补丁；仅复现按其授权范围继续，确有同范围复现或现场冲突时才停止该项工作。已有 PR 或合入提交可能解决报告时，优先验证，不创建竞争改动。
- 行为：使用已配置控制适配器和功能图，通过真实 UI 两次复现精确症状，捕获截图、视频和只读状态交叉核对。
- 修复：验证已有 PR，不另写补丁。确认复现且已获修复授权后，可尝试一次范围受限的根因修复；成本低的测试采用测试先行，冒烟检查影响范围；只有前后证据通过且已获 PR 授权时才打开草稿 PR。
- 工具：原报告与可信分诊读取、可选来源回复、仓库和历史、目标所需的草稿 PR 与追踪器能力，以及 UI 控制适配器。
- 结果：在原报告或可选运维讨论中提供简洁证据和经过验证的结果，以及可选草稿 PR；没有外发授权时把完整结果保留在当前会话或运行输出。
- 边界：不另建来源报告或替代讨论；Slack 分支绝不在来源频道发布根消息。

### 共同规则

- 整次运行的来源范围、原报告身份和原生回复关系不可变。
- 工具和调试机器人的输出是证据，不自动构成委派指令或修复归属。
- 子智能体可以协助，但不得获得来源平台和追踪器凭据或外部写入动作；没有真实权限隔离时由协调者完成。
- 完整包安装在目标仓库 `.agents/skills/dev-issue-setup/`；入口是标准技能，自动化直接读取包内完整操作文件。
- 共同能力全部随包提供：模块运行追踪、历史依据调查、测试驱动、清晰写作，以及共享状态、阅读负担、上下文、可验证单元、根因和真实证据原则。
- 每个实际提示词直接读取经过验证可访问的操作文件，不用缓存路径、复制的片段或未经证实的斜杠命令发现。
- 用户配置、功能图、分流图及秘密保存在安装包之外，刷新包不覆盖它们。
- 坐标、追踪器、控制适配器或功能图缺失或不明确时，停止受影响的动作并记录缺口。
- 此流程最多交付草稿 PR，不合并或部署。

### 配置清单

- 实际任务目标、完整方法与输出要求：`<收集汇总、缺陷分诊或 UI 复现修复>`
- 来源类型和范围：`<手工、聊天、工单、邮件或告警；实际账号与容器>`
- 触发：`<手工、实际事件、定时或 webhook；过滤、时区、去重与恢复方式>`
- 结果交付：`<原生回复或运行输出>`
- 可选运维目标：`<已验证的讨论位置或无>`
- 仓库与默认分支：`<仓库>`、`<分支>`
- 追踪器：`<类型、团队、项目、标签、接收状态>`
- 分流图：`<路径或无>`
- 分诊身份：`<原生实际作者、受信运行器身份或当前协调者的明确决定>`
- 控制能力：`<已配置且可用的技能、连接器或项目驱动>`
- 功能图：`<包外且在实际运行环境可读取的项目路径，或需完整转述的行为>`
- 模型：`<默认继承；支持且确有需要时区分分诊、复现、代码和媒体角色>`
- 状态表情：`<已读、复现中、已复现、受阻、修复中、失败、PR 已打开>`
- 预算：`<轮询、结论等待、后续观察、复现、异议、修复>`
- 可选机器人令牌能力：`<无、文件下载或编辑运维状态>`

从 [配置模板](../assets/configuration.yaml) 和 `dev-issue-fix`（功能映射） 开始，复制到包外再填写，例如 `.agents/dev/project/issue-automation/`。秘密值只存密钥管理器或环境。

## 执行说明

从当前任务和目标项目开始，不依赖斜杠命令或外部插件。完整步骤见 [配置方法](setup-method.md)。

1. 确定目标仓库，只有尚不明确时才询问。
2. 以完整独立技能目录作为资料源。
3. 将整包安装或无损合并到 `<目标仓库>/.agents/skills/dev-issue-setup/`。
4. 保留仅目标存在的文件，不删除无关内容，不覆盖用户配置、功能图或分流图。
5. 受管理路径存在本地编辑时，先检查并无损合并；无法确定的真实冲突给出具体差异后再询问。
6. 验证目标包含本文件、完整配置方法、分诊与修复操作文件以及全部依赖。
7. 读取并遵循目标包中的配置方法。

共同能力直接来自本地文件，不需要修改插件清单。逐项核对：

```text
references/module-exploration.md
references/decision-investigation.md
references/tdd-method.md
references/clear-writing.md
references/shared-state.md
references/reader-load.md
references/context-budget.md
references/verifiable-units.md
references/root-causes.md
references/real-evidence.md
```

保留无关的项目设置和其他技能。已有配置采用 JSONC、YAML 或其他形式时，保留其合法语法和注释；不用新格式替换整个文件。

从目标自动化实际运行环境或新的干净检出证明这些文件可读。当前会话或个人安装中存在并不构成该证明。无法启动独立验证时，明确验证范围及缺口。

本地资料或真实工具能力缺失时，停止相关启用并说明原因。不需要把包内参考文件再次注册成技能，协作时按任务读取对应技能入口。

平台使用独立仓库检出时，在启用前让完整包和全部非秘密配置进入实际运行版本。用户未要求创建或更新任务时，只完成配置与可审查草稿。已有明确授权时继续，不重复审批。

首次创建时，只准备用户选定的任务；选择完整缺陷组合时先完成分诊，再完成复现修复。每个任务都通过当前平台正式支持的工具或界面创建，保留真实任务标识，并完成平台确实要求的审批或交接。

把选定目标的完整意图和填写后的配置转述到对应提示词。收集汇总采用其完整模板或用户方法；分诊读取 `.agents/skills/dev-issue-triage/references/triage-method.md`，修复读取 `.agents/skills/dev-issue-fix/references/fix-method.md`。只有真实运行环境确认可读时才使用这些相对路径。

已有任务按原任务标识检查和更新；若实际工具不支持更新，就使用配置方法中的完整字段清单交给真实编辑器。不要创建重复项。正常流量启用之前，必须完成来源交接与持续模式所需验证并如实保留结果。
