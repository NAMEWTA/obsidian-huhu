# 问题自动化概览

两个相互配合的任务处理指定来源的报告：一个分类、查重和分流，另一个通过真实 UI 复现可信缺陷，并可在授权范围内准备小型草稿修复。来源和触发方式按[来源适配](source-adapter.md)选择；可以只做分诊或手工接续。

若实际目标是收集材料或需求汇总，使用[相应模板](../assets/collection-prompt.md)或用户的完整方法，只配置该目标；不自动建立缺陷任务，不把功能诉求过滤掉。

包内文件是完整的方法、配置与任务模板。安装技能不会自动创建或启用任务，也不依赖宿主具备斜杠命令。

## 配置顺序

1. 阅读 [自动化目标与运行契约](automation-intent.md)，确定目标仓库与已有授权。
2. 将整个独立包安装到目标项目 `.agents/skills/dev-issue-setup/`；保留仅目标存在的文件，审阅冲突，不覆盖本地编辑。
3. 按 [配置方法](setup-method.md) 核实完整共同能力在实际运行环境中可读：

```text
模块运行追踪与历史依据调查
测试驱动与清晰写作
共享状态、阅读负担、上下文和可验证单元
根因修复与真实对象证据
```

4. 用户拥有的配置保存在安装包之外，例如 `.agents/dev/project/issue-automation/`。适配[配置模板](../assets/configuration.yaml)，选择来源、原生回复或运行输出、手工／事件／定时／webhook。选择 UI 复现时再补`dev-issue-fix`（功能映射）。
5. 实际平台使用独立仓库检出时，启用前确保完整包与所有非秘密配置已经存在于其检出版本；本地读取型任务则验证实际路径可读。
6. 完成新任务的可审查配置，或按原身份更新已有任务。使用已获授权的无害报告或平台测试事件验证原报告身份、可信交接、原生回复与重复投递处理；Slack 还确认每条来源消息都留在原线程内，然后按已有启用授权接入正常流量。
