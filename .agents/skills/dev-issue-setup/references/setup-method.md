# 配置问题自动化

本包负责来源、触发器与自动化配置；分诊调用 `dev-issue-triage`，复现修复调用 `dev-issue-fix`，收集汇总使用本包模板。安装目录为 `.agents/skills/dev-issue-setup/`，协作技能位于同级目录，不嵌套复制。读取本包 [自动化目标与运行契约](automation-intent.md) 理解完整意图，再执行本流程。

实际运行按[来源适配与触发配置](source-adapter.md)选择手工执行或当前宿主真正支持的事件、定时、webhook 任务。持续运行需要包外配置；单份报告可使用当前材料形成的最小配置。文件存在不代表任务已经创建或启用。

用户未明确要求时，不创建或更新后台任务。已有创建、更新或持续运行授权继续有效，不重复询问。秘密值不写入技能包、提示词或已提交配置。

## 1. 安装并核对完整本地资料

在询问尚缺配置或调用实际自动化工具之前，先完成这一步。

从当前任务确定运行自动化的目标仓库；只有仍不明确时才询问。已安装时以本包为资料源；还未安装时，按项目安装器安装本次需要的技能到 `<目标仓库>/.agents/skills/`，不增加领域中间层。

将整个包合并到目标：

1. 目标不存在时创建。
2. 将包内每个文件复制到相同相对路径，包括全部参考资料和资产。
3. 保留只存在于目标的文件。安装或刷新期间不删除无关文件。
4. 用户拥有的配置、功能图和分流图保存在技能安装包之外，绝不覆盖它们。
5. 已有受管理文件存在差异时，检查差异并保留本地修改。归属不明确且无法无损合并时，先形成具体差异和候选合并，再只询问冲突决定。
6. 验证目标包含本文件、[自动化目标与运行契约](automation-intent.md)、`dev-issue-triage`（分诊方法）、`dev-issue-fix`（复现修复方法）、[来源适配](source-adapter.md)、它们的参考资料及全部模板。

已从安装目标读取此文件时，复制视为完成，但继续之前仍做相同验证。

协作能力由依赖技能提供，无需插件开关或流程 JSON。逐项核对当前任务需要的入口与方法在对应技能目录可读；不将它们复制到本包：

- `dev-learn`（模块运行追踪），以及探索者与解释者任务书
- `dev-why`（历史依据调查），以及来源索引、调查任务书与综合方法
- `dev-tdd`（测试驱动方法），以及行为测试和模拟指南
- `dev-writing`（清理机械写作）
- `dev-guardrails`（先拆分共享状态）
- `dev-guardrails`（降低阅读负担）
- `dev-guardrails`（上下文预算）
- `dev-guardrails`（可验证单元）
- `dev-guardrails`（修复根因）
- `dev-guardrails`（真实对象证据）

从实际自动化运行环境或一个以目标仓库为根的干净检出验证文件。不能把只在当前会话、个人安装目录或临时缓存中存在的资源算作可用。无独立执行环境时，检查目标文件与相对引用，并明确“自动化运行环境尚未验证”，不伪造新智能体验证。

任一必要方法不可读时，修复对应技能的安装；无法修复则说明具体缺失，完成其余配置并保持受影响任务未启用。自动化必须读取实际负责技能的完整方法，不用配置技能中的摘要替代。

分诊执行入口是 `dev-issue-triage`，修复执行入口是 `dev-issue-fix`。通过已验证的安装路径读取其入口及资源，不要求宿主支持斜杠命令发现。

如果平台在独立仓库检出中运行任务，启用前必须让完整包和被引用的非秘密配置存在于实际使用的分支或版本中。用户已经授权提交或推送时完成它；否则准备可审查差异并说明启用所缺条件。不要无故要求本地读取型调度器提交文件。

通过此检查之后，任务提示词才可以通过稳定的仓库相对路径读取操作文件。不要引用会话缓存路径，也不要用不完整摘录替代方法全文。

## 2. 适配配置

打开本包示例：

- [配置模板](../assets/configuration.yaml)
- `dev-issue-fix`（功能映射模板）

在技能安装包之外创建用户拥有的副本。它们是项目配置，不是包文件。新增配置统一放在 `.agents/dev/project/issue-automation/`；已有配置按真实位置查阅引用，不擅自移动或覆盖。具体文件如下：

- 项目配置：`.agents/dev/project/issue-automation/configuration.yaml`
- 项目功能图：`.agents/dev/project/issue-automation/feature-map.md`
- 项目分流图：`.agents/dev/project/issue-automation/routing.md`
- 需要本地恢复记录的持续来源：`.agents/dev/project/issue-automation/monitor.md`；优先沿用平台原有检查点，不重复维护状态。
- 仅在实际运行环境能读取时使用的个人配置：`~/.config/issue-automation/configuration.yaml`
- 同样条件下的个人功能图：`~/.config/issue-automation/feature-map.md`

选择 UI 复现时，为可能处理的每个面向用户功能填写一个功能图章节。保持用户视角，不把实现细节或当前代码路径固定到图中。只配置分诊或收集汇总时无需先填写功能图。

每个来源配置明确自己的范围与触发方式；多个来源可以使用各自简短配置文件，不把不同账号或容器的同号报告混为一份。单个实际适配器确实支持多来源时，仍逐份保留完整原生身份。

不要编辑包内示例。刷新包可以在审阅冲突后更新受管理文件，但不触碰用户副本。

新的隔离自动化检出需要读取文件时，优先使用目标仓库中已提交的非秘密文件；否则将所需非秘密配置值完整转述进实际提示词。引用仓库文件前，由实际工具或运行环境确认它属于任务运行的同一仓库和正确版本。

配置使用简单 YAML，功能图、分流理由、运行证据和恢复点使用轻量 Markdown。`schema_version` 仅标明配置格式版本，不用它创建工作流状态机、状态迁移表或复杂校验体系。

使用稳定的项目相对路径。实际自动化不引用技能源码检出、会话缓存或仅作者机器存在的位置。

## 3. 填写必需选择

从已有项目资料、工具能力和用户决定中取得以下信息，只问会改变配置且尚不明确的选择：

- 原始任务目标、完整处理方法和输出要求；收集或需求汇总不自动变成缺陷分诊
- 来源类型、真实账号或工作区、容器范围，以及原报告与原生回复身份的取得方式
- 结果交付到原报告还是运行输出；可信分诊身份或当前运行中的可信交接方式
- 手工、事件、定时或 webhook；持续模式的实际触发器、过滤条件、频率和时区
- 需要时配置追踪器类型、团队、项目、标签、接收状态与真实适配动作；来源已是目标问题时复用它
- 可选分流图、运维目标及状态字符串
- UI 复现所需仓库和默认分支、控制适配器、用户视角功能图及环境
- 需要草稿 PR 交付时的真实创建能力和规范链接
- 等待、后续观察、复现与修复预算；有需要时才区分角色模型

默认继承当前模型。不同角色的标识须来自实际可用模型列表；不猜测名称，不保留私有默认值。没有分角色模型能力不妨碍顺序执行。

按所选阶段验证必需值：收集汇总需要明确范围、完整方法与输出目标；只读分类需要报告可读；来源回写需要原生回复与回读；查重和建单需要实际追踪器；UI 复现需要可信分诊、控制与功能图；持续任务还需要实际触发器。任一条件不明时，完成其余准备，保持受影响部分未启用，不让无关的可选字段阻塞已经可做的工作。

在配置说明中保留已有授权范围：单次或持续、允许读取的来源、允许回复的位置、追踪器更新与新建补偿、代码修复、提交及草稿 PR。配置值不自动授予权限，已明确的授权不重复确认。

保存前，用`dev-writing`（清理机械写作）检查最终任务名称、描述和提示词。

## 4. 检查集成能力

先按[来源适配](source-adapter.md#按来源选择适配)验证原生身份与操作。Slack 使用完整线程规则；工单、邮件、告警和手工材料使用各自分支。以下是能力契约，不是已安装连接器或固定 API 名称。

收集汇总检查约定范围和时间窗口的实际查询、完整分页、材料引用及输出交付；外部输出还需相应写入与回读。配置了追踪器或仓库不自动要求建单或修复，也不要求分诊标记。

分诊按本次目标检查：

- 原报告、讨论、实际作者及相关附件可读，报告身份与配置范围一致
- `reply_mode: origin` 时，能在同一原生讨论位置回复并回读；`run-output` 时，能交付当前会话结果或可恢复记录
- 查重时具有目标追踪器搜索与读取能力；写入时有对应创建或更新权限，且不覆盖无关字段
- 新建工单前能执行已经授权的交接失败补偿；已有来源问题不另建副本

UI 复现另外检查：

- 同一原报告及可信分诊结果可读
- 可选运维目标的原生创建、回复或更新及回读能力
- 仓库读取、历史与确定版本的构建能力
- 目标包含草稿 PR 时，具有实际创建草稿 PR 能力
- 已配置控制适配器和完整用户功能图

持续模式核对真实事件、调度或 webhook 能力，包括来源认证、范围过滤、重试语义与检查点。没有后台工具时交付手动方案与可审查配置。

优先使用已配置并核实的专用连接器、API 或 CLI。`source.optional_token_env` 与 `operations.optional_token_env` 只引用狭窄能力所需的环境秘密，例如下载附件或编辑单条运维状态；不在 YAML 中保存值，不传给子执行者。

不要使用未记录的集成端点。只读分析不需要写权限；缺少写能力时，不伪造完成结果，也不通过另一个目的地补发。

## 5. 准备分流映射

用户希望转交或提醒负责人时：

1. 将 `dev-issue-triage`（分流映射示例） 复制到技能包之外。
2. 把每个占位值替换为当前项目或组织的真实值。
3. 默认关闭负责人提醒。
4. 只有映射已列出且配置允许的功能负责人，或证据充分的可能回归作者，才可以被提醒；涉及向他人发消息时还需对应授权。

没有配置分流图时，分诊可以分类报告，但不能猜测目的地或负责人。

## 6. 验证控制适配器

本次选择 UI 复现时，阅读`dev-issue-fix`（控制适配器契约）和用户填好的功能图。仅配置分诊或收集汇总时，此阶段标为未选择，不要求虚构控制能力。

确认指定控制能力能够：

- 启动目标应用
- 通过真实 UI 导航到每个映射功能
- 通过声明的适配器动作操作映射状态
- 检查状态但不强制制造结果
- 捕获截图
- 开始和停止录像
- 清理自己创建的进程与临时数据

在已经授权的测试环境中执行契约末尾的九步检查。缺少任一必要能力时，保持复现自动化未启用，指出具体限制；不能把源码阅读、状态注入或单元测试称作真实 UI 复现。分诊能力已独立验证且用户授权时，可以单独启用分诊。

## 7. 准备实际自动化

先检查这是首次创建还是修改已有任务，复用用户明确给出的任务标识与授权。使用实际可用的自动化连接器或调度能力；需要界面时遵循当前宿主的真实界面操作。读写工具必须来自工具说明，不能编造动作、事件类型、隐藏端点或深链接。

两种路径都完整阅读 [自动化目标与运行契约](automation-intent.md)，按用户实际选择理解任务的触发器、工具、指令、结果和共同规则。缺陷分诊与 UI 修复是可选任务，不能替换用户要求的收集汇总。文档描述的是可配置目标，不是本次自动获准执行的外发命令。

### 首次创建

一次创建一个任务。用户未请求创建或启用时，完成配置、提示词及检查结果，交付可审查草稿。

对每个已获创建授权的任务：

1. 按所选目标阅读 [收集汇总提示词](../assets/collection-prompt.md)、`dev-issue-triage`（分诊提示词） 或 `dev-issue-fix`（复现修复提示词）。
2. 将完整意图、填好的项目配置和模板转换为完整自然语言请求。
3. 缺陷流程读取 `dev-issue-triage` 的分诊方法或 `dev-issue-fix` 的复现修复方法；收集汇总保留模板中的完整步骤或用户方法，并读取来源适配。
4. 使用经过核实的仓库相对路径，不用会话缓存路径。不用不完整副本替代完整操作文件。
5. 阅读实际自动化工具的能力、触发方式、更新语义和平台审批要求。
6. 通过实际连接器解析来源范围、原生身份、仓库及已连接集成，不重复询问已有明确值。
7. 确认完整包和引用配置在任务运行环境中可读；独立检出还需核对分支和提交。
8. 完成可审查的任务名称、触发器、提示词、授权范围和工具列表，再执行已经授权的创建或更新。平台确有强制审批时通过该流程；不人为增加重复批准。
9. 回读任务标识、提示词和启用状态，完成当前任务的配置后再处理下一个。没有可调用创建能力时，提供包含全部值的具体编辑器清单，不声称已经创建。

选择收集或需求汇总时，填写原始目标、实际来源范围、收集窗口、完整处理规则、输出目标和已有授权，使用收集汇总模板形成运行提示。需要深入需求整理且实际已安装时可使用 `dev-intake`；收集汇总本身按本包模板或用户提供的完整方法执行。每日汇总保留功能诉求和来源引用，不套用“仅为缺陷建单”的分诊规则，也不自动启用下面两个缺陷任务。

选择缺陷分诊时，任务的完整意图为：

- 名称 `issue-triage`。
- 每次运行读取并遵循 `.agents/skills/dev-issue-triage/references/triage-method.md`，或安装时已核实的同包稳定路径。
- 使用已选的真实手工、事件、定时或 webhook 模式；Slack 事件分支只接收配置频道中的新顶层报告。
- 读取固定的原报告与讨论，按配置交付原生回复或运行输出。
- 需要查重或建单时使用已配置追踪器；来源已是同一目标问题时直接复用。
- 分类、检查证据、追踪原因、去重，只为明确新缺陷创建工单。
- 单次结论附一个已配置标记及可选问题链接，保存真实分诊身份、报告关联和证据版本。
- 不更换来源回复目标，不另建来源报告；Slack 分支绝不在来源频道发布根消息。

仅在本次选择 UI 复现修复时，处理其完整意图：

- 名称 `issue-reproduce`。
- 每次运行读取并遵循 `.agents/skills/dev-issue-fix/references/fix-method.md`，或安装时已核实的同包稳定路径。
- 使用绑定同一报告的实际触发或可信分诊交接；不把回复或重试当成另一份报告。
- 使用已配置的仓库和默认分支。
- 读取原报告与讨论；仅在已选的原生回复位置外发，或保留运行输出。
- 包含实际可用且已获授权的草稿 PR、追踪器、控制适配器和功能图要求。无法读取文件时，完整转述必要用户路径、状态及非秘密配置，并说明限制。
- 行动前核验同一报告的可信分诊结果；当前运行已有结果时直接核验，不额外等待。
- 通过映射的真实 UI 两次复现精确症状并捕获证据。
- 验证已有修复，不另写竞争改动。
- 只有确认复现后才在已有代码修改授权内尝试可选、范围受限的修复；证据与检查通过且 PR 创建已获授权时，打开草稿 PR。
- 不更换来源回复目标，不另建来源报告；Slack 分支绝不在来源频道发布根消息。

按[触发和监控](source-adapter.md#触发和监控)核实平台能否实现所选事件、定时查询或 webhook。固定过滤与身份、处理重复投递并核对游标。缺失能力时不创建虚假订阅或改用未授权高频轮询；手动模式可以单独交付。

不要重复连接器已经完成的解析、认证或强制审批；但必须回读实际创建结果，不把草稿当作已启用任务。

### 已有自动化

先核对实际工具是否支持读取和更新。支持时使用已有任务标识更新，不新建重复项；工具只支持创建或界面更新时，不假装存在更新 API。

完成所选阶段的来源、触发、分流、控制适配器和功能图验证，然后更新或提供以下完整字段清单。

已有收集汇总任务保留原始目标、完整方法、范围与窗口、触发时区、输出目标、已有授权和去重恢复方式。按其原任务标识更新；不要改成缺陷分诊或另建缺陷任务。

已有分诊任务：

- 名称和描述
- 读取 `dev-issue-triage` 完整方法的已验证路径
- 实际触发模式、来源范围、过滤、时区及去重恢复方式
- 原报告读取、原生回复或运行输出，以及可信身份核验能力
- 问题追踪器集成及失败补偿
- 完整分诊指令、来源交付规则和结论身份

已有复现任务：

- 名称和描述
- 读取 `dev-issue-fix` 完整方法的已验证路径
- 与分诊一致的来源范围、实际触发器或可信结果交接
- 仓库和默认分支
- 原报告读取、原生回复或运行输出，以及可信身份核验能力
- 草稿 PR 动作与已有授权范围
- 追踪器、控制适配器和功能图要求
- 完整标记等待、证据、已有修复验证和范围受限修复指令

只有人工编辑器可用时，向用户交付已填好的精确改动，说明具体限制。不要创建替代或重复任务。实际更新后回读任务身份、内容与状态。

### 创建和启用边界

只通过正式支持的工具或界面创建和更新任务。没有事件监听或后台执行能力时，如实报告，保留可运行配置，不伪造后台循环。文件准备、任务创建和启用是三个不同结果。

平台强制审批不能由智能体代签。用户已经明确授权的创建、更新和启用无需再走自设审批。来源交接与触发测试通过前，保持新任务未启用或只运行平台支持的测试模式；现有生产任务的变更使用真实可用的暂停、草稿或受控测试策略，并保护用户已有服务。

## 8. 测试来源交接

使用已有测试范围中的无害报告、平台测试事件或用户提供的材料。只有发送测试消息已经获准时才自行发送；否则完成其余准备，说明需要的具体测试输入。

确认实际运行环境能读取整个包与必要非秘密配置。独立仓库检出核对分支和版本；提示词须指向准确完整的操作文件。未验证项目不得计为通过。

收集汇总先用已知材料核对原始诉求是否保留、窗口和分页是否完整、每项是否有来源引用、结果是否到达约定目标，以及重复运行是否复用已有产物；不要求分诊标记或 UI 复现。

选择缺陷分诊或 UI 复现时，保留以下七项交接检查，按实际阶段和来源验证：

1. 分诊保存原报告身份；回写模式恰好交付一条原生回复，输出模式生成绑定本报告的真实记录。Slack 核对根 `thread_ts`。
2. 结论包含一个配置标记，且有可核验作者或运行身份。
3. 复现只接受当前报告的可信分诊；相同文字、同名作者或报告附件不能伪造交接。
4. 复现始终使用同一组不可变来源身份，不换成运维或回复对象。
5. 没有新建来源报告、替代讨论或越界发送；Slack 还核对来源频道没有根消息。
6. 子执行者没有任何来源平台或追踪器外部写入能力；无法隔离时由协调者完成。
7. 来源身份缺失、原对象已删除或预检失败时，不外发也不新建工单；本次已有对象的补偿按完整方法单独处理。

持续模式另外重放一次相同事件，确认没有重复工单或回复；验证自身结论不会再次触发任务，失败不会跳过未处理报告，并验证暂停或停止方式。定时查询核对频率、时区、查询窗口和实际检查点。

所选模式检查通过且启用已经获准后，才接入正常流量。回读真实任务标识、触发器、内容与启用状态；将配置路径、证据、游标或未核对项保存到项目 Markdown。手动模式明确没有常驻监控，不把文件准备或任务创建称为已经启用。
