# 分诊自动化提示词

> 用于准备可审查的任务提示词。只有用户已经授权对应触发、持续运行和外部写入，且实际调度器或自动化连接器确认能够读取这些文件后，才创建或更新任务；已有授权继续有效。平台要求的审批由平台完成。

本次运行读取并遵循 `.agents/skills/dev-issue-setup/references/source-adapter.md` 与 `.agents/skills/dev-issue-triage/references/triage-method.md`，两者都必须在实际运行环境中可读。

配置来源。只有实际运行环境确认能够读取同一目标仓库中这个稳定路径时才包含它；隔离检出需要文件已在指定版本中。否则把非秘密配置值完整转述到任务提示，并说明原位置。绝不引用只在编写会话可见的缓存路径：

```text
{{ISSUE_CONFIG_PATH}}
```

从已配置工具的真实事件或用户指定材料取得输入，不要求所有平台提供同一组消息字段：

```text
来源类型与实际范围：{{SOURCE_TYPE_AND_SCOPE}}
原报告的原生身份或材料引用：{{SOURCE_REPORT_REFERENCE}}
实际触发方式与事件引用：{{TRIGGER_OR_MANUAL_INPUT}}
结果交付：{{ORIGIN_REPLY_OR_RUN_OUTPUT}}
```

如果来源是 Slack，额外使用真实 `source_channel_id`、`ts`、`thread_ts`，按完整适配方法冻结根坐标，且事件分支只接收配置频道的新顶层报告。工单、邮件、告警使用它们自己的稳定身份和原生回复关系；手工输入不伪造这些字段。

先核对当前平台实际支持所选触发及字段。手工模式只处理本份报告。持续模式按已授权范围过滤事件、排除本任务自身结论、处理重复投递并使用真实检查点；不支持时交付手工方法或配置草稿，不宣称正在监听。

把来源范围、原始报告身份和交付目标视为不可变。身份缺失或与配置不匹配时不外发、不写追踪器；仍可交付已有材料的只读分析与缺口。

完整操作文件负责分类、附件审阅、原因追踪、分流、去重、追踪器动作及最终结论。来源本身已是目标问题时不另建副本；只要求分类且没有追踪器时注明查重未执行。不发布进度消息，不新建来源报告、替代讨论或 Slack 来源根消息。

协调者是唯一外部回写者。委派执行者只读并返回发现，不能获得来源平台或追踪器凭据及写入动作。不能真实隔离时，由协调者完成。

单次结论必须以恰好一个配置的标记结束：

```text
[issue:bug]
[issue:performance]
[issue:other]
```

缺陷或性能标记可以增加 `tracker=<URL>`。

将标记与原报告身份、实际作者或运行身份和证据版本一起交付。`origin` 模式在已有授权内原生回复并回读；`run-output` 在当前会话或真实运行记录交付。结果未知先核查，不盲目重发或新建对象。
