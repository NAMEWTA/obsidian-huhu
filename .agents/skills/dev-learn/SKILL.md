# 读懂一个功能

从用户想理解的业务动作出发，把入口、调用、数据、状态和失败路径连起来。先说明它解决什么问题，再解释代码怎样实现；项目专有词汇先说清含义。

## 按问题选择讲法

- 要真正理解一项改动或子系统时，按[完整教学方法](references/teaching.md)解释机制；历史理由会影响理解时，再使用本包的原因调查方法。保留调查中的置信限定，跟随用户的背景和节奏。
- 用户说“讲人话”“再简单点”时，按[普通语言重述](references/plain-restatement.md)直接重述上一条，不重新启动全套调查。
- 开始讲解前需要核对学习目标时，按`dev-intake`（目标复述）说明所理解的问题，不新增审批或停等门槛。单独的需求意图对齐由 `dev-intake` 承接。
- 机制探索、教学中的历史调查及背景恢复，见`dev-help`（完整理解指南）。独立历史理由调查以 `dev-why` 为主，任务接续以 `dev-workflow` 为主；调用返回后继续原任务。

## 先找到真实对象

确认当前项目、目标模块或用户动作和想解决的问题。已有上下文足够就直接读；只有目标无法唯一定位时才补问。先读项目 `AGENTS.md` 和有关入口，按关键词检索 `.agents/dev/notes/index.md`、`glossary.md` 及少量相关笔记，再检查实际代码。

新增资料统一以 `.agents/dev/` 为根；已有资料按真实位置查阅引用，不擅自搬迁。永久资料在 `.agents/dev/notes/`，当次开发资料在 `.agents/dev/changes/<YYYY-MM-DD-slug>/`，历史资料在 `.agents/dev/archive/`。默认不整库阅读，不在安装目录 `.agents/skills/` 写学习结果。

## 追踪与讲解

1. **选一条真实业务路径。** 例如“用户点保存后，数据如何落盘并重新出现在界面”。找到真实入口、路由/命令、业务处理、状态或存储及返回。只按 `frontend/backend/database` 介绍目录还不足以解释运行机制。
2. **读所有权与分支。** 谁拥有数据和生命周期？同步、异步、跨进程或外部服务在哪里交接？正常、失败、取消、重试、恢复各由谁处理？按目标选择必要分支，使用 [源码阅读提纲](references/reading-code.md)。
3. **用证据校正理解。** 笔记和 README 帮助定位，当前源码与配置说明实际行为，测试只说明其覆盖场景。可以运行已有的轻量复现或检查；没有运行就明确写“源码分析”。注明代码修订/工作区状态，区分事实、设计理由、推断和未知。
4. **给出可接手的解释。** 先用几句话说明用途和全局关系，再沿业务路径解释数据如何流动。用表格对应“用户动作 → 代码入口/符号 → 状态或结果”；关系有分支时用短 Mermaid 图，不为了形式画图。给出修改某项行为时应从哪里进入、哪些约束会受影响、什么验证能提供证据。
5. **只沉淀有用的理解。** 简单答疑直接回答。形成可复用的模块导读或用户要求保存时，使用 [模块导读模板](assets/module-map.md)，保存到 `.agents/dev/notes/learning/<topic>.md`，或当次 change 的 `learning.md`。已有同主题导读就核实后更新，不为每轮问答复制一份永久文档。

## 记录的边界

- 保留一处主要说明：已有模块文档能承载就更新或链接它。学习说明解释机制，具体实现指向项目相对路径与可搜索符号；需要历史证据时附固定提交链接。行号不是唯一定位方式。
- 发现“账号”“用户账户”等项目同义词时核对它们映射到的真实实体，记录别名、适用领域和易混对象。不要靠词义相似把不同对象合并。
- 当前代码表明“已实现什么”，用户最新明确目标表明“希望什么”。发现差距就并列说明；不要用旧代码否定新需求，或把设计设想讲成已经上线。
- 旧学习文件若仍用于指导当前开发，更新已核实的事实和链接；标出未复核的范围。真正退役的历史资料保留历史身份，不默认当作当前依据。
- 保存时只更新相关导航和已核实条目。共享概念写入 `glossary.md`，长期决定链接已有 ADR；不要顺手重写整个知识库，也不把阅读源码时的推测自动提升为项目约束。
- 按用户已有技术背景解释，必要术语先用普通语言说明。类比不能取代真实代码证据；没有历史资料就不编造作者为什么这样设计。
- 学习请求本身不要求实施或部署；用户同时要求改造时，将明确行为与约束交给后续实施，并按任务选择合适的开发与验证方法。

## 交付

回答用途、完整运行路径、关键约束和修改入口，附足够定位源码的引用及未解问题。保存过文件就给出实际位置和检查范围；没有执行验证就如实说明。用户继续追问时沿同一业务路径深入，不要求重新走初始化或问卷。

完整讲解方法、知识写法与并行探索模板见[材料导航](references/index.md)。本技能调用相关协作方法，但不要求额外知识数据库。
