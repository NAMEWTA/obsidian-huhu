### 调查

**你负责答案。规划、路由、写作。**

调查请求只读，产出有引用的解释或建议，不改代码。

1. 经 [模块探索](module-exploration.md) 路由。动机问题也经 `dev-why`（决策调查）。
2. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only investigation`。
3. 产出 模块探索 形态输出，即概览 / 关键概念 / 工作机制 / 代码位置 / 注意事项；若请求是在替代方案间决策，给建议和权衡表。
4. 回复应用 `dev-writing`（清晰写作）。

不开 PR、不跟进、不运行 `架构设计`，除非调查是代码改动前置。若是，则交还用户，再路由缺陷修复或功能开发。

**回复：** 调查结果。“我们确定吗”类回答包含有理由的真实判断。前提错误就提出异议，见自主性。
