# 学习与图解工作流

从用户想理解的对象和问题开始。学习可以发生在需求实现前、开发中或实现后；它帮助理解，但不自动启动实现。

## 1. 确定学习问题

使用用户当前请求和已有上下文，确定对象、本轮问题及读者背景。缺少对象或问题时只补问缺失项；已有信息足够就直接读。按用户熟悉程度讲解，陌生术语先用日常语言解释，再给专业名字。

带着需求学习时，先说明参考对象解决什么问题、具有什么功能、为什么会采用这种机制。只有有记录的理由才能当作设计动机；源码只能证明现在怎样实现。

## 2. 定位依据

按问题读取当前项目的代码、测试和文档。关联某次需求时才读取该需求的来源、规格、任务、验证和评审记录。不默认整库读，不先扫描全部历史。

以当前源码和配置确定实际行为，以真实运行或已有测试确定已经验证的范围。记录文件、符号、章节和修订。资料不可访问或关键事实缺失时，停止依赖它的结论，继续有依据的部分。

依次追踪入口、业务处理、状态和数据所有者、持久化、返回、失败、取消、重试和恢复。详见[源码阅读提纲](reading-code.md)。

## 3. 确定保存位置

简单答疑直接回答。用户要求保存，或确有长期复用价值时，再选择位置：当前需求内可写 `learning.md`；长期模块导读写 `.agents/dev/notes/learning/<topic>.md`；已有模块文档能承载时优先更新它。

同一轮续学复用已选对象。指定对象不存在或身份冲突时先消歧，不自动挑另一个需求。无需为学习自动创建需求、流水编号、状态文件或空目录。

## 4. 讲解与图示

按[讲解格式](lesson-format.md)写作。先交代全局关系，再沿真实业务路径解释。需要表现关系、分支或时序时用简短 Mermaid 图；简单顺序直接用文字或表格。一个图只回答一个问题，箭头有方向，标签使用清楚名词与动词。

覆盖“它是什么、为什么需要、怎样流动或被调用”。每个新术语先解释意思，类比不能替代证据。有当前改造需求时，说明可借鉴内容和适用条件，把尚未决定的取舍留作问题，不写成已批准方案。

## 5. 保存、续写与交接

已有当前导读中可核实的错误原地纠正；新理解按主题合入，不为每轮问答强制复制一份永久文档。历史资料保留历史身份，不悄悄改成当前说明。

写前重读，避免覆盖并发修改。创建新文件后再补导航并回读；文件已存在或内容已被其他人修改时，先合并相关变更，不覆盖未知内容。正文已保存但导航未更新时，验证正文后补链接，不重复生成。

保存的结果说明用途、完整运行路径、术语、关键约束、修改入口和未解问题。引用足以定位实际代码，区分源码分析与已运行验证。图解交付不证明用户已经掌握，也不改变需求的完成或上线状态。

用户追问就沿同一业务路径深入。用户另行要求开发时，把目标行为和限制写清，并按任务选择合适的实现与验证方法。
