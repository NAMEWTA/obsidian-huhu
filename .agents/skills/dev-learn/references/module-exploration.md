# 如何运作

探索代码库，回答“X 如何工作”。按用户已有背景及接手子系统所需的层次解释架构，足够建立可用心智模型，又不至于像逐行注释源码。

探索与讲解使用当前环境实际提供的只读工具；任务可分解且有子 Agent 能力时并行，默认继承当前模型。没有并行能力时按同样角度顺序调查。不要猜测宿主工具名、指定未提供的模型，或为读取代码扩大权限。

## 1. 判断复杂度

范围模糊时，说明你的理解并开始探索，用户可以调整方向。

- **简单**（单个模块、小工具、例如“函数 X 怎么工作”的窄问题）：无需探索者。由当前 Agent 或一位解释者一次完成探索和解释，按[讲解提示词](explanation-prompt.md)构建提示，移除探索发现一节。转到第 4 步。
- **复杂**（跨多个文件或服务的子系统、横切功能、完整架构概览）：转到第 2 步。

拿不准时选简单路径。

## 2. 探索（仅复杂情况）

把问题分成 2 至 4 个角度，每个是子系统的独立切片。在一条消息中派出所有探索者，每位拿到填好角度的 [探索提示词](exploration-prompt.md)。

## 3. 综合（仅复杂情况）

全部探索者返回后，派一位解释者，给出 [讲解提示词](explanation-prompt.md)，填入所有探索发现。

## 4. 展示

展示解释者输出。可以为清晰度或对话背景做轻微编辑，不要大幅重写。

## 输出格式

解释采用 [讲解提示词](explanation-prompt.md) 定义的章节，删除不适用部分：概览、关键概念、工作机制、代码位置、注意事项。
