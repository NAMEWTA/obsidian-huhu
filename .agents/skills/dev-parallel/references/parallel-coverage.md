# 并行群体执行

## 开始

启动任何执行者前，建立待办清单，每个阶段一项。

1. 确定任务
2. 扇出
3. 汇总
4. 报告

## 阶段 A：确定任务

1. 陈述完成判据，以及群体必须交还的产物或报告。
2. 选择形态：拆成切片、让 N 位执行者竞赛同一份简报，或两者混用。竞赛或混合形态在派生前声明 `first pass`、`rank all` 或 `best-of`。
3. 默认继承当前模型。只有用户或项目已配置且工具支持时，才为不同工作选择不同模型。模型竞赛先指明各组实际能力。并发数量不超过当前工具上限；超额切片分批，未能执行的覆盖明确记录。
4. 执行者需要写入时，为其分配独立可写输出。验证或测量提交时，每份简报写明精确 SHA。测量简报还要指出方法（样本量、一个样本是什么、顺序）。执行者在结果中记录这两者。

## 阶段 B：扇出

在当前工具并发上限内一起派出独立执行者，优先后台运行。默认使用隔离的工作区或输出路径；需要本机认证、模拟器或运行中服务时使用实际可访问环境。没有多智能体工具时顺序运行同样的切片并如实标记，不能声称独立群体验证。

执行者必须从非默认的已推送分支开始时，在简报中指定该分支及精确 SHA，并用宿主支持的检出方式准备。

每份简报都应独立成立，包含目标、范围、精确切片或竞赛分组、如何验证，以及报告内容。报告用 `PASS`、`ISSUES` 或 `BLOCKED` 并附证据。能够证明缺陷的执行者报告 `ISSUES`，列出所有可证明的问题，不只报第一个。

执行者退出时，继续用 N-1 位，并记录退出。

## 阶段 C：汇总

阅读终态结果。结果未记录简报要求的 SHA 和方法时，丢弃该结果并重新派该执行者一次。第二次仍遗漏，则记录覆盖缺口。缺口不算通过。覆盖任务的每个必需切片都要有结果。竞赛任务采用预先声明的选择规则：首个通过、全部排名或择优。不要粘贴原始执行者输出。

## 阶段 D：报告

在聊天中返回一份合并报告，包括结果表、每个问题的一句话摘要、缺口或退出情况，以及使用时的竞赛规则。
