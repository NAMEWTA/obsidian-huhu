# 本地技能结构规则

先明确一个可识别任务：输入是什么，何时触发，用户能看到什么结果，最容易误用的边界是什么。通用模型已经知道的基础知识不必重写；任务专有判断、完整方法和反例必须保留。

## 文件结构

源仓库使用 `skills/<domain>/<domain>-<name>/`，安装后使用 `.agents/skills/<domain>-<name>/`。包中包含：

- `SKILL.md`：仅有 `name`、准确的 `description` 两个 frontmatter 字段，正文说明成果、步骤、判断和资源入口。
- `agents/openai.yaml`：中文显示名、简短说明和点名 `$技能名` 的默认提示，字符串加引号。
- `references/`：按需读取的完整方法、例子和领域知识，所有必需链接在包内。
- `assets/`：复制后填写的模板或实际产物素材。
- `scripts/`：确实值得确定性复用的程序，只有需要时增加，并真实运行验证。

不强制每个目录存在。不留示例占位代码、无关 README 或制作过程笔记。入口保持聚焦，长材料移入参考并说明何时读取。

## 编写与验证

已有可用的技能编写工具时，可用它初始化和校验；工具不可用时仍按上述结构编写，不把未安装工具当必需依赖。只使用当前宿主支持的元数据，不放固定模型、流程状态或复杂 schema。

保留完整参考里的条件、例子、反例和边界。自身方法的资源保存在本包并用相对链接读取；其他方法通过技能名调用，不复制其正文。不能只在开头加覆盖声明，却留下正文中的相反指令。

检查名称与目录一致、描述能选中正确任务、默认提示点名本技能、文件引用存在且不越出包、没有外部来源依赖。根据实际风险用代表性请求检查行为；低风险主观文字不增加模仿实现的测试。

确定性脚本必须实际运行正常与关键失败路径。没有运行或不能访问目标时，明确未验证，不以格式校验冒充行为证明。许可证与来源追踪放源仓库维护位置，不混入运行指令。

## 保存与交付

按用户指定源仓库保存，不编辑插件缓存。个人偏好与项目事实分开；秘密不入技能。按已有授权提交、推送、PR 或交付草稿，不额外发明审批。说明生成的任务能力、关键边界、实际验证和未覆盖部分。
