# 垂直切片与实施计划

使用**曳光弹式垂直切片**：每个切片贯穿完成该行为所需的层，交付一件可以演示或验证的事情。计划服务于实施，不建立额外的工作流状态机。

每个切片说明目标行为、真实依赖与验收方式；可以采用 TDD 短循环、实现后行为验证或适合该切片的其他方式。

## 从完整上下文开始

读取规格、相关讨论和已有计划。用户提供 issue / PR 时读取正文、评论和当前改动。用领域词汇描述任务，遵守本次已经确认的约束与授权。

定位当前代码和可复用实现。确有结构阻碍时先安排小范围前置调整；不要把泛化重构、工具换代或技术债清理偷偷加入本次范围。

小而明确的改动可只有一个切片。不要为了有计划而拆成多个文件或人为增加审批阶段。

## 切成可交付的行为

每个切片应当：

- 贯穿所需的数据、业务、接口、UI 与验证层，而非“先做数据库，再做全部 API，最后做全部 UI”。
- 完成后可独立演示或给出行为证据。
- 尺度适合一个实施者在可控上下文内完成；超出时按用户行为继续拆分。
- 有独立验收条件与清楚的边界，不依赖实施者猜测“做到什么算完”。

先做能尽早暴露关键假设的最小完整路径，再扩展场景。若一项只是调查或原型，它的交付是一个决定或事实，不伪装成已完成的产品功能。

为每个切片记录**真实阻塞**：只有前项的产物、决定或共享不变量确实是开工前提时才连接依赖。无阻塞切片可以同时推进；“看起来顺序更整齐”不是依赖。

## 对复杂重构使用诚实的整合边界

跨全仓库的机械改动可能无法按功能切片单独保持可运行。此时明确一条整合分支及最终统一验证边界。

若项目确实要求迁移期间持续兼容，可采用“扩展 → 分批迁移调用者 → 删除旧接口”；只有这种约束存在时才保留过渡层。用户已经允许直接替换时，规划一次完成全部调用者迁移及旧实现清理，不凭空引入兼容包袱。

说明哪些中间提交允许暂时不可运行，以及哪个整合点必须完整通过验证。中间状态不能被标记为可部署交付。

对于尚不明确的大需求，把“问题已清楚、答案待调查”与“还无法定义的问题”分开记录。只拆当前能说清的工作，完成调查后再展开后续切片。

## 写计划与任务

使用 [计划与切片模板](references/plan-template.md)。已授权的 tracker 继续按实际能力使用；新增本地计划与切片资料统一放在 `.agents/dev/changes/`，已有计划按真实位置引用：

- `.agents/dev/changes/<YYYY-MM-DD-slug>/plan.md` 保存目标、切片索引、依赖与执行顺序。
- 只有内容足够大、需要多人分工时才使用 `tasks/<NN>-<slug>.md`，每个文件描述一个切片。
- `progress.md` 保存当前进展、证据入口和下一步。计划中的目标与执行结果分开。

任务写“交付什么”，而非逐行修改教程。当前文件、符号可作为检索指针，并注明实施时复核。每项验收写明证据，例如运行命令、请求响应、真实界面状态或截图。

对适合并行的工作明确唯一写入者与文件/模块边界。先完成共享契约，再并行实现独立部分；不让多个代理同时覆盖同一分支或同一共享文件。

## 进入执行

如果用户要求先审方案，交付计划后停在所要求的位置。如果已经要求持续实施，说明计划并按授权继续；只为影响目标、不可逆操作或确实缺失的产品决定寻求补充。

发布 issue / sub-issue 需要已有授权。按阻塞项在前的顺序创建，使用真实链接建立依赖；不要编造未来编号，不自动关闭父 issue。

实施时工作前沿是“所有阻塞已满足的切片”。完成一项就更新依赖事实，继续推进可开始的下一项。不用预设状态枚举或复杂 Schema。

本技能交付一张可执行的工作图。实施授权已明确时调用 `dev-build`，传递计划与验收条件。

## 本地完整方法

| 任务形态 | 本包材料 |
| --- | --- |
| 已有规格，需要拆成端到端切片 | [完整切片方法](references/vertical-slicing.md) |
| 大需求尚看不清路线 | [决策地图](references/uncertainty-map.md)，区分已知问题、尚未明确和范围之外 |
| 组织实现分工与共享写入边界 | `dev-build`（功能执行） |
| 跨阶段或多个 PR，需要实施与证据清单 | [多阶段完整计划模板](references/multiphase-plan.md)，按规模保留适用部分 |
| 没有外部 tracker | [本地工作记录](references/local-work-records.md) |
| 还缺产品选择或准确术语 | `dev-grill`（决策访谈）、`dev-architecture`（领域建模）、`dev-archive`（词汇表格式） |
| 需要记录持久取舍 | `dev-archive`（决定记录格式） |
| 未知问题能通过实际运行解决 | `dev-build`（原型方法）、`dev-build`（逻辑原型）、`dev-build`（界面原型） |
| 未知问题依赖技术资料或代码事实 | [研究方法](references/research-method.md) |

本包资源使用链接，其他方法按技能名调用。复杂模板提供完整可选覆盖面，不要求小任务机械填满全部栏目。
