# 大型需求的决策地图

一个松散想法来了，大到单个智能体会话装不下，且笼罩在迷雾中：从这里到**终点**的路还不可见。探路是找出那条路，而不是冲向终点。本技能在项目工作记录上绘制**共享地图**，再逐一推进**决策任务**；它们是解决后形成决定的问题，而不是准备执行的构建切片，直到路线清楚。

每项工作的终点不同，命名终点是绘图的第一步，它塑造每个任务。终点可能是一份可交接并迭代的规格、开始规划前必须锁定的决定，或原地完成的数据结构迁移等变更。地图不限领域：工程工作、课程内容，凡符合这种形态的工作都可使用。

## 规划，不执行

探路默认是**规划**：每项任务解决一个决定；当道路清楚、执行者动手前已无决定待定时，地图完成。想直接做工作的冲动通常意味着已抵达地图边缘，该交接了。某项工作可以在**笔记**中覆盖此默认，把执行纳入地图本身；没有这种覆盖时，产出决定，而非交付物。

## 按名称引用

每张地图和每项问题都有**名称**，即本地文档或跟踪事项的标题。在人会阅读的一切内容中，包括叙述、地图的“目前决定”，都用名称引用，绝不用裸 ID、编号或 slug 代替。满屏 `#42、#43、#44` 不可读，名称一眼就能理解。ID 和 URL 不会消失；用名称包住链接，让它们位于名称**内部**，不代替名称。

## 地图

地图是当前变更目录的一份 map.md，或已有跟踪器中的一个父事项。它是索引；问题可作为 questions/ 下的文件或已有子事项，不新建强制标签体系。

地图是**索引**，不是存储。它列出已经作出的决定，并指向持有细节的任务；一个决定恰好存在于一个地方，即它的任务，因此地图不重述，只概括并链接。

**地图、子任务、阻塞关系和前沿查询实际放在哪里，取决于跟踪器。** 优先沿用项目约定；没有外部跟踪器时阅读[本地工作记录](local-work-records.md)，用普通 Markdown 保存地图、问题、负责人和答案。

低分辨率呈现整张地图，恢复工作时先加载它。开放问题从 questions/ 文件、计划索引或已有跟踪器查询；地图只放必要入口，不重复存储整份问题正文。

### 任务

每项问题通过稳定文件路径或真实事项 ID 与地图关联。正文写问题，大小适合当前执行环境中一个可控上下文的会话：

```markdown
## 问题

<本任务要解决的决定或调查>
```

每项问题记录采用研究、原型、访谈或前置操作哪一种方式，见[任务类型](#任务类型)。用普通文字或现有跟踪器字段即可；这些是决定，不是实现任务，不需要新增标签命名空间。

并行会话**先认领**问题，再做工作：在进度记录或已有跟踪器写明唯一负责人，其他会话跳过。单人工作无需另建锁或复杂状态系统。

已有跟踪器支持原生依赖时使用它，可直接呈现可领取前沿；本地文件或不支持原生依赖的平台在正文写依赖与答案指针。当全部前置问题已有可核对答案时，问题**解除阻塞**；**前沿**是尚未解决、未阻塞、未认领的问题，即已知区域的边缘。

答案在问题解决时记录为独立的“答案”节或已授权的评论，不预填结论，见[推进地图](#推进地图)。解决任务时创建的资产从事项链接，不整段粘贴。

## 任务类型

每项任务要么是 **HITL**，即人在循环中，与能代表自己发言的人共同完成；要么是 **AFK**，由智能体独立推动。HITL 任务只能通过真实互动解决，智能体绝不能替人扮演另一方；追问智能体自行回答自己的问题就违反了这一点。

- **研究（AFK）**：阅读文档、第三方 API 或知识库等本地资源，找出某项决定所等待的事实。按本包[研究方法](research-method.md)解决；有并行能力可委派独立子智能体。需要当前工作目录之外的知识时使用。
- **原型（HITL）**：按`dev-build`（原型方法），制作便宜、粗糙、具体的成果供人反馈，提升讨论保真度，例如提纲、粗稿、桩或 UI／逻辑代码。把原型链接为资产。关键问题是“应该长什么样”或“应该怎样行为”时使用。
- **追问（HITL）**：对话，默认类型。阅读`dev-grill`（决策访谈）和`dev-architecture`（领域建模）。
- **操作（HITL 或 AFK）**：在能作出**决定**之前必须先发生的手工工作；没有东西要决定、原型化或研究，但不做就无法继续讨论。例如注册服务以便评估 API、配置访问权限、搬运数据以便看清形状。这是唯一**执行**而不作决定的类型，它凭解除决定阻塞获得位置，不是为了交付终点。智能体能独立做就自己做，属于 AFK；否则给人准确清单，属于 HITL。工作完成即解决；答案记录做了什么，以及后续任务依赖的事实，例如凭证位置、新 URL、行数。

## 战争迷雾

地图**有意**不完整：看不见的地方不要绘制。当前任务之外是**战争迷雾**：能隐约看出未来将出现的决定和调查，但因为依赖尚未解决的问题，还无法锁定。解决任务会拨开它前方的迷雾，把刚刚能够明确表达的内容升级为新任务，逐步推进，直到通往终点的路线清楚、没有任务剩下。

地图的**尚未明确**保存这种模糊视野：怀疑将遇到的问题、以后要重访的领域。它是**朝向**终点的未发现前沿；这里的全部内容都在范围内，只是不够准确，暂时不能制成任务。按视野允许的程度宽松或完整地写，它也给协作者指明工作的方向。

**是迷雾还是任务？** 检验在于现在是否能准确表述问题，**不是**现在是否能回答。

- **写成任务**：问题已经准确，即使被阻塞、暂时无法行动。
- **列为尚未明确**：暂时无法那么准确地表述。不要预先把迷雾切成任务大小；它比任务粗，一片迷雾在前沿抵达时可能升级成多个任务，也可能一个都没有。

**尚未明确**不包括已经决定的内容，即“目前决定”；也不包括已有活跃任务或范围之外内容，见下一节。

## 范围之外

迷雾只沿着**朝向**终点的方向积聚。终点确定范围，超出终点的工作就是**范围之外**：它不是迷雾，也不属于**尚未明确**。把主动排除在**本项**工作之外的内容放到地图独立的**范围之外**节。它由范围决定，而不是由清晰程度决定。

范围之外工作永不升级，因为前沿在终点处停止。只有重画终点后它才会返回，而且应作为新工作，不是恢复旧工作。

划定范围是范围管理，不是路线中的一个步骤。当已有任务被发现位于终点之外，例如绘图时误纳入，或某个答案暴露了这一点，**把它移出当前前沿**：本地写明范围排除与理由；只有已有关闭授权时才关闭外部事项。然后在**范围之外**留一行要点和排除理由，并链接已关闭任务。它不进入**目前决定**；那里记录实际走过的路线，而范围边界不是路线上的一步。

## 调用

两种模式。不论哪种，一次集中解决一个有依赖的问题；完成后记录答案。是否在同一会话继续取决于上下文余量和用户授权，不强制每个问题另起会话。

### 绘制地图

用户带着松散想法调用。

1. **命名终点。** 阅读`dev-grill`（决策访谈）和`dev-architecture`（领域建模），明确地图正在寻找通路的是什么：规格、决定还是变更。终点确定范围，所以先确定。
2. **绘制前沿。** 再追问，这次**广度优先**：展开整个空间，不深挖单个线索，找出未决决定和现在可走的第一步。**如果没有发现迷雾**，即路线已经清楚、全程小到一个会话能完成，就不需要地图。省去地图，按当前授权直接形成规格或计划；用户只要求规划时交付该规划。
3. **创建地图**：填写终点与笔记，目前决定为空，把迷雾勾勒在**尚未明确**中。
4. **创建现在能明确描述的任务**，保存为问题文件或已授权创建的子事项，再在**第二遍**连接阻塞依赖，因为引用目标必须先真实存在。交叉引用也在这一遍用真实 ID 写入；占位符 `#<n>` 会自动链接到无关事项。接线把任务分为前沿和被阻塞者；不能明确的内容仍在迷雾中，即**尚未明确**节。
5. **启动研究子智能体。** 为独立研究问题按[研究方法](research-method.md)并行分工，或在缺少并行能力时顺序调查；把发现保存到变更目录 research/ 下，在问题中留上下文指针。若项目已有隔离研究分支约定可沿用，远端推送须已有授权，不默认建立或推送分支。
6. 保存地图与当前前沿。用户仅要求绘图时交付地图；已授权持续规划时可继续推进一个已就绪问题，不把会话切分当作强制停止门禁。

### 推进地图

用户提供地图文件、现有事项链接或编号调用。任务是**可选的**：不指定时由你选择下一个决定，而不是让用户选。

1. 加载**地图**，即低分辨率视图，不读全部任务正文。
2. 选择任务。用户指定了就使用它，否则按顺序取第一个前沿任务。并行工作时**认领它**：先在本地进度或已授权跟踪器记录唯一负责人。
3. 按问题记录的工作方式解决，见[任务类型](#任务类型)。读取问题正文、方式和相关证据，不依赖隐藏在标签中的唯一信息。**按需放大**：需要时获取相关或已关闭任务的完整正文；按 `## 笔记` 的相关资源指针阅读本地资料；需要访谈或术语核对时阅读`dev-grill`（决策访谈）和`dev-architecture`（领域建模）。
4. 记录解决结果：把答案保存为问题的**解决记录**，标记已解决，再向地图“目前决定”**追加上下文指针**。如使用外部跟踪器，仅在已有授权时发布评论或关闭事项。
5. 添加新发现任务，先创建再接线；把答案使之能够准确表述的迷雾升级为任务，并从**尚未明确**清除对应内容，让它只存在于新任务。如果答案揭示当前或其他任务位于终点之外，就**划到范围之外**，而不是当作路线上解决的任务。如果决定使地图其他部分失效，更新或删除这些任务。

用户可能并行推进未被阻塞的问题，所以修改地图或共享进度前先读最新内容，保留其他会话的更新。

所有凭证只记录安全存储位置、用途和取得方式，不把密钥明文写进地图、原型或研究记录。远程评论、指派、关闭与推送均需现有授权；本地草拟和查证可以连续推进。
