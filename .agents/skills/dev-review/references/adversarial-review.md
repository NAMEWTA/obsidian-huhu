# 对抗性质询

对抗者尝试破坏改动或设计。只有运行证实的发现才保留。报告发现，不应用修复。

## 确定范围

范围以用户指定为准。未指定时，取当前分支与基础分支的合并基点直到工作区的差异。使用 **意图复述** 技能，根据用户消息、提交和 PR 描述复述意图。意图不清楚时询问用户。

## 扇出

使用当前可用的独立审查上下文，给各审查者相同的范围、意图和基线。需要可写复现时，为每位准备隔离工作树并复制本次范围内未提交修改；保护原始工作区，不共享写入。模型默认继承当前会话；无并行工具时顺序审查并说明独立性限制。每位审查者使用以下完整简报：

> 破坏这个改动。每项发现都要通过真实代码上的运行证明，例如失败测试、复现脚本或显示错误行为的命令输出。对设计或计划，运行原型或探查当前代码树。复现保留在你自己的工作树。每项报告包含标题、精确命令、它打印的输出，以及意图要求的输出。凡未运行的内容都省略，包括样式、命名、结构，以及只有未来发生某项改动才有影响的风险。没有发现是有效结果。

## 验证

由协调者在对应版本上重新运行每条发现的命令。只有输出显示失败，且失败违背意图时才保留。删除其余发现。合并根因相同的发现。

这里不选择单一获胜方案，也不应用实现改动。对抗者找到不同失败，因此裁决保留所有已验证发现，而非只选一位对抗者的列表。

## 输出

- **意图**：复述。
- **发现**：每条已验证发现的命令、输出、如何违背意图，以及哪些对抗者发现了它。无保留项时写“没有已验证发现”。
- **排除**：每位对抗者被排除的发现数量及原因。
