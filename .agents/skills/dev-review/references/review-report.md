# 审查报告模板

按实际规模删减，但保留两轴与证据层次。

```markdown
# <变更名称>审查

范围：<基准 → 目标提交；是否包括工作树>
契约：<spec / issue / 用户请求>
限制：<不可运行环境、缺少材料等>

## 规格
### <影响程度> <问题名称>
- 要求：<来源与原意>
- 现状：<具体行为和代码定位>
- 触发：<必要条件>
- 影响：<用户或系统会遭遇什么>
- 证据：<运行 / 代码；实际与预期>
- 建议：<达到原要求的最小修复方向>

## 规范
### <影响程度> <问题名称>
- 性质：<明确规则违反 / 启发式判断>
- 依据：<规范位置或审查基线>
- 对应代码：<当前路径与符号>
- 实际代价：<为何值得修改>

## 已验证与已排除
<具体检查及它能证明的范围>

## 尚待证实
<真实的剩余风险与最低成本验证方法；不能冒充确定缺陷>

## 当前结果
<各轴发现数量及主要影响；有授权时说明已经修复与复核内容>
```

“没有发现问题”是当前范围与证据下的结论。不能从类型检查通过推导 UI 交互、网络重试或生产部署已经正确。

同一根因不要用多个表象重复计数；两轴可互相引用同一证据，但不要让其中一轴掩盖另一轴。
