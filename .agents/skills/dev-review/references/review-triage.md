# 审查机器人分类

跟进手册（`dev-workflow`（本地执行支持））处理 审查机器人 或自动审查评论时使用。目标不是默认忽略机器人，而是不再把每条评论都视为必改代码。

## 决策规则

行动前分类每个 审查机器人 线程：

- `fix`：评论指出可信的正确性、安全、隐私、数据丢失、认证、计费、迁移、幂等、竞态、已交付行为问题。在最低所属 PR 修复，已有外部回复授权时，再用提交 SHA 回复并解决线程；否则准备回复和证据。
- `dismiss`：评论匹配已记录的低风险噪声模式，且当前代码与背景证明无需修改。有授权时简短说明理由并解决线程，否则在报告保留具体反证。
- `ask`：评论新颖、高严重性、涉及安全隐私数据或有歧义。先调查证据，不猜；需要用户决定或缺少权限时才问。

先用代码与最低成本实验排除事实性歧义；只有产品取舍、权限或关键证据仍缺时才问。忽略噪声质量评论代价低，漏掉真实数据或安全缺陷代价高。

## 经验模式格式

后续模式按此形态添加：

```markdown
### <简短模式名称>

- 置信：候选 | 反复出现 | 强
- 可跳过条件：<必须成立的条件>
- 不可跳过条件：<风险边界>
- 示例信号：<识别该模式的措辞或代码背景>
- 来源：<PR/评论地址或简短历史说明>
```

一两个例子用“候选”，多次真实驳回后用“反复出现”；只有范围窄、反复验证、低风险才用“强”。

## 反复出现的跳过候选

### 有意的 UI 或设计系统视觉变更

- 置信：候选。
- 可跳过条件：PR 描述、截图、设计审查或相邻代码明确视觉变更，评论只是重复共享视觉默认值已变。
- 不可跳过条件：评论指出无障碍、焦点可见性、键盘导航、颜色对比度，或 PR 未有意改变的组件 API 契约。
- 示例信号：焦点轮廓、按钮大小、间距、共享视觉默认值评论，负责人答“有意如此”。

### 机器人看不到的上层或堆叠内用法

- 置信：候选。
- 可跳过条件：机器人说导出、组件、工具或文件未使用，但活动平台 PR 列表和差异、上层差异、PR 背景显示后续堆叠项会用。
- 不可跳过条件：当前 PR 不在堆叠、符号是公共 API、或无法核实所谓上层用法。
- 示例信号：“导出组件从未使用”，人工答“上层用了”。

### 并行实现期间临时重复

- 置信：候选。
- 可跳过条件：PR 有意复制少量代码，让新路径与正在删除、替换或验证的旧路径并行。
- 不可跳过条件：重复代码影响安全、计费、数据访问、API 行为，或长期共享抽象明显降低风险。
- 示例信号：“大量重复”“重复校验逻辑”，负责人解释旧路径将删或重复有意保持局部。

### 现有框架或组件不变量已覆盖警告

- 置信：候选。
- 可跳过条件：当前差异或附近代码可见的共享组件、框架契约、类型不变量、唯一事实来源已保证该条件。
- 不可跳过条件：不变量只是猜测而非强制、依赖时序、或跨值可能分叉的异步状态边界。
- 示例信号：共享 popover 已限制视口，却说内部缺 max-height；或本地已检查值和传递值来自同一来源却警告可空。

### 负责人声明的后续或延后清理

- 置信：候选。
- 可跳过条件：负责人明确说是已知后续，当前 PR 未恶化行为，且不是高风险区域。
- 不可跳过条件：智能体没有负责人输入、问题是中高严重性产品行为、延后会合入新回归。
- 示例信号：“以后再处理”“最终会删”。

### 自行撤回或明确误报的规则评论

- 置信：反复出现。
- 可跳过条件：正文或后续机器人回复明确撤回、合规、误报，且智能体能本地核验规则。
- 不可跳过条件：唯一证据是人在高风险问题上无解释地说“误报”。
- 示例信号：文件命名评论正文自己说文件已合规。

## 必须调查的高风险类别

即使过去 PR 驳回类似内容，也不自动跳过这些类别：

- 安全、隐私、认证、计费、数据保留、训练数据、权限边界发现。
- 高严重性发现。
- 迁移、模式、幂等、并发、跨系统行为发现。
- 建议修复很小、明确减风险且不改变产品意图的评论。

历史数据里人有时驳回安全或数据流评论，应把它当负责人判断，不是全团队跳过规则。

## 近期跟进的候选经验

跟进期间或之后，把看似对团队有用但未成熟的经验追加到这里。多个 PR 确认后，优先提升到上节反复出现候选。

### 手工重做浏览器原生行为

- 置信：候选。
- 可跳过条件：几乎没有。差异用手工等价物替代原生浏览器行为时，如原生 sticky 改为 JS 定位克隆、原生滚动目标改为转发 wheel/touch、绘制顺序遮挡改为 masks/clip-path，机器人对此代码的逻辑问题一直是真实的。
- 不可跳过条件：事件转发缺口（wheel deltaMode、触摸平移、边缘滚动链、轻触容差）、遮罩或裁剪命中测试差异、观察者与 React 状态时序竞态，默认修复。
- 示例信号：“遮罩不影响命中测试”“覆盖层阻止滚轮”“忽略 deltaMode”“在 React 应用状态前于 IntersectionObserver 回调运行”。
- 来源：一个 sticky 遮挡 PR，六轮机器人审查、约十八条发现，全部修复而非驳回。

### 契约检查漂移成本低，先运行检查

- 置信：候选。
- 可跳过条件：永远不跳过验证本身，只需一条命令。PR 交付固定协议或文档文字的契约检查，例如 SKILL.md 正则、文案快照，机器人说“检查不再匹配文档”或反过来时，分类前先在 PR 尖端运行。失败经验性确认主张；通过为驳回回复提供具体反证。
- 不可跳过条件：不适用。这是验证捷径，不是驳回模式。多轮倾向驳回规则会在这里误判，因为文字固定检查恰恰因之前修复轮次改文字而漂移。
- 示例信号：之前修复改过固定段落的 PR 被指出“契约检查漏了修复前等待”；尖端检查正好在对应断言失败。
- 来源：一个文字固定 PR 共八轮审查，前轮均修复解决，但第七轮主张仍真实。

### 同一 PR 后续已修复的过时安全发现

- 置信：候选。
- 可跳过条件：智能体安全审查等声称缺授权或校验调用，而当前 PR 尖端明确包含精确门禁和检查，通常是审查后加固提交加入。
- 不可跳过条件：所引工具对讨论主体无作用、检查晚于应保护的副作用、或缺少该主体覆盖。
- 示例信号：HIGH“缺授权检查”，但尖端精确防护已在副作用前调用。
- 来源：一个 webhook 端点 PR，加固提交晚于审查。

### 扩大刻意收窄的错误条件会掩盖真实错误

- 置信：候选。
- 可跳过条件：发现要求把具体 errno、错误码或状态类别扩大为全捕获，而窄条件编码真实区别。典型是只在 `ENOENT` 时依赖回退：“二进制未安装”不同于“命令已运行但失败”。任何非零退出都重试，会把合法失败，如未找到、认证过期、网络错误，再跑回退并报告回退错误，掩盖原始错误。
- 不可跳过条件：窄条件遗漏同类情况，如另一种二进制不可用 errno `EACCES`、另一种传输失败；未处理路径丢数据或留半状态；或重试幂等且原始错误仍展示。
- 示例信号：“仅当 X 以 ENOENT 失败才重试，即使可用 Y 存在也不回退”，而代码回退目的为依赖缺失，不是操作失败。
- 来源：一个 CLI 重命名 PR，回退针对缺失二进制，而非命令失败。
