# 开发环境与宿主配置

交付一份与当前环境一致的配置，并证明最小工作链路可用。只记录实际观察到的能力、模型和限制。用户已经指定范围或预算时直接沿用。

## 配置顺序

1. 阅读项目指令和当前工具说明，按 `dev-help`（宿主适配方法）区分可用、不可用与尚未确认的能力。
2. 按 [完整角色配置方法](references/configure-models.md) 读取现有设置，确定预算，建立角色映射并验证每个真实值。使用 [角色配置模板](assets/model-roles.md)，不把示例值传给工具。
3. 按 `dev-help`（接入与首个任务指南） 核对技能是否可读取、配置如何加载，以及第一个真实小任务如何验收。
4. 项目缺少行为验证时，提供一次按 `dev-verify`（创建验证技能） 补齐的建议；已有授权就执行。形式化检查仅在有明确属性与范围时选择 [形式化验证适配](references/formal-options.md)。
5. 用户要离线持续运行时，再读 `dev-help`（无人值守完整指南），确认完成条件、权限、隔离、证据与实际调度机制。

## 报告来源与监控

本技能配置宿主、模型与验证能力。用户要求接入聊天、工单、邮件、监控告警，或按来源自动发现需求时，可选用 `dev-issue-setup` 完成来源、追踪器、仓库路由和触发器初始化。调用时传入真实连接器、已有授权、触发与失败恢复要求，交付可用配置，不假定后台服务存在。

来源平台不决定代码仓库或问题追踪器。手工单次任务不要求启用监控；定时、事件或 webhook 方式必须对应宿主中实际创建并验证的触发机制。新增来源与触发配置存入 `.agents/dev/project/issue-automation/`，秘密只保留安全引用。

## 输出与持久化

按当前任务读取 `.agents/dev/AGENTS.md` 和相关子目录说明，不假定宿主会递归自动加载。默认持久化骨架由安装器在选中 dev 技能时补齐，不属于本技能的执行步骤；本技能不维护骨架模板或初始化脚本。业务记录仍按真实内容创建。

本套技能新增的项目配置统一使用 `.agents/dev/context/model-roles.md` 保存简短角色表，在现有项目指令中加入必要导航。仅修改本次管理的设置，不覆盖用户其他规则。不因项目配置请求写入全局偏好。

配置文件不会凭空改变宿主。说明当前会话能否读取它、子智能体是否接受覆盖参数，以及新会话是否经过实际验证。未检查自动加载时，只说文件已保存。

使用 [环境记录模板](assets/environment.md) 记录事实来源、验证命令或观察、未覆盖范围；不复制秘密、完整会话或工具全量输出。交付包括已配置项、保持继承的角色、实际验证结果、以及真正缺少的条件。
