# 配置角色模型与预算

用一份小型角色表表达本项目的模型和推理预算。文件是项目配置，只有宿主或当前智能体实际读取并支持它时才生效；不虚构自动应用机制。

## 步骤

### 1. 检测可用模型

列出本次会话子智能体工具 schema 实际接受的模型及推理参数。宿主若提供当前账户有权使用的模型列表，可核对完整性；它不取代本次工具可接受值。没有可靠枚举时，保留继承，或让用户提供其真实可用的配置。

不写入未经确认可用的真实模型标识。`inherit-parent` 和 `auto` 在本地角色表中表示继承，不是保证每个宿主接受的工具值；调用时按当前 schema 省略覆盖字段或使用宿主明确支持的继承方式。

### 2. 加载当前状态

先读项目已有角色配置和用户当前约定。没有配置时默认沿用本次会话与工具自身的设置，不先写死模型家族。

本文件提供的角色表是建议覆盖面，不要求每个项目启用全部角色。已知退役且属于本技能管理的角色可以从活动表移除，并在本次改动说明列出；自定义或未知角色先保留并标注待核对，不能因不在示例中就删除。

重复运行时保留用户按模型家族、评审列表或继承方式作出的覆盖。删除某个覆盖表示恢复项目或宿主当前默认，而不是恢复历史默认。

### 3. 选择预算、建立映射并说明结果

**(a) 确定预算。** 用户已明确预算或模型时沿用。缺失且会实质影响成本或结果时，提出一个短问题；结构化工具存在且支持所需选项数量时再使用它，不发送不存在的多选字段。四档可用作沟通标签：

| 档位 | 目标含义 |
| --- | --- |
| 不限预算 | 请求已支持的最高推理等级，目标可记为 `max` |
| 较高预算 | 高强度推理，目标可记为 `xhigh` |
| 中等预算 | 在成本与判断质量间折中，目标可记为 `high` |
| 较小预算 | 优先较低成本和延迟，目标可记为 `medium` |

这些词不保证宿主支持相同枚举，也不表示可突破用户限额。未收到选择时，保持现状，不擅自提高预算。

**(b) 应用预算。** 只在真实检测的模型与推理组合中选择。若宿主把推理级别编码在模型标识中，依据它的真实命名解析；若用独立参数，就分别配置，不靠拼接字符串造模型。对于实际支持 `max > xhigh > high > medium > low` 的宿主，可用此顺序寻找同一模型家族中不高于目标的最高可用等级；没有对应关系时标为待选择，不能默认假设。

例如，检测结果显示某家族只有 `high` 与 `medium`，目标为更高一级时最多选已确认的 `high`。若另一个家族允许更高等级，它可以单独提高；不要把一个家族的上限推广给所有模型。速度选项也按真实字段处理。继承条目保持继承。

**(c) 展示角色表。** 对每个启用角色展示实际值、继承或待核对状态，以及预算调整前后的变化。列出将移除的受管理旧角色。已有授权和明确选择时直接写入；确有未解决的成本或能力选择时，才请用户在真实可用值中选择。

评审组的列表每个条目对应一个独立执行上下文，重复的继承条目也计入数量。列表长度表达希望的独立视角数，并发数仍受实际工具上限和预算限制；缺少并行能力时可以顺序执行，不能虚报并发。交叉裁判候选池按偏好排列，只选择实际可用且满足独立性目标的一个；若要求不同模型家族而没有可用选项，明确这一限制。继承别名本身不能证明跨模型独立性。

并行工作者角色是默认值，比较实验只有在用户授权且工具支持时才按实验分支覆盖。

### 4. 验证

所有真实模型和推理组合都必须出现在当前已确认能力中。继承是本地配置语义，最终工具调用仍要通过 schema 检查。选定模型不可用时，保留原配置并说明缺口；若用户允许继承回退就执行并记录，否则只解决那个真实选择，不重复询问已明确的其他角色。

### 5. 写入角色配置

本套技能新增的项目角色配置统一写入 `.agents/dev/context/model-roles.md`。按 [角色配置模板](../assets/model-roles.md) 保留预算、能力来源和角色表，不需要 JSON 状态机。

默认角色覆盖如下，可按项目删减未使用项：

| 角色 | 选择方式 |
| --- | --- |
| 功能实现与重构 | 当前已确认模型，或继承 |
| 缺陷修复 | 当前已确认模型，或继承 |
| 性能调查 | 当前已确认模型，或继承 |
| 迭代优化 | 当前已确认模型，或继承 |
| 判断与文字 | 当前已确认模型，或继承 |
| 最困难的问题 | 当前已确认模型，或继承 |
| 模块探索 | 当前已确认模型，或继承 |
| 模块讲解 | 当前已确认模型，或继承 |
| 历史调查 | 当前已确认模型，或继承 |
| 历史综合 | 当前已确认模型，或继承 |
| 工具复盘 | 当前已确认模型，或继承 |
| 判断、发散与综合复盘 | 当前已确认模型，或继承 |
| 独立方案候选组 | 当前可用值列表，数量有界 |
| 交叉裁判候选池 | 当前可用值按偏好排序，只选一个 |
| 并行工作者 | 当前已确认模型，或继承 |
| 架构候选组 | 当前可用值列表，数量有界 |
| 对抗审查组 | 当前可用值列表，数量有界 |

如果文件完全由本技能管理，可以完整重写受管理内容保持幂等；存在其他用户内容时，只更新明确归属的章节。写前保留可恢复版本，写后重新读取并比较，不丢失自定义规则。

宿主确实支持自己的全局规则目录，且用户明确要求全局设置时，才按 `dev-help`（宿主适配） 生成所需格式。不要在多个目录复制同一份技能或配置造成漂移。

### 6. 说明生效范围

报告文件保存位置、角色变化、验证结果，以及当前会话或新会话如何读取。真实验证了宿主自动加载才声称自动应用；否则提供明确的本地读取入口。再次运行更新同一份配置。

### 7. 可选：补齐行为验证

检查项目是否有驱动真实应用的测试设施或项目验证技能。没有时，只提出一次建议，并说明它能启动应用、执行真实用户路径、保留证据和清理实例。已有生成授权时按 `dev-verify`（创建验证技能） 直接完成；没有时交付具体建议，用户拒绝后继续其余配置，不反复推销。

### 8. 可选：补齐形式化验证

检查是否已有模型检查、证明或其他验证设施。并发、重试、解析器和状态转换中存在高价值属性时，按 [形式化验证适配](formal-options.md) 判断范围。明确验证一个性质及其假设，不声称验证所有代码。已有授权就实施可用方案；不适用时说明原因，不把形式化工具安装当作配置门槛。
