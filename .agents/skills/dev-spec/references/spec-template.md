# 规格模板

模板提供完整思考面，按实际需求保留相关部分。小需求可以将下列内容写成几段，不要求固定 Schema、状态字段或自动编号系统。

```markdown
# <需求名称>

## 问题
<用户是谁，当前痛点是什么，为什么值得解决>

## 目标体验
<从用户视角描述完成后如何工作>

## 来源与约束
- <请求 / issue / 讨论 / 原型>
- <已确认约束与交付范围>
- <尚未证实的假设，及为何采用>

## 场景与行为契约
### <场景>
- 条件：<输入、角色、已有状态>
- 行为：<用户或系统动作>
- 结果：<可观察输出与状态变化>
- 重要边界：<与本场景相关的失败、取消、重试或权限>

## 验收
- [ ] <条件与动作> 后 <可观察结果>。
- [ ] <相关边界行为>。

## 实现决定
- <模块或领域职责>
- <接口语义、不变量、数据生命周期>
- <有真实取舍的决定与理由>
- <可推迟到实施时决定的细节>

## 验证决定
- 真实入口：<应用 / CLI / API / 存储>
- 执行方法：<现有命令、操作或待实施后补充的验证>
- 证据：<输出、截图、状态或记录位置>
- 重要回归风险：<具体风险与验证>
- 环境限制：<目前不能运行的部分；不得当作通过>

## UI（适用时）
<现有设计系统、关键界面、加载 / 空态 / 错误状态、交互与参考图>

## 上线（适用时）
<目标环境、版本、配置引用、恢复方式及用户可观察的上线成功条件>

## 范围之外
<本次明确不做的功能、清理、兼容或迁移>

## 待决问题
<确实影响实施的问题及被阻塞部分；没有则省略>

## 现状证据
- <领域 / 接口>：<仓库相对路径>，<符号 / 检索关键词>；
  观察于 <日期 / 提交>；实施前核对最新代码。
- <运行证据或设计决定链接>
```

## 语义与证据的分工

“匿名用户不能读取私有文档”属于目标契约。“当前鉴权入口位于某文件的某函数”属于现状证据。移动函数不应使目标契约失效；变更权限需求也不能被旧代码位置束缚。

规范词汇保持统一。用户说“账号”而领域叫“用户账户”，在适用领域内写同一规范词，并引用词汇表里的别名映射。不同领域语义不同的同名概念要分别说明。

## 有用的验收示例

- 用户撤销一次保存后，重新打开文档看到撤销后的内容。
- 下载失败后给出可重试状态；重试成功后只留下一个完整文件。
- 功能模块关闭后，对外调用该模块入口得到明确的不可用结果。
- 重构完成后，同一组输入的公开输出和持久化语义保持一致。

这些是写法示例，不代表目标项目已有这些功能。验收表达成功条件；按任务选择自动或手动验证，可将行为条件转为测试先行的检查。
