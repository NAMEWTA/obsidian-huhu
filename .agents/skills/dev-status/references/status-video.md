# 视频进展回顾

遵循 [进展回顾方法](status-report.md)，但用带字幕的短视频展示发生的变化，替代其中的总结与图示。时间范围从用户在 本次视频回顾请求 之前的最后一条消息开始，不是从任何更早的 更早的普通回顾请求 开始。在仓库外编写和渲染视频是其只读规则的唯一例外。回复由进展回顾的开场句、内嵌视频、一行说明你自己尚可完成的工作，以及待办事项组成。视频展示某项决定的选项时，使用视频里的名称称呼各选项。渲染失败时，用一行说明，然后只给出待决定事项。

## 幻灯片

使用工作产生的截图、录屏、diff 和数据，不使用聊天里关于它们的叙述。绘制前，先写一句用户看完应记住的要点，再为每张幻灯片写一行。删去不会改变用户认识的幻灯片。最多 10 张，越少越好。这两份笔记都不放入回复。

每张幻灯片只表达一个要点。以同一张图为基础逐页变化，不要切到无关画面。同一种颜色或形状在每页都表示同一含义。用画面展示工作，例如系统如何运行、标出各 PR 状态的 PR 栈、修复前后对比，或并排选项。用箭头、突出显示和运动指出变化。幻灯片不能是项目符号清单、状态清单、表格，或没有关系连线的方框。

文字尽量少。把标签放在它命名的对象上，用人会说的普通话，不用“测试：通过”这种标记。不要给画面已经展示的内容再配重复说明；不要在不同幻灯片或下方正文中重复同一个事实。

展示用户提出的每件事的结果，以及它是完成、仍在运行、失败，还是未检查。仍等待用户的事项不得展示为完成。展示过程中发现并修复的 bug。若可见变化没有截图，就在对应幻灯片说明，并指出屏幕上改了什么。只根据已有事实绘制。不得编造数字，不得绘制未实际截取的屏幕。

## 字幕

每张幻灯片配一条短字幕，约十个词，只依据该页展示的内容，用你向用户说明时的口吻表达要点。说明画面的含义，不要念标签。字幕放在画面下方的独立条带中；每页条带高度相同，除字幕外保持空白，避免遮挡幻灯片。字号较小，但在聊天尺寸播放时仍可读。

## 渲染

渲染一个无声横向视频，例如 mp4，并在幻灯片之间加入运动。每一帧都由幻灯片本身铺满上方画面，下方留字幕条带。用幻灯片生成帧，不要录制屏幕；将每条字幕烧录到对应幻灯片的帧中，使它在整段停留时间持续显示。停留时间是该页完整显示的时长，不包括转入和转出的运动。每页停留时间应足够读完新增文字，至少每三个词一秒。一页新增文字包括字幕和前页没有出现的每个词，包括改过的标签。第一页的所有文字都算新增。截图内部文字不计入。

内嵌视频前，检查渲染后的文件。按聊天尺寸查看每张幻灯片的一帧，确认字幕可读且没有遮住内容。通过把文件中的帧与幻灯片匹配来测量每页停留时间，不用静止帧检测器，因为它会把淡入淡出末端的浅色画面也算作静止。核对每页新增词数与测得的停留时间。修正任何无法在该时长内读完的页面，重新渲染，再次检查。

使用当前实际可用的排版、渲染和视频检查工具，不假设专有生成 API 存在。用户只授权回顾时不临时运行应用获取新截图。中文以自然短语检查阅读时间，保留至少每三个词一秒的基线，并实际试读，不把不可靠的分词结果当作可读性证据。制作时可用[分镜模板](../assets/storyboard.md)记录计划与成片测量。没有查看成片或测量停留的能力时，说明未完成验证，不宣称已达到交付标准。
