# 代码界面设计系统

为页面与组件建立可复用的设计变量、语义颜色、文字样式和状态。先检查项目实际使用的框架、样式入口与组件；用户要求和已有设计系统优先。没有既定系统时采用下列完整默认，不需要设计文件或外部设计工具。

- 新建完整设计系统时使用全部基础表；局部修改只补当前用户路径所需的缺口，不另建未使用的组件库。
- 在项目现有样式和组件组织中实现，使用 CSS 自定义属性、主题对象或宿主的等价机制；不为采用这些规则更换框架。
- 创建或绑定设计变量、文本样式之前，读取[完整设计变量参考](design-tokens.md)。产品 UI 与营销页的标题字重在该表中分支，已有项目保持同一份实际约定。

## 工作流程

1. **先检查实现。** 读取主题、样式、组件封装和相邻页面，搜索已有变量、命名文本样式、组件及其状态。先复用已有内容，再创建新内容；设计记录引用真实文件与符号。
2. **先补基础缺口。** 新建完整设计系统时，在构建页面之前建立以下全部内容；已有项目只补本次范围中确实缺少的项：
   - `spacing` 与 `radius` 变量。
   - 两个颜色层：先 `Core Colors`，再包含 Light 与 Dark 模式的 `Color System`。
   - 文本样式。

   浅色和深色通过同一语义变量的主题映射切换，不在各组件内复制两套硬编码颜色。新系统默认提供两种主题；已有产品只处理本次要求支持的主题。
   - **在可运行预览中展示设计变量。** 沿用项目已有组件预览或文档页面，建立 `Foundations` 展示区，每个集合一节；无现成预览时使用项目可运行的最小页面，不要求安装额外工具：
     - `Core Colors`：每个色板一行，每个色阶一个色块。
     - `Color System`：每组一行，并排展示声明支持的 Light 与 Dark 映射。
     - `spacing`：每个设计变量一根条形，尺寸等于其值。
     - `radius`：每个设计变量一个采用该圆角的正方形。
     - 文本样式：每种样式一行示例。
   - **绑定示例，使其随设计变量更新。** 色块、间距条和圆角示例读取实际 token；文本示例使用真实命名样式。修改变量后，预览与产品组件一同更新。
   - **标签：** 每个示例标注变量名，`Color System` 还标注别名，例如 `Surface/Primary → Grayscale/870`。数值标签尽量由实际变量生成；手写标签在变量变更时同步核对，不维护另一套独立色值。
3. **逐区块构建。** 先首屏，然后每次完成一个区块。不要一口气构建整页。每完成一个区块就截图，修正之后再继续。
4. **让布局随内容变化。** 内容容器使用项目布局组件、Flex、Grid 或宿主等价布局，内边距与间隙读取间距变量；在窄屏和长内容下检查换行、排列与溢出。
5. **绑定，不手填。**
   - 颜色、边框、圆角、内边距和间隙引用实际变量或已映射的样式。
   - 每个文本元素使用命名文本样式。
   - 设计只绑定 `Color System` 设计变量，不直接绑定 `Core Colors`。
6. **完成前自查。** 执行本文件末尾清单，修复当前范围内不通过的项，报告实际完成、未验证与不适用的内容。

## 字体排版

- **字体：** 产品界面使用项目、用户或品牌指定字体；核对字体文件、可用字重及实际加载结果。没有既定字体的新营销页采用[落地页的字体选择](landing-page-guide.md#字体)。
- 除非用户要求配对，否则**每个产品只用一个字体家族**。只有代码、数据或数字内容，才允许在主字体旁使用 Geist Mono。
- **不使用斜体样式，字重不超过粗体。**
- **字号只来自 Tailwind 比例：** 12、14、16、18、20、24、30、36、48、60、72、96、128。字号位于两个刻度之间时，向下取刻度，并采用该刻度行高。
- **文本样式。** 创建[设计变量参考 → 文本样式](design-tokens.md#文本样式)中的命名样式，包括 Heading 1 到 6、Title 1 到 5、Body 1 到 6、Button-lg/md/sm/Xsm、Caption 1 到 5。名称与大小写必须完全一致。
  - 保留 `Heading / Heading 1`、`Body / Body 4`、`Button / Button-md` 等语义名；在代码中映射为项目约定的类或 token，例如 `heading-1`、`body-4`、`button-md`。
  - 每个文本元素使用其中一种样式，不在使用点重复写字号与字重。已有项目名称不同则复用并记录对应关系。
- **分组用途：**
  - **Heading：** 页面与区块标题，从大到小。Heading 1 用于首屏。
  - **Title：** 卡片标题、列表项标题、区块起始标签和导航项。
  - **Body：** 连续正文。同一字号内，1 的字重最强，最后一个为常规。
  - **Button：** 只用于按钮内部文字。主按钮使用 Button-md，小型页头按钮使用 Button-sm。
  - **Caption：** 元数据、辅助文本、徽章、时间戳和细则。
- **新增样式。** 项目确有需要时，在所属组增加下一个编号，例如 Body 7，数值来自既有刻度。不发明新名称或比例外字号。
- **文案：**
  - 文本内不使用连字符。
  - 标题末行不单独剩下一个单词。优先使用平衡换行；需要控制标题节奏时在语义完整处换行，并检查窄屏，不通过任意缩窄容器挤出换行。
  - 首屏标题（Heading 1）不使用句点，末尾和短语之间都不使用。两个意思用换行分开，例如 `看见低质内容` / `决定修复什么`，而不是 `看见低质内容。决定修复什么。`。

## 间距

- 只使用 `spacing/*` 数字变量：0、2、4、8、12、16、24、32、40、48、64、80、96。不使用中间值。
- 内边距与 `gap` 通过样式变量或主题对象读取同一间距尺度，不在各处手写数值。`spacing/75` 可映射为 `--spacing-75`，现有项目沿用其命名。
- 设计值位于两个设计变量之间时，取最近的一个并绑定。
- 主按钮垂直内边距为 8（`spacing/75`），水平内边距为 12（`spacing/100`）。

## 圆角

- 只使用 Tailwind 圆角值（0、2、4、6、8、12、16、24、full），保存为 `radius/*` 变量并映射到实际 `border-radius`；需要分角时仍引用同一尺度。
- **嵌套圆角规则。** 一个形状位于另一个形状内部，且间隙小于 32 时：
  `内圆角 = 外圆角 − 间隙`
  仅在结果大于 2 时应用。例如卡片圆角为 16、内边距为 8，则内部元素圆角为 8。
- 检查嵌套容器：读取父容器圆角与实际间距，计算内部圆角，并选用匹配的 `radius/*` 变量。

## 颜色

### 设计变量结构：原始色板与语义用途两层

新系统采用下列完整结构，十六进制颜色值遵循用户品牌；已有系统复用等价语义及名称。完整名称清单见[设计变量参考 → 颜色](design-tokens.md#颜色)。

1. **`Core Colors` 集合：** 原始色板。包含 `Primary`、`Secondary`、`Accent`、`Grayscale`，以及语义色板 `Red`（错误）、`Green`（成功）、`Yellow`（警告）。
   - 每个色板至少 10 个色阶，从接近白色的 `00` 到接近黑色的 `1000`。`500` 是基础色相。
   - 根据品牌基础色生成色阶。
   - 透明色也放在此层，保存为 `Grayscale-Alpha` 色板（`700-16` … `700-80`），不透明度存入变量本身。让 `Overlay/*` 直接引用带透明度的颜色值，避免对整个容器设置 opacity 连带影响子内容。
2. **`Color System` 集合：** 包含 `Light` 和 `Dark` 模式的语义设计变量。每个值都是指向 Core Color 的别名，不能是原始十六进制颜色。
   - 分组为 `Border/`、`Surface/`、`Action/`、`Text/`、`Icon/`、`Overlay/`。
   - 每种角色有基础变量，以及所需变体：`-Hover`、`-Click` 或 `-Selected`、`-Disabled`、`-Subtle`、`-Inverted`。

- 设计只绑定 `Color System`，更换品牌时只需修改 `Core Colors`。
- 按角色命名变量，不按原始颜色命名，例如不能叫 `Surface/Blue 500`。
- 按用途使用变量：表面读取 `Surface/*`，文本读取 `Text/*`，边框读取 `Border/*`，图标读取 `Icon/*`。组件不绕过语义层直接使用原始色阶。

### 表面

- **深色模式背景只使用：** `#000000` · `#181818` · `#1F1F1F` · `#272727` · `#313131` · `#131209`。
- **背景不使用渐变。** 所有表面为纯色，包括按钮和渐隐叠加层。
- **首屏标题**是唯一渐变例外，只在文字上由左向右渐变：
  - 深色主题 `#FFFFFF` → `#9B9B9B`。
  - 浅色主题 `#000000` → `#666666`。

  两个渐变端点都引用语义颜色变量，使渐变随主题切换。
- **一个强调色**，饱和度保持低于 80%。
- **边框要么环绕四周，要么不用。** 不给卡片添加单侧边框。分隔行时，使用颜色来自 `Border/*` 的 1px 分隔元素，不把卡片样式改成单侧边框。

## 对比度与无障碍

- 正文相对背景至少达到 **4.5:1**。
- 大字（24 及以上，或粗体 18 及以上）和界面部件，包括图标、输入框边框、焦点环，至少达到 **3:1**。
- 渐变标题检查渐变最浅端的对比度，不只检查最深端。
- 状态不能仅靠颜色区分，还应配合图标、标签或字重变化。
- 移动视口的触控目标至少为 44 × 44 CSS 像素。
- 品牌色与白字对比度不合格时，为 `Action/*` 变量选择同色板的更深色阶，不修改文字颜色。

## 布局

- 首屏主标题与副标题最大宽度为 **680**。
- 默认不在标题上方添加眉题标签，即小胶囊或小标签，例如 `● 设计质检，并非重新设计`。只有用户要求，或用户上传的灵感图片包含此元素时才添加。
- 新设计默认在 1440px 桌面视口检查，居中内容容器宽 1200 到 1280px。
- 响应式页面同时检查 768px 和 390px，并根据真实目标设备补充视口；这些是检查尺寸，不把页面宽度写死。
- 不默认将三个等宽卡片排成一行。考虑双列交错、不对称网格或便当盒布局。
- 并排卡片的共享元素对齐：标题、价格、列表和按钮应从相同的 Y 坐标开始。

## 图标

- 使用 Phosphor、Solar 或 Iconamoon。不使用 Material Icons 或 Material Symbols。
- 全产品使用一致的描边粗细；已有图标系统优先。
- 通过项目图标组件或 SVG 使用图标，颜色读取 `Icon/*`，例如由语义变量设置 `currentColor`。不另用基本图形重画已有图标。

## 组件与状态

- 重复使用的同类界面提取为项目组件，将可变文本作为属性；复用已有组件而不建立平行副本。
- **交互组件**具备 **Default、Hover、Pressed、Focus、Disabled** 变体。输入框另加 **Error** 和 **Filled**。
- **新建完整按钮组件库时**使用以下两个属性，每个尺寸覆盖全部 25 种组合；已有组件或局部页面只补当前承诺需要的缺口：
  - `Type` = Primary | Secondary | Tertiary | Error | Warning。
  - `State` = Default | Hover | Pressed | Focus | Disabled。

  填充绑定 `Action/*`，例如 `Action/Primary`、`Action/Primary-Hover`、`Action/Primary-Click`、`Action/Primary-Disabled`；边框绑定 `Border/*`；标签绑定 `Text/*`。Focus 增加可见焦点环，使用 2px 外侧描边，对比度至少 3:1，不只改变颜色。
- **数据视图**具备 **Loading**（与实际布局形状一致的骨架屏）、**Empty**（完整设计的开始使用视图）和 **Error** 状态。

## 动效

- 新设计采用自定义贝塞尔曲线 `cubic-bezier(0.22, 1, 0.36, 1)`：
  - 布局位移 500ms，使用 transform 承载，不逐帧改变布局尺寸。
  - 颜色或不透明度变化 300ms。
- 不直接使用默认 linear 或 ease 预设；已有项目沿用已确认的动效系统。
- 支持 reduced motion，去掉非必要位移并保留最终可读状态；营销页的导航与滚动显现读[完整动效规则](landing-page-guide.md#b7-动效)。

## 内容

- 使用实际草稿文案，不放占位文本。
- 虚构原型使用符合产品行业的可信姓名、品牌和数字，并标明虚构。避免可疑整数或“Acme”之类套用名称。真实产品的价格、客户、评价和统计必须有真实依据，缺失时显式标出待补内容。
- **禁止空泛词语：** “颠覆革新”“全面加速”“尖端”“毫不费力”“改变你的工作流”“提升到新高度”“发挥强大力量”“世界级”。
- 标题与按钮使用句首大写风格。

## 落地页

任务是落地页时，还要阅读本地[落地页设计](landing-page-guide.md)，遵循页面结构与文案要求，包括需求采集问题、区块顺序和行动按钮规则。其中包含大字标语区块，以逐词显现作为原型交互；减少动效模式直接显示最终文字。全部所需规则已随本技能提供。

## 文件整洁

- 组件、样式与预览用有意义的名称，例如 `PricingCard` 与 `Pricing / Card / Pro`，不保留编号式临时名称。
- token 按 `spacing`、`radius`、`Core Colors` 和 `Color System` 分组；主题在语义层映射。已有代码按其实际目录组织，不为匹配指南新增顶层目录。
- 文本样式按 Heading、Title、Body、Button、Caption 分组并保持映射一致。
- 预览按 `Foundations`、`Components`、`Screens` 组织。完整系统展示全部基础项，局部改造仅更新已有预览中的相关部分。
- 保护用户已有页面、组件和未提交工作；不因建立预览而覆盖无关实现。

## 检查清单（汇报前执行）

- [ ] 每个文本元素使用选定尺度上的命名文本样式，产品 UI/营销页默认与已有项目约定已明确。
- [ ] 每个内边距和间隙绑定间距变量。
- [ ] 每个圆角绑定圆角变量，嵌套圆角符合公式。
- [ ] 每个颜色与边框引用 `Color System` 语义变量，不直接使用原始十六进制值或 Core Color；声明支持的主题均已检查。
- [ ] 新建完整系统的 Core Colors 每个色板至少 10 个色阶，Color System 变量均引用原始色板；局部改动保持既有映射。
- [ ] `Foundations` 预览展示本次范围内的变量和文本样式，读取实际实现，标签保持同步。
- [ ] 正文对比度通过 4.5:1，大字和界面部件通过 3:1。
- [ ] 没有背景渐变、单侧边框或斜体。
- [ ] 首屏主标题与副标题宽度上限为 680；首屏标题没有句点；用户未要求且上传灵感图未包含时，不添加眉题标签。
- [ ] 交互组件覆盖当前承诺的全部状态；新建完整按钮库覆盖 5 类型 × 5 状态。
- [ ] 图标来自既有系统或所选默认库，描边粗细统一。
- [ ] 文案、素材与示例身份已核对；缺失事实明确标注，组件和样式名称有意义。
