# 落地页设计

落地页不同于首页。首页服务多种意图；落地页要促成一种意图：

**一个主张 → 一类受众 → 一个主要行动。**

本技能分为两部分。**A 部分**决定页面说什么以及怎样组织。**B 部分**是新设计的完整默认视觉体系。先完成 A，再处理 B。

## 适用范围

页面结构与转化规则适用于落地页、营销网站和营销原型。视觉体系用于没有既定设计规范的新设计；业务表单、工作台和仪表盘不强加营销区块。用户明确要求和项目已采用的设计系统优先；保持现有组件约定，并记录必要覆盖理由。新建页面采用下列完整默认值，不因框架默认值改变设计意图。

**已有页面改造。** 先定位当前用户路径、组件与视觉约定，保持既有结构中的有效部分；按本文件逐区块诊断和修正，不整体覆盖已有设计。

# A 部分 — 策略与结构

## A1. 需求采集

在设计或写文案前收集以下信息。只询问缺失内容，集中一次询问，不逐题打断。

**目的**
- 唯一的主要行动是什么？试用、预约演示、购买、加入候补名单，还是下载？
- 提供什么，访客具体能够获得什么？
- 什么算转化？点击、注册，还是购买？

**受众与背景**
- 理想客户画像是什么？
- 他们试图解决什么问题？
- 最主要的三个顾虑是什么，也就是他们现在不转化的原因？
- 流量来源：广告、搜索、社交媒体或邮件。
- 访客进入页面前已经知道什么？

**证据与素材**
- 证明材料：标志、客户评价、数字、案例研究。
- 截图、演示视频、产品 GIF。
- 保证、退款条款、取消条款。

**限制**
- 品牌语气：轻松还是专业？
- 设计方向：简洁编辑风格、活泼的 3D，还是玻璃质感界面？
- 是否优先考虑移动端？

如果用户无法回答，做出合理假设，用一行说明，然后继续。不要让构建停滞。

## A2. 页面结构

**首屏（必需）**
1. 主标题，说明结果和受众。
2. 副标题，解释实现方式并补充具体信息。
3. 主要行动按钮，使用明确动词并说明用户将得到什么。
4. 一个可信度信号，例如标志条、统计数字或简短评价。
5. 首屏视觉，例如产品截图、视频或有表现力的插画。

**页面中部（论证）**
6. 从问题到解决方案，一个区块。
7. 三到五项以结果为导向的收益。
8. 三步说明运作方式。
9. 社会认同，例如客户评价或案例研究。

**页面底部（回应顾虑）**
10. 六到十二个常见问题。
11. 降低风险的承诺，例如试用、随时取消或保障。
12. 最终行动按钮，与顶部一致。

在页面中部论证的某处加入 B11 要求的标语逐词显现区块，通常放在首屏之后或收益之后。

## A3. 布局选择

选择一种，并说明理由。

| 类型 | 使用场景 |
|---|---|
| **A. 经典首屏加区块** | 一张首屏截图就能让人理解产品。这是最常见的形式。 |
| **B. 长篇叙事** | 需要教育受众并消除怀疑时。 |
| **C. 极简转化页** | 高意向流量，例如向已有用户发送邮件；或下载、候补名单等简短主张。 |
| **D. 对比页** | 搜索意图包含替代方案，例如“X 与 Y 对比”“最适合谁”。通常配合 SEO 页面。 |

## A4. 转化规则

**让信息匹配流量来源。** 流量来自广告时，在首屏呼应广告标题，并保持同样的承诺和视觉语气。

**让下一步一目了然。** 只有一个主要行动按钮。首屏不能放互相竞争的行动按钮。

**先写收益。** 功能说明产品做什么；收益说明这对用户意味着什么。

**具体表达。**
- ❌ “节省时间，提高效率”
- ✅ “把每周制作报告的时间从 4 小时缩短到 15 分钟”

**降低风险。** 至少选择一种：免费试用、免费方案、不需要信用卡、随时取消或退款保证。

**用一个区块回应顾虑，不要把它藏进脚注。** 对决策阻力大的主张，将常见问题提前。证据直接放在其支持的说法旁边。

## A5. 文案

**标题公式**
- “获得{结果}，无需承受{痛点}”
- “为{受众}打造的{品类}”
- “在{时间}内交付{结果}”

**副标题。** 一到两句话，解释这是什么，以及适合谁。

**行动按钮。** 动词加用户将得到的东西。不使用“了解更多”或“提交”。使用“开始免费试用”“预约演示”“获取清单”。

**收益要点。** 加粗收益，随后给出证据或细节。例如：**更快迭代**——一键生成三个布局变体。

注意：仍须遵守 B1 文案规则。句子中不使用连字符，末行不出现孤立单词。

## A6. 构建顺序

按以下顺序逐区块开展：

1. 首屏。
2. 收益。
3. 运作方式。
4. 证据。
5. 常见问题。
6. 最终行动按钮。

不要每次迭代都重建整页。逐区块构建便于控制，也能让差异保持可评审。

## A7. SEO 与 AEO

仅供广告使用的活动页，或时效非常强的促销内容，**不要建立索引**。使用 `noindex`，或放在不被索引的路径下。

长期有效、搜索意图与页面承诺一致的主张和页面，**应建立索引**。添加清楚的标题和元描述，从首页和功能页建立内部链接；常见问题使用清楚的问答形式，方便答案引擎理解。合适时添加 FAQ 结构化数据。

## A8. 常见问题

- 首屏行动按钮过多。
- 价值主张含糊，例如“简化”“优化”。
- 堆积功能清单，却没有说明结果。
- 把证据埋在页面底部。
- 移动布局破坏可读性。
- 没有明确的下一步。

# B 部分 — 视觉体系

每一个视觉数值都必须由以下规则确定，不临时随意发明。

## B1. 字体排版

### 字体

**使用：** Geist、Manrope、Geist Mono、Poppins。

**禁止使用：** Inter、Roboto、Arial、Open Sans、Helvetica。

界面的任何位置都**不使用斜体**。

**每个网站只使用一个字体家族。** 除非请求明确要求，否则不要配对两种字体。只有代码、数据或确实需要等宽字的数字界面，才允许在主字体旁使用 Geist Mono。

**不使用超粗字重**（900 / black）。上限为半粗体或粗体。

### 文案规则

**文本中不使用连字符。** 正文、标题或标签内不使用 `-`，改写词语。

**避免孤立单词。** 末行不能只剩一个单词。标题使用 `text-wrap: balance`，正文使用 `text-wrap: pretty`。

### 字号比例

字号始终使用 Tailwind 默认字号比例。不要保留任意值，包括 `text-[19px]`、`font-size: 22px` 或 `1.4rem`。

现有字号未准确落在某个刻度时，向下取**最接近的刻度**，同时使用该字号配套的行高。

完整字号、行高和 Tailwind 对照见[设计变量参考 → 字号比例](design-tokens.md#字号比例)。

评审时，不要一边对齐字号刻度，一边在别处独立设置自定义行高。字距与行高的调整只能在匹配刻度已经提供的值**以内**进行，避免两条规则冲突。

### 文本样式

每一段文本使用完整表中的一个命名样式。不要用零散的字号和字重为文本设置样式。名称与大小写须完全一致。

完整样式表见[设计变量参考 → 文本样式](design-tokens.md#文本样式)。新营销页将 Heading 1–6 统一设为半粗体，其他样式沿用表中数值；已有项目使用已经确认的统一字重。

各组的用途：

- **Heading** 用于页面和区块标题，按从大到小排列。Heading 1 用于首屏标题。
- **Title** 用于卡片标题、列表项标题、区块起始标签和导航项。
- **Body** 用于连续正文。在同一字号内，1 的字重最强，最后一个为常规字重。
- **Button** 只用于按钮文本。主按钮用 Button-md，小型页头按钮用 Button-sm。
- **Caption** 用于元数据、辅助文字、徽章、时间戳和细则。

字号来自上方比例，因此样式不能引入刻度之外的值。项目需要新样式时，在所属组添加下一个编号，例如 Body 7，并使用已有刻度，不另外发明名称。

在代码中，将每个样式定义一次，成为可复用类或设计变量。使用同名的短横线写法，例如 `heading-1`、`body-4`、`button-md`、`caption-2`，然后应用它，不在每个元素上重复字号与字重工具类。

## B2. 间距

间距使用完整表中的数值，不使用中间值或范围以外的值。

完整间距表见[设计变量参考 → 间距](design-tokens.md#间距)。代码中的 `Spacing-75`、`spacing/75` 或 `--spacing-75` 是同一语义的命名映射，沿用项目现有形式，不重复定义数值。

**主按钮：** 垂直内边距 8px，水平内边距 12px。

## B3. 圆角

只使用[设计变量参考 → 圆角](design-tokens.md#圆角)中的 Tailwind 圆角值。

**嵌套圆角公式。** 一个形状位于另一个形状内部，且两者间隙**小于 32px**时：

```
内圆角 = 外圆角 − 间隙
```

仅在结果**大于 2**时应用。低于此值，保留内部形状的直角或保持原样。

示例：外层卡片使用 `rounded-2xl`（16px），内边距为 8px，内部元素圆角就应为 8px（`rounded-lg`）。

## B4. 边框与背景

- **不只给卡片的一侧加边框。** 边框要么包围四周，要么不使用。
- **背景不使用渐变。** 背景为纯色。

### 深色模式背景色

只使用以下颜色：

`#000000` · `#181818` · `#1F1F1F` · `#272727` · `#313131` · `#131209`

## B5. 首屏区块

### 标题颜色

- **深色主题：** 标题文字从左到右渐变，`#FFFFFF` → `#9B9B9B`。
- **浅色主题：** 标题文字从左到右渐变，`#000000` → `#666666`。

这是唯一使用渐变的位置，而且只用于文字，不能用于背景。

### 布局

- 主标题与副标题的**最大宽度都为 680px**。
- 阅读标题文案，在**语义完整**的位置插入换行。
- 不让换行生硬地切断短语，或增加句子理解难度。按意思分段换行。

## B6. 图标

**使用：** Phosphor、Solar 或 Iconamoon。

**禁止使用：** Material Icons、Material Symbols。

## B7. 动效

动效应有重量感，并减速到位。不要发布浏览器默认曲线（`ease`、`linear`、`ease-in-out`）。

**基础曲线：** `ease-[cubic-bezier(0.22,1,0.36,1)]`，布局和位置变化使用 `duration-500`。悬停时颜色和透明度的变化可使用 `duration-300`，但不能短于 200ms。

只对 `transform` 和 `opacity` 添加动画。不要对 `top`、`left`、`width` 或 `height` 添加动画。

遵守 `prefers-reduced-motion`：用简单透明度变化替代位移动画。

### 导航

**静止状态。** 使用紧凑的悬浮栏，与顶部边缘保持距离，不紧贴边缘；水平居中，宽度随内容。半透明表面叠加背景模糊，让后面的页面内容隐约可见。间距遵循 B2，圆角遵循 B3。

**菜单开关。** 打开与关闭图标在两种状态之间变形，不瞬间替换。使用 B6 的图标，或自行绘制线条；无论哪种方式，都以基础曲线完成变化。

**移动菜单。** 打开为全高面板，不使用小下拉框。面板背景使用主题基础表面的高不透明度版本，并配合较强模糊。

**链接入场。** 展开菜单中的链接按阅读顺序逐个入场，每项向上移动一小段（Spacing-300，24px）并渐显。每项比前项晚 60ms，整个序列上限为 400ms，避免长菜单显得拖沓。

### 滚动显现

区块进入视口时，向上移动一小段（Spacing-400，32px），并以基础曲线在 600 到 800ms 内从完全透明变为不透明。每个区块只显现一次；向上滚动时不重复播放。

用 `IntersectionObserver` 或 Framer Motion 的 `whileInView` 触发显现。不要把工作挂到未经节流的 `window.addEventListener('scroll')` 上，它会逐帧运行并损害移动端性能。

## B8. 内容真实性

每份示例内容都应读起来像来自一个有真实用户的真实产品。

- **写出文案。** 不使用占位拉丁文，也不写“这里放你的标题”。以产品语气写完整句子。
- **人物。** 为评价者和团队成员使用符合产品受众与地区的完整、具体姓名。不要给两个人重复使用同一张脸。
- **品牌与标志。** 虚构名称应符合产品所在行业。物流工具的客户名称应像物流公司，不像泛泛的科技初创公司。
- **不编造事实。** 真实产品页面的价格、保障、统计、客户数量、评价和标志必须来自用户或真实来源。缺少事实时，使用明确标记的占位项，例如 `{{price}}` 或 `{{testimonial}}`，不要编造。
- **示例数字。** 在虚构演示和原型中，可以使用上述虚构姓名与品牌，但避免可疑的整数。价格要像真实定价；指标带小数或非整齐末位；列表中的日期应有所变化。
- **禁止空泛词语。** 不写“颠覆革新”“全面加速”“尖端”“毫不费力”“改变你的工作流”“提升到新高度”“发挥强大力量”或“世界级”。改用朴素语言说明产品做什么。
- 标题与按钮使用**句首大写**风格。
- **系统消息。** 确认语气平静且具体，例如“发票已发送给 Dana”。错误要说明失败原因及下一步，例如“上传失败。文件超过 20 MB。”不加俏皮感叹词或感叹号。

## B9. 状态

每个交互元素都要交付完整状态集：

- **悬停**：背景变化、轻微缩放或位移。
- **按下**：使用 `scale(0.98)` 或 `translateY(1px)` 提供触感反馈。
- **聚焦**：可见的焦点环。这是无障碍要求，不可省略。
- **加载中**：与实际布局形状一致的骨架屏，不用圆形旋转图标。
- **空状态**：完整设计的“开始使用”视图，不能是空白面板。
- **错误**：就地呈现具体错误，不使用 `window.alert()`。

不保留失效链接。指向 `#` 的按钮应连接真实目标，或在视觉上禁用。导航中必须标识当前页面。

## B10. 发布要求

以下内容容易遗漏，会让页面显得尚未完成：

- 页脚中的隐私政策与条款链接。
- 自定义、符合品牌风格的 404 页面。
- 客户端表单校验，包括邮箱格式和必填字段。
- 为键盘用户提供跳转到正文的链接。
- 适用地区要求时提供 Cookie 同意机制。
- 品牌 favicon。
- `<title>`、元描述、`og:image` 和社交分享标签。
- 每张有意义的图片都有替代文字。
- 语义化 HTML：`<nav>`、`<main>`、`<article>`、`<aside>`、`<section>`。
- 每个页面都有返回路径。
- 在 390px 宽度检查：不水平溢出，按钮文字不超出按钮，首屏可看到主要行动。

## B11. 标语显现区块（必需）

每个落地页都包含一个独立于首屏的大字区块，说明核心收益或标语。它放在页面更下方，形成自己的段落，不直接堆在首屏下方。

**文案**
- 至少两行文字。
- 使用 A5 的语气写收益陈述或标语，不写泛泛的区块标题。

**排版**
- 根据行数，从 B1 中选择 Heading 3 到 Heading 1。
- 最大宽度与首屏一样受限，使换行遵循 B5 的语义规则。

**动画**
- 文字初始为柔和、低强调的色调，大约是主题基础文字颜色的 25% 到 35% 不透明度。
- 区块滚入视口时，每个词按阅读顺序独立从低强调色过渡到完整文字颜色。
- 每个词经过触发线时逐一激活，不让整个文本块同时切换。过渡使用 B7 基础曲线，不使用线性淡入。
- 可以为每个词使用 `IntersectionObserver`，也可以用单个通过 `requestAnimationFrame` 节流的滚动监听器。遵循 B7，不使用未经节流的 `window.addEventListener('scroll')`。
- 在 `prefers-reduced-motion` 下，立即以完整颜色显示最终文本，不逐词播放动画。

# 输出格式

从零生成落地页时，先按顺序给出以下内容，再写代码：

1. **页面大纲**：区块及顺序。
2. **首屏文案**：主标题、副标题、行动按钮、证据短句。
3. **收益**：三到五项结果导向的要点。
4. **运作方式**：三个步骤。
5. **常见问题**：六到十二组问答。
6. **SEO / AEO**：是否索引的建议；若索引，给出标题与元描述。
7. **布局建议**：A、B、C 或 D，以及原因。

随后依照 A6 逐区块构建。

# 快速检查清单

**策略**
- [ ] 一个主张、一类受众、一个主要行动。
- [ ] 首屏没有互相竞争的行动按钮。
- [ ] 使用具体数字而非含糊动词。
- [ ] 至少一种降低风险的承诺。
- [ ] 证据位于其支持的说法旁边。
- [ ] 有意识地选择布局类型。

**视觉**
- [ ] 单一允许使用的字体，无斜体，无超粗字重。
- [ ] 文案没有连字符，没有孤立单词。
- [ ] 每个字号都落在 Tailwind 比例刻度上。
- [ ] 每个文本元素使用命名样式（Heading、Title、Body、Button、Caption）。
- [ ] 每个间距值都来自间距表。
- [ ] 嵌套圆角遵循公式。
- [ ] 卡片没有单侧边框，背景没有渐变。
- [ ] 首屏主标题和副标题上限为 680px，并按语义换行。
- [ ] 图标来自 Phosphor、Solar 或 Iconamoon。
- [ ] 每个过渡使用 B7 基础曲线，滚动显现使用 IntersectionObserver。
- [ ] 包含标语显现区块，至少两行，滚动时逐词激活。
- [ ] 不编造价格、统计或评价；缺失事实使用明确标记的占位项。
- [ ] 已检查 390px 宽度，没有溢出。

**内容与交付**
- [ ] 完整草稿文案、可信姓名与数字，没有禁止的空泛词。
- [ ] 悬停、按下、聚焦、加载中、空状态、错误状态均完整。
- [ ] 没有失效链接，导航标识当前项。
- [ ] 404、法律链接、表单校验、favicon、元标签和替代文字齐全。
