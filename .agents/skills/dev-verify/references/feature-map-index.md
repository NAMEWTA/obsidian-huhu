# 笔记验证图

本目录是持续维护的笔记应用用户行为验证来源。驱动应用前先读索引，再用匹配功能文件作为配方。

## 基线前置条件

- 在 `http://127.0.0.1:4173` 启动笔记应用，使用可丢弃数据目录。
- 设置 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`，使并行运行不共享状态。
- 创建标题为 `Quarterly plan` 和 `Grocery list` 的种子笔记。
- 把 `control-notes` 和 `notes` CLI 放到 `PATH`。
- 运行 `control-notes doctor`，要求预期地址、数据目录和构建版本。
- 不驱动非本次验证启动的实例。

## 驱动约定

- 除非前置条件另有说明，每份配方从基线状态开始。
- 优先 ARIA 角色和可访问名称，而非 CSS 选择器或 DOM 位置。
- 每条命令按字面执行，保持引号内名称和参数不变。
- 浏览器操作通过 `control-notes browser`。
- 终端操作通过 `control-notes cli -- <command>`。
- 修改后恢复种子数据，清理时不删证明产物。

## 证明与跳过报告

- 捕获用户动作与结果状态，不只最终屏幕。
- UI 证明含 ARIA 快照和能识别应用身份的截图。
- CLI 证明含命令、stdout、stderr、退出码。
- 修改证明含对存储值的第二个只读视图。
- 每份产物记录功能 ID 和所用入口。
- 不可到达路径要报告尝试命令和未满足前提。
- 不得用另一路径的验证宣称被跳过入口已验证。

## 功能条目契约

每功能文件先用 H1 标题和一段文字描述用户可见行为，随后严格按顺序使用四个 H2：

1. `子功能` 列短 ID，每行为一条。
2. `如何到达（用户视角）` 列每个用户入口。
3. `使用 <驱动工具> 驱动` 以 `前置条件：` 开头，用有标签条目把每个用户动作与精确命令、可观察结果配对。
4. `注意事项` 列可能浪费或使验证失效的陷阱。

功能图不写实现细节，只写用户路径、稳定定位、必要状态、命令、可观察证据。
