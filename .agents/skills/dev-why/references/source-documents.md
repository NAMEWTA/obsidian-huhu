# Notion 文档

## 这个来源包含什么

- PRD（产品需求文档）
- 技术规格与 RFC
- 架构决策记录（ADR）
- 设计评审会议记录
- 提供领域背景的团队页面
- 事故复盘
- 可能解释防御性代码的运行手册
- 确定优先级的战略文档

“为什么”在成为代码之前，经常以长篇文档形式存在于 Notion。重要功能通常有对应文档。

## 如何搜索

有已授权的文档连接器时，使用其实际读取工具。

1. **通过 `notion-search` 搜索关键词。** 尝试：
   - 功能名
   - 目标代码中的关键符号／类名
   - 作者账号名，设计文档通常早于代码提交
   - 错误字符串或用户可见术语
   - 已知代码上线时间时，使用限定时间的查询
2. **通过 `notion-fetch` 获取候选页面。** 阅读完整内容，不只看预览。理由经常埋在文档中段。
3. **追踪反向链接和子页面。** 设计文档常把考虑过的替代方案、附录或实现说明放在子页面中。
4. **检查相关数据库。** `notion-query-data-sources` 和 `notion-query-meeting-notes` 可以找出讨论该决定的会议记录。
5. **搜索作者专属空间。** 如果 PR 作者有个人笔记本，这在某些公司很常见，其中可能有代码之前的探索性思考。

## 这里的好证据是什么样

- PRD 的“问题陈述”或“动机”一节与目标代码用途相符。
- “考虑过的替代方案”或“否决的方法”一节。
- 把目标代码列为某个事故修复方案的复盘。
- 会议记录写着“我们决定 X，因为 Y”，并与 PR 的作者／日期范围一致。
- 内容具体的 ADR，而非空泛填写的模板（状态、背景、决定、后果）。

## 常见陷阱

- **过时文档。** 规格往往在实现前写成，之后未更新。文档可能描述已经变化的计划。与实际 PR 交叉核对。
- **文档与现实偏离。** 规格可能说“我们将做 X”，代码实际却做 Y。标明这种偏离。综合者会呈现矛盾。
- **套话模板。** 某些组织要求“为什么”一节，实际却填满空话。寻找具体内容。
- **未被链接的文档。** 最相关的文档可能没有任何地方链接它。宽泛的关键词搜索有帮助。
- **多份草稿。** 同一主题有多份文档时，找到定稿或最近更新的一份。检查日期。
- **受访问限制的页面。** 无法访问某个页面时，记为缺口。

## 返回什么

对每份相关文档：
- 标题与 URL
- 作者和最后更新日期
- 动机原文，逐字引用并标明页面／章节位置
- 相关链接页面，便于综合者引证
- 文档是定稿还是草稿
