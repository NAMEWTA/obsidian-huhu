# Sentry 错误历史

## 如何搜索

有已授权的错误追踪连接器时，使用其实际读取工具。

1. **确认环境。** 如果不知道项目标识和组织：

   ```
   find_organizations
   find_projects
   ```

2. **搜索与目标有关的问题。**

   ```
   search_issues（自然语言，例如“PaymentService 超时中的错误”“uploadFile 中未处理的异常”）
   ```

   根据目标处理的异常类名、函数或类名、检查的错误消息字符串，以及文件路径构造查询。

3. **按发布版本和时间窗口缩小范围。**

   ```
   search_issue_events（按版本、时间、环境、调用链 ID、标签筛选）
   get_issue_tag_values（查看某个问题在不同版本、用户、环境中的分布）
   ```

   对可疑问题，检查**首次出现**与**最后出现**（停止时间是否与目标上线日期一致）、**受影响的版本**（哪些出现问题，哪个版本修复）、以及**频率轨迹**（是否先突增再解决）。

4. **获取完整事件以了解背景。**

   ```
   get_sentry_resource（传入 Sentry URL，或类型与 ID）
   ```

   堆栈跟踪是否经过目标代码？标签和面包屑是否与目标所防范的条件一致？

5. **检查目标日期附近上线的版本。**

   ```
   find_releases（目标提交日期附近）
   ```

   将发布版本与 PR 合并日期交叉核对。

6. **谨慎少量使用 Seer。**

   ```
   analyze_issue_with_seer
   ```

   Seer 的 AI 根因分析用于生成假设。将它视为推断，不视为权威结论。实际事件和堆栈跟踪才是一手证据。

## 返回什么

对每个相关问题：
- 问题 ID 和标题
- 项目与组织
- 首次出现／最后出现的时间戳
- 事件数量，以及已知时的采样率
- 受影响的版本
- 能说明与目标关联的代表性堆栈片段，逐字摘录而非摘要
- 首次／最后出现时间与目标上线日期的关联
- 问题链接
- 任何作者评论或解决说明
