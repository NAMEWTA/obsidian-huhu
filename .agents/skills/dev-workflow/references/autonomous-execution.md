### 自主执行

**你负责退出条件。定义完成，然后不停顿地推进到它。**

1. 首轮迭代前，把退出条件写成可检查判据，如测试全绿、复现已修复、全部 N 个 PR 已合并、像素差为零。
2. 使用当前环境实际提供的事件通知或定时能力选择唤醒机制。有 CI、合并、引用推进等事件时优先事件观察，必要时用合理间隔心跳兜底。没有后台调度能力时在当前会话持续执行，保存恢复点，不声称会在会话结束后自动醒来。并发和模型遵循实际工具能力。
3. 每轮做证据支持的最小改动，按判据验证；有推进就按已有授权保存成果，没有帮助就撤回本轮自身改动。“也许有用”的双保险要回滚，不搭便车留下。
   按 **可验证单元** 原则安排工作，下一个单元前验证当前单元，不把检查攒到最后。
4. 途中发现且支持目标的事项由你负责。通过 开发执行规程 自行处理损坏技能、相关缺陷、不稳定验证器、审查噪声、工具故障、无人接手的后续事项、可修复漂移。范围外工作记录为后续，不自动创建或发布 PR。当前范围内可逆工作持续推进，已有授权不重复询问；真实缺少授权、实验无法解决的产品选择或真正死路才交由用户决定。以判据为主驱动力，每次支线修复后回到它。
5. 每轮用 **决策轨迹** 保存检查点，一行记录改了什么、判据是否推进。
6. 满足判据时停止。平台期不是停止理由，继续并换方法突破。达到约定资源上限、必要条件缺失或真正死路时说明并保留恢复点，不空转；绝不放宽判据来宣告胜利。

**回复：** 退出条件、执行轮数、落地内容、丢弃内容、最终判据状态。
