### 自动堆叠

执行完全自动手册，但不合并。

1. **用验证完成后停止替代第 5 步。** 每个 PR 当前头都已验证且绿色后停止，交给操作人。交接后，操作人未发开始指令前任何人不得推送。每次循环周期提示都指出本文件，让每周期看见禁止合并规则。
2. **只有确实建立在另一个 PR 之上才堆叠。** 这是第 3 步的唯一例外。按 `dev-deploy`（打开 PR） 的**大小与堆叠**，把 PR 基础设为另一个 PR 分支，而非主干。每项验证以实际父项为基线，堆叠根以主干为基线。父项变化时先检查依赖、冲突和拟落地结果；只有需要更新基线时，才按分支所有权、仓库策略和已有授权采用合并或变基。更新后结合补丁、基线、依赖与构建或运行证据判断裁决是否仍有效，不仅凭 `git patch-id` 相同就继续。

**回复：** 用每个 PR 及其裁决列表，替代已合并内容。
