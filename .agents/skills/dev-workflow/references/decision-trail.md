# 保留可审查的决策证据

长时间、多阶段、无人值守或需要事后审查的工作，保留一处主要记录。记录重要选择与证据，使接手者能核对发生了什么。短小明确任务可以直接在交付中说明，不强制生成日志。

## 信息格式

优先沿用项目已有 Markdown 记录；没有时可使用[决策记录模板](../assets/decision-trail.md)。每项决定至少能说明以下信息，不要求所有任务填满空栏目：

- **时间。** 实际观察或决定时间，跨环境时明确时区。
- **阶段。** 当前单元或工作流。
- **决定。** 选择或完成了什么，一行。
- **理由。** 用普通语言说明为什么；原则影响决定时解释具体影响，不只贴术语。
- **证据。** 可定位的代码修订、相对路径与符号、真实产物、轨迹或截图。指针应证明主张，不用段落冒充引用。
- **结果。** 实际通过、回滚、无结论、受阻或尚待验证的事实，不用状态标签代替解释。

以下只是格式示例，不是当前项目事实；其中数字、提交和路径必须由实际工作替换：

| 阶段 | 决定 | 理由 | 示例证据 | 结果 |
| --- | --- | --- | --- | --- |
| 界定 | 清点约100个组件、估计75小时 | 长时间工作前知道规模 | 调查记录及真实提交 | 有5个待解决问题 |
| 测量准备 | 改动前保存旧版截图 | 新旧对照捕获视觉变化 | 实际截图脚本与基线目录 | 保存120张基线截图 |
| 组件 | 迁移样式并保持外观 | 小改动、可比较结果 | 对应提交及像素差证据 | 外观相同且相关检查通过 |
| 组件 | 发现验证截图为空，撤销本轮结果 | 读取真实产物，避免相信自述 | 差异和实际恢复记录 | 已恢复，并修正观察方法 |

## 何时记录与如何追加

像向同事说明工作一样写，使用具体动作和普通语言。记录分岔选择、完成单元及验证、转向或回滚及原因、真实阻塞、修正检查。循环优化通常每轮一条；跳过微小、不言自明的动作。

同一执行可以跨多轮对话和摘要，不因每轮回复重复开日志。接手者或新会话回来时，先读末尾和当前差异，标明接续位置、之前证据范围和新的责任者。多人工作优先每位执行者拥有自己的记录，再在读取边界汇总；共享文件采用单写入者或项目已有并发机制。

若采用 TSV，按[表头模板](../assets/decision-log.tsv)保留 `ts/phase/decision/why/evidence/result` 六列。已有 Node.js 时，可运行本包[追加脚本](../scripts/append-decision-tsv.mjs)：

```bash
node <本技能实际路径>/scripts/append-decision-tsv.mjs <日志路径> <阶段> <决定> <理由> <证据> <结果>
```

每个参数按当前 shell 规则作为独立数据引用，不把不可信文本拼成命令。脚本补 UTC 时间、首行表头、清除单元格内制表符与换行，对以 `=`、`+`、`-`、`@` 开头的值加单引号，避免电子表格把它当公式。它只负责格式，不检查证据真实性，也不提供并发锁；同一日志串行写入。没有 Bash 就使用 Markdown，不要求为日志安装工具。

## 保存与历史

新增决策轨迹统一放在 `.agents/dev/changes/<日期-主题>/progress.md` 或该目录内的专门记录；已有记录按真实位置引用。私有原始产物、凭据和无关业务数据不写入仓库。只有后续审查确实需要且当前授权覆盖时，才随相关代码提交。

决策轨迹记录发生过程，更正错误时新增一条说明替代关系、真实事实与证据，不悄悄抹去重要转向。长期项目知识则按当前事实维护，不因日志追加原则变成只能堆历史的文档。明确删密等特殊修订按项目规则处理并记录修订事实。

## 对照真实过程复核

交付前读取本次可访问且已授权的会话、命令输出、差异和产物，核对属于本次工作的记录。没有会话导出时，用现有证据并说明覆盖局限；不假设宿主提供固定转录目录，不跨工作区搜私密聊天。

- 每条记录是否对应真实决定或动作。
- 证据能否定位，是否真的支持主张。
- 塑造结果的重要分岔、转向、放弃方案是否遗漏。

纠正记录，不改写故事。虚构或错误主张应新增明确更正和可解析指针。本次没有复核的他人历史不一概背书；亲自发现旧记录有误时记录更正，不假装已经审计全部历史。

## 独立复核

复杂或高影响工作有独立代理能力时，让未参与实施者读取轨迹与实际证据，检查薄弱主张、未证明验证、过早决定、范围膨胀、症状修补及用户可能漏看的风险。有可用且获准的不同模型系列时可采用；没有就使用独立上下文或自行复核，并如实说明独立性，不伪造审查者身份。

复核不重做全部工作，也不替代实际门禁。报告具体记录或证据位置；“没有发现”是有效结果。用户真正需要注意的事项放在交付中，不要求每轮机械追加固定标题、模型名或空清单。

## 阅读与复用

从上到下读，沿证据指针抽查。Markdown 可直接阅读；选择 TSV 时可用实际可用的表格工具，或支持的终端 `column` 命令。不要因为文件看起来齐全就推断证据有效。

同一任务其他方法引用这处记录，不复制相同事实到多个格式。性能试验日志需要专门指标列时，在同一记录中扩充，或明确职责分工并互相引用，避免两处结果漂移。
