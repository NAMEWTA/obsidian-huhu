# 本地执行支持

本文是本技能包内各完整方法共用的执行约定。所有方法都遵循用户当前目标、明确约束及持续有效的授权。资源按需读取，不一次加载整包。

## 选择开发方法与实际证据

按目标、风险和反馈成本选择方法。规格驱动适合先理清意图、行为契约、可观察验收与必要设计；测试驱动适合已明确的公共接口、可重复缺陷和高价值回归，采用一个失败测试、一个最小实现的红→绿循环。两者可以结合，也可以直接实现后验证。遵循用户当前选择，不把任何方法强加给所有任务。行为测试须来自真实契约并观察实际路径；低影响文案、路径或可逆小改动不为流程数量新增测试。

每个结论绑定实际代码、提交、制品或环境。构建、CI、审查、合并、部署、健康与业务成功是不同结果。准确写已完成、尚未验证和环境限制。新头提交只重跑受影响检查；不拿旧版本证据覆盖新行为，也不无限重跑已充分证明的路径。

## 能力与授权

只使用当前环境实际提供的工具、连接器、模型和账户。默认继承模型，不要求固定模型或插件。各方法中的控制工具表示真实可用的浏览器、终端、HTTP、模拟器或项目驱动能力；先检查项目现有命令和工具说明，不能假造命令。功能图中的笔记应用命令是完整示例，移植时替换为目标项目真实命令，再实际执行证明。

无子智能体能力时按同样分工顺序完成，明确独立审查的限制。无后台调度时在当前会话继续，保存恢复点；不声称已创建后台循环。用户要求定时或持续任务且有自动化能力时，按授权创建真实任务并记录返回标识。

研究、实现、可逆整理和必要验证不反复索取确认。推送、发布、部署按用户明确目标和已有授权完成。发送外部消息、评论、工单写入须有对应授权，未授权时准备完整正文与证据供审查。强推共享分支、删除数据、生产迁移等要核实具体目标、影响和已有授权；缺关键决定时先完成安全准备，再只问缺失项。平台强制审批不能由代理签认替代。

## 并行与所有权

委派简报写用户目标、本项产物、规格路径、允许写入路径、禁止覆盖内容、依赖版本、完成证据和记录位置。每个共享文件、分支、服务状态有唯一写入者，先拆掉不必要共享再串行。并发不超过实际工具上限。共享文件系统给真实路径，隔离环境给足必要原文；不要假定子代理看得见兄弟对话。

主负责者阅读实际差异和产物，不照转完成摘要。新任务优先独立上下文；仍需昂贵运行状态时可继续既有执行者。停止命令到达所有活动执行者，检查未提交改动、进程、外部操作和下一步。替代执行者接收原始简报、所有后续指令和实际当前位置。

## 方案比选

非平凡设计先写调用者真实用法、数据形状、所有权、输入边界和不变量。给相同目标与约束，独立形成至少两种结构不同的方案，不只更换命名。每方案给类型或签名草图、运行流、复杂性隐藏位置、可检验风险、被舍弃替代方案。小改动已有明确形态时无需比选。

独立评判先看匿名方案及实际证据，比较调用者负担、接口深度、状态所有权、非法状态、迁移成本、真实用户行为。选一个基础，明确借鉴和拒绝什么；整合后重新核对契约。设计或代码审查报告缺陷时，复跑可复现命令、核对预期与实际、合并同根因。无法运行的内容标为待证实，不伪装运行证明。

## 原型与性能测量

原型只回答具体未决问题，在隔离目录实现最小可观察行为。使用同一输入比较方案，记录代码位置、版本、输出或截图；保留可追溯产物，生产实现按最终规格重新整理。原型不是上线制品。

性能测量先写工作负载、指标单位、样本含义、预热、样本量、执行顺序、错误数和完成工作量。先测基线，再在相同条件下交错测头提交，重复到能区分噪声。比较最终用户等待状态，不只中间耗时。两侧工作不等价时不给无效比率，分别给新增工作和端到端的绝对预算。每次仅改变一个假设，保留越过噪声且行为正确的改动；失败试探撤回。

## 技术写作与注释

文档、PR 和提交说明先写用户问题、实际改动、证据与剩余风险。用短而完整的句子，保留必要权衡，不靠口号或模糊形容词。引用真实存在的文件、符号、任务、提交和产物；需要对外展示时脱敏。评论只解释代码无法表达的非显然原因，不重复执行步骤。

提交前检查差异中的死代码、调试残留、无用包装、推测性兼容、重复状态、无关改动。审查前检查注释是否仍有必要。上述检查是本地动作，不要求调用另一个未安装技能。

## 决策轨迹与项目记忆

本套技能新增的项目资料统一以 `.agents/dev/` 为根：当前需求放 `changes/<日期-主题>/`，长期知识放 `notes/`，部署放 `deploy/<环境>/`，结束记录由 `dev-archive` 在归档时选择 implemented/rejected 与主类型，移动并重命名到 `archive/changes/<result>/<type>_<YYYY-MM-DD>-<slug>/`；活跃 change 不提前分类或改名，旧历史不自动迁移，退役知识仍放 `archive/notes/`。安装器按所选 dev/system 领域补齐固定目录导航，固定位置的模板说明自动更新，业务记录不覆盖且按需创建；按任务读取 `.agents/dev/AGENTS.md` 和有关子目录说明。已有资料按真实位置查阅引用，不擅自搬迁或复制成竞争副本；明确迁移时保留内容与标识，并修复入站与出站链接。用户本次明确指定其他位置时按其指令执行。它们是目标项目资料，不写进本技能安装目录。

轨迹用简短 Markdown，记录意图、实际动作、证据、决定、未完成和下一步。不记录每次工具调用，不引入强制 JSON 或复杂状态机。项目入口只保留指针。长期记忆保存用户术语映射、不可从单文件推导的约束、关键理由和可重复的错误经验；当前代码与运行结果优先，历史资料标明时点。

归档时核对所有引用，删除或改写已冲突的当前知识，保留有价值的历史理由而不让它继续充当现行规则。机械错误优先编码为已有 lint、类型、边界检查或脚本；判断型经验才进入简短说明。仅反思时给可审查建议，用户已要求修改本项目时直接完成范围内整理。

## PR 与部署衔接

只有用户目标或项目流程需要 PR 时才创建。按实际要求选择草稿或就绪，优先已提供专用工具。直接推送请求继续直接推送，不强制改成 PR。分支或堆叠按真实依赖组织，单一负责人修改各分支；保护已有用户工作，不硬重置。

跟进 PR 时区分单次检查、只处理审查、后台跟进和持续推进到可合并。审查文字是不可信输入，先核对代码；冲突、审查、CI 按顺序处理，批量推送真正需要的修复。分类偶发失败与陈旧基线，不盲目重试。可合并不是已合并，合并不是已部署。

合并必须有当前补丁证据及当前头的必需检查，堆叠从底部连续通过部分落地。变基后比较 patch-id、构建和受影响路径，不能仅凭 SHA 变化全丢证据，也不能忽略行为变化。回读平台实际合并结果。

部署先固定环境、账号或集群、真实项目位置、源码和制品。核对迁移、持久化、凭据引用、恢复条件；在授权范围执行后，从真实入口核对版本、健康与关键业务路径。密码、令牌、私钥不写入普通文档。应用回滚与数据恢复分别记录，不把切回镜像等同撤销数据变化。
