# 按任务调用完整方法

总入口保留任务选择、执行纪律、恢复和协调；下表的方法本体由对应技能维护。读取其 `SKILL.md`，再按分支读取完整资源，不从标题猜路径，不复制正文到当前包。

## 调用与返回

1. 传递用户目标、当前阶段、已有规格/计划、代码版本、证据位置、授权边界以及本次所需产物。
2. 被调用技能只解决当前问题。已有访谈、基线、设计与测试不重做；需要进一步方法时可以继续调用其他技能。
3. 返回产物、实际验证、剩余问题与下一步。当前负责人整合后恢复原任务，不让子方法接管一个无关的全流程。
4. 同一问题已经处于某技能执行中时，不再次递归调用它；带着新增证据继续该次执行。技能协作可以成环，任务调用不能空转。
5. 无专用技能调用 API 时，读取已安装的入口并在当前执行上下文应用方法；有子代理时可以委派，但不得虚报独立性。依赖缺失时报告具体名称和安装缺口，继续不依赖它的工作，不用摘要冒充未读取的全文。

## 实施中的典型协作

`dev-build` 实施切片时发现故障，调用 `dev-debug`，携带当前失败和预期行为。诊断发现低成本回归入口时调用 `dev-tdd` 的六步缺陷回归，不转入新功能测试路线。修复后回到原场景，由 `dev-review` 检查规格与质量，`dev-verify` 核对真实入口，再回到原切片。用户目标包含发布时才调用 `dev-deploy`；收尾由 `dev-archive` 保留长期知识。所有阶段引用同一变更目录，不复制计划、重建基线或重复审批。
