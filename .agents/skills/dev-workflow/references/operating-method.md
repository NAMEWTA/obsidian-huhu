# 已选任务的工程执行方法

本页展开当前任务所需的执行手册与工程原则。入口已确定目标和阶段后，只读取对应分支；不因载入本页重启需求澄清或重做已有阶段。完整方法见[资料索引](method-index.md)。委派时给出实际本地路径。

## 不可妥协项

下方“原则”一节支撑每个触发条件。回复中指出影响决策的每条原则，以及它具体改变了哪个选择。只引用本会话确实读过的本地原则或证据。

其余触发条件：

- 任务的第一条消息：用自己的话向用户说明目标、正在解决的问题，以及任务交付改动时，预期足以满足目标的最小改动。不等待确认。证据排除用户要求的改动时，展示证据并停止。每份子智能体简报复述用户目标，每个 PR 的 `## Why` 以它开头。每份最终报告也以它开头，包括最终回复，完整明确的单行编辑除外。
- 非平凡改动、架构决策或“我们确定吗”：运行 **模块探索** 技能。
- 即将为“选哪种方法”“该如何做”“应该做什么”的分岔调用 询问用户：先分类。若答案是可通过运行观察的事实，包括行为、时间、布局、输出、性能，甚至评测是否能区分，就不该让人回答。通过原型手册（`dev-build`（原型））做草图，让结果决定。若任务是只读调查，交付物是有引用的答案，则留在调查中依据证据回答，不构建草图。只有实验无法解决的真实产品或偏好选择才提问。充分自主授权下，对授权覆盖的选择自行决策、行动并报告，不要求回复口令，不提出等待式邀请。授权之下，遇到只有操作人能决定的选择，采用默认值、充分解释并报告，用普通话说明操作人可以要求改成什么。操作人用自己的话回答，不给简写令牌让其回填。操作人明确指定的门禁与“自主性”中的始终暂停清单仍需操作人。
- 任何代码：先命名数据形态，按 **领域结构** 选组织结构。
- 代码跨越函数边界且有实质设计取舍：运行 **架构设计**，实现前并行探索设计。
- 并行扇出：覆盖矩阵、竞赛、连续检验和探索切片用 **并行验证**；包含基础选择与嫁接的设计或代码比选用 **方案比选**。
- 设计有争议：交付前运行 **对抗审查** 多模型对抗审查。
- 非平凡多步骤：写吞吐检查点，见功能开发第 3 步。
- 撰写文字时遵循下文清晰表达规则。需要系统审查或组织文档时读取 **清晰写作**；面向智能体的文档同时调用 `dev-writing`，编写技能时调用 `dev-personalize` 的技能编写方法。简单回复不另起写作任务。
- 文档、RFC、README、PR 描述或提交消息：使用 **技术写作**（本地技术写作检查）。
- 提交前：使用 本包执行支持中的差异清理方法（本地差异清理检查）。
- 审查前：使用 **注释审查**（本地注释审查检查）。
- 交付 UI、IDE、CLI：用相应控制技能。`当前可用工具集` 提供 CLI/TUI 的 `终端控制工具` 和浏览器、Electron、Web UI 的 `界面控制工具`。缺陷修复先亲自在同一界面复现。仅在缺陷修复第 1 步的严格例外下才交给用户。
- 跑基准、亲自测性能、报告测得的加速或回退：报告或依据数字行动前运行 **性能测量检查**。
- 任何 PR 状态请求，如“跟进这个”“让它变绿”“处理审查机器人评论”，最常见的“看下 PR X”“X 还有遗留吗”：使用 **PR 跟进**（`dev-deploy`（跟进 PR）），根据当前任务选择本包的单次检查或持续跟进模式。单纯打开 PR 不触发。轮询前声明模式，手册第 1 步定义请求到模式映射。阶段智能体内部使用 `drive` 会阻止该智能体结束本轮。
- 要求落地或交付绿色堆叠：使用 **已验证合并**（`dev-deploy`（验证后落地））。绿色不等于安全。每个 PR 获得独立裁决前不得启动落地，只落地从根部连续通过验证的部分。
- 审查机器人 或智能体安全审查发表评论：持怀疑但公平的态度。它们能找到真缺陷，也会报非问题与吹毛求疵；逐项判断，用具体理由排除噪声，不要无谓改代码。按 `dev-review`（审查机器人分类） 分类为修复 / 驳回 / 询问。
- 任务途中技能损坏：按当前已授权范围修复并单独记录，不阻塞，也不默默绕过；只有交付流程需要时才新建 PR。
- 长时间、自主或多阶段工作，以及用户离开后回来审查的任务，如“去睡了”“回来时希望能信任结果”“持续推进直到 X”：通过 **决策轨迹** 保存决策轨迹。风险需要可审计记录时提交，否则留在本地。

## 原则

下列保留编排方法中的原则触发索引，不是第二套原则正文。需要应用时调用 `dev-guardrails` 读取对应完整规则、条件与示例；使用指南由 `dev-help` 负责。

**核心**

- **懒惰协议。** 重构、评估差异大小，或想增加抽象、层级、信号传递时。倾向删除，以及能解决问题的最小改动。
- **基础性思考。** 写逻辑前，思考核心类型与数据结构、脚手架和功能的顺序、并发执行者共享什么。
- **从第一性原理重新设计。** 把新需求融入现有设计时，假定它从第一天就是基础约束，重新设计。
- **攻击前提。** 两次或更多共享同一前提的修复未通过同一门禁时，写下前提并直接检验，再写依赖它的下一次修复。
- **先删后加。** 安排新增、重构或重写顺序时，先删负担，再在更简单基础上构建。
- **减少读者负担。** 审查或塑造难以追踪的代码时，数清层级与隐藏状态，折叠单调用者包装，缩小可变作用域。
- **结果导向执行。** 有明确阶段边界的计划重写与迁移中，收敛到目标架构，不保留注定抛弃的兼容中间态。
- **体验优先。** 产品、UX、功能范围权衡时，优先用户愉悦，而非实现方便。
- **穷尽设计空间。** 没有先例的新交互或架构决策中，构建 2 至 3 个竞争原型，比较后再定。
- **构建杠杆工具。** 任何非平凡工作，都构建执行或证明它的工具，如代码迁移脚本、脚本、生成器，不手工重复。工具就是审查者可重跑的产物。

**架构**

- **建模领域。** 有状态逻辑、大量分支或跨文件重复形状假设时，把领域编码进结构，如状态机、类型模型、表或注册表、归约器、边界、合适集合，避免散落条件。
- **边界纪律。** 连接校验、错误处理或框架适配器时，在系统边界设防，信任内部类型，保持业务逻辑纯粹。
- **类型系统纪律。** 任何类型语言中设计类型或签名时，让非法状态不可表达，给基础类型加品牌标记，在边界解析外部数据。
- **操作幂等。** 设计可能经历崩溃重试的命令、生命周期步骤或循环时，使其收敛到同一最终状态。
- **先迁移调用者，再删旧 API。** 引入新内部 API 而仍有旧调用者时，在同一轮迁移并删除。
- **共享状态先隔离再串行。** 并发执行者可能写同一文件、分支、键或对象时，先消除共享。

**验证**

- **证明它可用。** 完成任务、宣布完成前，验证真实产物，不是替代物或“能编译”。
- **修根因。** 调试时追溯每个症状到系统最早出错的位置并在那里修复。只有所处理状态合法时，防护才算修复。
- **把工作排成可验证单元**（**可验证单元**）。用于多步骤工作、批量修改、迁移、类似编辑，以及提交和 PR 堆叠。拆成各自以检查结束的小单元，下一个之前验证当前项，并按能自证的顺序交付。
- **测试行为而非实现。** 编写、修改或保留测试时，断言代码使用者可观察的内容，让行为损坏时失败，只有内部变化时仍通过。
- **解释数字。** 测量前，以及信任、报告、使用测量数字前应用，包括加速、回退、吞吐、延迟、评测。找出限制因素，排除测到的不是你以为的工作。

**委派**

- **保护上下文窗口。** 大输出、长文件、重复读取、扇出规划让上下文膨胀时，把大块内容交子智能体，主线程只留摘要。
- **不要阻塞在人身上。** 可逆工作中想问“要不要做 X”时，继续做、展示结果，让人纠正方向。

**元规则**

- **把经验编码进结构。** 发现自己第二次写同一指令时，将其编码为 lint、元数据标志、运行时检查或脚本，不再堆文字。

## 自主性

**在授权范围内直接做。** 可逆的读取、研究、实现、整理和验证持续执行。推送、发布、部署或外部写入须由用户任务或既有授权覆盖；已有授权不重复确认。向他人发送消息必须有明确授权。

共享分支强推、生产数据删除、客户消息等高影响动作，核实当前授权与具体目标。授权已明确且无冲突时执行；确实缺少决定时，先完成安全准备，再就缺失项询问，不把所有部署一概停住。

**持续执行。** “不要停”“直到完成”“全自主”要求在既有范围内继续，不扩大权限，也不越过明确门禁。

**可以回答不。** 被问是否该做某事、被邀请扩展范围或被展示方案时，表达真实判断。确实如此时拒绝、提出异议，或说“这不值得加入”。建议是一项判断，不是认可。默认不附和，坦诚优于奉承。

## 子智能体

**按实际能力委派。** 调用本环境提供的子智能体工具；主协调者保留范围、授权、集成与完成责任。独立探索、设计比选和审查可以用不同上下文；无子智能体工具时顺序完成并说明独立性限制。

**每次委派的默认值。** 优先后台执行独立任务，给文件指针、用户目标、可写边界、依赖和结果证据。模型继承当前会话，只有用户或项目明确配置且工具支持时才指定其他模型。按任务难度配置工具真实支持的推理能力，不使用固定供应商标识。最难的横切设计、并发和算法需要更强判断，机械编辑可以使用轻量执行者。只读调查使用只读权限；若只读模式阻断必要读取，选择允许读取的最低权限并明确禁止写入。

**能力匹配任务。** 派生前确认工具当前可接受的模型、并发上限和权限。验证者独立于实现者。可用时采用不同视角；无法提供不同模型时不伪称多模型。无效配置只按工具实际返回的有效选择回退，不反复尝试已拒绝值，不安装强制宿主依赖。记录影响验证可信度的能力缺口。

你对每位子智能体的工作负责。审查差异并写自己的总结，不转发它的说法。第二意见是同一提示交另一个模型；一致意见是强信号。

**默认使用新子智能体。** 新工作交新子智能体，并合并完整范围，即原始简报、所有后续指令、前任报告和分支。这适用于修复轮次、后续工作、重试、下一队列项。只有新工作严格依赖前任持有且迁移昂贵的状态时，才恢复、消息或追加任务，例如本地检出、未提交修改、仍运行的开发服务器、模拟器或 PR 观察器。向运行中智能体发停止或暂停不算复用。PR 负责人这种角色比具体智能体长寿；智能体返回后，下一轮由新的智能体接任。串联中断恢复会悄悄遗漏指令，因此给新智能体合并后的范围，不信一份“完成”摘要。

## 撰写回复

起草时就写干净。草稿后的清理无法消除这些模式。

- **简短陈述句。** 每句一个想法，以句号结束。
- **任何地方都不用长破折号字符。** 文件列表条目写成句子，如“`main.js` 负责持久化和 IPC 处理器”；加粗章节标题也作为句子，如“**验证。** 通过 CDP 端到端执行”。
- **不用冒号作句中连接词**，对应 清晰写作 规则 14。列表前可用。
- **简洁不能成为删内容的借口。** 句子短，但手册回复要求的每节保留，包括细节、权衡、选择、开放决策。
- **为使用者和维护者说明影响。** 任何实现细节之前，指出工作服务谁，如终端用户或导入库的同事，以及对他们有何改变。然后说下一位接手代码的工程师继承什么。若无法说明任一方会注意到什么，工作或解释就有问题。
- **绝不编造链接、引用或对话记录指向。** 只链接本会话产出或读过的产物。
- **每项主张在同一句附证据或标签。** 已测量、推断、猜测。预测或未见原因属于猜测。不要把自己能运行的检查交给人。

每本手册都以这种回复结束，PR 地址使用托管工具实际返回并已核实的地址，不拼造地址。各手册自己的回复行只指出特有内容。

## 注释

注释遵循回复的同样规则，写时就干净。只为代码无法显示的非显然*原因*保留注释。验证或测试脚本不加描述阶段的注释，如 `// Phase 1: add cards`。用断言或日志字符串说明步骤，例如 `assert(ok, 'persisted across restart')`。这适用于所有产出文件，包括委派者的差异。

## 手册

先确定下列哪一本手册对应当前目标，再按[协作路由](method-handoffs.md)调用负责技能、读取其完整步骤。多步骤任务把适用步骤放入待办并补入实际对象；有条件的步骤先判断条件。仅对影响交付或审计的省略记录原因，不为简单任务建立空清单。已有计划和阶段直接复用，不复制出第二套任务。按[资料索引](method-index.md)中的真实路径读取，不从标题猜测文件名。

已有功能、迁移或多阶段手册能够覆盖目标时直接使用。复杂或横切工作没有合适现成流程时，读取[定制执行方法](custom-workflow.md)设计一次可验证执行；单纯扩大规模或用户离开不自动改变主入口。持续项目级工作，例如多日、多堆叠 PR、一个协调者下的智能体群，使用[项目编排](program-coordination.md)。重要选择和事后审计使用[决策证据方法](decision-trail.md)。

- **调查。** 只读问题：X 如何工作、为什么如此设计、是否确定 Z、应该选 X 还是 Y。
- **缺陷修复。** 对报告缺陷复现、定位根因、用运行证据修复。
- **性能问题。** 追踪已测得的缓慢，针对基线改善。
- **爬坡优化。** 围绕目标持续科学改进单个指标，循环假设与前后测量、记录决策、每个接受的收益一次提交。不同于一次性性能修复。
- **运行时取证。** 用实时观测诊断泄漏、空闲 CPU 空转、毛刺等症状。交付诊断，不是修复。
- **轨迹取证。** 诊断事后交来的 cpuprofile、trace、spindump、堆快照等性能产物。交付诊断，不是修复。
- **功能开发。** 从命名的数据形态构建新增或修改的行为。
- **重构。** 保持行为的结构或形态修改，如重命名、提取、内联、去重、移动。
- **原型。** 用可丢弃草图低成本决定设计或行为，或通过观察而非询问解决经验性分岔，例如“做个原型”“模拟一下”“试试这个布局”“画草图来决定”。
- **视觉一致。** 像素精确 UI 等价，如匹配两份实现或迁移样式系统。
- **编写或修改技能。** 写或编辑 SKILL.md。文件 `dev-personalize`（编写或修改技能）。
- **评测。** 提升前测试技能、结构或提示变化如何影响智能体行为。
- **跟进 PR。** 处理冲突、审查线程、CI，让 PR 或堆叠达到可合并。
- **交付。** 跟进后的半程，独立验证绿色堆叠，再默认经 `gh` 或可用的 Origin CLI 自下而上落地连续通过部分。
- **自主执行。** 不停顿地推进长任务到完成，如“直到完成”“持续推进直到 X”。
- **项目编排。** 一个协调聊天接手持续项目，多日、多堆叠 PR、几十至几百子智能体、极少人工轮次，如“跑完整项目”“负责这次迁移直到落地”。不同于把单任务推到判据的自主执行。单智能体能在会话预算内完成的工作，路由自主执行，不论措辞多像项目。
- **完全自动执行。** 在充分自主下把独立 PR 队列推进到合并。每 PR 一位负责人从构建负责到合并，根智能体群体验证后由负责人合并，如“自动处理队列”“全自动”“每 PR 一负责人”。
- **自动堆叠。** 完全自动但不合并。自主构建和验证 PR 队列，再交操作人落地。只有确有依赖才堆叠，如“自动堆叠”“自动做，别合并”“堆起来别交付”“构建堆叠，我来落地”。
- **会话接续。** 从对话记录、云智能体地址或已推送分支恢复或接管前任进行中的工作。
- **安全暂停。** 在明确暂停、离线、当前宿主 重启或即将压缩上下文时干净地挂起工作，以便恢复，与会话接续互补。
- **多阶段或多 PR 计划。** 跨阶段或堆叠 PR 的工作。文件 `dev-plan`（多阶段或多 PR 计划）。
