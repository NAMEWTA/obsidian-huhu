### 项目编排

**你运营项目，不写代码。决定哪个智能体做哪块，再检查各自产物。** 适用于交给单个协调聊天的持续项目，多日、多堆叠 PR、几十至几百子智能体、极少人工轮次。把单任务推到判据属于自主执行；需要定制流程的一次宏大执行属于 复杂任务规划。单智能体能在会话预算内完成的工作不是持续项目。

使用当前真实可用的子智能体工具派工。将本次新增的状态记录统一保存到 `.agents/dev/changes/<日期-主题>/progress.md`。优先用 PR/CI 事件通知观察；没有订阅时做有界状态查询，不忙轮询。必要脚本先读内容并在授权内运行。通过共享记录和任务说明提供依赖，不无意义地来回转述状态。无委派能力或一个执行者足够时，改用本包自主执行方法，不假装存在编排层。

#### 拓扑

- **每个 PR 一位负责人。** 负责人是分支唯一写入者，从构建负责到合并。只有负责人推送、变基或改目标。关闭或改基础 PR 目标会让上方全部 PR 失去基础，因此只能按你的决定做。你不编写或编辑代码，冲突合并、链式变基、修复交负责人。
- **每个独立任务使用新执行者。** 启动说明带齐所需内容，包括依赖报告的真实文件指针；无法共享文件系统时再提供必要原文。不假设执行者能读取兄弟上下文。默认独立工作区或当前工具实际提供的隔离环境，除非工作需要本机，如 `当前可用工具集` 的 `界面控制工具` 或 `终端控制工具` 运行检查、本地对话、模拟器、只存在本机的认证。按本包执行支持与当前工具能力选择实际可用的模型、推理能力和速度。
- **只有某领域有许多并行执行者时才设子协调者。** 它负责该领域执行者和启动说明，只向你交一份汇总，不交原始报告。最多三层：你、子协调者、执行者。每个协调者的并发数不超过实际工具上限，按任务复杂度控制，每完成一个就启动下一个，不等整批。
- **新工作需要执行者已建立状态时分叉，** 例如检出、未提交修改、运行进程。按当前工具的真实语义查询状态，避免使用会意外重启任务的调用；同一工作的后续指令通过对应消息或跟进能力传递。
- **每个 PR 有独立于作者的验证者，** 可用时采用不同模型系列，否则至少采用独立上下文并如实说明。负责人只有在当前头提交得到验证通过后才合并。
- **从一个单元开始。** 先完整走过启动、负责人、验证者、合并，再扇出，让启动说明缺陷只浪费一位而非五十位智能体。几乎相同且便宜的单元，第一项就是这个试验。

#### 监督

- **每份启动说明指出完成证据，** 如命令和预期输出、控制技能检查、产物。也写目标、可写与不可写路径、禁止行动。不能命名证据，说明单元尚未划清。
- **阅读差异或产物，不只读摘要。** 绿色 CI 是裁决输入，不是裁决。行为工作需要类型检查之外的证明。裁决覆盖一个头 SHA，新推送就需要新裁决。子协调者的执行者运行时，抽查其启动说明，发现失败就修指令。
- **范围漂移或超出要求的工作退回。** 只保留阻塞项目的修复，其他放后续事项。
- **报告 PR 前查看实时状态，** 用 `gh pr view`、`gh pr checks` 或托管工具等价功能，不用执行者最后报告。每个派出的执行者都要交代为完成、替换或被其他执行者范围吸收。
- **停止或替换停滞、循环的执行者。** 根据推送和 PR 活动判断，不看状态文字。按原因重试：上下文或内存限制后缩范围，连接断开后用同简报，工具错误后换模型。两次重试后放弃该单元，围绕它重规划。被停止执行者晚返回时，对照 PR 当前状态检查结果，把独特发现交给新执行者。
- **只为真实决策或阻塞询问用户，** 如不可逆行动、实验无法解决的产品或偏好选择、重新规划仍无法解决的死路。变基细节、重试、CI 偶发失败、审查分类和“是否继续”不交给用户。

**回复：** 对照目标落地了什么，每个 PR 的实时状态、裁决及链接，放弃了什么及原因，等待用户的决策。
