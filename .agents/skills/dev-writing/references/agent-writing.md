# 面向 Agent 的文档写作

这是一份编写智能体所读文档的参考：技能、`AGENTS.md`／`CLAUDE.md`，以及经由指针访问的文档。包装不同，写法相同：相同的调节方法让各类文档具有可预测性，因为智能体每次执行的是同一种**过程**，并不要求每次产出相同结果。

如果正在编写技能，阅读 [`SKILL-MECHANICS.md`](skill-format.md)，了解 frontmatter、调用方式选择和路由技能。

## 上下文指针

**上下文指针**是保留在智能体上下文中的引用，指出某项尚未加载的材料，并编码访问它的条件。技能描述是一种；`AGENTS.md` 中指向某份文档的一行也是同一种对象。决定智能体何时访问材料、访问是否可靠的是指针的**措辞**，不是目标本身。如果必要材料藏在措辞薄弱的指针后面，这就是行为波动缺陷：先把措辞写准确；只有加强措辞无效时，才把材料内联。

指针有两个任务：说明材料是什么，并列出应该触发访问的**分支**。分支是文档处理的不同情况，因此不同执行会走不同路径。常驻指针的每个字在每轮都会产生成本，因此它比正文更需要修剪：

- **把引导词前置**：指针正是引导词发挥触发作用的位置。
- **每个分支一个触发条件。** 只是为同一个分支换名的近义词，相当于把同一分支写两遍；合并它们，只保留真正不同的分支。
- **去掉正文已经承载的身份说明。**

## 两类负担

每增加一份文档或一个指针，都会消耗两种预算之一：

- **上下文负担**是常驻材料占据智能体窗口的成本：`AGENTS.md` 的一行、技能描述，以及任何每轮都在上下文里的内容，无论是否触发都消耗 token 和注意力。
- **认知负担**是人的成本：有哪些文档，何时使用哪一个。人充当索引。这个成本并非一味越少越好：它是人保有判断和行动能力的代价；需要人的判断时就承担，不需要时就移除。

只通过指针访问的材料，用指针自身一行的成本避开正文的上下文负担；完全没有指针的材料则全部依靠人的认知负担。

## 信息层级

文档由两种内容构成：**步骤**，即智能体依次执行的动作；以及**参考**，即按需查阅的定义、规则和事实。两者可以自由组合：全是步骤的操作配方、全是参考的审查规则或本文档，以及两者混合。核心决定是每项内容放在**信息层级**的哪里；这架梯子按智能体需要材料的即时程度排序：

1. **文件内步骤**是首要层级：智能体按顺序做什么。
2. **文件内参考**按需查阅。它经常合理地表现为一组平级项目，例如审查的每条规则处在同一层；这种安排很好，并非异味。
3. **展开式参考**被移到单独文件，由上下文指针访问，只在触发指针时加载。范围可以是同目录的相邻文件，也可以是技能内按主题组织的完整本地参考。方法正文归属一个技能，其他技能按需调用它，不递归复制资源。

下移太少，顶层会膨胀；下移太多，就会藏起智能体实际需要的材料。整个决策正是对这股张力的处理。

**渐进式披露**就是把内容沿梯子向下移出主文件、放到指针后面，让顶层保持清楚。它首先不是 token 优化，而是保护层级的方法。分支是最清晰的披露检验：每个分支都需要的内容内联；只有部分分支需要的内容放到指针后。如果文档包含步骤，本该展开披露却留在文件里的参考会把步骤埋起来，使能否注意到步骤像抛硬币一样：这是控制行为波动的方法，不仅是可读性问题。

**就近组织**是文件内的对应方法：层级决定内容放得多深，就近组织决定到达那里以后哪些内容放在一起。把一个概念的定义、规则和注意事项放在同一标题下，避免散落各处，这样读其中一部分时也会读到相邻内容。检验方法是：这份文档读起来应当像专门为智能体写的文档。聚合的材料符合这一点，散落的材料不符合。这与重复不同：重复是在两处重述同一含义；散落是把一个含义拆碎到多处。

这里的失败模式是**蔓延**：即使每行都有效且独特，文档仍可能单纯太长。过量内容分散注意力，每多一行就多一处需要保持有效。解法是层级：把参考放在指针后，并按分支或顺序拆分，让每条路径只携带自己需要的内容。

## 步骤与完成条件

每一步都以一个**完成条件**结束，即告诉智能体工作已经完成的条件。两个性质使它成为有效的调节方法：

- **清晰度**：智能体能否判断完成与未完成？模糊的边界，例如“已经理解”，容易造成**提前完成**：任务尚未真正完成就结束步骤，注意力滑向“已经做完”。仍然可见的后续步骤，即**完成后步骤**，产生拉力；完成条件的清晰度提供抵抗。依次防守：**先把边界写准确**，这是局部且便宜的处理；只有边界确实无法消除模糊，而且观察到抢跑时，才通过拆分顺序隐藏后续步骤。隐藏必须跨越真正的上下文边界才有效，例如交接或派发子智能体；内联调用仍把后续步骤留在上下文中，没有清除任何东西。
- **要求强度**：条件要求做到多少。“说明每个修改过的模型”会推动完整工作，“产出变更列表”则不会。要求强度驱动**调查功夫**，即智能体在工作中做的深入探查；它隐含在措辞里，而非单独写成一步。要求也不局限于步骤：“应用每条规则”约束平级参考整体，正如“完成每一步”约束一个序列，因此全参考文档也能具有穷尽性的门槛。

最强的完成条件既可检查，又覆盖完整。

## 何时拆分

把一个文档拆为两个会增加两类负担之一，因此只有拆分值得时才拆：

- **按顺序拆分**：当后续步骤诱使智能体急着完成眼前步骤时，把这段步骤拆开。让后续内容暂时不可见，能驱动对当前任务更多的调查功夫。也要警惕反向情况：合并多个序列会让每一步的后续步骤暴露在当前上下文中，诱发提前完成。
- **按调用方式拆分**，仅适用于技能：参见 [`SKILL-MECHANICS.md`](skill-format.md)。

## 引导词

**引导词**是模型预训练中已经存在的紧凑概念，智能体执行文档时会用它思考，例如“经验”“战争迷雾”“曳光弹”。把它作为一个词反复使用，绝不反复使用整个句子，它就能累积出分布式定义，并借用模型已有先验，用最少 token 锚定一整片行为。自创词也可行，前提是定义清楚，但新造词无法调动已有先验：预训练词免费提供的内容，自创词必须用定义 token 支付；先找现成词。

它有两重锚定。在正文中锚定**执行**：每次出现该词，智能体都调动相同行为；在平级参考中，它把注意力聚焦在某类应寻找的东西上。在指针中锚定**调用**：当提示词、文档和代码库使用同一个词，智能体就会把共享语言与材料连接起来，更可靠地访问它。

寻找用引导词重构的机会：在三个地方写出的三项描述，或者花一整句才指向一个概念的指针，都是应压缩为一个词的段落：

- “快速、确定、低开销”→ **紧凑**，例如紧凑反馈循环。
- “一个你相信的循环”→ **红**，把模糊门槛转成二元、可观察的状态：循环在缺陷上变红，或者没有变红。这是把判断改写为可核验指令的例子，不规定所有开发任务的顺序。

这样有双重收益：token 更少，智能体思考时可抓住的钩子更清晰。默认每份文档都含有能被引导词淘汰的重复表述，去把它们找出来。

这个方法旁边的失败模式是**否定**：用禁止来引导会把禁止的行为拉进上下文，让它更容易被激活。不要想大象，大象却成了脑中唯一东西；否定只是弱修饰，而被强烈激活的概念会压过它，禁令于是有一半像是在要求做这件事。用**正向**提示：写目标行为，例如“写一行注释”，这样被禁止的行为根本不被说出。只有无法用正向表达的硬性护栏才值得使用禁止；即使如此，也应配上正向目标，让注意力落在该做什么上。

## 修剪

- 让每种含义只有一个**事实来源**：一个权威位置，改变行为只需修改一处。**重复**——相同含义存在多处——增加维护和 token 成本，并使某个含义在层级上获得超过真实等级的突出程度。这是引导词的意外反面；引导词有意重复的是词，而不是完整含义。
- **环境**也是事实来源，例如 `package.json` 中的脚本、配置文件、目录结构、`--help` 输出。重述它们的文档是**缓存**，是查询结果的副本，只有查询成本很高时才值得承担负担。缓存智能体无法直接看到的内容：未写明的惯例、选择背后的原因、配置不会坦白的陷阱。一份文件或一条命令就能查到的信息留给环境，那里不会过期。
- 检查每一行的**相关性**：它是否仍关系到文档的用途？一行失去相关性，可能因为从未与任务有关，例如纯说明或应按需展开的分支；也可能因为所描述的行为或世界发生变化而过时。短文档更容易保持有效。没有修剪纪律，默认结局就是**沉积**：添加看起来安全，删除看起来有风险，过时层不断沉积，直到不得不钻探才能找到仍然有效的内容。
- 逐句寻找**无效指令**：模型默认已经遵守的指令，只是在增加负担却没有信息。检验标准是它是否改变默认行为；这取决于模型，而不是读者。两个人对一句话是否无效有分歧，实际是在争论默认行为，应通过运行文档解决，而非辩论。如果一句话不通过检验，删除整句，而不是只压缩用词。这个检验也适用于引导词：弱到不足以超越默认行为的词，比如对已经相当细致的智能体说“细致一些”，仍是无效指令；解法是更强的词，例如“穷追不舍”，而不是换一种技术。
