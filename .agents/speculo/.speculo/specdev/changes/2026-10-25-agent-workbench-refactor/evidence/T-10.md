状态：done。T10 的代码、适用自动化、构建产物和独立双轴审查已完成；真实 Obsidian、Provider、OS IME、Windows/macOS/Linux 五种平台的实机验收仍由用户按既定分工执行。本票不包含提交、推送、发布或后继 T11–T18 的完成声明。

## 1. 实现摘要

T10 在现有 SpaceService 的单 writer、tail、lease 与 JsonStore 之上加入版本化 Inbox 子文档，以及 `send/read/list/ack` 业务 facade。消息拥有显式 `spaceId/sessionId`、稳定 `messageId`、来源、有限正文和当前 Vault metadata 引用；写入成功后才回执，读取不确认，重复 ack 返回已确认事实且不产生额外写入。停止 Session 可继续收信，归档或失效目标拒绝新写入；冷 primary 查询不会为了恢复而写盘。

控制协议、TypeScript/Rust 生成物、原生 CLI、handler、commands、paging 与 router 已接到同一 `InboxService`/`SpaceService` owner。四项 capability 在真实 owner、handler、CLI 和生产消费者闭合后宣布可用；业务 `messageId` 与 wire `requestId` 分离，session-only 请求从持久 Session 的原 Space 解析，不读取 cwd、当前 UI 或 caller hint。旧自动化和快捷入口必须先要求用户选择 Space，不能按 cwd 或当前界面自动补归属。

生产工作台增加被动 Inbox 工具、未读标记、跨 Space/Session 目标选择、summary-only 列表和显式 Read detail。到达消息只更新未读计数，不打开工具、不切 Space、不抢焦点、不 attach、不开 PTY、不粘贴、不启动模型。send、read、ack、失败核对和 pending/unknown observation 相互独立；settled observation 只能由用户显式收起，unknown/conflict/not-found 继续保留。

分页第一页冻结 recipient、high-water 和 generation；后续页必须携带相同 fence。fence 外追加不改变旧页，fence 内替换、删除或重排返回 `STALE_RUNTIME:inbox-page-stale`。Fence 只保存固定 16 字符摘要和元数据；两个 cursor 索引均最多 16 条、TTL 10 秒，每次 list 清理，dispose 清空，避免保存正文/引用快照或形成永久 lineage。
