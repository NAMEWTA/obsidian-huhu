# 084 T-11 native: provenance admission, non-available rows, OpenCode snapshot reads

## Behavior delivered
- S-075-1 provenance: every row needs a persisted `source_status` in {available, missing, changed, unsupported, permission-denied} AND a non-empty `sources` list whose first entry is the transcript, confined to a vault account (or the named system provider dir). Legacy rows (empty status / empty sources / non-managed transcript) are excluded from query and refused by read ("session outside vault") in vault AND account scope. `history_sources` no longer returns an empty list for "plain vault" files; scan now requires `account_path` for non-system roots in every scope (non-managed vault roots produce a warning, not rows). Stamp prefix is now `sources-v2` (adds inode), so all old rows are rescanned.
- S-075-2 statuses: scan reconciles previously indexed rows per root (matched by agentId + accountKey + sourceRoot): a row not refreshed in the pass gets `missing` (file/root gone), `permission-denied`, `unsupported` (unparseable / metadata budget / OpenCode over cap or not a DB), or `changed` (size/mtime/inode drift, concurrent OpenCode change). Rows are never deleted (annotations are keyed outside the index); status + `sourceReason` are written with json_set and the revision is bumped. A non-available row stays listed (lexical confinement check only) and `read` returns it with `text:""` and the status. `read` of an available row also re-checks the stored fingerprint and returns `changed` (or the precise failure) instead of reparsed/stale text. A same-fingerprint `unsupported` row is not retried every scan; other non-available rows are retried. Other sources continue after a failure.
- OpenCode snapshot (F1/F2/F3): db and `-wal` are copied with `O_NOFOLLOW` read-only std::fs into `std::env::temp_dir()/huhu-opencode-<pid>-<ns>-<seq>` (0700 dir, 0600 files on unix, `Drop` guard removes it on all paths); stat before/after the copy, one retry, then `changed`; SQLite opens only the copy (READ_ONLY), the connection is closed explicitly (close error is reported) before the dir is removed. Source dir is never written (no -shm/-journal). Cap: 512 MiB for db+wal, over cap = `unsupported` with reason. Same admission as baseline: `parent_id IS NULL` only, cwd inside vault unless account scope. Scan stores metadata + usage only (text lazy); `read` re-snapshots and loads the body for that session. `-shm/-journal` are not persisted in `sources` (never read) but their existence is part of the fingerprint.

## Follow-up (Lead: `changed` must not fire on ordinary appends)
Superseding the earlier "read returns `changed` on any drift" statement and gap:
- `read` of an available row on stamp drift now re-verifies identity instead of returning `changed`. Gate (`drift_verifies`, from the stored `sources-v2` stamp): same inode (skipped when either side is 0, i.e. Windows) and not shrunk (len >= indexed len; OpenCode exempt since a db may shrink). Then the normal parser re-runs provider/session-id/cwd admission and the resulting key must equal the row's key. Verified => fresh body from the current file (stored text is ignored when drifted); mtime-only drift verifies too. Failure of any step (inode change, shrink, other session id, cwd out of scope, source gone) => `changed` with reason "source identity can no longer be verified", no text.
- OpenCode: drift => fresh snapshot, session id still present => fresh body; id gone => `changed`.
- Windows/no-inode fallback: size-shrink + session-id identity (unit-asserted via `drift_verifies` with inode 0).
- Stored stamp is NOT refreshed in the read path (index opened read-only there); the next scan updates it. Scan-time reconcile is unchanged (a persisted `changed` only comes from failed/unverifiable sources).
- Tests: `appended_or_touched_sources_stay_readable_and_replaced_ones_are_changed` (append => fresh text with new content, mtime touch => available, truncated => changed, other session id => changed, same-size atomic replace/new inode => changed on unix, inode-0 gate) and `opencode_drift_returns_fresh_body_while_the_session_exists`. These replace the earlier `a_source_that_drifts_after_indexing_is_changed_not_stale_text`.
- `cargo test --locked` (full native suite) exit 0: 83 bin tests (34 agent_data) + all integration suites ok. `generate-control-protocol.mjs --check` still matches (wire_generated.rs restored after `cargo fmt` again).
- Remaining: a pre-scan source file deletion of an `available` row still errors "session outside vault" (unchanged).
