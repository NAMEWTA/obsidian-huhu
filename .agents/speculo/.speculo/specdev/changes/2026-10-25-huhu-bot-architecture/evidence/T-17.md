# Profile API/HAP integration addendum 2026-10-27

The public application facade now exposes `ProfileAPI` only when the concrete SQLite purge store/service is assembled by `bootstrap.OpenWithOptions`. HAP maps the generated `profile.deletePreview` and `profile.delete` DTOs to the entrance-neutral API, applies the command epoch/revision fence and explicit memory retention IDs, and validates encoded results against the existing wire schema. Routers without the injected profile service do not advertise or dispatch these methods. No credentials or provider state cross the purge boundary.
