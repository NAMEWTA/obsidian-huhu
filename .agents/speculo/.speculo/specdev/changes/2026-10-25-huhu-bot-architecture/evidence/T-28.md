# T-28 code-level evidence

本票新增一次性产品验收入口和安全的代码检查入口：

- `scripts/obsidian-acceptance/huhu-bot.mjs --check` 只检查 Bot module、八个页面 factory 和 Go portable entrance 的接缝，不启动 Obsidian、Runner 或 Provider。
- 传入绝对的新根目录时，脚本复用 `fresh-vault.mjs` 创建一次性 Vault/Profile/evidence，写入固定 Bot/资料夹具，检查 workbench 与 `huhubot` module 激活，并在结束时关闭自有 Obsidian 子进程。
- `scripts/obsidian-acceptance/fixtures/huhu-bot/seed.json` 保存固定夹具；`test/huhu-bot-integration/architecture.test.ts` 验证 `--check` 无副作用。
- `docs/huhu-bot-acceptance.md` 说明 `HUHU_OBSIDIAN_EXECUTABLE`、`HUHU_BOT_BINARY`、`HUHU_PLUGIN_SOURCE` 和用户自行配置 Provider 的边界。

```text
node scripts/obsidian-acceptance/huhu-bot.mjs --check  # exit 0
pnpm exec vitest run test/huhu-bot-integration/architecture.test.ts --reporter=dot  # 1 file / 1 test passed
```

真实三协议、Obsidian 页面/键盘、Vault、目标 OS、endpoint/modelId/凭证和跨进程故障场景未在本窗口运行，按用户约定由用户后验；本证据不把代码检查冒充现场通过。
