## 目标与来源

升级前能生成 DB＋Blob 一致备份，迁移失败可恢复；旧 binary/坏库被明确拒绝而不重建空库。

代码基线为 `66083cdb9f7f31a4bcbd3e380c6c7f64f2e74e93`；Bot 的 Go/module/contracts 路径均待本 change 创建，不把新测试命令说成当前已有。真实生产消费者是 BotClient、对应应用 API 及模块 UI/宿主能力，具体调用链按下列步骤落地。

**开源参考：** [REF-07 mattn/go-sqlite3](https://github.com/mattn/go-sqlite3/commit/dbbe931904f2ee06546448fbe7cf7780f61bc110)；[REF-08 ncruces/go-sqlite3](https://github.com/ncruces/go-sqlite3/commit/da0ceb8b723e44c2dfde7b287286a2be4ded0016)。具体文件、许可、依赖与已知限制见 <Path>{roots.state}/specdev/changes/2026-10-25-huhu-bot-architecture/IMPLEMENTATION-REFERENCES.md</Path> 对应 REF。遇到本票未覆盖的陌生点，实施前先按该文件的检索流程补比较，在本票 Evidence 记录采用/拒绝理由，再写代码；不从未经核验的示例直接复制。

## 行为与范围

IN：schema/binary 兼容检查、停受理/锁/一致备份/迁移/校验、备份删除传播。REUSE：选定 SQLite driver 的备份 API。OUT：直接复制运行中主 DB、跨设备运行同步。

### 有序实施步骤

1. 定义版本兼容与迁移顺序；仅当前真实 schema 的演进有迁移，不造旧品牌迁移。
2. 先停止准入并处理在途→持有实际库锁→一致备份及 Blob 清单/hash→迁移→完整性校验。
3. 失败区分程序回退和数据恢复；保存原始副本/诊断，坏库不覆盖；旧 binary 只报不兼容。
4. 验证自管备份参与 T-17 清除：备份不能重新注入已撤销/删除的数据或旧命令代数。
