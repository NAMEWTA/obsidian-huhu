# 统一实体与迁移短设计（待共识）

这是当前 Grill 的具体推荐输入，供确认；外部行为最终由 spec.md 负责，架构决定确认后进入 ADR.md。以下不是当前已实现的格式，也不产生源码修改授权。

## 一份数据、三种附属信息

Annotation 统一表示文字选区高亮和旧行级批注。字段语义如下，字段的代码名称允许实现者在不改变合同的前提下调整。

| 字段 | 合同 |
|---|---|
| id / kind / source path | 原 ID 稳定；kind 为 range 或 line；路径在 per-file 文档拥有，索引导航 |
| anchor | 复用 text/hash/before/after/offsets/lineHint；不确定位置不能仅按距离猜一个 |
| anchorState | attached / orphaned；独立于讨论与归档 |
| color | range 必须有稳定颜色 ID 和可恢复色值快照；line 可为空，继续行图标 |
| note | 可空的自由笔记，含正文、作者及时间；与 discussion messages 分开 |
| messages / discussionState | 原消息数组原样保留，可为空；none/open/resolved/unknown，unknown 仅用于 v2 orphaned 未保存原解决状态的情况 |
| tags | 字符串标签集合，去空白、去重复；不以标签文字承载系统归档状态 |
| pinnedAt / archivedAt | 独立时间字段；归档默认从侧栏活动列表隐藏，不删除正文高亮，不改变讨论或锚点状态 |
| createdAt / updatedAt / legacy | 保留旧时间；legacy 保存来源版本与原 status，未知信息不伪造 |

新高亮默认黄色、无笔记、零消息。四色点击立即创建且只在持久化确认后报告已保存。“添加笔记”先创建默认色高亮再开编辑；取消只放弃未保存笔记，高亮保留。旧讨论不抽出首消息充当自由笔记，避免改变作者与回复语义。空笔记可清除，空讨论不伪造消息。

旧 range 颜色继承迁移当时的旧强调色/自定义色快照，以 legacy 颜色 ID 表达；新四色不反向覆盖旧色。旧 line 不生成伪选区。原 status=orphaned 的旧条目保留该原值，无法恢复其过往 resolved 信息；重新挂接只恢复位置，不替用户猜讨论状态，用户可以明确“重新打开/解决”。

## v2 → v3 的安全落点

唯一活跃根仍是 .huhu/editor/comments/。一次升级覆盖 index 和全部被管理 sidecar，避免静默混读两个版本。新数据仍是按文件 sidecar，不引入数据库或双真源。

1. 获得现有 App 实例唯一写入权，停止接收新动作；未知版本、v1、结构损坏和不可解析 pending 阻止升级，原文件保留并给出具体恢复位置。
2. 在任何恢复/替换前，把整个旧根（含 pending、set-aside 和未知文件）复制到同模块旁边的 .huhu/editor/comments-backups/<migration-id>/；排除该旁路备份自身，不递归复制。逐文件记录相对路径、字节摘要和数量，回读全部成功才进入下一步。
3. 按旧协议对账并重放可验证的 v2 pending；无法证明恢复成功则停止。构造全量 v3 staging，逐条对照 ID、kind、文本、作者、消息顺序/ID/时间、旧 status 与锚点，数量不变；索引与 sidecar 相互验证。
4. 迁移日志记录稳定 migration-id、源/目标版本、备份和 staging 摘要、阶段及逐文件提交结果。活跃写入在整个升级期间保持禁用，不能把逐文件替换当作整库原子提交。
5. 备份和 staging 全部验证后才提交；中断时先按同一个日志和摘要对账，继续同一事务，不能重复创建卡片、覆盖不认识的文件或新建空索引掩盖失败。全部 v3 回读成功后才发布为可写。
6. 提交前失败可保留 v2；部分提交后保持恢复状态并可重试原事务。回退必须使用完整且已验证的备份，不做新旧文件拼接。v3 开始接收新编辑后不自动回滚，以免丢失新数据；用户显式恢复时展示恢复点与将丢弃的后续变更。

跨设备依靠库文件同步，不能宣称自动解决同时编辑冲突。检测冲突副本或源摘要变化时停写受影响文件，保留双方、指出对象与下一恢复动作；无关文件可以继续读。备份不自动删除。

## 管理、导出与原生高亮互操作

- 以现有高亮侧栏承载当前文档与全库；按文件/颜色/标签分组，搜索摘录/自由笔记/讨论/标签，按字符原文位置、创建时间、最近修改排序。精确原文顺序不被置顶强行打乱；非原文排序可先置顶。
- 笔记详情在同一侧栏内展开；批量选择后统一换色、标签或确认删除。标签按当前选择范围取值；全选只针对当前已显示的结果，有数量提示。导出支持单卡、文件组和当前选中项。
- 单一主方案复用现有侧栏/Popover/Sheet，不新增独立 Card Studio 页面。全库浏览已经是管理视图，不另造一套导航/实体。
- 自定义颜色在设置或管理弹层维护；选区工具条只选色。改名字不改历史 ID；删除调色板项保留已有卡片快照与可筛选显示，不把历史高亮置空或重着色。
- Markdown 导出提供预览和复制；保存时使用用户可选的库内路径，默认 huhu/导出/高亮/，沿用 VaultPathField 校验，拒绝覆盖已有文件并生成唯一名称。输出含摘录、颜色名/快照、笔记、标签、来源与可读定位信息；可选带讨论，默认保留作者。不向原笔记写 mark。
- 原生 ==文字== / <mark> 推荐默认关闭扫描。开启后显示“原生”只读条目，可显式“纳入 HUHU”建立 sidecar；保留原生语法、不自动建第二份或重复计数。重复纳入通过来源文件+解析位置+原生签名关联同卡。HUHU 只管理自身数据，删除卡片不删除原生语法；原生内容有变时重新验证，歧义则脱离。无法可靠识别的 HTML/跨块结构明确跳过。此项由 D-004 决定。

## 可观察失败与验收责任

保存、换色、笔记、批量动作均带稳定操作 ID；结果未知时先查询/flush 同一操作，不能重新追加。批量动作报告逐项成功/失败并只重试未确认项；成功项不回滚或重复。错误以持续横幅/卡片状态保留，草稿仍可编辑或复制，关闭浮层不抹去失败诊断。

验证沿用 CommentFs 故障注入、service 幂等、anchor 重复文本、decorations/reading 分段、DOM 多窗口与真实 Obsidian acceptance 的接缝。HTML 原型只演示行为与状态，不证明磁盘迁移或真实多窗口已通过。
