# UI-001 设计评审记录（Sonnet 5.5 执行者自评，不构成用户批准）

评审对象：final 六个页面与三个候选，使用真实 Chrome 的截图（evidence/screenshots）。

发现与复核：
1. 初版画廊按钮矩阵的标签与相邻行挤在一起，且区块之间缺少分隔；已改为按变体分行加状态标签，并为每个区块加上边框分隔，复核截图后通过。
2. 初版 Home 笔记组件在小组件内又套了一层带边框列表，违反“不做卡片套卡片”；已去除内层边框，复核后通过。
3. 候选 A 的开关与按钮共用了尺寸规则，渲染成大色块；改为 44x36 命中区加 36x20 轨道后正常。候选 C 窄容器下行标题缩进错位，已修正选择器优先级。
4. 终端状态切换最初会让窗格滚动位置和选择丢失（重复 appendChild）；已改为窗格已在宿主内时不再移动，并在整页重绘时保存滚动位置。这条是对“不重建终端窗格”合同的真实问题发现。
5. 保险箱解锁失败时输入内容曾被重绘清空、生成密码曾被重绘覆盖；已把值保存到状态，修复后通过。
6. 视觉判断：层级只有页面底、内容面、浮层三级；强调色只用于主操作、选中与焦点；没有渐变、发光、玻璃、巨大标题；hover 仅改色。圆角 6/8/12/14，没有把所有控件做成药丸。原自评曾称亮暗两套截图均无遮挡；主 Agent 后续在 list-420-light.png 发现 toast 遮挡第三行，此项原结论撤回。
7. 仍保留的取舍：窄屏顶部显示选项默认折叠；候选 B 的展开式行与 AC-241 冲突，仅作对照；候选 C 的 32px 命中区只达桌面下限。
