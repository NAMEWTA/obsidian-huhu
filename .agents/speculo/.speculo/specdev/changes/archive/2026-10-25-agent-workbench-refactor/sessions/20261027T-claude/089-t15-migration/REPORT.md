# 089 T-15 REPORT

## Behavior delivered
- Shared pure recovery protocol (`RecoveryOwner`, `RecoveryStorage` with `remove`, journal codec, `RecoveryGate`) and the transaction state machine: preflight (BUSY, never stops work) -> quiesce all -> strict drain all -> common snapshot -> stage -> verified old/new copies -> journal -> replace -> adopt -> release. `recoverPending` runs before any owner loads.
- Journal format: two alternating slots `.huhu/recovery/transaction/journal.{a,b}.json`, monotonic `seq`, highest valid wins (a torn write falls back one phase). Phases `prepared -> committing -> committed -> done`; `rolling-back -> rolled-back`. Entries carry path, owner, old/new sha256 and copy paths `<opId>/old-N.txt|new-N.txt` (kept permanently as user recovery copies). Recovery: `committed` rolls forward; `prepared/committing/rolling-back` roll fully back (prepared never clobbers a foreign edit); unverifiable copy -> `UNRECOVERABLE`, gate held, nothing guessed. Source drift before the first replace aborts.
- One-shot legacy import (`runLegacyMigration`): legacy `workspace.json` v1 -> one "Import Space · Legacy workbench" (vault-root directory, layout stored byte-identical, id = `legacy-import-<digest16>`); same-cwd Spaces never merged; existing records and selection untouched; damaged/newer/empty layouts create no Space and are reported; damaged primary + valid backup imports the backup; unreadable/newer/foreign/invalid/backup-only `workbench-v2.json` -> refused, never replaced by a default. History annotations classified (account-attributable vs not) and kept in place with copy; retired `index.sqlite` only reported (never read/copied/migrated); credentials/native logs untouched. State + report in `.huhu/terminal-agent/<device>/legacy-import.json` (source digests); re-run by digest = no write; changed source after cutover -> `source-changed`, no second import. Another window's writer lease -> `busy`, nothing written. Legacy automation/shortcut definitions stay unbound (state flag + UI notice).
- Old writer refusal: retained `createWorkspaceStore` (v1) refuses load and every write once `legacy-import.json` exists (re-checked before each commit, already-open instances included).
- Live owner adapters with strict methods (no swallowing flush): settings (`holdWrites/drainWrites/reloadNamespaces`, only named namespaces reloaded + persisted baseline replaced), history annotations, usage stats (deferred counts during quiesce, replayed on resume), automation-session registry.
- App wiring: `RecoveryHost` (owner registry for T-16: `register`, `run`, `recoverBeforeStart`) on the plugin as `recovery`; `main.ts` runs journal recovery before settings load (failure holds the gate, Notice, aborts start) and the legacy import after settings (cheap gate: only when legacy `workspace.json[.backup]` exists and no marker; desktop only).
- Settings page: new "Legacy import" tab (loading / empty / report / source-changed / error, en+zh), unbound-business and rollback guidance.

## T-16 owner-registration protocol
`plugin.recovery.register(owner)` with `owner: RecoveryOwner {id, owns(path), preflight, quiesce(token), drain(token) [must reject on any write failure], adopt(token,{paths}), release(token) [idempotent]}`; then `plugin.recovery.run({operation, stage(read)->{writes:[{path,content|null}], copies?}, ownerIds?})`. Paths must be owned by exactly one participating owner and be vault-relative; the package never chooses paths. Ready adapters: `createFileOwner`, `historyAnnotationOwner`, `usageStatsOwner`, `automationRegistryOwner` (services/migrations/agent-owners.ts), `settingsOwner` (src/app/recovery.ts).
