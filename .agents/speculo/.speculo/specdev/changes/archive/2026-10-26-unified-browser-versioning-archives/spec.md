## 问题与目标

用户需要在同一分支、同一 change 中继续处理三个重构目标。独立浏览器和版本管理已有不同 PR，档案仍是固定个人/企业实现；直接按 Issue 重做会覆盖已有成果，直接按 PR 合并宣布完成又会丢掉残余需求。

**非 UI 合同与 UI-001 修订 2 的五个主页面已确认；未展示扩展 UI 保留设计前置。** 设计树的八个节点均已回答，具体采纳与验证义务见 ADR-001–ADR-006；`draft` 仅保留未展示扩展 UI 的整体 Ready 边界，不表示这些非 UI 决定仍待确认。

本规格以合并提交 `265e65f64bd0deb38fb7f1b5fccd08bfcb8a6bfa` 为当前实现基线。目标用户是使用 Obsidian 的笔记作者、操作受管网页的人与 Agent，以及维护个人/企业/项目等档案的人。成功意味着三个来源的目标分别闭合、相邻模块能共存，且恢复、隐私和资料迁移在失败后仍可解释、可核验。

用户已选择保留三份 Issue 的全部目标。首阶段/后续扩展是实施层次，不是删减范围；来源中的“按需”“可选”“目标预算”仍保持其条件，不把它们转成无条件硬承诺。完整来源条款保存在 [浏览器全文](sources/issue-1-body.md)、[版本管理全文](sources/issue-2-body.md)、[档案全文](sources/issue-3-body.md)，本规格的 AC 是验收分组。任何源条款遗漏由原文补足；当前用户决定和本 change ADR 显式补充跨域恢复边界，不能用源文中的旧路径覆盖合并后真实路径。

## 解决方案与外部行为

### 独立浏览器

用户从独立 browser 入口创建 personal/task Space；每个 Space 拥有独立资料、进程树和 Page 身份，Agent 关闭不影响浏览器。观察默认只读，personal 不接受 Agent Run；控制权按明确租约切换，人工接管先完成 native revoke ACK，再阻止旧写者与 Agent 实时读取。人的当前标签不能作为隐式目标。

操作经过同一 gate，并以持久 prepare/dispatch/结果账本记录。超时、取消、崩溃与未知结果分别表达；旧操作不自动重放，重复票据不能产生重复网站效果。身份导入保留源语义，staging 和 target 分别完整验证；首次创建失败可清理新资源，旧 profile 重开失败必须保留原资料。文件与材料有作用域、摘要、授权和生命周期。

PR #5 已实现 Linux x64 子集；完整 observation/frame coverage、事件、低水位回收、元素设计材料、跨平台与压力故障矩阵仍要补齐。当前不支持的平台/存储语义继续明确拒绝，不能因插件 CI 成功宣称运行时支持。来源 G-01～G-06、T-01～T-22 是平台完成门。

完整交付的必需平台固定为 Windows x64、macOS ARM64、macOS x64、Linux x64；Windows/Linux ARM64 留作后续扩展，移动端不承诺受管运行时支持。名单是后续验收目标，不等同当前已支持状态（ADR-004，LOG-007）。

Cookie/Identity 为必需主线；localStorage/IndexedDB 保留条件扩展。源文 FR-17 与 12.5 的歧义按用户决定解释：“第一方 origin”是未来 localStorage 扩展的起步边界；未支持时明确拒绝，不静默跳过后报告完整导入成功（ADR-006，LOG-009）。

### 版本管理与笔记历史

Git 更改/历史/比较三个模式共享版本读取与 diff，导航和正文独立；未暂存、已暂存、历史、buffer 是不同端点。用户从右侧历史栏选择版本，在中央比较页浏览左右/上下/行内布局，保留原 Markdown leaf 和未保存内容；B 端固定到首次捕获，只有显式刷新才变。

恢复遵循 prepare → checkpoint → revalidate → apply → verify → receipt → undo。预览/取消只读，检查点失败不得覆盖；新编辑、多叶差异、文件身份或 Git 状态漂移拒绝旧计划。恢复保留 HEAD/index，自动同步持久 hold，批注正文不回滚。副本已被继续编辑或添加批注时，旧撤销不能删除它。

PR #4 已提供 A–D 闭环及部分 E，本轮已在联合产物验证 Linux Obsidian 25 场景。持续本地历史、保留策略、精确按块恢复和 F 阶段的按需能力仍保留；各项是否可发布由后续证据判定。`sync` 改为 `versioning` 的设置不自动迁入；升级须核对仓库和自动同步设置，笔记与 Git 对象保留。

自动本地历史由用户主动开启，未开启不采集；记录普通笔记当前内容，包含未保存 buffer，排除隐藏及受管敏感内容。内容变化时默认每 5 分钟、切换笔记或重要操作时采样并按 hash 去重；默认保留 30 天、每库每设备 1 GiB，间隔/保留期/配额可配置。此数字为已确认产品默认值，不是实测性能承诺（ADR-003，LOG-006）。

保留和配额清理仅回收无保护引用的旧快照；未闭合恢复和仍承诺可撤销的对象保留。空间不足则暂停新自动采集并持续提示，不删除恢复依据，不借采样保存笔记或自动提交 Git。关闭/暂停自动历史不豁免恢复前强制检查点；检查点无法写入时拒绝正文覆盖。

### 通用档案

用户本轮明确档案交互继承现有类型树（[SRC-007](sources/SRC-007.md)，LOG-012）：左侧按动态档案类型分组，类型下列实例。点类型名称打开右侧该类型的实例列表/卡片；点实例进入详情，展开箭头只改变树的展开状态。类型字段可勾选是否在列表/卡片显示；两种视图共享该类型的显示字段，所有类型默认显示创建时间、更新时间。显示字段与筛选记录条件分开，隐藏字段不清空值；新增类型复用相同导航与视图，不再新增硬编码分支。

按用户采纳的 Issue #3 基础设计，在 archives 内建立类型、字段、表单、创建模板、实体、关系类型、关系记录和视图八类对象。个人/企业为预设，用户可无代码新增项目/税务等第三类型；fieldId、storageKey、label 各司其职，表单只引用字段、不复制值。

实体与关系使用新的 v2 外层标识及稳定身份；类型定义、不可变修订、实体/关系、迁移清单与提交/回退事实位于可见档案目录，隐藏根只保存可丢缓存与设备恢复材料。关系独立文件为单一真源，反向列表是投影。定义分叉通过 parent graph 识别，不能以时间/数字版本最大覆盖另一发布。

保存草稿和标记完成采用不同校验；未知字段/自由正文/注释保留，不显示字段不等于清空。不同字段修改可合并，同字段冲突保留草稿。v1 可读并按旧 codec 编辑基本字段；旧关系或 v2 新字段写入前显式迁移 owner。迁移先冻结源 hash/稳定映射、写并核验关系、CAS 切 owner，再写可携带回执；staged 不双计，缺件不当零条，已完成 owner 丢失不让独立关系失活。

结构化保存、删除、迁移或受管恢复前，检查所有受影响的原生编辑叶；任一 buffer 与磁盘不一致或叶之间分歧时拒绝写入、保留表单草稿。用户先保存或解决差异后再重试；提交前重新校验，不能用旧预检覆盖刚发生的新编辑。拒绝操作不会自动保存或丢弃原生正文；一致后才按既有字段级三方合并执行（ADR-005，LOG-008）。

档案拥有主资料和关系，home 拥有任务/里程碑/执行，按引用关联。历史浏览可只读；任何档案覆盖恢复先由 archives 预检实体、关系与迁移状态，不支持或无法安全恢复时明确拒绝。该最后一项是新增已确认合同，当前普通 Markdown 恢复尚未实现此边界。
