## 二、实施决策

### 领域和格式

类型、字段、表单、记录模板、实体、关系类型、关系事实、视图分离。`fieldId` 是内部身份，`storageKey` 是 Markdown 属性名，`label` 可独立改名。表单只引用字段，不保存第二份值；关系一条事实一个 Markdown 文件，不在两个实体中存重复 ID 数组。

v2 使用新的外层 `huhu-type: archive-record/archive-relation`，与仅识别 `person/company` 的旧解析器隔离。保留原实体 ID、目录、附件和提醒；旧格式不会因读取而升级。个人/企业作为可持久化的预设定义安装，用户编辑后的定义不被升级覆盖。

定义、不可变修订、当前指针、表单、视图、关系和迁移回执都放在可见根内。隐藏目录不是数据真源。复制完整可见根并重建索引能恢复数据；备份、迁移原文不进入活动实体发现。

### 依赖取舍

参考 JSON Forms 的数据 schema/UI schema/renderer 分离和声明式规则，参考 Frappe 的 DocType、布局及带身份的子表；不复制源码，不引入第二套 UI 框架或后端数据库。JSON Forms 的完整 JSON Schema/Ajv/渲染生态不是本插件持久化协议的替代品。HUHU 使用现有 React/shadcn 与 YAML AST，自行实现有限条件和字段编解码，不执行用户脚本，不加载远程 `$ref`。

参考入口：
- [JSON Forms React 集成](https://jsonforms.io/docs/integrations/react/)、[规则](https://jsonforms.io/docs/uischema/rules/)、[项目及许可](https://github.com/eclipsesource/jsonforms)。
- [Frappe 字段](https://docs.frappe.io/framework/user/en/basics/doctypes/fieldtypes)、[子表](https://docs.frappe.io/framework/user/en/basics/doctypes/child-doctype)、[自定义](https://docs.frappe.io/framework/user/en/basics/doctypes/customize)。

### 写入与同步

单文件使用最新字节上的三方字段/托管正文合并；只修改明确脏字段，不把缺失、null、空串、空数组、false、0 合并为同一种值。输入在入队前复制，校验和提交使用同一副本。应用命令统一承接界面及公共 API。普通保存不清理隐藏字段或自由正文。

多文件操作使用可移植计划、预分配身份、原文备份、逐步读回和回执。迁移先写关联，再以原文比较切换 owner；提交证据决定权威来源。回滚按 after 内容检查，绝不覆盖迁移后用户编辑。断点恢复不重新随机生成关联 ID。

定义修订具有唯一 ID、父修订和语义摘要。当前指针只是提示；索引从完整修订 DAG 找出未合并的 heads，分叉时阻止受影响写入。数字版本不充当冲突解决。不同 schemaRevision 的实体继续按各自准确版本解释。

这是个人 Vault 协议，不是跨设备分布式事务数据库。同步乱序以 pending/incomplete 表达，重复 ID、孤立端点、非法基数和定义分叉可诊断，不承诺离线并发唯一性。

### 黄金样本改写到通用协议

旧的 `test/golden/archives-v2.test.ts`、`archive-relation.test.ts`、`archive-migration.test.ts` 依赖已删除的并行档案 API（`createEntityMarkdown`、`createRelationMarkdown`、`ContactsApplication.archives.migrations`）。验证意图已改写到通用实现：`encodeEntity` / `decodeEntity`、`encodeRelation` / `patchValues`，以及 `RecoveryCommands`。前导零、`false`、金额字符串、月精度、Markdown 托管块、关系上下文、不受管理的正文，以及迁移原文备份与附件，仍由这些测试锁定。

以下旧场景不再按原字节断言，原因是协议有意更换，不是放宽检查：

| 旧断言 | 现在怎么证明 | 为什么原样不再适用 |
|---|---|---|
| 实体外层 `huhu-created-at` / `huhu-updated-at`，以及迁移后 `createdAt === null` | 通用外层没有这两个键；身份仍是 `huhu-id`，迁移后 `format === 2` | v2 实体用 `draft` / `active` / `archived`，时间取文件修改时间，不再写创建时间字符串 |
| 日期旁路键 `tax-period-precision: month` | 月精度写在字段定义上，值本身是 `2026-03`；把 `2026-03-01` 写入月精度字段会拒绝 | 精度属于类型，不再在每条记录上重复一个兄弟键 |
| 关系顶层 `status: past` 与 `lifecycle: active` 并存 | 通用生命周期仍是 `active`；任职「在职/离任」是预设字段，不是外层状态。黄金样本锁定有效期（`2024-05` 月、`2025-06-30` 日）和上下文角色 `project` | 旧 `status` 是 v1 任职投影，不是通用关系外层 |
| 路径 `迁移恢复/<id>/原始.md` 和单独的 `迁移记录/<id>-完成.md` | 原文备份是 `迁移记录/<id>/原文/<ownerId>.md`，且字节等于迁移前全文（含附件行）；回执是同一条 `huhu-type: archive-migration` 计划，提交后 `state` 为 `committed` | 计划与备份都在可见迁移目录，不再另写一份完成回执 |
| 回执里的 `collectionId` 字节 | 断言它是本次库的 36 位身份，并把快照中的该字段替换成 `collection-id` | 集合身份在首次引导时随机分配，不属于这条企业记录本身；其余回执字节仍被样本锁定 |

## 四、测试矩阵

- 纯模型：类型/字段标识、保留字与跨类型 Properties 冲突；枚举历史值；子表 rowId；条件深度与非法输入；语义摘要/DAG 分叉。
- 持久化：BOM/CRLF/注释/未知 YAML/自由 Markdown；单字段保存、缺失/null/空值；托管块重复与损坏；未来格式只读。
- 并发：两个窗口改不同字段合并、同字段冲突、schema 变更、修改调用方参数、排队取消、根切换、卸载后迟到读取。
- 关系：有向/对称、自环、双端基数、历史作用域、重复事实策略、DAG、contextRefs、端点删改和同步乱序。
- 迁移：ID/路径不一致、无 ID 手工行、重复 rowId、反向投影去重、上下级方向、月份、current/past/keyRole、每一步断点、已提交 owner 删除、回滚后再次同步与外部编辑保护。
- DOM：第三类创建、字段设计、两表单、条件/只读、列表/卡片/筛选、显式迁移与失败草稿、键盘及中文组合输入。
- 规模：现有 100/1000/5000 旧格式夹具；新 1000/5000 实体加 5000/25000 关联，记录冷建、增量、查询 p50/p95，区分逻辑基准与真实宿主首屏。
- 工程：类型、定向及扩展测试、ESLint、架构/i18n/Promise 回调、样式/文档/包预算及产物漂移。
