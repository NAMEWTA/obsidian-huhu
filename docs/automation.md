# 自动化与通知

自动化是图标栏上独立的一级功能“**自动化看板**”，与首页、AI Agent 并列。自动化就是定时任务：在固定周期或指定时间做某件事（终端和智能体的、提醒的、写待办的……）。看板页管理全部自动化任务和运行历史：列表可切换到运行记录；搜索名称、提示词或目录，并按动作、智能体、启用状态或结果筛选。表头支持名称和上次运行排序；搜索框中用 ↑↓ 选择，Enter 打开详情，Esc 清除搜索。图标栏底部的通知铃铛打开独立收件箱。离开页面不停止调度；停用模块后数据保留，页面显示开启提示，重新开启后继续使用。通知模块可独立使用。

命令“打开自动化看板”、状态栏的自动化项、通知和看板里的自动化入口都会直接打开这个页面（手机上同样）。需要智能体执行时，自动化经智能体模块的服务调用，不属于智能体工作区。

## 操作类型

| 操作 | 作用 | 手动 | 定时 | 需要桌面端 |
|---|---|---|---|---|
| 提醒 | 发送一条带你所写内容的通知 | 是 | 是 | 否 |
| 新建待办 | 向已注册看板的待办卡片，或日历当前配置的存储目标添加待办 | 是 | 是 | 否 |
| 运行智能体 | 在库内的工作目录中用提示词启动编程智能体 | 是 | 是 | 是 |
| 终端脚本 | 在工作目录中运行 PowerShell 或 Bash 脚本 | 是 | 是 | 是 |
| Obsidian 命令 | 运行一个 Obsidian 命令 | 是 | 否 | 否 |
| 打开笔记 | 打开一篇笔记 | 是 | 否 | 否 |
| 打开网页 | 在[内置浏览器](browser.md)中打开网页（浏览器模块关闭时用系统浏览器） | 是 | 否 | 否 |

Obsidian 命令的结果只表示命令已被调用。脚本的结果取真实退出码。

## 创建自动化

**在自动化看板里**，“新建自动化”和编辑会把页面切换成**页内编辑器**（不是标签或对话框）：表单居中、两侧留有统一边距：左侧是名称和动作内容，右侧是“执行 / 时间与容错 / 通知”三组设置，页面窄时右侧设置堆到下方；整页滚动，底部的操作栏始终可见。选择“动作”后，内容和执行选项随动作变化。填写名称、动作、内容、时间、预检和通知后，可保存或保存并运行，Ctrl/Cmd+Enter 保存；保存后回到看板，保存并运行则跳到这次运行。有未保存的修改时关闭编辑器会先在页内确认；离开页面再回来时编辑器和修改还在。“打开网页”需要填写网址（只接受 http 和 https，缺少协议的裸域名按 https 保存），为空或无效时会在输入框下提示；它只能手动运行。列表和运行记录在容器变窄时依次隐藏次要列，不再出现横向裁切。空列表提供每日笔记整理、每周回顾、检查失效链接、整理收件箱和喝水提醒模板。

**从其他功能**（看板、日历、档案、命令）新建时，一律弹出同一个“**新建自动化**”对话框，内容是同一套动作表单，按动作切换，保存后写入自动化定义，随即出现在自动化看板。自动化模块经 `AUTOMATION_COMPOSER` 服务（`open({ action, prefill, source })`）提供它，其他模块只经这个服务调用，不自制对话框。预填项有名称、内容、单次时间和来源笔记链接：

- **待办提醒**：看板待办分区中任务上的铃铛，预填提醒动作、任务的提醒时间和内容，并以该任务为来源；提醒仍属于看板笔记里的这条任务（来源提醒只能是提醒动作）。任务勾选完成或被删除后不再调度。
- **日历与待办提醒**：行内铃铛打开同一待办编辑器；日期、任务时间和提醒时间分别设置，不再创建脱离来源的独立提醒。提醒保存在源任务中，通知打开该任务；完成或删除即停止，撤销完成只恢复尚未到期的提醒。只有日期时可以在当天内提醒，有任务时间时提醒必须不晚于该时间。重复规则与每次任务的完成状态分别保存，编辑或删除可选本次或本次及以后。
- **档案提醒**：在档案记录的菜单中选择“新建自动化”。自动化列表里的“来源”会打开这条档案。
- **自动创建待办**：选择动作“新建待办”，再选择“待办卡片”或“日历待办”。卡片目标需要选择看板和卡片；日历目标选择看板后使用日历的有效存储位置，目标看板无需包含待办卡片。填写待办内容后，可以马上创建，也可以按周期创建。
- **独立操作**：在自动化看板新建，例如“运行智能体”或“终端脚本”，运行方式可选“快捷操作（手动）”“指定时间”“重复执行”或“马上执行”。

在任务列表里，每条自动化都可以立即运行、暂停或恢复、编辑和删除。

“待办卡片”目标必须是能显示和管理待办的卡片，包括混合分区中的任务卡。备忘、普通项目、数据库查询和网页卡等不是有效目标。目标改名不会改变它的身份；目标被删除、类型改变或不再唯一时，请重新选择有效的卡片后再保存。写入前 HUHU 会重新检查磁盘上的目标，不会自动改投第一张卡片，也不会转换卡片类型；同一次运行有运行 ID，重复确认不会插入两次。未填写目标类型的旧自动化保持原来的卡片含义。

### 日历待办的日期与存储

日历目标复用手动添加日历待办的设置：日记、指定文件、按日期存入文件夹，或每条任务单独笔记。目标区域显示当前有效位置。日历服务由看板模块提供，执行不要求看板或日历界面保持打开；模块关闭时会报告不可用，不会自行打开模块或改投其他目标。

例如“每周五 09:00 创建复盘待办”，任务归属日取本次计划在保存时区内的周五。即使在宽限内延迟到周六执行，仍属于原周五。“任务时间”可另外填写 14:30；“提醒时间”可填写 13:45，两者可独立留空，计划的 09:00 不会被当成任务时间或提醒时间。任务按普通 Markdown 复选框写入，并带独立的归属日期和可选提醒标记。任务内容只接受单行，避免一次配置意外生成多条任务。

写入前会保存计划日期、时区和已解析的实际目标。目标笔记已存在时使用原子更新，保留其中其他内容；需要新建时先准备完整模板内容，再连同待办一次写入。未启用日记、目标被排除、来源不存在、模板缺失或模板需要交互输入时，运行记录说明原因，不会创建空文件冒充成功。依赖外部模板引擎的新文件创建不在后台静默执行：可以先手动创建日记，再投递到已有笔记，或使用无需外部引擎的模板。

每次已接纳的投递有稳定标识。失败或中断的记录提供“重试这次投递”：保留原计划日期、原定义与目标快照，先查找已写入的标识，再决定是否写入。即使写入后保存运行回执失败，重试也不会重复创建；之后修改日历存储设置不会把这次重试改投新位置。正常点击自动化的“运行”是新的一次手动执行，会获得新的投递标识。下一周的计划也是独立的一次任务。

写入已完成、但日历刷新失败时，运行结果会显示“已写入，等待刷新”并保留来源回执；可打开源笔记确认。日历待办在各入口使用同一个源任务，勾选会写回原笔记。普通看板待办与日历待办的显示、筛选和写回边界见[看板](dashboard.md)。

要把操作作为看板按钮使用：保存时把运行方式设为“快捷操作（手动）”，选择“添加到看板”并选择目标看板，见[看板](dashboard.md#快捷操作)。

## 运行方式与时间

- Obsidian 必须运行。没有云端调度、操作系统守护进程、远程运行，也不会创建 worktree。
- 可选“马上执行”“指定时间”，以及“重复执行”：预设为“每小时”“每天”“工作日”“每周”，或“自定义”（五字段 Cron 表达式或 RRULE）。RRULE 支持 `FREQ=HOURLY`、`FREQ=DAILY` 和 `FREQ=WEEKLY`，配合 `BYHOUR`、`BYMINUTE`，每周还支持 `BYDAY`。其他字段会在保存时被拒绝，不会被默默忽略。
- 日历计划明确保存时区，默认使用本机时区。因夏令时而不存在的本地时间会被跳过，重复的一小时按两个不同的时刻处理。HUHU 每分钟检查一次计划，窗口获得焦点时再检查一次。
- 只考虑最近一次错过的时间，不补排所有错过的执行。默认宽限 720 分钟（可在“补执行宽限”中修改），另加两分钟的轮询容差。超出宽限，或上一次运行尚未结束时，该次记为 **已跳过**。
- HUHU 先保存待执行记录和调度游标，再执行动作。重启后，未完成的运行被标为 **已中断**，不会自动重放。日历投递可明确重试原记录，复用原标识和目标；重试不回退调度游标，也不扩展为无限补跑。
- 每个定义保留最近 100 条已结束的运行；进行中的运行始终保留。“清理已结束的历史”只移除已结束的运行，保留进行中的运行和投递回执。
- 倒计时和纪念日的提醒在小组件的设置里配置，通过同一个自动化服务运行，日期由小组件决定。无需保持看板打开。

## 智能体参数

新建或指定会话可填写额外参数，例如 `--model opus`。允许模型与推理强度参数 `--model` / `-m`、`--effort`、`--reasoning-effort`，Claude 另支持 `--add-dir`；权限、会话、配置和提示词控制参数（如 `--dangerously-skip-permissions`）被拒绝。沿用存活会话时不追加参数。保存与执行均会校验，不把参数当 Shell 脚本拼接。提示词可使用 `{{date}}`、`{{time}}`、`{{vault}}`、`{{folder}}`。

## 预检命令

预检在正式动作之前执行，空命令不启动预检。非零退出码或超过 60 秒会跳过正式动作，运行记录显示“预检未通过”。HOME、XDG、临时及 CLI 配置和状态目录位于当前库的 `.huhu/automation/<device-id>/precheck-home/`，不继承宿主的数据目录变量。创建目录和每次启动前会逐级检查库内父链与实际路径；目录或父级含符号链接、不是目录或越出当前库的 `.huhu` 时，会拒绝启动并提示预检失败。移除链接或恢复真实目录后再重试，不会跟随链接在库外创建目录。

预检是用户自己编写的命令，拥有宿主进程的权限。HUHU 在正常退出、超时、取消和模块关闭时尽力回收其进程组及可识别的后代。**预检不是安全沙箱，刻意脱离会话/进程组的后台进程不保证被回收。** 不要把预检用于运行不受信任的命令，也不要依赖它约束命令主动访问的路径。

## 通知

通知渠道按每条自动化分别设置，不是全局默认值。

| 渠道 | 行为 |
|---|---|
| 应用内 | 写入收件箱，并显示一条 Obsidian 提示 |
| 系统 | 桌面操作系统通知，需要系统的通知权限 |

“执行后通知”可选“成功或失败时”“仅失败时”或“不通知”。

在收件箱里可以全部标为已读、清理已读通知，以及打开通知的来源。清理后仍保留防止重复投递的回执。回执显示“已提交”“待投递”“失败”或“状态未知”：重启后无法确认投递结果的渠道保持“状态未知”，不会自动重发。通知按运行 ID 去重。

通知是独立的功能模块。在 **设置 → 常规 → 功能模块** 中关闭后，自动化照常运行，结果只显示一条 Obsidian 提示，不写入收件箱；重新开启后，之前的通知仍在。

## 运行记录

| 状态 | 含义 |
|---|---|
| 待执行 | 等待开始 |
| 执行中 | 操作正在运行 |
| 已提交；完成状态未知 | 操作已启动，但还不知道它是否完成 |
| 已完成、失败 | 操作的结果 |
| 已停止 | 你停止了这次运行 |
| 已中断 | 运行时 Obsidian 被关闭 |
| 已跳过 | 预检未通过、超出宽限窗口，或上一次运行仍在进行 |

详情显示运行时间线、预检退出码、输出和错误；运行记录提供耗时、已知 token、“打开终端”、停止和重跑，取不到用量时显示“—”。日历投递还显示归属日期、时区及实际来源笔记，失败/中断时的重试复用原投递。可以按状态、自动化和时间筛选记录，每次加载 50 条。删除定义会保留它产生的运行记录，仍可查看其历史；请先停止进行中的运行。

## 智能体操作

可以选择任何已启用且已安装的智能体，见[智能体工作台](agent-workbench.md)。会话方式有：

- **每次新建**
- **沿用上次存活会话**：上次的会话仍然存活且空闲时沿用，否则新建
- **指定会话**：从历史中选择（可搜索），或填写准确的原生会话标识；Pi 还需要会话文件路径。HUHU 用 CLI 自己的恢复参数恢复该会话，不会回退到新会话；会话不可用时这次运行失败。

手动运行会自动打开终端；定时运行可在运行记录中点“打开”。关闭工作台叶子保留存活进程；关闭运行中的终端标签需要确认并结束进程。结束会话或在运行记录中点“停止”也会结束进程。关闭自动化页不会停止调度。

Claude Code、Codex、Gemini、Grok、Pi 和 OpenCode 通过 HUHU 在启动会话时安装的原生 hook 报告生命周期。已有的 hook 和设置会保留，原文件会备份，见[智能体工作台](agent-workbench.md#状态-hook)。对没有原生完成事件的 CLI，运行一直显示“已提交；完成状态未知”，直到进程退出或你停止它；输出变安静从不被当作成功。需要输入提示词的 CLI 必须发出可识别的输入就绪信号，否则运行超时失败，并提示手动完成初始化。

各 CLI 的目录信任、登录和 hook 权限由 CLI 自己管理，请先手动完成。如果“确认提示”是默认的 YOLO，且该智能体带有此类参数，请先手动启动一次该智能体并确认权限模式；在此之前，自动化运行会失败，并提示“请先手动启动一次该智能体，确认已配置的权限模式”。用量取原生会话累计值在运行前后的差额；取不到基线或原生记录时显示缺失，不推算费用。

## 设备归属

每个定义都有归属设备，只有该设备会运行它。从另一台电脑同步来的定义显示“此任务绑定了另一台执行设备”。设备映射位于 `.huhu/config/identity.json`，复制库时须核对宿主身份和设备归属，不能据同步文件重放旧运行。恢复文件不会自动改变运行设备。

## 模块开关

**设置 → 常规 → 功能模块 → 自动化** 控制整个功能，默认开启。关闭时会先等待正在启动的自动化，停止自动化拥有的智能体终端并保存取消状态，然后停止计划检查和文件监听。独立的手动终端不受影响。已经送达的通知和已经完成的文件修改不会被撤销。

关闭期间，自动化页会提示功能已关闭，看板上保存的操作按钮不可用；通知收件箱仍可使用。定义、运行历史和调度游标都保留在磁盘上。重新开启时，会按原有的设备归属、游标和宽限规则检查未处理的触发，不重放已处理的事件。保存开关失败时，开关恢复原值；停止运行或保存运行状态失败时，开关保持新值并提示失败，原因排除后可再次切换。

## 数据保存在哪里

| 内容 | 库内位置 |
|---|---|
| 待办提醒 | 看板笔记，在任务行上 |
| 日历待办提醒 | 独立定义（下一行），`linkPath`/`linkLine` 属性记录来源笔记 |
| 日历自动创建的待办 | 日历配置的目标笔记；任务行的隐藏标记保留任务 ID 与投递标识 |
| 档案提醒 | 该档案的 `基本信息.md`，位于 `<!-- huhu:reminders -->` 标记之间 |
| 倒计时和纪念日 | 看板设置 |
| 独立操作定义 | `.huhu/automation/definitions/<名称>-<ID>/操作.md`（随库同步；各设备的运行状态在同目录兄弟的 `<device-id>/` 里，不同步） |
| 调度游标、运行历史及日历投递快照/回执 | `.huhu/automation/<device-id>/runtime.json` |
| 通知及投递回执 | `.huhu/notifications/<device-id>/inbox.json` |
| 自动化启动的会话 | `.huhu/terminal-agent/<device-id>/automation-sessions.json` |

请备份相关笔记和整个 `.huhu` 目录（见[数据与恢复](data.md)）。

操作文档无法读取时会报告加载失败，不会当成空操作列表。修复提示中的 Markdown 文件后，可重试加载或重新开启自动化模块。保存和移除定义也会在无法读取最新文档时停止；临时写入失败可在排除原因后重试。

## 扩展：新增一种动作

每种动作是“策略”对象，编辑器、列表、运行服务和文档编解码都经注册表取用，不按 `kind` 分支。新增一种动作（例如“发送 Webhook”）需要：

1. `src/shared/automation/types.ts`：在 `AutomationAction` 联合里加一个成员，并在 `metadata.ts` 的 `isDefinition` 里加结构校验。
2. `src/modules/automations/core/actions/<kind>.ts`：导出 `ActionDefinition`（`definition.ts` 有逐项说明）——`kind`、`nameKey`、是否可定时（`scheduled`）、是否需要桌面端（`desktop`）、是否可存在来源文档里（`sourceBound`）、`create`（默认草稿）、`text`/`setText`、`document`（序列化到文档和从文档解析，常用 `propertiesCodec`）、`contentError`/`settingsError`（校验）、可选的 `normalize`/`verify`/`notice`，以及 `run`：`direct`（在插件进程里执行，返回结果或可停止的句柄）或 `terminal`（在智能体终端里启动并由服务持有）。
3. 在 `core/actions/registry.ts` 的 `registered` 里登记一行；少登记会在类型检查时失败。
4. `src/modules/automations/ui/actions/<kind>.tsx`：导出 `ActionView`——图标、内容表单 `Content`、可选的执行选项 `Options`、详情页事实 `facts`、列表提示 `hint`/`badge`、保存前检查 `beforeSave`；在 `ui/actions/registry.ts` 登记。
5. 在 `i18n.ts` 或共享词典里补 `automation.<kind>` 等键（en 与 zh）；在 `registry.test.ts` 之外无需改测试，注册表测试会自动覆盖往返、校验和可用性。

组合弹窗、编辑器、列表筛选、详情页都会自动出现新动作。

## 使用限制

应用内通知需要 Obsidian 运行，系统通知需要操作系统授权。六种 CLI 智能体的真实账号流程以及移动端尚未全部验证。

旧版浏览器流程动作已删除。现存定义仅作为废弃只读项保留，可显式删除，不再调度或执行，不会自动迁移。
