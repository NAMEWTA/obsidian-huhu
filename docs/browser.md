# 独立浏览器

HUHU 的浏览器有自己的工作台入口、空间目录、身份和文件管理。只开启“浏览器”模块即可使用；关闭“智能体”不会停止浏览器。在智能体的「+」菜单中也可以打开或引用浏览器页面，并与终端分屏。智能体工作区可以嵌入同一个页面的查看器，外部 CLI/MCP 也可以连接用户明确授权的任务空间。内置网页仅支持桌面版 Obsidian。

当前受管运行时只启用 **Linux x64**。Windows、macOS、Linux ARM64 和移动端没有可用的新运行时；不会回退到旧 Electron 网页或使用你的日常 Chrome。插件其他功能的支持范围不因此改变。平台门槛与安装命令见[运行时维护](browser-runtime.md)。

## 开始使用

1. 在“设置 → 常规 → 功能模块”开启浏览器，然后打开工作台图标栏中的浏览器。
2. 在浏览器设置或工作台中选择“安装运行时”，选择已解压的完整运行时目录。目录必须包含匹配当前插件的 Chromium、原生监督程序、Worker、manifest 和许可文件；不能只选择一个 Chrome 可执行文件。校验成功后显示版本和可用状态。
3. 创建个人空间或任务空间，可选择空白环境或已导入的身份版本。每个空间拥有独立进程树、浏览器资料和下载目录。
4. 新页面默认处于暂停/观察状态。需要手动浏览时，点击接管；让外部 Agent 操作任务空间时，显式交给 Agent，再复制连接文件路径。

首次安装完整运行时需要额外磁盘空间。插件不会在打开普通页面时联网下载一个不明版本的浏览器；已安装版本可以离线启动，访问网站仍需要对应网络。程序升级与资料版本由护栏检查，不自动用旧 Chromium 打开新版本资料。

如果系统凭据保护不可用，界面只提供经明确同意的临时使用。临时空间的网页资料仍会在本地磁盘短暂存在，并在结束或下次启动恢复时清理；“临时”不表示所有 Chromium 数据只在内存。此时不能持久保存身份版本，也不会用可预测的本地密码代替系统密钥。关闭 Agent 只释放终端运行资源，不关闭浏览器页面。

## 个人空间、任务空间和页面

| 对象 | 用途与权限 |
|---|---|
| 个人空间 | 人自己的浏览和登录；不会发放 Agent Run 或通过外部协议枚举个人页面 |
| 任务空间 | 单个自动化工作环境；只有用户发出的当前 Run 能力可以操作 |
| 页面 | 空间内的明确页面目标；每次动作带 Page ID，切换 UI 标签不改变 Agent 的目标 |
| 查看器 | 某个页面的画面订阅；多个窗口可以观察，只有一个查看器持有人类控制权 |
| 身份版本 | 显式保存的不可变登录种子；创建新空间时复制，后续登录和退出互不合并 |

可以重命名、停止、重启或删除空间。关闭查看器/Agent 浏览器标签只结束该视图的订阅；如果它持有人工控制权，会释放为暂停。删除空间与关闭页面是不同操作，删除会清理该空间的资料和内部文件。

地址栏接受 HTTP、HTTPS、裸域名、回环地址和搜索词。普通搜索使用 Google；`localhost` 和回环地址使用 HTTP。`file:`、本机绝对路径、嵌入用户名密码的 URL 及脚本协议会被拒绝。需要把文件交给网站时使用显式上传授权。

查看器提供后退、前进、刷新、停止、查找、缩放和多页面操作。缩放后的画面和输入坐标重新同步，旧画面不能继续产生点击。中文输入使用查看器的文本输入区完成组字，然后显式提交到当前网页焦点；不会把 Obsidian 编辑器的普通键盘输入转发给网页。

## 人观察、接管和交回

打开查看器只订阅画面，不会改变 Agent 控制权或操作系统前台焦点。帧队列有界；慢窗口只保留在途帧和最新帧，最后一个观察者离开后停止画面生产。静态页面仍会在有观察者时受限地刷新真实截图，避免长时间停留后误用过期画面。

接管会先撤销旧租约，等待原生写通道确认撤权，再给当前查看器新的 epoch 和租约。暂停和接管不排在旧页面动作之后；即使一个网页等待尚未结束，用户仍可请求停止控制。撤权后已发给网站的请求可能已经生效，HUHU 不会声称把网络副作用回滚。

一次只有一个人工控制者。其他窗口仍可看画面；它们的旧输入、旧租约、旧文档引用和旧缩放坐标都无效。关闭或隐藏控制视图会进入暂停，不自动把控制交回 Agent。再次交给 Agent 会生成新的 Run，旧连接文件不能获得新 Run 的凭证。新 Run 必须先重新观察页面才能继续写入。

任务空间已有 Agent 控制时，可通过“交接给另一个 Agent”确认目标 Agent、外部 Run 和 Attempt 标识。确认后撤销 A，再为 B 发新权限，保留同一真实页面和表单；不会自行创建或启动 Agent。取消不改变控制权，旧确认不能撤掉已经接管的后继 Run。B 需重新复制连接并观察交接页面，不能使用 A 的旧引用。

交给智能体的网页截图副本在 `.huhu/browser-materials/`。材料进入已有会话的输入区，不会自动回车，也不会为此新建会话。网页内容是参考材料，不构成新的操作授权。

alert/confirm/prompt、文件选择以及权限/认证请求作为绑定页面、文档和控制代次的状态显示。过期请求不能由旧提示卡回答。HTTP 认证、敏感设备权限和系统剪贴板权限按运行时策略拒绝；需要账号状态时，可在网页自己的登录表单中人工登录。网页不会因为查看器存在而取得 Obsidian 的剪贴板。用户主动点击“复制选中文本”才由 HUHU 的界面写入当前窗口剪贴板。

## 导入 Cookie 与保存身份

支持从文本、用户选择的文件和受支持的本机浏览器资料开始导入。文本/文件格式包括 Cookie JSON 数组、Netscape cookies.txt、明确的 HUHU identity seed。整个来源先预检，再显示数量、问题和可选择的精确域名；预览不会显示 Cookie 值。

预检区分过期、重复、无效、无法保留语义和冲突。不能通过取消选中某个域来掩盖来源中的非法项。Cookie 的 host-only/domain、Path、Secure、HttpOnly、SameSite、session/expiry、前缀约束和支持的 CHIPS 分区键会被检查；目标不能精确保留的语义会失败。非空 localStorage/IndexedDB 身份播种当前不支持，会明确拒绝，不静默丢弃。

本机资料只有在用户打开来源选择器后才检测，并绑定一次具体的来源授权。读取使用独立浏览器 helper 处理私有 SQLite 快照，不借用 Agent 服务，也不启动你的源浏览器 Profile。v20/App-Bound Encryption 等不能安全解开的来源会失败，可改为用户自行导出的 Cookie 文件或在新空间人工登录；没有自动启动源浏览器副本尝试解密的后备通道。

创建带身份的空间时，先在全新临时 staging 中写入并完整读回，再写入全新的目标空间并再次读回。只有校验与 staging 清理完成，目标才发布为可用。失败目标被隔离，清理任务保持可见。正常运行后的空间不接受原地覆盖身份。

人工登录后可显式保存新的身份版本，再选择它创建其他空间。这是复制登录种子，不是共享活跃资料；不会反向修改源浏览器或其他空间。成功导入 Cookie 也不保证任意网站免登录，设备绑定、服务端风控和其他存储仍由网站决定。

## 上传、下载和材料

上传先在 HUHU 界面选择文件，并明确授权给当前人工租约或当前 Agent Run。服务创建私有副本、记录摘要并返回 opaque fileId；网站和外部 Agent 接口不接收任意本机路径。网站收到保留安全文件名的副本，包括中文文件名；同名文件仍分别隔离。授权绑定空间与执行身份，文件只能被相应上传操作消费一次。接管、停止或新 Run 不继承旧授权。

下载归属发起它的页面和控制代次，保存到空间的下载目录。文件页显示状态和元数据；导出时由用户选择库外目的地。文件大小、总量和数量受到配额限制；未知、替换过的文件和丢失索引的持久文件不会被当作空目录直接覆盖或误删。

在持有人工控制权时，可把截图和语义摘录发送到启用的材料消费者。HUHU Agent 是可选消费者：仅列出正在运行、非自动化且输入可用的目标。材料放入所选会话的输入区，**不会自动回车提交**。截图经过私有文件服务保存，网页文字始终是参考材料。

## CLI 和 MCP

在任务空间显式交给 Agent 后，点击“复制连接文件路径”。此路径指向当前启动实例创建的私有 JSON 文件，包含 loopback 端点和该 Run 的凭证；不要分享文件内容。CLI 自动读取凭证，不要求把 token 放进命令行。

```sh
node browser-cli.cjs --connection "/absolute/path/to/connections/UUID.json" call page.list '{}'
node browser-cli.cjs --connection "/absolute/path/to/connections/UUID.json" mcp
```

Node.js 22 或更高版本运行外部 CLI；浏览器模块本身使用 Obsidian 提供的 utilityProcess，不要求另外安装 Node。CLI、stdio MCP 和 loopback RPC 共用一套 v2 schema 与授权规则。默认连接仅能使用指定的任务空间；复制连接时单独启用“允许新建一个任务空间”，才获得一次创建空白任务空间的权限。

协议、重试和操作记录示例见[浏览器协议](browser-protocol.md)。连接文件不是永久账号：暂停、接管、Run 过期、关闭模块或重启后，需要用户明确再次授权。

## 恢复、清理和支持边界

新数据位于 `.huhu/browser/<device-id>/v2/`。旧浏览器目录不会被迁移、覆盖或自动删除；旧 API、旧 RPC 和旧网页宿主已移除。重新开启模块只恢复目录并显示暂停/停止状态，不自动联网恢复页面，也不重放提交。

遇到 `cleanup_pending` 或隔离状态时，先使用界面的重试清理。恢复只处理归属可验证的资源；不会按一个旧 PID 杀进程，也不会删除当前正在使用的临时空间。浏览器停止失败时保留原模块实例和清理责任，再次启用前先重试，避免同时出现两个所有者。

当前默认上限包括 3 个活动空间、每空间 8 个页面、共 12 个活动页面；单个上传文件 100 MiB、内部文件总量 512 MiB、文件数 128。操作记录、消息、观察引用和帧也有上限，超限会拒绝而非无限累积。持久目录与日志整体有磁盘预算；操作账本达到 10,000 项会拒绝新意图，不会自动删除幂等性证据继续执行。

Linux 的真实 Chromium 与 Obsidian 验收并不代表 Windows/macOS、所有系统密钥后端、第三方真实账号、所有 IME 或任意站点均已通过。完整的运行边界见[运行时维护](browser-runtime.md)，本地数据与保护方式见[数据与恢复](data.md)和[隐私](privacy.md)。
