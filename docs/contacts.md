# 档案

档案是工作台里的通用资料页面。个人、企业是预设类型；也能创建项目、税务事项等类型，配置字段、多张表单、创建模板、列表/卡片视图和跨类型关系。资料、业务定义、独立关系及升级恢复记录都保存在可见的 Markdown 文件中。设计与验证边界见[实施方案](archives-implementation.md)。

## 开始使用

在 **设置 → 常规 → 功能模块** 开启档案，再到 **设置 → 档案** 选择资料目录。默认是 `huhu/archives`；切换目录须先预览并确认，不会自动移动或删除旧文件。根目录必须是库内可见相对路径，不能使用隐藏目录或 `..`。

打开图标栏的档案页面。新库或开始使用时，使用初始化入口安装个人、企业、表单和关系预设。预设一经写入即属于库内业务定义，后续插件加载不会覆盖用户修改。

侧栏按稳定类型 ID 动态生成，显示用户指定的类型名称与视图。选择类型后新建档案；名称只是资料，不承担身份，不同实体可以同名。新建目录包含 ID，改显示名称不会暗中移动附件。停用某类只停止创建，不删除原有实体。

## 设置

| 设置 | 行为 |
|---|---|
| 档案模块开关 | 关闭界面、索引订阅与服务，不删除内容 |
| 档案资料文件夹 | 默认 `huhu/archives`；预览并应用后重建索引，原目录保持原样 |
| 卡片最大列数 | 沿用 5/6 列上限；窄窗口自动减少列数 |

列表/卡片偏好按类型和视图保存。界面路由只保存有界的类型/视图/实体 ID、分页及查询，不把整份业务数据写入工作台状态。

## 自定义类型、字段和表单

在定义设计器创建类型，配置名称字段、可见目录、启用状态和字段。字段有三个不同概念：`fieldId` 是稳定身份；`storageKey` 是 Markdown 属性名；显示名称可以独立改动。停用或重命名字段不等于清除已有值。全库同一 storageKey 的类型不能无声改变，包含历史定义。

| 字段类型 | 保存含义 |
|---|---|
| 文本、多行 Markdown | 电话、编号应使用文本，保留前导零；Markdown 是原文，不执行脚本 |
| 整数、小数、金额 | 金额以精确十进制文本与币种表达，不用浮点计算冒充精确货币 |
| 布尔 | `false` 与未填写不同 |
| 日期、时刻 | 日期支持日/月精度；时刻需要明确偏移，不把月份补成某一天 |
| 单选、多选 | 选项有稳定身份，停用选项仍可解释历史值 |
| 字符串列表、文件引用 | 多值保持集合/列表语义；文件缺失产生诊断，不丢弃原引用 |
| 重复子表 | 每行有稳定 rowId，字段按子列定义校验与合并 |

表单由分组、1–3 列布局和字段控件构成，可设置只读、帮助文本及受限条件显示。多张表单编辑同一个实体草稿，切换表单不复制第二份实体，也不清空暂时隐藏的字段。创建模板提供初始值和自由正文；视图提供列表/卡片布局、列、筛选及排序。

定义发布前须预览校验结果和受影响实体。每次发布产生不可变修订，并记录父修订与内容摘要。已有档案仍按原 schemaRevision 解释；需要切换到新定义时，使用显式升级预览和恢复计划，不能通过改个版本号直接重解释旧数据。

## 新建、编辑与草稿

新建或编辑在页内进行。编辑区明确区分未填写、`null`、空字符串、空数组、`false` 和 `0`。必填规则用于激活记录；草稿可以保留不完整资料。保存失败或发生冲突时保留输入，不自动用空对象覆盖。

实体与关系表单的恢复草稿位于 `.huhu/archives/drafts/<设备>/<根摘要>/`，按设备和目录隔离，有数量/体积上限；它们不是已提交资料，也不是跨设备同步合同。列表提供恢复入口。保存或明确放弃后清理对应草稿。定义设计器目前使用内存草稿和离开确认，尚无重启恢复；长篇定义编辑请分次发布。

保存使用打开表单时的基线、当前磁盘和本次草稿做三方合并：不同字段可以合并，同一字段冲突会拒绝提交。未知 YAML、注释与非受管自由正文不会被整篇重新序列化。宿主适配在写入前检查所有 Markdown 叶子的未保存正文；有未保存原生编辑器时先保存或关闭该编辑，不能把 `Vault.process` 当成覆盖授权。

## 人物、企业与关系

个人和企业作为可修改的预设定义提供联系方式、标签、地区及备注等字段。任职、上下级、朋友/同事等关系由关系定义约束，不再是专门 React 页面里的第二份数据。

关系是有 ID 的独立事实，保存为一个 Markdown 文件。两端页面读取同一记录，编辑或归档任一端看到的记录会作用于这同一事实，不产生反向副本。关系定义可以限定两端允许的类型、方向与反向称谓、两端最大基数、基数统计范围、重复策略、自环、无环约束、上下文角色、属性和生效日期。

任职的现任/曾任状态、关键角色、部门、职务、备注，以及 `YYYY-MM`/`YYYY-MM-DD` 精度分别保留。“负责人/关键联系人”属于某段任职，不等于人与人的上下级关系。同公司任职不会自动生成朋友或同事关系。尚未建档的目标可以先新建；随后关联失败不会把已创建的目标删除。

关系的含义是“对方是此人的……”。例如“李四是张三的上级”记为张三汇报给李四。关系只由独立关系记录保存，不靠名称猜测。

## 人物阅读层与纪事

打开预设人物类型的详情进入「概览 / 资料 / 关系 / 纪事」，窄容器使用分段导航；企业和自定义类型继续使用通用详情，不会因为类型名称叫“人物”就套用阅读层。

- **概览**：最近三条纪事与独立关系摘要，并可进入完整纪事、关系视图。
- **资料**：按此实体绑定的定义修订显示字段，编辑仍进入现有动态表单；资源、归档、升级和恢复草稿入口在「资源与档案操作」中。
- **关系**：读取和编辑已有独立关系事实，按目标实体 ID 跳转。
- **纪事**：手工添加日期、标题、正文及关联档案，可编辑或确认删除；每行有稳定 rowId，同名人物的纪事互不混用。

纪事保存在人物档案的重复子表字段中，没有独立人物库。旧修订不会因浏览而自动升级；「为此人物启用纪事」先确认，再发布兼容预设并显式升级此人物，用户自定义过的结构不会被自动覆盖。纪事编辑是当前页的内存草稿，离开或进入其他视图前需确认放弃；它不同于完整实体编辑器的磁盘恢复草稿。索引重载或读取失败会保留当前输入，并在索引恢复前限制写入；保存冲突也保留草稿，需先核对原档案。纪事删除只移除指定行，不删除人物自由正文。不提供聊天素材、AI 画像或人物主库导入。

## 归物本与年度报告

档案侧栏的「归物」为物品档案提供专用阅读页。首次使用按页面提示安装物品预设，再新建物品；资料仍在档案实体 Markdown 中，可进入完整通用档案编辑器。页面包含库存成本、日均净成本等指标、状态条、搜索、年份/排序和卡片。金额按币种分别统计，不做换汇；缺失金额是未知，不当成 0，只有月份的日期不补成某一天计算精确持有天数。

物品支持使用中、闲置、已转售、已丢弃；状态流转需填写生效日期并明确确认，转售可填回收金额。退出和返库都追加生命周期事件，不删除旧历史。迁移完成后的「撤销」在当前 owner 实例中保留五分钟，通过条件补偿追加记录；若物品已被其他编辑修改、超过期限或实例已释放，拒绝覆盖。它不是无限期撤销栈，重启后不能依赖这项内存入口。

从归物页面打开「年度报告」，选择年份查看购入/离场数量、购入金额、回收金额、月度趋势、分类分布及持有时间等。报告与卡片使用同一 owner 统计，按生命周期事件重放，币种分栏，未知值与 0 区分。读取失败会提示并保留上一份已读结果及其年份；不把旧结果当作新年份的报告。报告为只读视图，不生成海报或另存一份统计主库。

## 查找和浏览

列表与卡片消费同一次类型化查询，每页 50 条。可搜索、按字段或关系过滤并排序，也可以选择已保存的视图；筛选表达式受限，不执行任意代码。查询返回实体/定义修订、完整性和诊断，加载未完成、关系端点缺失或定义分叉不能伪装为“确实没有数据”。

索引从文件身份标记识别内容，而非仅依赖中文目录名。重复 ID、未知类型、未来格式、缺失定义或关系端点会显示诊断；点击文件路径在来源窗口打开原始笔记。侧栏只展示有界数量的条目，更多实体使用分页列表查找。

通用详情和人物资料中的 Markdown 字段显示保留换行的原文；需要渲染整篇内容时使用“打开原始笔记”。人物阅读层的范围见上文，不含旧版全部命中摘要或关键人物专属布局。

## 详情页与相关资料

档案目录下的普通文件属于相关资料，按实际文件位置发现，不把它们复制进实体属性。资源列表支持名称/路径搜索和分页，每页 60 项。可以新建资料笔记、选择文件批量导入；同名文件使用不覆盖名称，每项分别返回成功或失败。来源文件保持不变。打开与预览由 Obsidian 提供。

“新建提醒”继续使用自动化模块的 composer，来源 wire 名保持 `contacts`。提醒正文不因升级而删除。新的定义、关系、集合清单和升级回执从 Home 最近文档中排除；普通附件笔记不被整目录排除。

## 文件、备份与停用

新库的默认可见目录布局如下，实际类型文件夹可自定义；默认路径使用固定小写英文名称，不随界面语言变化。其他目录不会被自动检测、读取、迁移或删除。已有明确配置的根目录及其文件保持原样：

```text
huhu/archives/
  collection.md
  definitions/
    types/<typeId>/current.md
    types/<typeId>/revisions/<revisionId>.md
    forms/…
    templates/…
    relation-types/…
    views/…
  people/<名称-ID>/profile.md
  companies/<名称-ID>/profile.md
  <自定义类型目录>/<名称-ID>/profile.md
  relations/<relationTypeId>/<relationId>.md
  migrations/<operationId>.md
  migrations/<operationId>/originals/<entityId>.md
  migrations/<operationId>/health-repair.json  # 归物体检修复的 owner 登记
```

新预置通过稳定 ID 和受限标签键显示中英文，基础预置修订标识为 `preset-<definitionId>-v2`，人物纪事扩展为显式发布的 `preset-type-person-journal-v3`；切换语言不改变内容哈希或路径。用户改名的预置保留原标签与原字节，不自动升级当前指针；用户编辑标签会清除对应翻译键。这里的预置修订代次与档案外层格式版本分开。

外层标记使用 `huhu-type: archive-record/archive-relation`；`person`/`company` 等其他 `huhu-type` 的文件按未知记录报告，不读取也不改写。实体 ID、schemaRevision、生命周期及字段有明确协议；托管 Markdown 段以标记划界，自由正文仍归用户所有。

### 备份与恢复

备份整个可见根，包含定义修订、当前指针、关系、升级计划、原文备份、回执和附件。只复制实体 `profile.md` 不是完整备份。放入另一个库并选择根目录后，可以重建索引；目录外引用的附件需要另行备份。隐藏恢复草稿不属于可移植正式数据。

结构升级先固定计划：保存并回读原文备份 → 比较原文并写入新结构 → 写完成回执。未完成计划可在恢复面板继续。模块关闭或写盘中断不等于已完成。

回滚会核对当前内容是否仍等于该步骤的 after 内容。若升级后有人编辑，回滚拒绝覆盖，需先保留新改动并人工处理。schema 升级与关系升级使用同一套可恢复协议。

### 删除与恢复

本轮通用界面只提供归档/恢复，不提供物理删除整个实体目录，也不执行关系级联删除。归档保留 ID、正文、附件与历史事实；影响预览列出关系、上下文、附件和提醒。关系删除使用保留身份的墓碑，避免同步重放复活旧事实。

从 Obsidian 文件列表手工删除时，受宿主回收站设置约束；其他实体不会自动删除，关联会显示缺失诊断。恢复需取回完整原目录与 ID，不能用同名新实体替代。物理删除命令的 restrict/retain 策略及复制实体向导仍待实现和验收，不把关系定义中的配置误当成已交付的删除入口。

## 体检与有限修复命令

从[数据体检](health.md)扫描档案完整性与归物状态投影。扫描只读；修复须先预览影响数、确认计划，再由档案 owner 执行有限命令。当前只支持重建派生档案索引，以及根据有效生命周期记录修复归物投影；后者复用档案原文备份、事务日志和回读复查，不改生命周期历史或定义结构。

缺失端点、重复 ID、定义分叉及损坏原文不会被“一键修复”猜测性重写。计划过期、原文哈希变化或有未保存编辑器时必须重新检查；部分提交、待确认提交和复查失败不能当作全部成功。存在持久恢复 ID 时在体检恢复入口继续或受保护回滚；升级后已有新编辑则拒绝覆盖。完整步骤见[体检的有限修复](health.md#有限修复)。

## 外部编辑与问题处理

| 提示 | 含义与处理 |
|---|---|
| 字段或文件冲突 | 保留草稿，核对磁盘修改后重新打开；不要反复强制保存 |
| 未保存编辑器 | 先处理所有窗口中该文件的原生编辑器内容 |
| 重复 ID | 找出重复文件并保留需要的版本；不会按名称随机选择 |
| 缺失定义/关系端点 | 等待同步完整，或恢复定义/目标；不要把缺失当空数据 |
| 定义分叉 | 同步出现多个未合并 head；设计器显式合并后再写入受影响资料 |
| 升级未完成或冲突 | 查看计划、原文备份、当前步骤和回执；继续或受保护回滚 |
| 文件字段失效 | 原路径保持可见；恢复文件或显式选择新路径 |

本地文件事务不等于跨设备分布式数据库，不保证两个离线设备同时编辑后自动无冲突合并。真实宿主的未保存多叶、移动端、弹出窗口、中文输入法与同步乱序需要独立验收；当前证据和未验项目见[实施方案](archives-implementation.md)。P5 的 CSV 导入、Lookup/Rollup、局部图谱及深入项目执行整合不在本轮交付中。
