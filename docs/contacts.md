# 档案

档案是工作台里的一页（图标栏上的 **档案** 图标）。你通过卡片、列表和详情页查看、编辑人物与企业资料；资料本身是 Markdown，便于备份、直接阅读和交给 AI。

## 开始使用

1. 在 **设置 → 常规 → 功能模块** 中确认“档案”已开启。
2. 打开 **设置 → 档案**，选择或输入档案资料文件夹，点击 **预览并应用**。确认框会显示目标目录以及识别到的档案数量。
3. 点击图标栏上的档案图标，或运行命令 `HUHU: 打开档案`。侧栏是“个人”和“企业”两棵树，展开后是各自的记录，旁边的数字是记录数。点击“个人”或“企业”打开对应的列表；点击具体的人或企业，直接打开他的详情，侧栏里的高亮跟着当前详情走。侧栏上方的搜索框按名称过滤，上千条记录也能流畅滚动。
4. 在个人档案列表点击 **新增**，填写姓名和联系方式并保存。点击卡片或列表行进入详情页，继续添加履历、关系和备注。
5. 在企业档案列表建档，记录企业的特别情况；也可以在新增工作经历时，通过企业选择器创建企业。

页面标题显示当前类型（“个人档案”或“企业档案”）。列表页头只有搜索框，以及右侧的列表/卡片切换、搜索范围、筛选、排序和新增；个人与企业之间的切换只在侧栏里。

新增与编辑在档案页内的表单中进行，顶部“返回”回到进入表单前的列表或详情。返回、取消、Esc，以及点击当前分类或另一分类，使用同一套放弃修改确认；没有修改直接离开，选择继续编辑则保留输入、当前分类和选中项，导航不会提前变化。返回同一分类尽量保留筛选、页码、滚动位置与卡片/列表偏好；切到另一分类会清除上一分类的筛选，但不会重置布局偏好。保存新档案后直接显示它的详情；如果它不符合原列表筛选，详情会说明原因并保留原筛选。输入法组合期间的 Enter 和 Esc 不会触发保存或退出，完成组合后仍可正常操作。未保存的草稿尚未写入 Markdown，重启后无法恢复。在工作经历里新建企业会打开一个小对话框，它是单独的保存操作，随后取消工作经历不会删除已经创建的企业。

## 设置

| 设置 | 默认值 | 作用 |
|---|---|---|
| 档案模块开关 | 开启 | 在 **常规 → 功能模块** 中切换。关闭模块会保留资料文件 |
| 档案资料文件夹 | `huhu/档案` | 库内的可见目录（相对库根，像 `huhu/日志/` 一样在文件列表里能看到）；设置里可用路径选择器按名字模糊匹配已有目录，也可以手写；目录不存在时首次保存档案时自动创建 |
| 卡片最大列数 | 6 | 可选 5 或 6；窗口变窄和手机上会自动减少 |

路径示例：`资料/档案`。手写的路径一律按库根的相对路径处理：开头的 `/`、`./` 会被去掉；不支持库外的绝对路径、隐藏目录（如 `.obsidian`、`.huhu`）和 `..` 上级路径。档案不在 `.huhu/` 里，Obsidian 自带的文件列表、搜索、反链和 Obsidian Sync 都能直接用。修改目录文本后，必须经过“预览并应用”才会切换。切换不会搬移或删除旧目录中的文件；切换到空目录时面板显示为空，切回旧目录即可重新读取旧资料。

## 人物与企业

| 资料 | 填写方式 |
|---|---|
| 姓名、别名 | 姓名必填。同名人物可以分别建档，系统用独立的身份标识区分 |
| 手机、固定电话、微信、邮箱 | 每项一行，点“添加一项”增加一行；可以粘贴多行，自动去重；电话按文本保存，保留前导零和国际区号 |
| 出生日期、出生地 | 使用日期控件，不知道时可留空 |
| 当前地区、标签 | 用于查找和筛选。人物的当前地区与企业地区分别填写 |
| 工作经历 | 企业、部门、职务、起止日期、现任/曾任、关键角色和任职备注 |
| 人际关系 | 关联另一位联系人，选择关系，可补充关联企业和备注 |
| 性格与偏好、生活习惯、备注 | 普通文字或 Markdown，保存后在详情页中预览 |
| 企业资料 | 名称、联系方式、网址、地区、标签和企业特别情况；人员列表来自人物的工作经历 |

### 记录履历

在人物详情的 **工作经历** 中添加任职。日期用 `YYYY-MM` 或 `YYYY-MM-DD`，也可以留空。状态以你明确选择的“现任”或“曾任”为准：离职后设为“曾任”，即使结束时间不清楚也可以保留；“现任”不能填写结束日期。同一个人可以同时在多家企业任职。

把现任经历的 **关键角色** 设为“负责人”或“关键联系人”，该人物就会出现在企业详情的 **关键人物** 中。这是在企业中的任职角色，与两个人之间的“领导/下属”关系分别记录。

企业详情列出当前任职和曾任职的人员。人数表示 **已收录的在职联系人**，不是企业的实际员工总数；同一个人在同一企业有多段职务时只计一次。

### 记录人际关系

关系字段的含义是“**对方是此人的……**”。例如，在张三的档案里选择李四，关系选“领导”，表示李四是张三的领导；李四的详情页会反过来显示张三是其下属。

“领导”和“下属”互为反向，“同事”和“朋友”双向显示。关系只需录入一次，反向显示由计算得出，不会再写入另一份记录。来自对方档案的关系，请回到对方的档案修改。自定义关系会显示来源和原始称谓，HUHU 不会推断另一方的称谓。

在同一家企业任职只构成任职关联，不会自动生成朋友或同事关系。尚未建档的人物，需要先创建联系人，再添加直接关系。

## 查找和浏览

| 方式 | 范围 |
|---|---|
| 搜索 | 默认搜索这份 `基本信息.md`：基本资料、联系方式、任职、性格、习惯、备注、关系备注，以及受管区域之外的正文。不搜索附件和其他笔记 |
| 仅基本信息 | 只匹配基本资料、职务和任职企业名称 |
| 联系人筛选 | 当前公司、曾任公司、当前地区、标签、关系类型 |
| 企业筛选 | 企业地区、标签 |
| 排序 | 按姓名，或最近修改。命中不会改变顺序 |

同一筛选项内的多选表示“或”，不同筛选项之间表示“且”。例如，当前公司选 A 和 B，地区选杭州，结果是“在 A 或 B 任职，并且当前地区为杭州”的联系人。搜索框里用空格（半角或全角）分开的几个词按“且”组合：每个词都要出现在这份档案里，可以分别在不同分区，例如一个在备注、一个在任职。单个词不会跨分区拼接。英文不区分大小写，中文按子串匹配。这条档案的 `huhu-id` 和 `<!-- huhu:row … -->` 标记不作为搜索正文；笔记里写出的其他编号仍可搜到。命中能对应到 `基本信息.md` 原文行时会给出该行，对不上就不编造行号。邮箱只是联系方式，相同邮箱不会合并，身份仍然是 `huhu-id`。

列表和卡片是同一次查询的两种显示。新打开的档案页，联系人用列表，企业用卡片。切换之后，联系人和企业各自记住上一次的选择，之后新打开的页面沿用它；每个页面自己的布局优先，刷新后仍在。宽窗格里的列表对人物显示姓名、当前任职、地区、首个邮箱和标签，对企业显示名称、地区、网站和已收录的在职联系人数；窄窗格只保留名称和两行辅助信息。命中时多一行纯文本摘要和来源，例如“命中：备注”；企业的备注显示为“命中：企业特别情况”。有多个词时，摘要取包含词最多的那一段。点这条摘要会打开详情里对应的分区；命中自由正文时会说明大约在第几行。“打开原始笔记”按钮在 Obsidian 的新标签页打开该文件，当前不会自动跳到命中的行；详情页不会把整段自由正文再渲染一遍。

卡片列表、列表和企业人员列表每页最多 60 条。点击企业或人物链接可以在档案内继续浏览，返回时恢复你在当前布局中看到的记录。手机上的新增、筛选、排序和删除入口在标签页菜单里。详情页顶部可编辑基本信息，其他分区保留各自的添加和编辑按钮。“打开原始笔记”是需要检查底层文件时的辅助入口。

旧页面保存的状态没有布局字段时，默认显示卡片；如果已为该类型明确选择过布局，则优先使用该选择。两种布局各自保留滚动锚点。在详情页重启后，返回时仍保留原来的搜索条件和页码。

## 详情页与相关资料

基本信息和相关资料显示在同一页。工作经历、关系、企业人员、性格、习惯和备注默认收起，点击标题展开。表单按身份、联系方式等分组，较宽时基本字段并列，窄窗口改为单列；别名和标签仍可多值录入，电话保留前导零。字段区域独立滚动，宽屏的保存/取消位于右侧居中，窄窗口和移动端位于表单底部的独立操作区，不覆盖字段。保存期间禁止重复提交和离开；校验或写入失败保留输入并提示，冲突时提供复制和重新载入。

“相关资料”递归列出该档案文件夹里的全部普通文件。入口 `基本信息.md` 通过更多菜单的“打开原始笔记”访问。资料归属由实际所在的目录决定，不需要逐个登记链接。

- **新建笔记**：输入名称，HUHU 在档案目录创建 Markdown 文件，并在 Obsidian 的新标签页打开。
- **添加资料**：选择本机文件复制进档案；桌面端也可把文件拖入资料列表。来源文件保留，同名时加序号，不覆盖。批量添加会逐项报告结果，成功的项目保留。
- 可以自行建立子目录。文件新增、修改、改名、移动或删除都会更新列表。搜索只匹配名称和相对路径，可按最近修改或名称排序，每页 60 项。
- 点击文件在 Obsidian 的新标签页打开，编辑与预览能力由宿主提供。更多菜单可以在 Obsidian 文件列表中定位档案目录。

## 文件、备份与停用

每个人、每家企业各有一个独立目录，基本信息保存为 Markdown。以下是默认布局（位于库里的 `huhu/档案/`）；与其他目录同名时，会加一个短 ID 后缀：

```text
huhu/档案/
  个人档案/
    示例人物/
      基本信息.md
      初次沟通.md
      简历.pdf
      项目资料/合作说明.pdf
    另一位联系人/基本信息.md
  企业档案/
    示例科技/基本信息.md
  档案格式说明.md
```

HUHU 只识别直接位于 `个人档案`（人物）或 `企业档案`（企业）下的实体目录里的 `基本信息.md`。无论界面使用什么语言，目录名和文件名都保持不变。显示名称变化不会移动目录；在磁盘上重命名实体目录后，只要仍保留上述层级和文件，HUHU 就按稳定的 ID 识别这条记录。

基本字段保存在 YAML 属性中，履历和关系保存在正文表格中，性格、习惯和备注保存在正文区域。HTML 注释标记身份和编辑边界，实际资料仍是普通 Markdown。为某条档案创建的提醒（见[自动化与通知](automation.md)）保存在同一篇笔记里的 `<!-- huhu:reminders -->` 标记之间。完整规则在 `档案格式说明.md` 中：HUHU 在第一次保存档案、且目录里还没有说明时，按当前界面语言在档案目录生成这份说明；已有的说明不会被覆盖。

面板从文件建立内存索引。档案资料不依赖任何数据库，也不依赖插件目录中的 `data.json`；插件设置只保留所选目录和显示偏好。

### 备份与迁移

1. 完成并保存面板或原始笔记中的编辑。
2. 复制整个档案目录，保留子目录结构。若正文引用了目录外的图片或附件，也要一并备份。
3. 在另一个库的可见目录中放入该目录，并在设置中选择对应路径；档案内容和关联关系会从文件重建。目录选择和面板布局不随档案目录备份。

在同一个库内移动档案根目录时，同样先完成编辑，在库内可见目录之间整体移动后重新选择目录。

关闭模块或卸载 HUHU 会保留已保存的 Markdown，可继续在 Obsidian 中编辑，或用文本编辑器、AI 读取。重新启用 HUHU 并选择原档案目录，即可恢复面板。资料不依赖面板而存在，但磁盘损坏或误删仍需要独立备份。完整备份范围见[数据与恢复](data.md)。

### 删除与恢复

删除确认会显示姓名、目录、文件数和受影响的关联数。确认后，整个实体目录（包括其中所有文件）按 Obsidian 的删除设置处理，其他档案不会被一并删除。确认之后目录内容有变化，删除会停止；请检查实际范围后重新操作。其他人的历史履历、关系文字和引用会保留，找不到的目标显示为失效关联。

需要恢复时，从宿主所用的回收站或独立备份中取回整个实体目录，放回所选档案根下的原有层级，并保留原来的 `huhu-id`。若宿主设置为永久删除，则需要从独立备份恢复。不要仅创建一个同名的新档案来代替，因为新档案有不同的身份；备份范围见[数据与恢复](data.md)。

## 外部编辑与问题处理

原始笔记保存后，面板会刷新。面板保存时，会比较打开表单时的内容和现在的文件：不同的基本字段或不同的正文区域可以合并；同一字段或同一张履历/关系表的并发修改会报告冲突，不会逐行自动合并。

| 提示或现象 | 处理方式 |
|---|---|
| 相同字段已被修改 | 表单保留你的草稿。先点“复制草稿”留存，再点“重新载入原始资料”，检查最新内容后重新编辑。复制结果是 JSON 文本，用于找回输入，不是 Markdown 导出，也不能直接导入 |
| 资料文件夹已切换 | 先复制需要保留的草稿，再从当前目录重新打开档案；旧表单不能写入新目录 |
| 属性、表格或区域标记无效 | 打开原始笔记，对照格式说明修正；面板会拒绝覆盖已损坏的内容 |
| 多份文件使用同一个 ID | 检查是否复制了原文件；要创建另一个人，请在面板里新增，不要复制身份标识 |
| 可见链接与关联身份不一致 | 对照原始笔记核对链接目标和身份注释，不要只改其中一项 |
| 部分档案读取失败 | 检查相关文件是否可读，再点“重新读取”；其他正常的档案仍可显示 |
| 档案已保存，但格式说明未能创建 | 档案已写入；检查目录的写入权限。之后保存档案时会再次尝试生成缺失的说明 |

草稿只保留在当前表单中，关闭工作台或重启前请先保存或复制。面板的冲突检查不能代替同步工具对跨设备文件冲突的处理。

## 让 AI 阅读

把档案目录和其中的 `档案格式说明.md` 提供给 AI 即可，无需面板接口。例如：“读取这个档案目录，列出星河科技已收录的现任联系人及职务，附上来源文件；区分现任和曾任，不要推测未记录的关系。”

文件中的相对链接可用于追踪人物与企业，`huhu-id` 可用于区分同名记录。是否把文件发送到外部 AI 服务由你决定，档案本身不提供自动上传或同步 AI 的功能。

## 当前范围

已包含：手工建档、面板内编辑、企业视角、任职履历、直接人际关系、组合筛选和 Markdown 存储。不包含：CSV 或 Excel 导入、手机通讯录同步、关系网络图、自动生日提醒，以及跨设备冲突的协调。
