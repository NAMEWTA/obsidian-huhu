# 档案

档案是工作台里的通用资料页面。个人、企业是预设类型；也能创建项目、税务事项等类型，配置字段、多张表单、创建模板、列表/卡片视图和跨类型关系。资料、业务定义、独立关系及迁移记录都保存在可见的 Markdown 文件中。设计与验证边界见[实施方案](archives-implementation.md)。

## 开始使用

在 **设置 → 常规 → 功能模块** 开启档案，再到 **设置 → 档案** 选择资料目录。默认是 `huhu/档案`；切换目录须先预览并确认，不会自动移动或删除旧文件。根目录必须是库内可见相对路径，不能使用隐藏目录或 `..`。

打开图标栏的档案页面。已有 v1 个人/企业会只读索引，不因打开页面而迁移。新库或开始使用新模型时，使用初始化入口安装个人、企业、表单和关系预设。预设一经写入即属于库内业务定义，后续插件加载不会覆盖用户修改。

侧栏按稳定类型 ID 动态生成，显示用户指定的类型名称与视图。选择类型后新建档案；名称只是资料，不承担身份，不同实体可以同名。新建目录包含 ID，改显示名称不会暗中移动附件。停用某类只停止创建，不删除原有实体。

## 设置

| 设置 | 行为 |
|---|---|
| 档案模块开关 | 关闭界面、索引订阅与服务，不删除内容 |
| 档案资料文件夹 | 默认 `huhu/档案`；预览并应用后重建索引，旧目录保持原样 |
| 卡片最大列数 | 沿用 5/6 列上限；窄窗口自动减少列数 |

列表/卡片偏好按类型和视图保存。界面路由只保存有界的类型/视图/实体 ID、分页及查询，不把整份业务数据写入工作台状态。

## 自定义类型、字段和表单

在定义设计器创建类型，配置名称字段、可见目录、启用状态和字段。字段有三个不同概念：`fieldId` 是稳定身份；`storageKey` 是 Markdown 属性名；显示名称可以独立改动。停用或重命名字段不等于清除已有值。全库同一 storageKey 的类型不能无声改变，包含历史定义。

| 字段类型 | 保存含义 |
|---|---|
| 文本、多行 Markdown | 电话、编号应使用文本，保留前导零；Markdown 是原文，不执行脚本 |
| 整数、小数、金额 | 金额以精确十进制文本与币种表达，不用浮点计算冒充精确货币 |
| 布尔 | `false` 与未填写不同 |
| 日期、时刻 | 日期支持日/月精度；时刻需要明确偏移，不把月份补成某一天 |
| 单选、多选 | 选项有稳定身份，停用选项仍可解释历史值 |
| 字符串列表、文件引用 | 多值保持集合/列表语义；文件缺失产生诊断，不丢弃原引用 |
| 重复子表 | 每行有稳定 rowId，字段按子列定义校验与合并 |

表单由分组、1–3 列布局和字段控件构成，可设置只读、帮助文本及受限条件显示。多张表单编辑同一个实体草稿，切换表单不复制第二份实体，也不清空暂时隐藏的字段。创建模板提供初始值和自由正文；视图提供列表/卡片布局、列、筛选及排序。

定义发布前须预览校验结果和受影响实体。每次发布产生不可变修订，并记录父修订与内容摘要。已有档案仍按原 schemaRevision 解释；需要切换到新定义时，使用显式升级预览和恢复计划，不能通过改个版本号直接重解释旧数据。

## 新建、编辑与草稿

新建或编辑在页内进行。编辑区明确区分未填写、`null`、空字符串、空数组、`false` 和 `0`。必填规则用于激活记录；草稿可以保留不完整资料。保存失败或发生冲突时保留输入，不自动用空对象覆盖。

实体与关系表单的恢复草稿位于 `.huhu/archives/drafts/<设备>/<根摘要>/`，按设备和目录隔离，有数量/体积上限；它们不是已提交资料，也不是跨设备同步合同。列表提供恢复入口。保存或明确放弃后清理对应草稿。定义设计器目前使用内存草稿和离开确认，尚无重启恢复；长篇定义编辑请分次发布。

保存使用打开表单时的基线、当前磁盘和本次草稿做三方合并：不同字段可以合并，同一字段冲突会拒绝提交。未知 YAML、注释与非受管自由正文不会被整篇重新序列化。宿主适配在写入前检查所有 Markdown 叶子的未保存正文；有未保存原生编辑器时先保存或关闭该编辑，不能把 `Vault.process` 当成覆盖授权。

## 人物、企业与关系

个人和企业作为可修改的预设定义提供联系方式、标签、地区及备注等字段。任职、上下级、朋友/同事等关系由关系定义约束，不再是专门 React 页面里的第二份数据。

关系是有 ID 的独立事实，保存为一个 Markdown 文件。两端页面读取同一记录，编辑或归档任一端看到的记录会作用于这同一事实，不产生反向副本。关系定义可以限定两端允许的类型、方向与反向称谓、两端最大基数、基数统计范围、重复策略、自环、无环约束、上下文角色、属性和生效日期。

任职的现任/曾任状态、关键角色、部门、职务、备注，以及 `YYYY-MM`/`YYYY-MM-DD` 精度分别保留。“负责人/关键联系人”属于某段任职，不等于人与人的上下级关系。同公司任职不会自动生成朋友或同事关系。尚未建档的目标可以先新建；随后关联失败不会把已创建的目标删除。

旧关系的含义仍是“对方是此人的……”。例如原 v1 行写“李四是张三的上级”，迁移保持这个方向。旧表中没有行 ID 的手工资料不靠名称猜测成关联事实；预检会显示需要处理的行。旧关系投影在迁移前只读，基础字段仍通过 v1 保真适配保存。

## 查找和浏览

列表与卡片消费同一次类型化查询，每页 50 条。可搜索、按字段或关系过滤并排序，也可以选择已保存的视图；筛选表达式受限，不执行任意代码。查询返回实体/定义修订、完整性和诊断，加载未完成、关系端点缺失或定义分叉不能伪装为“确实没有数据”。

索引从文件身份标记识别内容，而非仅依赖中文目录名。重复 ID、未知类型、未来格式、缺失定义或关系端点会显示诊断；点击文件路径在来源窗口打开原始笔记。侧栏只展示有界数量的条目，更多实体使用分页列表查找。

当前通用详情对 Markdown 字段显示保留换行的原文；完整富文本预览、旧人物页的全部命中摘要/关键人物专属布局尚未移植。需要渲染整篇内容时使用“打开原始笔记”。

## 详情页与相关资料

档案目录下的普通文件属于相关资料，按实际文件位置发现，不把它们复制进实体属性。资源列表支持名称/路径搜索和分页，每页 60 项。可以新建资料笔记、选择文件批量导入；同名文件使用不覆盖名称，每项分别返回成功或失败。来源文件保持不变。打开与预览由 Obsidian 提供。

“新建提醒”继续使用自动化模块的 composer，来源 wire 名保持 `contacts`。提醒正文不因迁移实体格式而删除。新的定义、关系、集合清单和迁移回执从 Home 最近文档中排除；普通附件笔记不被整目录排除。

## 文件、备份与停用

默认可见目录布局如下，实际类型文件夹可自定义：

```text
huhu/档案/
  档案集合.md
  档案定义/
    类型/<typeId>/当前.md
    类型/<typeId>/修订/<revisionId>.md
    表单/…
    记录模板/…
    关系/…
    视图/…
  个人档案/<名称-ID>/基本信息.md
  企业档案/<名称-ID>/基本信息.md
  <自定义类型目录>/<名称-ID>/基本信息.md
  关联记录/<relationTypeId>/<relationId>.md
  迁移记录/<operationId>.md
  迁移记录/<operationId>/原文/<entityId>.md
```

v2 外层标记使用 `huhu-type: archive-record/archive-relation`；旧 v1 parser 不会把它当个人/企业重新写入。实体 ID、schemaRevision、生命周期及字段有明确协议；托管 Markdown 段以标记划界，自由正文仍归用户所有。

### 备份与迁移

备份整个可见根，包含定义修订、当前指针、关系、迁移计划、原文备份、回执和附件。只复制实体 `基本信息.md` 不是完整 v2 备份。放入另一个库并选择根目录后，可以重建索引；目录外引用的附件需要另行备份。隐藏恢复草稿不属于可移植正式数据。

在迁移/恢复面板先预检，查看实体、关系、无 ID 手工行、提醒与诊断。确认后逐实体执行：固定计划和关系 ID → 保存并回读原文备份 → 写独立关系 → 比较原文并切换实体 → 写完成回执。未完成计划可继续，不重复生成随机关系 ID。模块关闭或写盘中断不等于整批已完成。

回滚会核对当前内容是否仍等于该步骤的 after 内容。若迁移后有人编辑，回滚拒绝覆盖，需先保留新改动并人工处理。不要直接从旧备份覆盖 v2 owner：索引会显示迁移冲突，要求按恢复计划处理。schema 升级与关系升级使用同一套可恢复协议。

### 删除与恢复

本轮通用界面只提供归档/恢复，不提供物理删除整个实体目录，也不执行关系级联删除。归档保留 ID、正文、附件与历史事实；影响预览列出关系、上下文、附件和提醒。关系删除使用保留身份的墓碑，避免同步重放复活旧事实。

从 Obsidian 文件列表手工删除时，受宿主回收站设置约束；其他实体不会自动删除，关联会显示缺失诊断。恢复需取回完整原目录与 ID，不能用同名新实体替代。物理删除命令的 restrict/retain 策略及复制实体向导仍待实现和验收，不把关系定义中的配置误当成已交付的删除入口。

## 外部编辑与问题处理

| 提示 | 含义与处理 |
|---|---|
| 字段或文件冲突 | 保留草稿，核对磁盘修改后重新打开；不要反复强制保存 |
| 未保存编辑器 | 先处理所有窗口中该文件的原生编辑器内容 |
| 重复 ID | 找出重复文件并保留需要的版本；不会按名称随机选择 |
| 缺失定义/关系端点 | 等待同步完整，或恢复定义/目标；不要把缺失当空数据 |
| 定义分叉 | 同步出现多个未合并 head；设计器显式合并后再写入受影响资料 |
| 迁移未完成或冲突 | 查看计划、原文备份、当前步骤和回执；继续或受保护回滚 |
| 文件字段失效 | 原路径保持可见；恢复文件或显式选择新路径 |

本地文件事务不等于跨设备分布式数据库，不保证两个离线设备同时编辑后自动无冲突合并。真实宿主的未保存多叶、移动端、弹出窗口、中文输入法与同步乱序需要独立验收；当前证据和未验项目见[实施方案](archives-implementation.md)。P5 的 CSV 导入、Lookup/Rollup、局部图谱及深入项目执行整合不在本轮交付中。
