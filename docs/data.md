# 数据与恢复

HUHU 的数据分在当前 vault 的两块根里。**`huhu/`（可见）**放你的内容和资料：日志、闪念、收件箱、待办归档、项目管理、档案、记账/习惯/番茄钟/阅读记录、RSS、默认新笔记和导出；它们是普通的库内文件，Obsidian 会索引、搜索，同步工具也照常同步。**`.huhu/`（隐藏）**放 HUHU 自己的配置和运行数据：设置、看板布局（`.huhu/dashboards/`）、自动化定义（`.huhu/automation/definitions/`）、智能体、浏览器、通知、同步、图标、批注、保险箱、缓存和恢复。HUHU 自动生成的文件夹和文件名不含空格，用 `-` 连接（例如 `2026-10-21-1654-新备忘.md`）。普通笔记、宿主自己的数据与 Git 自有元数据保留原位置。系统 CLI 账号、状态 Hook、导航器 IndexedDB 缓存和用户指定导出另有明确边界，见[库之外的数据](#库之外的数据)。插件安装目录只保留代码、清单、样式及发行许可声明，不存放用户数据。

## 库内路径规则

库内逻辑路径统一使用 `/`，相对当前打开的 vault；Windows 的 `\` 在路径入口转换，后续目录识别、索引键、事件、队列及读写均使用转换后的值。系统盘符路径和 UNC 根目录只交给桌面文件系统适配层，不写入库内路径字段。普通笔记保留宿主的文件名规则，HUHU 私有目录继续采用跨平台的严格校验；不会通过折叠 `..`、截断绝对路径或删除非法字符来放行输入。`.huhu` 内的符号链接和 Windows junction 不得将读写重定向到其他位置。

看板设置与页面状态保存完整的 `.huhu/dashboards/名称` 引用（无扩展名），读写时统一转换成 `.huhu/dashboards/名称.md`；文件名扩展名固定为 `.md`。路径缺省时使用默认看板，显式非法引用直接报错，不推测裸名称、不映射旧目录，也不清空配置或覆盖其他文件。隐藏文档接口只允许看板和自动化定义，私有配置及恢复文件不能回落为普通笔记读写。

## 私有文件权限

桌面 POSIX 路径以 `0700` 创建目录、`0600` 创建普通文件，helper 使用 `0700`。账号及 helper 私有目录在 Windows 通过 DACL 限定为当前用户与 SYSTEM；权限失败阻止交付进程。交付前检查当前子树并拒绝链接，迁移保留恢复来源。访问控制不等于加密，也不会阻止你同步文件。普通笔记保持原权限；移动端和非文件系统适配器的具体权限行为据实说明，不冒称已实测。

## 库之外的数据

默认的“系统账号”不重定向 HOME、提供方数据根或 XDG/Windows 数据目录，CLI 沿用本机已有登录。HUHU 的运行事件保存在库内；开启状态 Hook 或自动化运行所需 Hook 时，会在 `~/.huhu/agent-hooks/` 保存共用脚本与备份，并修改真实提供方配置中的约定条目或扩展文件。它们不会随关库自动移除，具体范围和移除操作见[智能体工作台](agent-workbench.md#状态-hook)。

“托管账号”使用库内的 HOME、提供方配置目录、XDG/Windows 数据目录和临时目录，状态 Hook 与事件文件同属账号。浏览器 Cookie、站点数据、缓存、下载与抓取附件也进入库内设备/profile 或 artifacts 目录。库外 CLI homes 不自动搬迁；托管账号不回退到系统账号，也不复制系统登录。

继续历史会话时，HUHU 在用户级操作系统应用状态目录保存“原生引用占用”记录：Linux 为 `$XDG_STATE_HOME/huhu/native-refs/`（默认 `~/.local/state/huhu/native-refs/`），Windows 为 `%LOCALAPPDATA%\HUHU\native-refs\`，macOS 为 `~/Library/Application Support/HUHU/native-refs/`。它用来保证同一条原生对话在本机至多一个 HUHU 可写运行，跨 HUHU 实例和不同的库都有效；以提供方真实存储位置里的转录文件路径加原生会话 ID 为键，不含库的设备标识。它特意放在库外，因为库可能被同步，也不放在主目录的点目录里，避免以主目录为库时被同步。每条记录是一个很小的 JSON 文件，只含 Provider、原生会话 ID、转录路径的摘要键、占用它的库/Space/Session/运行代次与实例标识、进程号与启动标记、主机名和时间，不含对话正文、凭据或环境变量。运行被核实退出时删除；关闭 Agent 模块时，在运行时停止后只删除确认已结束的记录，未能确认的保留。占用进程已不存在，或进程号被别的进程复用时，其他实例会接管，异常退出残留的记录和临时文件会被自动清理。插件被重新加载时，上一次加载仍保留着尚未确认结束的占用：它在进程内一直登记为存活，直到它确认退出并释放了全部占用之后，同一进程里的新加载才会把这些记录视为失效；在此之前新加载按冲突处理。若运行的退出在模块完全关闭之前得到确认，占用会被释放并取消登记；否则该占用保留到 Obsidian 退出为止。
已知限制：跨主机（主目录经网络共享）的记录、macOS 上主机名随网络变化后的旧记录，以及 Windows 上没有启动时间标记的进程号复用，都无法自动证实占用者已不存在，会按冲突处理。只有在确认没有任何 HUHU 实例（包括其他库的窗口）正在运行相关对话时，才可以手动删除该目录或其中的 `.lock` 文件；仍有运行时删除会让同一对话可能被两个实例同时继续。备份或迁移库时不需要带上它，它也不会随库同步。

导航器的可重建预览缓存使用宿主 IndexedDB，不在库目录内；保险箱加密导出写入你通过原生选择器指定的路径，可以位于库外。普通笔记虽保留原位，导航器的模板、周期笔记、合并与标签操作仍会按你的操作创建或修改它们。“保留原位”不表示这些笔记只读。

设备映射位于 `.huhu/config/identity.json`，利用宿主只读身份识别当前设备。复制库需要识别或明确选择设备归属，不会自动接管另一设备的运行队列。普通笔记、宿主配置、系统 IPC 对象与 Git 自有元数据不是 HUHU 业务数据。

### 空间与目录授权

在智能体侧栏新建空间时，先保存名称与目录；空空间不会启动终端、智能体或辅助程序。同名、同目录的空间也有独立 ID、会话和布局。重命名不会改变身份。新终端先保存会话记录，再核对目录与写入权；保存或回读失败不会启动关联新进程。重开只恢复记录与非活动布局，不自动启动旧终端。

库内目录使用相对路径，留空代表库根。库外目录只能通过所属窗口的原生目录选择器选择，并在保存表单时明确授权；取消选择或表单不保存授权。授权绑定当前设备、物理库与真实目录，符号链接/junction 改向、目录替换或授权撤销后拒绝启动与继续；不会降级到库根或主目录。目录绑定不是操作系统沙箱。

v2 记录由当前 TypeScript 进程懒取得一个本机排他监听来保护写入；查询、打开空页面和目录选择不监听，也不启动 helper。监听仅用于合作实例的单 writer 互斥，不提供命令服务：同一物理库和设备使用同一确定端口；端口占用或碰撞明确冲突，不自动换端口、删除旧锁或按 PID/时间抢占。正常关闭先排空已接纳持久写入再释放，进程崩溃由系统释放监听；重新打开后仍占用时应先核对另一实例或本机端口。端口由物理库与设备的确定性散列落在 16384–65535 之间；若本机另一个无关程序恰好占着该端口，这个库的 Space 写入会以 `OWNER_CONFLICT`（原因 `port-in-use`）安全失败，不会换端口。处理办法：先用系统的端口占用查询找到占用者并释放端口；若占用者是另一个 HUHU 窗口则关闭它。重启 Obsidian 只在占用者是短暂程序或残留的旧 HUHU 进程时有效，长期占用的无关程序不会因重启而消失。该机制不防御同账号恶意进程。

旧工作台迁移（仅桌面端，首次启动新版时自动执行一次）：先在任何模块读取这些文件之前完成未竟操作的恢复；然后在同一物理库的独占 writer 监听保护下，保存来源与被替换文件的可回读恢复副本和事务日志，再把旧 `workspace.json` 的标签、分组、分屏和已关闭标签原样放入一个新的“导入空间 · 旧工作台”（目录为库根），最后写入 `legacy-import.json`。已有同目录的 Space 不会被合并或修改，已有记录和当前选择保持不变；`workbench-v2.json` 缺失之外的任何情况（损坏、新版本、属于别的库或设备、仅剩备份）都会拒绝并保留原件，不会用默认空对象覆盖。无法归属账号的历史标注（不是“智能体、账号、会话”三段键）与已退役的账号总索引 `index.sqlite` 原地保留并写入报告，不迁移其内容；凭据与原生日志从不移动。同一来源摘要重复启动不会重复导入，导入后旧文件又被旧版本写入只会提示“来源已变化”而不再导入。另一个 HUHU 窗口持有 writer 时导入推迟到下次启动。

进程中断（崩溃、被强制结束）或磁盘写满后，下一次启动在业务读取前依据事务日志把相关文件整体恢复为旧版本或整体采用新版本，不会出现新旧混合；恢复本身再次中断可重复执行。写入使用普通的就地写入加读回核对，不做 fsync 和原子重命名，所以真正的断电可能让某个文件的数据没有落盘：此时摘要核对会发现不一致，HUHU 保持恢复门、停止启动并提示，不会拿不完整的数据继续写；这种情况需要你用 `.huhu/recovery/transaction/` 里的恢复副本手动恢复。无法确定时同样保持恢复门，不覆盖任何数据。回退：先退出 Obsidian 并备份整个 `.huhu/terminal-agent`（其中已有新空间），再安装旧版本；旧版本不认识新格式，之后在新旧两版之间不做逆向转换。设置页“旧数据导入”页签显示报告；导入被拒绝或失败（库被复制或移动、`workbench-v2.json` 损坏、状态文件不可读、另一个窗口占用）时，页签会说明原因和下一步，而不是显示“没有旧数据”。旧布局文件损坏或来自新版本时，导入只保留原件；修复 `workspace.json` 后若要重新导入，先退出 Obsidian，删除同目录的 `legacy-import.json`，再启动。

其他模块要复用同一恢复协议，在应用的 `recovery` 主机注册自己的文件 owner（预检、关闭写入口、严格排空、采用重载、释放），详见[智能体工作台](agent-workbench.md#旧工作台迁移与恢复协议)。

新 v2 不覆盖旧 `workspace.json`；业务入口（看板按钮、技能按钮、快捷命令、一次性运行、自动化智能体/脚本操作）已要求明确的 Space，旧定义保持未绑定并等待你选择。当前模块内缺少明确目标的创建入口会要求选择空间，即使只有一个候选也不会猜测。无空间时网页仍可打开。遇到不支持的新版本或损坏且无有效备份的数据时保留原件，停止写入并显示错误；有效备份的恢复写入也受同一 writer 保护。

## 多设备与同步

`.huhu/` 以点开头，**Obsidian Sync 不同步这类隐藏目录**；宿主配置目录是官方列出的例外，`.huhu/` 不属于它（见 [Obsidian 官方说明](https://obsidian.md/help/sync/settings) 的 Hidden files and folders）。所以 `.huhu/dashboards/` 中的看板和 `.huhu/automation/definitions/` 中的自动化操作，以及 `.huhu/` 下的其他 HUHU 专用数据（含加密的保险箱）不会经 Obsidian Sync 到达另一台设备；库内可见的 `huhu/` 下的日志、闪念、收件箱、档案、记账等记录和其他笔记不受这一排除规则影响。需要同步 HUHU 专用数据时，请使用并核对能同步隐藏目录的工具：Git、iCloud、Syncthing 等。桌面端可以使用 HUHU 的 [Git 同步](sync.md)，其私有数据排除范围见下文。

- `.huhu/config/settings.json` 由库的所有设备共用；`.huhu/config/devices/<device-id>.json` 和各模块的 `<device-id>` 目录只属于一台设备，按设备隔离。用 HUHU 的 Git 同步时，这些设备配置、身份映射、同步计时和通知状态不跟踪；浏览器会话、智能体账号与运行目录、缓存、恢复副本和锁文件等设备私有数据默认不提交（见[Git 同步](sync.md#默认不提交的-huhu-私有数据)）。
- 自动化只在它所属的设备上运行，见[自动化与通知](automation.md#设备归属)。
- 使用共享 `JsonStore` 的设置和 JSON 数据在写入前做三方合并，并保留上一份有效内容为 `.backup`。保险箱是独立密文协议，不执行自动合并；图标、批注、内容移动和看板也有各自的恢复规则。同步工具产生的冲突副本仍需手动处理。

## 日常备份

1. 在编辑器和面板中完成保存，确认没有“未保存”或“存在冲突”的状态。
2. 备份你的 Markdown、相关附件和整个 `.huhu/` 目录。备份工具需要包含隐藏目录。
3. 恢复前，先关闭相关模块，保留当前出问题的文件副本，再恢复确认有效的内容和设置。
4. 重新开启模块后检查内容和设备设置。不要为了让功能恢复运行而重放被中断的外部操作。

缓存和索引可以重建。实体正文、业务记录、评论和通知回执不能当作缓存清理。浏览器会话与托管 CLI 账号在 `.huhu/` 中，应按敏感数据备份；系统账号沿用库外位置。登录状态跨设备不保证可用，可能需要重新认证。

## 业务备份与恢复

设置 → 智能体 → “备份”导出和导入 HUHU 自有的业务数据。导出文件是一个可读的 JSON，放在库内 `.huhu/exports/`；它含你的业务数据，Git 同步默认不会提交该目录，其他同步工具则会同步它，请在需要时把它移到私密位置。

- **包含**：智能体设置（可携带部分）、Space 与会话、布局、被动邮箱与确认、历史标题与备注、自有用量统计、自动化会话引用、自动化运行/调用/结果、通知及其已读与投递回执（含已清除记录的去重墓碑）、自动化定义。
- **导出完整性**：主文件缺失而 `.backup` 有效时，包含备份里的数据；无法确认有效内容时明确拒绝。读取期间再次核对设备目录、定义文件清单、已有文件及缺失路径，检测到外部新增、删除或内容变化便中止。导入只重新绑定业务记录所属的库和设备，原生会话引用的来源设备、账号、会话和定位信息保持原样。
- **明确不含**，并在导出清单与导入界面逐项列出：Provider 的对话全文、账号凭证与账号目录、环境变量的值、启动参数、缓存与索引、运行中的端点/锁/终端、浏览器 Cookie 与下载、辅助程序、你的 YOLO 确认、本机程序/Shell/技能目录路径、库外目录的授权、旧统计文件，以及自动化所指向的笔记。原生会话缺失时界面只给出说明和显式继续入口，不会自动启动任何智能体。
- **导入前检查**：校验版本、结构、每个数据集的摘要与整包摘要，再逐项检查身份冲突、目录是否存在、库外目录授权。你确认范围后才会改动数据。目标已有不同内容的非空数据一律拒绝（不合并、不覆盖、不改名）；“非空”包括无 Space 的网页布局、目录授权、历史归属和当前选择，也包括主文件缺失但 `.backup` 仍有效的数据；空数据集会被填充，同时刷新同名 `.backup`；内容完全相同视为已完成。可携带的智能体设置在导出和导入边界都使用递归字段白名单；包里的 Shell、环境变量、程序与技能目录字段不会替换本机配置。有效权限也不会因“继承全局”而升高。白名单字段替换你设置里的同名项，其余设置不动，被替换的文件有恢复副本。自动化定义在写入前用自动化模块自己的仓储解码器逐份检查，无法读取的定义（例如来自更新版本的未知动作）会在写入前整体拒绝。
- **库外目录**需要在目标机器重新授权；库内目录若在本机不存在则导入被拒绝，你可以选择把这类 Space 导入为“已归档”。
- **导入不会运行任何东西**：不会启动智能体、终端、自动化、定时任务，不会发送通知，也不会补发历史通知。包里仍在运行的任务以“已中断”的历史呈现；自动化定义全部以停用状态到达，原先启用的名单显示在“上次导入”里，由你明确重新启用；权限模式不会被悄悄升到 YOLO。
- **冻结与取消**：已有自动化定义的保存、删除或来源更新尚未完成时，导入与导出返回忙碌，待它们收束后再操作。设置在恢复冻结期间会在修改内存与通知界面前拒绝新操作，排空不会临时开放入口。每步提交前的冻结、排空和暂存默认最多等待 30 秒，也可在页面取消；本步骤未替换数据时中止，已有保存可能仍在收束，新恢复会被拒绝直到它完成。同一库重新开启插件时，启动恢复和模块加载也会检查尚未收束的旧保存，不能绕过这道门禁。已经进入替换的步骤继续完成原子提交；多步导入保留此前完成的步骤。
- **失败与恢复**：每次替换前，被改动的文件都有已校验的恢复副本（`.huhu/recovery/transaction/`）和事务日志。写入失败会回到原状；进程中途被终止时，下次启动先完成或撤销，再加载任何业务数据。大批量定义会分成几次事务（先定义，最后才是核心数据），每完成一步就把进度（目标设备、包摘要、选项、每个已写文件的摘要）记在 `.huhu/recovery/backup-import/progress.json`；中断后重新运行同一导入会跳过已完成的步骤，且这些步骤已写的文件原样保留：之后被你改动的文件不会被重新写入（报告里提示“已改动”），被你删除的文件不会重新创建（报告里提示“已删除”）；只有一个步骤记录的文件全部不存在（记录不可信，例如被篡改）时该步骤才会重新执行。重启 Obsidian 也不会让重试被拒绝；尚未执行的步骤仍照常检查冲突。完成后进度文件被清除。
- 当前范围：设备范围内可枚举到的数据，不是整个库的镜像；移动端不提供 Space 恢复。真实 Obsidian 中两个一次性库的往返、来源缺失提示与目录授权流程需要你在真实宿主验收。

## 保存失败与冲突

读取失败、已损坏的文件或无法解析的受管区域会阻止写入。使用共享 `JsonStore` 的文件会保留上一份有效快照为 `.backup`；主文件损坏而备份有效时，加载备份并保留损坏主文件，没有有效备份则报告错误，不覆盖原文件。这不适用于所有持久化格式：图标使用自己的[备份轮换](icons.md#数据备份与关闭模块)，保险箱需要[显式认证恢复](safe.md)，不会自动回退备份。磁盘错误不会被显示为保存成功。

出现错误时，先保留当前输入，再检查权限、同步冲突和文件内容。支持重试的面板提供错误详情和重试；恢复草稿位于 `.huhu/recovery/drafts/`。档案冲突时，先复制草稿，再重新载入原始资料；草稿 JSON 不是可直接导入的 Markdown。

采用三方合并的存储可以合并不同字段或记录的修改，同字段冲突仍需你决定；保险箱会保全冲突密文并停止覆盖。原始笔记有未保存编辑时，请先保存编辑器。受管文件删除使用下面的恢复区机制。

## 受管内容删除与恢复

`.huhu/dashboards/` 与 `.huhu/automation/definitions/` 内的受管文件或目录删除前会检查范围、路径及未保存编辑，再移动到 `.huhu/recovery/trash/<随机 ID>/`。单文件保留在该批次目录内，目录保留其相对 `.huhu/` 的结构；这与 Obsidian 回收站分开。可见 `huhu/` 与其他目录中的档案和普通笔记通过 Obsidian 的删除接口处理，遵循宿主设置，详见[档案](contacts.md#删除与恢复)。保险箱记录使用自己的加密回收站，见[保险箱](safe.md)。

当前没有统一的受管回收站恢复界面。需要手工恢复时先停止相关编辑并备份当前内容，核对原路径和目标是否已存在，再把保存的文件或完整目录放回上述受管根内的原位置；不要覆盖同名新内容。`.huhu/content-moves/manifest.json` 及 `recovery/renames/` 是移动/引用更新的恢复材料，不应当作可随意清理的缓存。

## 看板冲突

外部编辑与看板保存发生冲突时，HUHU 暂停写入原看板，并把恢复副本保存到 `.huhu/recovery/dashboard/conflicts/<id>.json`。提示中显示实际的文件路径。“副本已保存”不表示修改已写入原文；继续编辑会更新同一冲突的最新修订。

看板上的状态区提供“复制当前草稿”“复制副本路径”“重试保存”和“重新载入原文”。副本保存失败时页面保持打开：先复制草稿，修复磁盘或权限后再重试。重新载入需要确认，并保留恢复副本。副本是包含原始、当前和外部文本的 JSON，不能当作看板 Markdown 去覆盖看板。强制结束进程或磁盘不可写时，不能保证尚未落盘的输入被保存。

## 格式与语言

图片裁剪位置保存在看板 Markdown 中：卡片的 `coverPos` 行保存封面位置，格式是 `"x,y"` 字符串。坐标是 0 到 100 的整数百分比，未设置时为 `50,50`。只读时仅对显示归一化，越界值限制在范围内，无效值按居中显示，不自动改写原文。编辑或重置某张图片只改它的位置，图片文件本身不变。

语言设置只影响界面，从不改变文件路径、身份标识、笔记正文或操作参数。

旧看板的备忘与网页卡迁移到收件箱时，使用稳定迁移标记及目标文件名，先写入并读回核对，再移除看板中的旧卡。重试复用同一目标，已被用户改写的目标不会覆盖。快捷操作保存于各看板的 `quickActions`，旧全局快捷命令和快速笔记配置只在该看板首次合并时复制。

天气缓存位于 `.huhu/cache/weather/`，仅缓存所选坐标的公开预报，不属于可同步的业务内容。工作空间用量索引与历史抽屉共用 `workspace-index.sqlite`，账号级 `index.sqlite` 已停止写入（可安全删除），当前 Vault 投影是唯一的历史索引。

OpenCode 的历史存放在库外的 `opencode.db`。读取时 helper 把数据库及 WAL 复制到系统临时目录里的一次性只读副本再打开，源文件及其目录不会被 SQLite 打开或写入，副本在读取结束后立即删除；若进程被强杀，副本可能短暂残留在临时目录，其中含该 Provider 全部项目的对话，属于库外的敏感数据，不属于 Vault 备份范围。

## 新身份与版本边界

HUHU 从 0.0.1 及新的插件身份开始，仅使用 huhu/ 和 .huhu/ 目录，不自动读取、导入或改写其他插件身份的数据。已有笔记保留原位，显式选择的内容目录仍按当前路径规则处理。
