# 保险箱

保险箱用独立主密码保存网址、账号、密码和备注。每个 Obsidian 库只有一个保险箱，入口在工作台左侧图标栏，也可运行「打开保险箱」。模块默认开启、按需加载；第一次设置主密码之前不会创建数据文件。目前仅支持桌面端。

## 创建与使用

1. 打开保险箱，输入两次相同的非空主密码。主密码没有固定长度区间；大小写、空格和有效 Unicode 字符形式都保留原样，不裁剪、归一化或截断。建议使用独立、足够长的主密码，但建议不阻止继续。账号记录里的密码仍采用下方独立字段规则。
2. 点击「新增条目」。一个条目有标题、网址、图标和备注，下面是一个或多个**账号**：每个账号是一块「用户名 + 密码 + 备注」，可以添加、删除和上下移动。例如「苹果账号」条目下可以有多个 Apple ID，各有自己的备注。至少保留一个账号，一个条目最多 50 个账号。
3. 点击「保存」。只有密文写入并回读核对成功后，界面才认为保存完成。正在编辑的表单不会自动保存。
4. 列表显示条目、网址和账号数量；多账号条目点开数量按钮即可逐个查看账号，用户名和密码的复制按钮就在账号旁边。密码默认遮罩，显示和复制需要主动操作；备注只作为纯文本显示，不加载网页图标或其他远程资源。

右上角可在**列表**和**卡片**两种视图间切换，选择按设备记住。

字段上限：标题 200、网址 2048、用户名 512、密码 4096、备注 32768 个 Unicode 码点（条目备注和每个账号的备注各自计算）。用户名和密码不能为空，前后空格不裁剪。全部记录序列化后的 UTF-8 明文最多 5 MiB；读取密文文件最多 10 MiB，超限会提示错误，不截断内容。

网址只在点击「打开网址」后交给系统浏览器。没有协议的有效域名会补 `https://`；仅允许 HTTP(S)，不会把无效输入发送给搜索引擎。这个操作不自动填写或发送账号、密码。

### 图标

条目可以上传自己的图标（PNG、JPEG、WebP 或 GIF，8 MB 以内）。图片在内存中裁成 64 像素的方块，以小图片数据保存在加密载荷里，不会以明文落盘。没有自定义图标时显示首字母和稳定的主题配色块；HUHU 不联网获取网站图标，因为那会向网络泄露保险箱里有哪些网站。

## 搜索

解锁后可以按条目的标题、网址、备注，以及每个账号的用户名和备注搜索。搜索不区分大小写，使用子串匹配，支持中文；用空格分隔多个关键词时，每个关键词都必须在至少一个可搜索字段中出现。密码字段不参与搜索。

搜索只在当前内存中进行。不会写入搜索索引、工作台路由、设置或全局搜索，也不向智能体或自动化暴露记录。

## 锁定与未保存内容

在「设置 → 保险箱」选择何时锁定：

| 设置 | 选项 | 默认 |
|---|---|---|
| 未操作多久后锁定 | 5 分钟、20 分钟、60 分钟、自定义（1～10080 分钟）、永不 | 20 分钟 |
| 切换到其他页面或标签时锁定（Obsidian 窗口被隐藏时同样适用） | 开 / 关 | 关 |
| 关闭保险箱页面时锁定（关闭任一保险箱页面都会锁定整个保险箱） | 开 / 关 | 关 |
| 关闭 Obsidian 或卸载插件时锁定 | 始终开启，不能关闭 | 开 |

- 点击「立即锁定」或运行「锁定保险箱」命令可立即锁定。
- 更改立即作用于已解锁的保险箱，空闲时间从最后一次操作起算。窗口重新获得焦点和每次敏感动作前也会检查到期时间，所以计时器被系统延迟也不会延长会话。选「永不」时没有到期时间，直到手动锁定或关闭 Obsidian。
- 把保险箱页面移到另一个窗口会重建页面，会话不带过去，一定锁定。所有页面和分屏共享同一解锁会话。
- 锁定页和已解锁页底部的提示按设置显示实际规则。
- 打开原生文件选择框、切到其他程序复制内容产生的普通失焦，不会立即锁定。

表单内点击关闭或锁定时，有修改会询问保存或放弃。锁定会直接清除未保存草稿，因此编辑区持续显示提醒。锁定清除页面、搜索、表单和服务中的明文引用及解密密钥；JavaScript 和操作系统不保证这些字节已从物理内存擦除。

如果保存已经完成加密并进入文件提交阶段，锁定后可以继续提交这一份密文；尚未到达该阶段的保存会取消。迟到的解密、文件选择和保存结果不能重新打开已经锁定的页面。

## 复制

复制账号或密码后，30 秒内如果剪贴板仍然是这一次复制的文本，HUHU 会尝试清空；锁定时也会尝试清空。后续复制会替换先前的清理任务。HUHU 不保存密码到清理计时器，只保留此次复制的指纹和操作标识。

系统剪贴板没有原子的「比较后清空」操作，检查和清除之间仍可能发生其他程序复制的竞争。剪贴板不可用时会给出固定错误提示；清理属于尽力执行，不能删除系统剪贴板历史或其他程序已经读取的内容。

## 回收站

删除记录先移入保险箱里的回收站，可以恢复或明确确认永久删除。回收站同样加密。下次解锁时，删除满 30 天的记录会通过正常的密文保存流程清理；清理失败会提示，已经验证的记录仍可以读取。

永久删除只影响当前保险箱。旧备份、冲突副本、导出文件、文件同步历史和 Git 历史可能仍含这条记录，不代表安全擦除。

## 修改主密码

在保险箱操作菜单中选择「修改主密码」，输入当前主密码和两次新主密码。修改会生成新的盐和新的随机数据密钥，对全部记录重新加密；保存成功后自动锁定，使用新主密码再次解锁。

修改主密码不会修改网站上的密码，也不能撤销已被复制的旧文件。旧备份仍需当时的旧主密码才能打开。

创建、修改、重新解锁、验证备份、导入和恢复采用同一套非空主密码规则。密文格式、算法与主文件位置未因取消长度区间而变化。

## 备份、恢复与冲突

保险箱文件位于 `.huhu/safe/`：

| 文件 | 内容 |
|---|---|
| `vault.enc` | 当前完整加密容器 |
| `vault.enc.backup` | 上一次提交前的完整加密容器；创建时先保存有效初始备份 |
| `.tmp-<随机 ID>` | 同目录原子替换过程中使用的临时密文文件 |
| `conflict-<随机 ID>.enc` | 检测到外部修改后保留的本次完整密文候选 |
| `preserved-<随机 ID>.enc` | 手动恢复前保留的当前主文件原始内容 |

「导出加密备份」导出最后一次成功保存的完整密文，不包含未保存草稿。导出位置由你选择，可以在库外；不能覆盖当前 `.huhu/safe/` 及其文件别名。文件名只使用产品名称、日期和随机标识。

### 导入备份（合并）

操作菜单里的「导入加密备份（合并）」把备份中的条目**加入**当前保险箱，不替换任何内容。选择文件、输入创建该备份时的主密码并验证后，会先预览结果，确认后才写入。写入之前，当前保险箱的完整密文先另存为 `preimport-<随机 ID>.enc`；这些副本不会自动删除。规则：

- 条目先按 ID、再按「标题 + 网址」匹配当前未删除的条目。标题忽略大小写和首尾空格；网址忽略协议、`www.`、大小写和结尾斜杠；标题和网址都为空的条目只按 ID 匹配。
- 匹配到的条目合并账号：用户名相同且密码、备注都相同的账号只保留一份（跳过）；用户名相同但密码或备注不同，保留更新时间较新的那一个（时间相同保留当前的）；用户名不同的账号追加在后面。条目的图标或备注为空时用备份的补上，其余条目字段保留当前值。
- 没有匹配的条目作为新条目加入，保留原时间；ID 已被占用时换新 ID。备份回收站里的条目不导入。
- 备份里两个标题和网址相同的条目也会合并成一个。
- 结果会列出新增、合并（新增和更新的账号数）、跳过的数量；没有任何新内容时不写文件。重复导入同一个备份不会产生变化。
- 旧版（每条记录一个账号）的备份同样可以导入。

「用备份替换保险箱」仍然可用，是明确的危险操作：验证备份后还要在页内勾选确认，才能点击「恢复并替换」。锁定页也可以使用它。恢复前保存当前主文件的独立副本（`preserved-<随机 ID>.enc`），不覆盖唯一可用的 `.backup`。恢复结束保持锁定。文件缺失与读取失败严格区分；有备份而主文件缺失时不会初始化一个新的空保险箱。

保险箱文件位于 `.huhu/safe/`：

| 文件 | 内容 |
|---|---|
| `vault.enc` | 当前完整加密容器 |
| `vault.enc.backup` | 上一次提交前的完整加密容器；创建时先保存有效初始备份 |
| `.tmp-<随机 ID>` | 同目录原子替换过程中使用的临时密文文件 |
| `conflict-<随机 ID>.enc` | 检测到外部修改后保留的本次完整密文候选 |
| `preserved-<随机 ID>.enc` | 手动替换前保留的当前主文件原始内容 |
| `preupgrade-<随机 ID>.enc` | 数据结构升级前的原始密文（见下） |
| `preimport-<随机 ID>.enc` | 合并导入前的当前密文 |

如果读取时发现超过 10 MiB、非 UTF-8 字节或权限错误，HUHU 无法取得可比较的原始字符串基线，会停止覆盖。先在文件系统中完整保留原文件，排除权限问题或把损坏主文件移到安全位置，再从有效备份恢复；程序不会自动删除不可读文件。

每次保存都会比较之前读取的主文件原始字节，发现外部变化则停止覆盖。只有冲突副本写入并回读成功后才提示已保留；保全失败时明确提示未保存。修改主密码时生成的冲突副本使用新主密码。

同一目录的 `.backup` 不能应对整盘损坏，应另外导出并备份。Obsidian Sync 不包含 `.huhu/`；如使用 Git 或文件同步工具，需要显式包含隐藏目录。当前只支持一个 HUHU 写入端，不提供跨设备自动合并或跨进程原子比较交换。切换设备前先锁定、完成文件同步；冲突时手动选择正确副本恢复。

忘记主密码后不能重置并保留内容。只有仍记得对应密码的旧备份可以恢复。

## 加密格式与保护范围

容器格式固定为 `huhu-safe` version 1，没有算法切换开关。容器内的明文数据结构有版本：第一版每条记录一个账号，当前版本每个条目含多个账号。

| 项目 | 实现 |
|---|---|
| 主密码派生 | Web Crypto PBKDF2-HMAC-SHA-256，600000 次迭代，16 字节随机盐 |
| 数据密钥 | 32 字节独立随机密钥，运行期间以不可导出的 CryptoKey 持有 |
| 密钥包裹 | 派生密钥使用 AES-256-GCM 加密原始数据密钥 |
| 内容加密 | 数据密钥使用 AES-256-GCM 加密整个记录数组 |
| IV 与认证标签 | 每次实际加密重新生成 12 字节 IV，128 位认证标签 |
| 附加认证数据 | 固定格式/version、随机保险箱 ID，以及 key/payload 的用途标记 |

标题、网址、图标、用户名、密码、备注、记录 ID、时间和删除状态全部位于加密载荷中。公开头部只包含读取格式需要的算法参数、盐、IV、随机保险箱 ID 和密文；文件存在、大小和文件系统时间仍然可见。无需第二份主密码校验哈希；认证失败不会暴露具体内容。

这项加密保护静态文件和备份。它不能隔离同一 Obsidian 进程中的恶意插件，不能阻止已解锁设备上的截图、输入监听、其他程序读取剪贴板，也不检测把文件回退到较早的有效版本。使用可信插件并保护设备本身。

### 从第一版升级

用主密码解锁旧保险箱时，HUHU 在内存里把每条旧记录变成一个只有一个账号的条目：ID、时间、回收站状态、标题和网址不变，用户名、密码和备注（备注属于该账号）原样保留，没有字段丢失。随后：

1. 把升级前的原始密文另存为 `preupgrade-<随机 ID>.enc`（写入并回读核对成功才继续），它仍可被旧版和当前版用原主密码打开；
2. 容器的盐、迭代次数、保险箱 ID、被包裹的数据密钥和 AAD 都不变，只用新的随机 IV 重新加密载荷；
3. 如果升级写入失败，记录仍可查看，旧文件保持原样，下一次保存会重试并同样先保留原始密文；界面会提示。

旧版程序打开新结构会报格式无效而不会覆盖。`preupgrade` 副本不会自动删除，确认无误后可自行清理。

本版本不包含手机解锁、自动填充、密码生成器、TOTP、附件、共享、CSV/KDBX 导入、生物识别或恢复密钥。
