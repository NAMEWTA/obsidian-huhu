# 任务待办

Task 是独立模块，不需要打开看板。工作台的「任务待办」入口与「打开任务工作台」「新建任务」命令可直接使用；看板中的任务小组件只是同一任务库的紧凑视图。

## 创建与时间

新建任务时填写标题，可选说明、事项截止日期、具体截止时刻、时区、计划处理日和提醒时间。创建时间由系统记录，不能通过改截止日期覆盖。

例如：9 月 20 日创建，9 月 30 日截止，9 月 25 日 09:00 提醒。提醒按任务的时区解释，是独立的时间点；有截止时间时，提醒不能晚于截止点。未填写时刻的截止日期按该时区当日结束计算。

可关联多份笔记、具体文件、文件夹或实体档案。关联不改变任务存放位置，不会把任务强行插入关联笔记。对象失效或对应模块停用时保留任务及引用，提供修复提示。

## 分类与过期

“全部”包含已完成和未完成；“未完成”包含已过期；“已过期”只列出未完成且超过原截止日/时刻的任务。完整页面可以搜索、按处理/截止/创建/提醒/完成时间查看和排序，并设置日期范围。

超过截止仍未完成，任务显示「未完成 · 已过期」，自动承接到当前处理日，原截止时间保持不变。次日继续承接，不会创建另一条任务。显式设置未来计划处理日时尊重该安排，但不会抹除逾期状态。

完成后停止提醒，可重新打开；重新打开不会补发已经过去的提醒。取消需确认，保留历史但退出普通任务列表，不会删除关联文件。

## 提醒与重复

提醒和重复计划使用自动化模块。每天、工作日、每周、每月、每年及自定义 Cron 均支持时区与结束日期，每次发生独立完成。编辑或取消重复任务时可以选择「仅本次」或「本次及以后」。查看未来预览本身不写文件；明确操作预览时才创建对应真实实例。

Obsidian 关闭期间插件不运行系统后台定时器；重新打开后恢复错过的实例并处理仍有效的提醒。自动化不可用时会提示，任务本身仍可管理。

## 数据与接口

Task 主数据是可见文件 `huhu/任务/tasks.json`。任务、系列、历史和幂等回执一起原子保存。备份时保留整个文件；损坏或格式版本不支持时拒绝覆盖。多设备离线同时改动仍需同步层处理冲突，不能手动丢弃回执或历史后声称完整恢复。

这是无兼容层的重构：旧看板/日记/待办 Markdown 复选框不自动加入新 Task 库，旧文件不自动迁移，也不会被删除。新自动化的「创建任务」直接写入 Task，不再选择看板或任务卡。

开发与 AI 集成使用 `src/modules/task/api.ts` 的服务和版本化工具，详情见 [Task 领域设计](task-domain.md)。当前提供进程内工具，不自动开放网络接口；可信 Agent 宿主必须另外负责授权与审批。
